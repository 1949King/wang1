## 一、先记住一个「家谱」

整个剪辑界面就像一个**大管家**（`EditorModule`），它手下有 4 个主要"部门"：

| 部门 | 代码里的名字 | 小白比喻 |
|---|---|---|
| 工具栏 | `_create_toolbar()`（572 行） | 你点按钮的地方，像遥控器 |
| 事件绑定 | `btn.clicked.connect(...)` | 遥控器按键 → 对应的动作 |
| 核心逻辑 | `_cut_clip` / `_delete_clip_by_id` 等 | 真正干活的"手" |
| 撤销栈 | `_record_action` / `_undo` / `_redo` | 后悔药，能反悔每一步 |

## 二、第一站：工具栏（遥控器）—— 572 行

```python
def _create_toolbar(self) -> QWidget:
    toolbar = QFrame()                       # 一条横条
    actions = [                              # 按钮清单：名字 + 按下后干啥
        ("📁 导入", self._import_video),
        ("✂️ 剪切", self._cut_clip),
        ("📋 复制", self._copy_clip),
        ("📄 粘贴", self._paste_clip),
        ("🗑️ 删除", self._delete_clip),
        ("🔄 撤销", self._undo, "undo"),
        ("🔄 重做", self._redo, "redo"),
    ]
    for text, callback in actions:           # 循环：每个按钮都造出来
        btn = QPushButton(text)              # 造一个按钮
        btn.clicked.connect(callback)        # 关键！"被点击"就连到对应动作
        layout.addWidget(btn)                # 摆到横条上
```

**小白一句话**：工具栏就是"列出按钮 + 告诉每个按钮：你被点时要去叫谁"。

## 三、第二站：事件绑定（按键 → 动作）—— 620 行

```python
btn.clicked.connect(callback)
```

这句话是整个界面的"神经"。`connect` 的意思是：
> 当这个按钮被点一下，就去执行 `callback` 这个函数。

比如"✂️ 剪切"按钮连着 `self._cut_clip`，所以你一点剪切，程序就跑进 `_cut_clip` 里。

> 🔗 对应 BYOX 主题：**前端框架 / 库**。React/Vue 也是"状态变了 → 界面更新"，原理一模一样，只是人家用的是框架，咱们用的是 PyQt 手写。

## 四、第三站：核心逻辑（真正干活的"手"）

以"剪切"为例，点完按钮跑到这里（`_cut_clip`，7350 行）：

```python
def _cut_clip(self):
    """在播放头位置切分当前片段。"""
    if not self._current_clip:                     # ① 你还没选中片段？
        QMessageBox.warning(self, "剪切", "请先选择一个片段")
        return                                      #    直接退出，不干活
    playhead = float(getattr(self, '_playhead_position', 0))  # ② 播放头在哪（秒）
    clip_start = float(self._current_clip.get("start_time", 0))
    clip_dur   = float(self._current_clip.get("duration", 0))
    local = playhead - clip_start
    if local <= 0 or local >= clip_dur:            # ③ 剪切点不在中间？
        QMessageBox.warning(self, "剪切", "请先把播放头移到片段中间再剪切")
        return                                      #    提醒一下，退出
    result = self._split_clip_at_time(self._current_clip, playhead)  # ④ 真切！
    if result.get("success"):
        QMessageBox.information(self, "剪切", result.get("message", "片段已剪切"))
    else:
        QMessageBox.warning(self, "剪切", result.get("message", "剪切失败"))
```

**小白一句话**：剪切 = "确认你选了片段" + "确认切割点在中间" + "调用底层把片段一分为二"。

> ⚠️ 第 ③ 步的边界检查是**本次新增的**。原来没有它：如果播放头正好停在片段最开头，会切出一个"0 秒的隐形空片段"，是个隐蔽 bug。现在加了保护，切不出来会温柔提示你"移到中间再切"。

底层真正切分在 `_split_clip_at_time`（7171 行）：它把原片段时长拦腰砍短，再生成一个新片段接在后面，然后把这次操作记进撤销栈。

## 五、第四站：撤销栈（后悔药）—— 修复重点

之前这模块有个大坑：**同名方法写了两遍**，后写的把先写的覆盖了，导致"剪切/删除/粘贴"根本没把记录存进撤销栈，Ctrl+Z 永远失效。

本次修复后，每个操作都会调用：

```python
def _record_action(self, action):
    self._action_history.append(action)   # 把这一步存起来
    self._redo_history.clear()            # 新动作清空"重做"栈
    self._update_undo_redo_state()        # 让撤销/重做按钮变亮可用
```

撤销 `_undo` 就是"把最后一步走反"：删了的片段加回来、切了的合并回去。

> 🔗 对应 BYOX 主题：**数据库 / 编程语言（解释器）**。撤销栈本质就是"操作日志"，和数据库的"事务回滚"、解释器的"执行栈"是同一个思想。

---

## 六、整体数据流（一图流）

```
你点按钮 ──→ 事件绑定(connect) ──→ 核心逻辑(_cut_clip 等)
                                      │
                                      ├─→ 记进撤销栈(_record_action)
                                      ├─→ 改时间线 UI(片段变多/少)
                                      └─→ 刷新预览窗口(看到变化)
```

撤销(Ctrl+Z)从撤销栈取出最后一步，把它"倒着做一遍"，于是界面又回到上一步。

## 七、还能继续优化的地方（下次可做）

1. **`QMessageBox` 弹窗有点多**：每个操作都弹个框，连续操作会很烦。可改成底部状态栏轻提示（和撤销用同一个 `_undo_redo_toast` 思路）。
2. **内核时间线未随撤销重建**：undo 时本地数据和界面回了滚，但底层引擎（`timeline_manager`）的片段没同步删/加。数据一致性没问题，但追求完美可补。
3. **批量删除无撤销记录**：`batch_delete_clips` 循环调用 `_delete_clip_by_id`，每次都记一条。可合并成"一条批量撤销"，一次 Ctrl+Z 全恢复。
