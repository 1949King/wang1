# 2026-07-12 — 剪辑模块可用性修复（续）

## 关键发现：致命的 `creation_flags` 拼写错误
- `app/modules/lego/video_processor.py` 中有 **12 处** `subprocess.run(..., creation_flags=...)` 误用带下划线的 `creation_flags=`。
- `subprocess.Popen` 仅接受 `creationflags=`（无下划线）。误用会导致 **所有 ffmpeg 调用**（`trim_video`/`apply_video_filter`/`merge_videos`/`merge_with_transitions` 等）执行时立即抛 `Popen.__init__() got an unexpected keyword argument 'creation_flags'`。
- 后果：整个剪辑后端瘫痪，UI 上点任何剪辑操作都静默失败。这是比 4.9.0 那批修复更根本的 bug——之前那批修复（effects 字典化、滤镜接通、导出设置生效等）都建立在这个后端能跑的前提下。
- 修复：用 `replace_all` 把 `creation_flags=` → `creationflags=`，全 `app/` 已确认无残留。

## 验证（真实 ffmpeg 跑通）
- 用 `D:\拾光剪影\.venv312\Scripts\python.exe` 跑 `D:\拾光剪影\_verify\verify_export.py`。
- 该 venv 的 `imageio_ffmpeg.get_ffmpeg_exe()` 可拿到真实 ffmpeg（`D:\拾光剪影\.venv312\Lib\site-packages\imageio_ffmpeg\binaries\ffmpeg-win-x86_64-v7.1.exe`）；沙箱 PATH 里没有 ffmpeg，但 project venv 有。

- 结果：`edited.mp4` 生成成功，`apply_export_settings` 返回 True，`final.mp4` 实测 `640 x 360 fps: 24`，`RESULT: PASS ✅`。
