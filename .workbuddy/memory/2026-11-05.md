## 团队小窗 502 根因：urllib 吃了系统代理（00:10-00:15）

**用户截图报障**：小窗显示红字「对方返回了 502，没说原因」。

🔴 **根因 = `urllib.request.urlopen` 默认读环境变量/注册表的系统代理**，把发往
`127.0.0.1:18765` 的**回环请求**也丢给代理，代理不认识这个地址 ⇒ 502。
实测环境：`http_proxy=http://127.0.0.1:60630`（Clash 类工具同理，Windows 下还会读注册表
`ProxyEnable/ProxyServer`）。**这不是沙箱特有，真实用户开着系统代理就会中招。**

**修法**：模块级建一个禁用代理的 opener，本模块所有请求走它：
```python
_OPENER = urllib.request.build_opener(urllib.request.ProxyHandler({}))
_OPENER.open(req, timeout=_TIMEOUT)     # 不用 urlopen
```
只影响本模块，不动全局 urllib 状态。

**对照实验（留证据，以后照这个验）**：
```
走代理   -> HTTPError 502
绕过代理 -> URLError「对方没有在跑团队服务 —— 让对方先点「启动团队服务」」
```
后者才是真原因，且是能照做的话。

**顺带修的排版**：`_msg`（错误提示）和 `_full_btn` 挤在一个 QHBoxLayout 里，
提示一长就把右下角按钮顶出面板边缘（截图为证）。改成提示独占一行、按钮独占一行右对齐。

**启动耗时的真因（顺带量出来）**：`startup timing: window shown +0.13s (boot 0.46s)`，
但从进程启动到「配置文件加载成功」隔了 **16 秒** —— 全花在 `import torch` + onnx 上。
即「首屏慢」不是 Qt 的锅，是重依赖的 import 时间。要提速得把 torch 改成真正懒加载。

**沙箱环境噪音（真实用户不会遇到，别当 bug 修）**：
`dpapi` 写 `%LOCALAPPDATA%\AI短剧编辑器\secret.key.dpapi` 权限拒绝、ComfyUI 8188 连不上。

## 发布包重建（「包内必须包含所有模块功能」这一轮）

**结论**：`dist/拾光剪影` 6.35 GB（`_internal` 1.95 + `runtime` 4.37），源码 512 个 app 模块
**被引用 399 个、包内缺失 0**；27 个特效/转场插件全在；自检 **22/24，2 项降级**；真机启动截图确认界面正常。

### 五个真凶（都是「打包成功 ≠ 功能在」这一类）
1. **`hiddenimports` 只写了包名，107 个模块根本没进包**（`app.core.editor_scheduler`、
   `app.modules.lego.timeline_widget`、27 个插件…）。产品模块是靠「目录/名字动态加载」的，
   静态分析一个都看不见。→ spec 里改成 `_app_modules()` **自动枚举 app/ 全量**（501 个）。
2. **`opentimelineio` 不能进 Analysis**：加入后 `import_library` 隔离子进程 0xC0000005
   （与 torch/gguf 同一族）。→ spec excludes + 由 runtime/ 供给。
3. **PyInstaller 只收「应用看得见的部分」**，AI 栈在 runtime/ 对它不可见，于是 `timeit`/
   `modulefinder`/`struct` 这类 stdlib、`markupsafe`/`safetensors`/`httpx2` 这类三方包全缺。
   → runtime/ 补 stdlib 补丁；三方包显式登记为根包。
4. **numpy/scipy/PIL/cryptography/yaml 是「残件」**（scipy 连 `signal` 都没有，numpy 连
   dist-info 都没有）。它们的 `__init__` 在 PYZ 里、`__path__` 指向 `_internal/<pkg>`，
   放 runtime/ **会被完全遮住**。→ `build_release.complete_internal()` 做**差集同步**。
5. **`app/core/video_processing`（原生引擎层）被排除 ⇒ 导出引擎整片缺失**。
   → `SYNC_APP_SUBPKGS` 以目录形态装进 `_internal`（绕开 Analysis），跳过 `build/` 与
   `_internal` 已存在的同名 FFmpeg DLL（省 570 MB）。

### 两个「入包但冻结点跑不起来」（记 WARN，不拦出包；门槛见 OPTIONAL_CHECKS）

  已排除 CRT 版本（包内 14.42 vs 系统 14.51）、CONCNRT140 缺失、同目录冲突。
- **opentimelineio**：冻结解释器 import 即段错误（**连无 Qt 的全新进程也一样**）；
  同一批文件用 `.venv312` 从 `dist/runtime` import 正常。

  → 新增 `main_qt6.py --otio-worker` 显式入口（import PyQt6 之前分流）。
- 自检新增 `--only <名字>`（判「同进程互相干扰」的假失败）与**逐项落盘**（原生库段错误时

### 口径更正（用户指出的「入包模块数接近 500」）
