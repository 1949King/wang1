## 工具栏编辑真正作用到视频（用户核心诉求：编辑不能在视频里应用）
- **根因**：工具栏剪切/复制/粘贴只改内存 `self._clips` + 画 UI 方块；预览 `QMediaPlayer` 永远播整段 `self._video_source`；导出 `_export_video` 只看 `self._clips[0]['path']` 整文件；`real_timeline_manager`(纯元数据) 仅删除时碰一下，split/copy 从不更新。故编辑全悬空。
- **修复（editor_module.py）**：新增 4 方法并接入
  - `_has_timeline_edits()`：判断是否相对源有真实编辑（多段/裁剪区间）。
  - `_build_edited_video(out)`：依 `self._clips` 的 in/out 从源 `trim_video` 各段 → `merge_videos` 按时间拼接（复用 `app/modules/lego/video_processor.py` 已有 `trim_video`/`merge_videos`）。
  - `_sync_kernel_timeline()`：每次编辑把 `self._clips` 重建进 `real_timeline_manager` 视频轨（修复 split/copy 不碰内核）。
  - `_refresh_preview_to_current_clip()`：选中/编辑后把 `QMediaPlayer` 源指向当前片段 in/out 区间（删整段时回退源文件；带 `_preview_seg_key` 缓存避免重复生成）。
  - `_export_video` 重写：有编辑时先 `_build_edited_video` 出中间产物再交给 `editor_scheduler.export_video` 套用分辨率/平台，使剪切/删除/粘贴进成品；无编辑走原单文件逻辑。
  - 调用点：split/copy/delete/add_clip/undo-redo(`_apply_action`)/`_on_clip_selected` 均接 `_sync_kernel_timeline`+`_refresh_preview_to_current_clip`。
- **验证**：端到端用内置 ffmpeg(`thirdparty/ffmpeg/bin/ffmpeg.exe`)造 3s 测试视频，模拟「切分后删第二段」→ 成品 1.0s、「保留全部」→3.0s、「无编辑」→3.0s，均正确；py_compile 通过。
- **注意（环境坑）**：managed Python 的 `subprocess.Popen` 不接受 `creation_flags`（沙箱限制），但 `video_processor.py` 用标准 `creation_flags=CREATE_NO_WINDOW if os.name=='nt' else 0` 在原生 Windows Python 正常。**勿因此改 video_processor.py**。
