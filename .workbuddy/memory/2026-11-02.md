## 追加：团队面板被压成一条窄缝（用户截图「就这么小一个窗口，你觉得谁能看到？」）

**根因不是 CSS 缺失**：产物里 `.sg-team-panel{position:fixed;right:18px;width:420px}` 完整存在。
真因 = **`.ic-nav` 有 `backdrop-filter: blur(10px)`**，它让该元素成为 `position: fixed` 后代的
包含块（与 transform/filter 同类）⇒ 面板挂在该导航栏里时 `right:18px` 变成相对 64px 导航栏，
420px 面板被推出屏幕左侧只剩 ~46px，内容挤成竖排。

**修法**：`createPortal(<TeamPanel/>, document.body)`；产物里已确认
`EC.createPortal(c.jsx(n$,{onClose:...}),document.body)`。

## 团队面板「WinError 10038」结案（提交 77d5faf，画布 0.3.36）

- 🔴 **先定责再改代码**：`app/logs/app_20261102.log` 当天团队只有 6 次调用 —— `GET /host/team/status` ×5 全 200、
  `discover` 204/**200**、`/host/team/start` **从未被调用**。⇒ 「扫描」这条链是通的，坏的是「加入」
  （它直连 `http://<内网IP>:18770`，而本机根本没东西监听 18770）。**日志比界面文案可靠。**
- 🔴 **真 bug：`Beacon.stop()` 会 `_stop.set()`，`start()` 从不 `clear()`** ⇒ 第二次启动线程进来就退出。
  判据 `_thread.is_alive()`：修复前 False / 修复后 True；修复前 `scan()` 扫不到、修复后能扫到。
  症状极具迷惑性 —— HTTP 服务照常能用、同事手填地址也能连，只有「扫描局域网」永远扫不到，
  跟「企业 Wi-Fi 广播抑制」一模一样，界面上无法归因。同时把 `listener` 挂 `self._listener` 显式关闭
  （原先靠局部变量 GC，「停止 → 立刻启动」时 45123 偶发没释放 ⇒ 静默降级成只广播），`_loop` 包 `try/finally`。
- **全库唯一会吐 `[WinError 10038]` 的地方就是 `team_discovery`**（`grep sendto|recvfrom` 只命中它）。
  其余 socket 面（`lan_ip`）自带 try/except 兜底。⇒ 以后见到套接字错误码先看这个文件。
- **错误码必须翻人话**：后端 `friendly_socket_error()`（8 个码）+ 前端 `teamClient.netError()`
  （`Failed to fetch` ⇒ net_down；`[WinError N]` ⇒ 按码给建议；原始异常只进 console）。
  `hostCall` 的 `authHeaders()` 要放 `try` **外面**，否则本地装配错误被误报成「连不上桥」。
- 🔴 **`docs/help/*.md` 是帮助正文的既有约定**（`HelpModule._load_markdown_topic(id)` → `docs/help/<id>.md`）。
  加话题 = `topics` 加一行 + 写 `_xxx()` 三行 + 落一个 md，**改说明不用改代码**。
  顺带修 `_render_markdown`：普通段落剥 `**粗体**`，**列表项一直没剥** ⇒ 界面上直接显示星号。
- 🔴 **`settings_module.py` 体积守卫只剩 1 行余量**（基线 2823 + 容差 30 = 2853，实测 2852）。
  新页签正文必须单独成文件（`settings_team_tab.py`），settings 里只留 1 行导航 + 4 行转发；
  本次靠删 4 行裸表达式死语句（`title` / `lang_group` 之类，ruff B018 21→17）腾出空间。
- **tsc 棘轮命令**：`cd vendor/packages/libtv && node node_modules/typescript/bin/tsc --noEmit --pretty false`，基线 37。
  ⚠️ 测试里 `.catch(e => e as Error & {code})` 会把**成功返回类型并进联合**（新增 9 个 TS2339）⇒
  写 `async function rejection(p): Promise<Error & {code}> { try{await p}catch(e){return e as ...} }`。
- **Qt 页面验收走两条**：`QT_QPA_PLATFORM=offscreen` 验结构（无字体 ⇒ 全是豆腐块，只能看布局），
  真实窗口 `QTimer.singleShot` 后 `grab()` 验像素（真字体）。**设置页 `**` 残留、分组标题在深底上偏暗
  都是这么抓出来的**（QLabel 默认 PlainText + QGroupBox 标题继承调色板）。
- 帮助页 `grab()` 里文字重叠/裁切是**既有现象** —— 同一环境抓「常见问题」话题同样如此，不是新内容引入；

## 团队服务能不能当「统一服务器」（架构事实，2026-11-02 逐条核实）

- ✅ 可以：`TeamServer` 绑 `0.0.0.0:18770`，端点只有 join/projects/pull/push/claim/release/handoff/inbox，
  **攻击面 = 文档读写**；数据 = `data/team/team.db`（SQLite）+ `projects/*.json`，复制该目录即备份。
- 🔴 **那台机器的 GPU 完全用不上**：团队服务不做任何推理；生图/生视频仍在**各自机器**上跑
  （`canvas_server` 绑 `127.0.0.1:18765`，是刻意的安全设计，不许暴露局域网）。想让大显存机器出图
  = 要另做受控的远程生成服务，目前没有。
- 🔴 **成员 ≠ 主程序账号**：join 时只填名字换令牌；`role` 字段存了但**不参与任何鉴权** ⇒ 所有人权限相同。
- 🔴 **bundle 内嵌 base64**：`getProjectBundle()` 原样返回 `nodes`，而生图返回的是 `image_data_url`（data URL）
  ⇒ 每张 512² 图约 300~500KB，`MAX_BUNDLE_BYTES = 100MB` ≈ **200~250 张图**就撞「工程过大」。
  想把画布长期挂在服务器上，得先在画布上清叠卡大图。
- 网络：明文 HTTP + UDP 45123 广播，**只适合同一局域网**；跨网需 VPN，且不要映射公网。

## 团队附件库：成片/剧本/图片进同一条链路（画布 0.3.38）

用户原话：「跑出一条完整 AI 视频，怎么传给同事看和改，包括剧本脚本、图片资产」——
之前团队同步只谈画布节点，核实后发现**四个独立缺口，不是一个**：

| 内容 | 之前 | 后果 |
|---|---|---|
| 剧本 | `script` 节点 `data.content` 在 bundle 里 | ✅ 一直能带 |
| 成片时间线 | **`getProjectBundle()` 不返回 `timeline`** | 同事只拿画布，时间线全丢 |
| 视频/图/音频 | 只有 `/inbox_file/x.mp4` 本地路径字符串 | 同事机上不存在 ⇒ 404 |
| 「我的资产」 | localStorage ≤80 条 | 拿不到 |

- 新增**附件层**：`hub.blobs_dir/<sha256>.<ext>`，同内容跨项目共享一份盘；`asset` 表 (project×sha)。
  `MAX_ASSET_BYTES=512MB`，**请求体 64KB 一块边收边写盘**（512MB 一次 read 进 8GB 机器会换页拖死）。
- 端点：`POST/GET /team/projects/{id}/assets`、`GET/DELETE …/assets/{sha}`；
  取字节支持 **Range(206)**（否则 `<video>` 拖不动进度条）+ **`?token=`**（媒体元素带不了 Authorization 头）。
- 🔴 **令牌绝不进 bundle**：push 前 `stripAssetTokens()` 剥 `?token=`；pull 时 `rebaseAssetUrls()`
  换 host + 注入当前令牌 ⇒ 顺手解决「服务器 IP 变了旧地址全废」。
- 🔴 **不改写渲染点，改数据层**：`videoUrl`/`imageUrl` 散落在 App/CanvasShell/codeVideoNode 等十几处，
  逐个改必漏；在 `loadProjectBundle` 之前一次性换好 URL 即可，所有组件零侵入。
- 🔴 **时间线 `clip.path` 是本地绝对路径，前端 fetch 读不到** ⇒ 新增 `POST /host/team/inbox-map`
  只做路径换算（毫秒级），字节仍由前端走 `/inbox_file/` 直传。
  **不能后端代传**：`canvas_server` 有 30 秒请求上限，200MB 成片必超时留半个文件。
- 纪律：`data:` 超 256KB 才上传（小图标内联更划算）；上传走 **XHR**（fetch 无上传进度事件）；
  一个失败不中断其余，逐条列进 `failed` 并显示在面板上。
- 诚实边界：拉下来的时间线仍指原作者路径 ⇒ 弹窗问一句再导，并说明「画布上的图和视频不受影响」。
- 测试：pytest 新增 4 例（去重/穿透/丢字节/HTTP 全链路含 Range）、vitest 新增 12 例（`teamAssets.test.ts`）。
