1. **网络不可达**（已实测三条路）：SSH 22 refused / HTTPS 443 走 `127.0.0.1:7897` 代理但端口无监听 / 绕代理直连被阻断。
2. **本地历史确实还有 3 个 >100MB 的 blob**（`git rev-list --objects --all` + `cat-file --batch-check` 实测）：
   - `拾光剪影-发布版.zip` **743.2 MB**
   - `assets/videos/纵年华--01.mp4` **722.9 MB**
   - `app/core/video_processing/cpp_engine/avfilter-11.dll` **104.5 MB**
   ⇒ GitHub 单文件硬限 100MB，**直接 push 必被拒**，手术不是可选项。
3. **`git filter-repo` 要求工作区干净**，而当前有 **38 个未提交改动**（多为 10-31~11-04 的历史遗留，不属于本次任务）。
   ⇒ 手术前必须先决定那 38 个文件怎么办 —— 这不是我能替他拍板的（可能含未完成的半成品）。

### 处方（代理起来 + 工作区干净后，按序执行）
```bash
# 0. 备份整个目录（手术不可逆，会重写全部提交哈希）
#    cp -r /d/拾光剪影 /d/拾光剪影_backup_$(date +%Y%m%d)

# 1. 确认代理真的通（不通就别往下走）
curl -x http://127.0.0.1:7897 -I https://github.com

# 2. 确认工作区干净（有未提交改动 filter-repo 会拒绝）
git status --porcelain | wc -l    # 必须为 0

# 3. 剥掉所有 >100MB 的 blob（与远程那次同口径，236 提交就是这样来的）
git filter-repo --strip-blobs-bigger-than 100M --force

# 4. 确认大文件已清（应无输出）
git rev-list --objects --all | git cat-file --batch-check='%(objecttype) %(objectsize) %(rest)' \
  | awk '$1=="blob" && $2>104857600 {print}'

# 5. 强推（历史已被重写，必须 --force）
git push --force origin main
```
⚠️ 第 3 步之后**本地所有提交哈希都会变**，任何别处引用旧哈希的记录（含本文件的提交号）都将失效 —— 到时以 `git log` 为准，别拿旧哈希找人。
