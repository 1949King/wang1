# 统一调用层架构重构计划

## Context（背景）

用户给出了顶层架构蓝图：

```
框架内总线（全局贯穿所有模块）
    ↓
1. Agent → 2. 调用层 → 3. 三大并列核心模块（剪辑/模型/拓展）
    ↓
4. 多任务调度 → 5. 账号运营（抓取数据+AI优化建议）
    ↓
6. 效果反馈回流至 Agent
长期运行沉淀：长期记忆 + 自主学习
```

**现状问题**：Agent（[editor\_module.py:8920](file:///d:/拾光剪影/app/modules/lego/editor_module.py#L8920)）直接调用 ExtensionsRegistry/SkillEngine，跳过了调用层；DataAnalyzer 的反馈只写文件不回流 Agent；无长期记忆系统。

**目标**：新建统一调用层 `CapabilityDispatcher`，Agent 只通过它访问三大模块；打通反馈闭环；实现长期记忆。

***

## 架构对齐

| 用户架构层   | 实现方案                                                 | 文件                                    |
| ------- | ---------------------------------------------------- | ------------------------------------- |
| 框架内总线   | EventBus 追加 4 个 EventType                            | `core.py` +4行                         |
| Agent   | 已有，接入调用层 + 注入记忆                                      | `editor_module.py` 改4处                |
| **调用层** | **CapabilityDispatcher 单例**                          | **`capability_dispatcher.py`** **新建** |
| 三大核心模块  | 5 类 handler（editor/model/extension/workflow/account） | `capability_handlers.py` 新建           |
| 多任务调度   | WorkflowCapabilityHandlers                           | 同上                                    |
| 账号运营    | AccountCapabilityHandlers                            | 同上                                    |
| 效果反馈    | AgentFeedbackBridge 订阅 PUBLISH\_RESULT               | `agent_feedback_bridge.py` 新建         |
| 长期记忆    | MemoryStore LRU+JSONL+learn\_from\_feedback          | `memory_store.py` 新建                  |

## 实施步骤

### Phase 1：基础层（新建 3 个 core 文件）

**1.1** **`app/core/capability_dispatcher.py`（新建，\~280行）**

* `CapabilityDispatcher` 单例

* `CapabilityRequest` / `CapabilityResult` dataclass

* `CapabilityCategory` 枚举（EDITOR/MODEL/EXTENSION/WORKFLOW/ACCOUNT）

* 核心方法：`register()` / `invoke()` / `invoke_async()` / `list_capabilities()`

* 每次 invoke → 写 MemoryStore trace + emit CAPABILITY\_INVOKED/COMPLETED

**1.2** **`app/core/memory_store.py`（新建，\~220行）**

* `MemoryStore` 单例，内存 LRU(5000) + `data/agent_memory.jsonl` 持久化

* 核心方法：`record()` / `query()` / `get_agent_context(top_k)` / `learn_from_feedback()`

* 5MB 自动压缩，保留高 score + feedback/learned\_rule 类别

**1.3** **`app/core/agent_feedback_bridge.py`（新建，\~150行）**

* `AgentFeedbackBridge` 单例

* 订阅 `PUBLISH_RESULT` / `WORKFLOW_COMPLETED`

* `submit_feedback()` → 写 MemoryStore + emit `AGENT_FEEDBACK_AVAILABLE`

* `get_pending_feedback()` 供 Agent 注入提示词

### Phase 2：Handler 实现（新建 1 个 core 文件）

**2.1** **`app/core/capability_handlers.py`（新建，\~350行）**

* `EditorCapabilityHandlers`：split\_clip/apply\_filter/add\_transition/get\_timeline\_context（lazy ref EditorModule）

* `ModelCapabilityHandlers`：chat/chat\_with\_fallback/list\_models（封装 AIEngine）

* `ExtensionCapabilityHandlers`：run\_extension/run\_skill/list\_tools（ExtensionsRegistry + SkillEngine fallback）

* `WorkflowCapabilityHandlers`：start\_workflow/submit\_batch\_task

* `AccountCapabilityHandlers`：collect\_data/optimize\_strategy/publish

* `register_builtin_handlers()` 注册 15 个 capability\_id

### Phase 3：EventBus 扩展（改 1 处）

**3.1** **`app/modules/lego/core.py`** EventType 末尾追加：

```python
CAPABILITY_INVOKED = "capability_invoked"
CAPABILITY_COMPLETED = "capability_completed"
AGENT_FEEDBACK_AVAILABLE = "agent_feedback_available"
MEMORY_WRITTEN = "memory_written"
```

### Phase 4：反馈闭环（改 1 处）

**4.1** **`app/modules/lego/data_analyzer.py`** `_update_strategy` 末尾追加：

```python
from app.core.agent_feedback_bridge import agent_feedback_bridge
agent_feedback_bridge.submit_feedback({...})
```

### Phase 5：Agent 接入（改 1 文件 4 处）

**5.1** **`app/modules/lego/editor_module.py`**

| 位置                            | 修改                                                                                                                                               |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `_create_edit_agent_panel` 末尾 | 注册 `register_builtin_handlers(lambda: self)` + 监听 `AGENT_FEEDBACK_AVAILABLE`                                                                     |
| `_build_edit_agent_messages`  | 注入 `memory_store.get_agent_context()` + `agent_feedback_bridge.get_pending_feedback()`；action 列表新增 call\_model/start\_workflow/account\_optimize |
| `_apply_agent_command`        | 新增 call\_model/start\_workflow/account\_optimize 分支，走 `_agent_dispatch()`                                                                        |
| `_agent_call_extension`       | 改走 `dispatcher.invoke("ext.run_extension")`，保留原逻辑作 except fallback                                                                               |
| 新增 `_on_agent_feedback`       | 收到反馈时在面板显示提示                                                                                                                                     |
| 新增 `_agent_dispatch`          | 统一调用层便捷封装                                                                                                                                        |

**关键原则**：编辑类高频动作（add\_clip/split\_clip/filter）保留原 `_apply_agent_command` 直接操作 `self._clips` 快路径，不走 dispatcher。

### Phase 6：启动接线（改 1 处）

**6.1** **`app/main_qt6.py`** EventBus 初始化后追加 eager init：

```python
MemoryStore.get_instance()
AgentFeedbackBridge.get_instance().event_bus
CapabilityDispatcher.get_instance()
```

## Agent 调用路径

| Agent action      | dispatcher capability\_id  | 落地模块                           |
| ----------------- | -------------------------- | ------------------------------ |
| call\_extension   | ext.run\_extension         | ExtensionsRegistry→SkillEngine |
| call\_model       | model.chat\_with\_fallback | AIEngine→Ollama/Cloud          |
| start\_workflow   | workflow\.start            | WorkflowManager                |
| account\_optimize | account.optimize\_strategy | viral\_optimization\_engine    |
| account\_collect  | account.collect\_data      | skill\_engine                  |
| 编辑类（add\_clip等）   | 不走 dispatcher              | EditorModule 快路径               |

***

## 反馈闭环流程

```
发布 → PUBLISH_RESULT → DataAnalyzer._update_strategy（既有）
    → AgentFeedbackBridge.submit_feedback（新）
    → MemoryStore.record(category="feedback")（新）
    → MemoryStore.learn_from_feedback()（3条同模式→learned_rule）
    → emit AGENT_FEEDBACK_AVAILABLE
    → EditorModule._on_agent_feedback 显示提示

下次 Agent 调用：
    → _build_edit_agent_messages 注入 memory_store.get_agent_context()
    → 模型参考历史 feedback/learned_rule 生成更优指令
```

## 验证方案

1. **静态验证**：`py_compile` 4 个新文件 + `frozen_zone_guard.py`
2. **启动验证**：`python main_qt6.py` 无报错，日志显示"调用层 & 记忆 & 反馈桥 已就绪"
3. **功能验证**：

   * Agent 输入"调用 account\_data\_collect 技能" → 走 dispatcher → 返回结果

   * 控制台 emit PUBLISH\_RESULT → Agent 面板显示反馈提示

   * 检查 `data/agent_memory.jsonl` 有 execution\_trace 条目

   * 3次低 views PUBLISH\_RESULT → 出现 learned\_rule 条目
4. **回归验证**：既有剪辑功能 + Agent 快捷指令不变

## 风险控制

* **循环导入**：handlers 全部 lazy import，dispatcher 用 property 延迟取 EventBus

* **线程安全**：dispatcher/MemoryStore/EventBus 均用 RLock

* **冻结区**：editor\_module.py 修改点 8265/8576/8627/8920 均不在 frozen\_zones.json

* **向后兼容**：`_agent_call_extension` 保留原 fallback；DataAnalyzer 既有文件写入不动；EventType 仅追加
