## ⚠️ 本版为什么换骨架

**上一版的病**：按**代码位置**分章（剪辑模块 / 画布模块 / Agent 模块 / 数字人模块）。
好处是好找文件，坏处是**看不出缺什么**——因为缺口从来不在某个模块内部，而在**模块之间的交接处**。

**本版的做法**：按**生产链**分章（想法 → 剧本 → 分镜 → 生成 → 剪辑 → 成片），治理层横切。
每个阶段定义一份**契约**（输入什么、输出什么、谁负责、怎么验收），缺口自动暴露在契约断点上。

| 视角 | 能回答的问题 | 不能回答的问题 |
|---|---|---|
| 模块视角（旧） | 「画布有哪些节点？」 | 「从一句立意到一集成片，哪一段是断的？」 |
| **生产链视角（新）** | **「断在哪、补什么、补完解锁什么」** | 单个模块内部怎么实现（交给事实源） |

## 第零章 总览：一部短剧怎么被造出来

### 0.1 价值链全景

   S0 选题        S1 剧本         S2 分镜/美术      S3 生成         S4 剪辑       S5 成片

图例：🟢 能跑通 ｜ 🟡 能跑但不成体系 ｜ ⚪ 依赖人工

### 0.2 阶段契约标准（Stage Contract）—— 本版新增的设计工具

每个阶段必须能填满下面这张表，**填不满的地方就是缺口**：

| 契约项 | 含义 | 填不满的后果 |
|---|---|---|
| **输入** | 从上游拿什么数据（字段级） | 上下游各自造格式，人肉搬运 |
| **输出** | 交给下游什么数据（字段级 + 落点） | 下游拿不到，只能重做一遍 |
| **责任人** | 这一段的唯一真相源模块 | 两端各写一套，漂移 |
| **验收** | 什么条件下算这一段「通了」 | 永远"快好了" |
| **失败语义** | 做不到时说什么（诚实失败） | 假成功，污染下游 |

> 这张表是本版所有阶段章的骨架。**下游只信契约，不信实现对**——这是从"模块各自进化"升级到"链路可替换"的关键。

### 0.3 缺口重估（关键修正 —— 旧结论有两条已过时）

> 旧记忆里写「四大缺口：① 编剧生产端完全空白 ② 抽卡选优闭环缺失 ③ 资产母版层弱 ④ 审美治理缺管辖」。
> **2026-10-19 逐文件核实后，② 已不成立，① 的措辞也不准确。** 以代码为准：

| 旧结论 | 实测状态 | 证据 | 现在的准确说法 |
|---|---|---|---|
| ① 编剧生产端**完全空白** | ❌ **不准确** | `ai/script_writer.py`(99) + `editing_script_generator.py`(396) + `ai/storyboard_memory.py`(209)；`drama_understanding_engine.py`(2,160) 是**消费类**（理解别人写的剧本） | **有单点生成 + 长篇结构模型（`script_doc.py`，2026-10-20）**；缺 UI/存储/分集生成/连续性校验**接线** |
| ② 抽卡选优闭环**缺失** | ❌ **已落地** | `ai/draw_orchestrator.py`(179) + `ai/gen_critic.py`(320) + `ai/draw_book.py`(321) + `ai/score_book.py`(278) + `ai/draw_ledger.py`(188) = **1,286 行**；闭环 = 生成 n 张 → 逐张评分 → 取最优 → 全量入账（含坏区体检、best_seed 竞争） | **闭环已成型**，缺的是**偏好回流**（账本 EMA 未回灌生成参数）与**跨模态统一**（图/视频/音频是否同一套抽卡） |
| ③ 资产母版层**横向支撑弱** | ✅ 准确 | 零件齐：`ai/character_anchor.py`(334) + `ai/prop_guard.py`(341) + `character_management_module.py` + `prompt_library_store.py`；**无**统一 Master 抽象 | **有零件，缺抽象**：角色/场景/道具各管各的，没有"母版 + 变体 + 继承"统一模型 |
| ④ 审美治理层**零件散落缺管辖** | ✅ 准确 | `five_dimension_scorer.py`(377) + `ai/gen_critic.py`(320) + `problem_router.py`(193) 都在，但无统一标准表、无闸门 | **准确**：能打分，不能"管"——没有"什么分数不许进下游"的硬闸门 |

**这张表本身就是本版最重要的产出**：它把「凭印象记的缺口」换成了「能查到行数的缺口」。

> **2026-10-20 增量（不改变上表口径）**：`script_doc.py`（长篇结构）与 `idea_card.py`（立意卡）
> 的**纯模型**已落地（41 例测试），`asset_master.py`（母版）与 `aesthetic_gate.py`（闸门）
> 也已落地；但均**未接 UI/存储/生成链路**，故 S0/S1/S2/G 的保守评分暂不上调，
> 只把文字口径从「没有」改为「有模型、缺接线」。

### 0.4 走通度评分方法与结果

**方法**：每个阶段按「契约完整度」打分——5 项契约（输入/输出/责任人/验收/失败语义），
每项 0/1/2 分（无 / 口头有 / 代码可验证），满分 10。

> ⚠️ **诚实标注**：下表的 0/1/2 分是**设计判断**（依据本章各阶段的代码核实结果），**不是代码度量**。
> 行数、文件、能力数才是实测；分数只用来做横向对比与排序，不要当 KPI 引用。

| 阶段 | 输入 | 输出 | 责任人 | 验收 | 失败语义 | 合计 | 判定 |
|---|---|---|---|---|---|---|---|
| S0 选题 | 0 | 0 | 0 | 0 | 1 | **1/10** | ⚪ 人工（`idea_card.py` 结构模型已落，未接线） |
| S1 剧本 | 2 | 1 | 2 | 1 | 2 | **8/10** 单集 / **4/10** 长篇 | 🟡 |
| S2 分镜美术 | 1 | 1 | 1 | 1 | 2 | **6/10** | 🟡 |
| S3 生成抽卡 | 2 | 2 | 2 | 2 | 2 | **10/10** | 🟢 |
| S4 剪辑 | 2 | 2 | 2 | 2 | 2 | **10/10** | 🟢 |
| S5 成片 | 2 | 2 | 2 | 1 | 2 | **9/10** | 🟢 |
| G 治理 | 1 | 1 | 1 | 1 | 2 | **6/10** | 🟡 |

> 结论一句话：**中间和尾部很强（生成/剪辑/成片 9-10 分），头部很弱（选题 1 分、分镜 6 分），治理拖着（6 分）。**
> 这解释了为什么"单个功能都能用，但做一整部片子还是累"——断在头部，不在中段。

## 第一章 S0 选题与立意（Idea）

### 1.1 阶段契约

| 契约项 | 内容 | 现状 |
|---|---|---|
| **输入** | 用户输入的主题/题材/参考作品；平台爆款样本 | ⚪ 纯人工 |
| **输出** | 结构化立意：题材标签 / 目标受众 / 集数预算 / 核心爽点 / 合规风险项 | ⚪ 无数据结构，只有自由文本 |
| **责任人** | — | ⚪ 无 |
| **验收** | 能产出「可拍立意卡」，含受众与合规预判 | ⚪ 无 |
| **失败语义** | — | ⚪ 无 |

### 1.2 现有能力

| 能力 | 落点 | 说明 |
|---|---|---|
| 剧本合规检查 | `project_agent_host.script_compliance_check` | **只有检查，没有选题**；且只对已成稿的文本工作 |
| 热门题材参考 | 无 | 未接任何榜单/趋势数据 |

### 1.3 缺口

1. **没有「立意」这个数据对象**——现在所有下游拿到的都是自由文本 prompt，没有结构。
2. **合规是事后检查**，不是事前预判（选题阶段就该知道哪些题材过不了）。
3. **没有预算意识**：选一个"100 集古装大场面"的立意，等于把成本压给 S3 生成阶段。

### 1.4 设计方向（建议立项，非现状）

**产出物 = `IdeaCard`（立意卡）**：

```
IdeaCard {
  topic: str              # 主题
  genre: [str]            # 题材标签
  audience: {age, gender, platform}
  episodes: {count, duration}   # 集数 × 单集时长 = 成本预算
  hooks: [str]            # 核心爽点/钩子
  compliance_risks: [str] # 预判风险项（分级：红/黄/绿）
  ref_works: [str]        # 对标作品
}
```

**验收**：给定 1 个题材，产出 3 张立意卡，每张能直接喂给 S1；合规风险项必须给分级而非"仅供参考"。

## 第二章 S1 剧本生产（Script）

### 2.1 阶段契约

| 契约项 | 内容 | 现状 |
|---|---|---|
| **输入** | IdeaCard（或自由文本主题） | 🟡 只吃自由文本 |
| **输出** | 结构化剧本：场次 / 对白 / 动作 / 时长 / 情绪 | 🟡 输出**纯文本**，靠下游正则解析 |
| **责任人** | `ai/script_writer.py`（单集）/ 长篇小说改编无**责任人** | 🟡 |
| **验收** | 单集：可拍 3-5 场景；长篇：N 集连续性通过 | 🟡 单集可，长篇无验收 |
| **失败语义** | 模板降级时 `fallback=True` 如实标注 | 🟢 已落实（不把占位说成 LLM 原创） |

### 2.2 现有能力（实测）

| 模块 | 行数 | 干什么 | 性质 |
|---|---|---|---|
| `app/core/ai/script_writer.py` | 99 | 文本生剧本引擎，三级降级（云 → Ollama → 模板），`pipeline.script_write` 能力入口 | **生产**（单集 30 秒，3-5 场景） |
| `app/core/editing_script_generator.py` | 396 | 剪辑脚本生成（镜头级指令） | **生产**（偏剪辑侧） |
| `app/core/ai/storyboard_memory.py` | 209 | 分镜记忆（偏好沉淀雏形） | **记忆** |
| `app/modules/lego/drama_understanding_engine.py` | 2,160 | 剧作理解（拆解已有剧本/结构/人物关系） | **消费**（不是生产） |
| `project_agent_host.script_compliance_check` | — | 合规检查（分桶着色，前端只展示） | **治理** |

> ⚠️ **易混点**：`drama_understanding_engine` 2,160 行看着像"编剧能力"，实际是**读剧本**（理解结构/人物/情绪），不是**写剧本**。旧文档把它算进"编剧生产端"是错的。

### 2.3 缺口：从「单集生成」到「长篇生产」

| 缺口 | 具体表现 | 影响 |
|---|---|---|
| **无剧本数据结构** | 输出是纯文本，下游（S2）必须自己解析"场景1/对白" | 解析脆弱，格式一变就断 |
| **无长篇连续性** | 没有人物小传、情节线、伏笔登记 | 10 集以后人物性格/称呼/关系崩坏 |
| **无集间钩子设计** | 每集独立生成，不管上一集结尾 | 追看率断崖 |
| **无时长预算** | 30 秒固定；不知道一集该塞多少信息 | 生成阶段素材量对不上 |
| **无改编流水线** | 有 105 章小说（实际项目），没有"小说 → 分卷 → 分集"的转换器 | 全靠人读 |

### 2.4 设计方向（建议）

**核心思路：把「剧本」从字符串升级成 `ScriptDoc`（可校验文档）**

```
ScriptDoc {
  meta: {title, episodes, genre, logline}
  characters: [CharacterCard]   # 人物小传：身份/性格/口头禅/关系/弧光
  plotlines: [Plotline]         # 情节线：主线/支线/伏笔（含埋点与回收集数）
  episodes: [Episode] {
    index, title, duration_budget,
    scenes: [Scene] {
      heading,      # 内景/外景 · 地点 · 时间
      characters: [char_id],
      beats: [{action, dialogue, emotion, est_duration}],
      hook_out      # 集尾钩子
    }
  }
}
```

**三个配套校验器**（纯函数，可单测）：
1. `validate_continuity(ScriptDoc)` —— 人物出现一致性、称呼一致、伏笔是否回收
2. `validate_budget(ScriptDoc)` —— 每集时长预算是否超/欠，场景数是否合理
3. `validate_compliance(ScriptDoc)` —— 复用既有合规检查，但前置到写作时

**分阶段落地**：
- S1-a：`ScriptDoc` 数据结构 + `to_markdown()` 兼容现有纯文本消费方（零破坏）
- S1-b：`script_writer` 增加"分集生成"模式，吃 ScriptDoc 上文
- S1-c：小说 → ScriptDoc 转换器（分卷/分章/提取人物与情节线）

### 2.5 验收标准

- 给定 1 个立意卡 + 集数 N，产出 N 集 ScriptDoc
- 连续性校验 0 错误（人物/称呼/伏笔）
- 每集时长预算偏差 ≤ 15%
- 模板降级时 `fallback=True` 且**不进下游**（或明确标注"未校验"）

## 第三章 S2 分镜与美术（Storyboard & Art）

### 3.1 阶段契约

| 契约项 | 内容 | 现状 |
|---|---|---|
| **输入** | ScriptDoc 的 scenes | 🟡 吃纯文本场景 |
| **输出** | 分镜表（shot list）：景别/运镜/构图/时长 + **母版引用** | 🟡 有分镜表，**母版引用是散字段** |
| **责任人** | 拉片/分镜：`bridgeStoryboard.ts` + 后端 `build_shot_table`；角色：`character_anchor` | 🟡 两端各自为政 |
| **验收** | 每镜头能定位到"用了哪个角色/场景/道具母版" | ⚪ 无 |
| **失败语义** | 景别/运镜测不出给空串 | 🟢 已落实 |

### 3.2 现有能力（实测）

| 模块 | 行数 | 干什么 |
|---|---|---|
| `app/core/ai/character_anchor.py` | 334 | 角色一致性锚定：锚定卡（prompt 片段 + 防漂移负面词 + 特征指纹），生成前固化、生成后比对 |
| `app/core/ai/prop_guard.py` | 341 | 道具一致性：结构拓扑规范化（单一主干/无分支）+ 握持姿态 + 防畸形负面词 |
| `character_management_module.py` | — | 角色库 UI（字段五处同步，`CHARACTER_FIELD_SCHEMA`） |
| `prompt_library_store.py` / `prompt_library_panel.py` | — | 提示词库 |
| 拉片 L2（深度拉片） | `bridgeStoryboard.ts` | 分镜表（景别/运镜/关键帧），L1 是子集不接 |
| 三视图 / 局部重绘 | 画布侧 | 角色多视角、局部修改 |
| 24 位灯位 | `stage3dLighting.ts` | 3D 灯光预设（单通道） |

### 3.3 缺口：母版层（Master / Variant）

现在的状态是**"每个功能有自己的描述方式"**：

| 资产类型 | 现在存在哪 | 缺什么 |
|---|---|---|
| 角色 | 角色库 JSON + `character_anchor` 锚定卡 | 没有版本、没有变体（少年版/战损版）、没有引用计数 |
| 场景 | **没有场景库**（只有散落的 prompt） | 完全缺 |
| 道具 | `prop_guard` 的描述规则 | 道具本身没有实体，只有"描述规范" |
| 风格 | 提示词库里的碎片 | 没有"风格母版" |

**典型后果**（为什么必须做）：
- 改一个角色的发型 → 要手工去找所有用过的镜头重生成（因为没有引用关系）
- 同一场戏在 3 个镜头里出了 3 种"破庙"（因为没有场景母版）
- 想把全剧从"写实"改成"古风插画" → 没有风格母版，只能逐条改 prompt

### 3.4 设计方向（建议）

**`AssetMaster`（母版）统一模型**：

```
AssetMaster {
  id: "char_linwan"            # 稳定 ID，被下游引用
  kind: character|scene|prop|style
  master: {                     # 母版本体（唯一真源）
    prompt_fragment: str        # 拼进生成 prompt 的片段
    negative: [str]             # 防漂移负面词
    fingerprint: {...}          # 特征指纹（供漂移检测）
    ref_images: [path]          # 参考图/三视图
  }
  variants: [Variant] {         # 变体（继承 + 覆盖）
    id, name, overrides: {...}, locked: bool
  }
  version: int                  # 每次改母版 +1
  usage: [node_id|clip_id]      # 引用计数（谁在用）
}
```

**三条铁律**（必须写进守卫）：
1. **母版是唯一真源**：下游只存 `master_id` + `variant_id`，不复制内容
2. **变体只能覆盖，不能删除母版字段**（可追溯）
3. **改母版必须让下游失效**：`version` 变更 → 引用它的镜头标 `stale`，提示重生成（不自动重生成，防烧钱）

### 3.5 验收标准

- 改一次角色母版 → 所有引用镜头在画布上标 `stale`，且能列出"影响 N 个镜头"
- 场景母版可创建、可复用，同一场景在不同镜头下描述一致
- 风格母版切换 → 全剧 prompt 片段批量替换（不是逐条改）

### 4.2 现有能力（实测，共 1,286 行抽卡四件套）

| 模块 | 行数 | 职责 | 关键纪律 |
|---|---|---|---|
| `app/core/ai/draw_orchestrator.py` | 179 | **Best-of-N 编排**：生成 n 张 → 逐张评分 → 取最高 → 全量入账 | 绝不重复记账；部分失败如实报 |
| `app/core/ai/gen_critic.py` | 320 | **代理评分**：5 指标加权 + 崩图闸门 | `is_proxy` 恒 True，**不宣称审美判断** |
| `app/core/ai/draw_book.py` | 321 | **抽卡账本**：代理桶 + best_seed 竞争 | 记录渠道真收到的种子 |
| `app/core/ai/score_book.py` | 278 | 评分账本 | — |
| `app/core/ai/draw_ledger.py` | 188 | 记账接线（生成收尾自动喂账本） | — |
| `app/core/canvas_gen_jobs.py` | 494 | 异步任务队列（submit/status/list/cancel） | 幂等键查重去重 |
| `app/core/gen_task_registry.py` | 484 | 生成任务 + 资产节点双表账本 | 跨进程稳定幂等键 |

**闭环数据流**：

```
分镜条目 ──▶ canvas_aigc.generate_*（seed 贯通）
                │
                ├─ 逐张生成 n 张 ──▶ feed_draw_ledger（自动入账：代理桶 + best_seed）
                │                        └─ inpaint_retry.plan_repair（坏区体检，只报不修）
                │
                ▼
          gen_critic.score_image（代理分：5 指标 + 崩图闸门）
                │
                ▼
          draw_orchestrator.select_best（排序取最优 + 返回 is_proxy 说明）
                │
                ▼
          最优素材 + 全部候选 + 逐张原因 → 下游 S4
```

### 4.3 缺口（不是"没有抽卡"，而是三处没闭合）

| 缺口 | 具体表现 | 影响 |
|---|---|---|
| **偏好不回流** | `draw_book` 有 EMA 与 `best_seed`，但**没有回灌到生成参数**（下次仍用默认 seed/参数起步） | 每次都在"重新抽"，不越抽越准 |
| **无预算/停止条件** | 固定 n，不知道"抽出第 3 张就够好了，别抽第 4 张" | 烧钱，或质量不够还停 |
| **跨模态不统一** | 图走 `draw_orchestrator`；视频/音频是否同一套抽卡未见统一入口 | 三套逻辑各自维护，标准不一 |
| **母版未参与抽卡** | 抽卡时靠 prompt 文本描述角色，没吃 S2 的母版指纹 | 抽出来的角色仍可能漂移 |

### 4.4 设计方向（建议）

**`DrawPolicy`（抽卡策略对象）**：

```
DrawPolicy {
  n_max: int                  # 最多抽几张
  budget: {money, seconds}    # 预算上限
  stop_rule:                # 停止条件（取先满足者）
    - score_threshold: 85   # 分数够高就停
    - marginal_gain: 2      # 边际增益 < 2 分就停
    - budget_exhausted
  weights: {sharpness, anatomy, composition, prompt_fit, artifact}
  seed_policy: from_book|random|fixed   # from_book = 用账本 best_seed 起步
  master_refs: [master_id]    # 母版指纹参与 prompt 拼装
}
```

**偏好回流**：
```
draw_book 的 best_seed + 高分参数
      ↓（每次抽卡后更新）
   SeedPrior（按 题材×模型×母版 分桶的先验）
      ↓（下次抽卡作为 seed_policy=from_book 的起点）
   生成参数
```

### 4.5 验收标准

- 给定预算，自动跑到停止条件（不超支、不早停）
- 同一母版 + 同一题材，第二次抽卡的平均代理分 **高于**第一次（偏好确实在回流）
- 视频/音频抽卡走同一 `DrawPolicy` 接口（不是三套）
- 代理分在 UI 上必须带"代理"标识（不冒充审美）

## 第七章 G 治理层（Aesthetic Governance）

### 7.1 什么是"审美治理"（先定义，再谈实现）

> **不是"再多打几个分"**，而是三件事：
> 1. **标准**：什么算好？（写在纸上，不是各人心里）
> 2. **闸门**：不合格的能不能进下游？（硬拦截，不是"仅供参考"）
> 3. **追溯**：为什么这条不好？（定位到具体维度，不是"感觉不行"）

**比喻**：现在项目里有体温计（评分器）、有听诊器（问题路由），但**没有病历本和出院标准**——
所以每次都能量出体温，但没法说"这个病人能不能出院"。

### 7.2 契约

| 契约项 | 内容 | 现状 |
|---|---|---|
| **输入** | 任一阶段的产物（剧本/分镜/素材/时间线/成片） | 🟡 只覆盖素材和时间线 |
| **输出** | 判定：pass / warn / block + 维度明细 + 可追溯原因 | 🟡 只有分数，无判定 |
| **责任人** | `five_dimension_scorer`（打分）/ `gen_critic`（代理）/ `problem_router`（归因） | 🟡 三个零件，无统一门面 |
| **验收** | 每个阶段的"出院标准"可执行 | ⚪ 无 |
| **失败语义** | 测不出给空串（不填默认值） | 🟢 已落实 |

### 7.3 现有零件盘点

| 零件 | 文件 | 能做什么 | 不能做什么 |
|---|---|---|---|
| 五维评分 | `five_dimension_scorer.py`(377) | 画面质量25 / 高光25 / 文案20 / BGM15 / 时长15 | `estimated_dims` 机制 ⇒ 部分是估算，**非真审美** |
| 代理评分 | `ai/gen_critic.py`(320) | 5 指标 + 崩图闸门（筛掉糊/崩/比例错） | 不判断"好不好看" |
| 问题路由 | `problem_router.py`(193) | 把问题分到 retake / video-edit / 时间线操作 | 只归因，不判级 |
| 语义标记 | `clip_semantic.py`(163) | 高光/质量分盖到 clip 元数据 | 无跨片段聚合 |
| 合规检查 | `script_compliance_check` | 剧本合规分级 | 只覆盖文本 |

### 7.4 缺口：缺"管辖"

| 缺口 | 表现 |
|---|---|
| **无统一标准表** | 五维阈值写在代码常量里，没人能一眼看到"什么算 A 级" |
| **无闸门** | 分数算出来了，但**没有任何地方因为分数低而拒绝**（D 级也只是"默认剔除"提示） |
| **无跨阶段聚合** | 单镜头 85 分，但整集节奏可能是散的——没有"集级"评估 |
| **无追溯链** | 说"这集不行"，追不到"是剧本问题还是生成问题还是剪辑问题" |

### 7.5 设计方向：三层治理

```
┌─ 标准层 Standard ──────────────────────────────┐
│  一张可执行的评分卡（YAML），按阶段分：           │
│  S1 剧本：结构/人物/钩子/合规                     │
│  S2 分镜：景别多样性/构图/连续性                  │
│  S3 素材：崩图率/一致性/分辨率                    │
│  S4 剪辑：节奏/转场/音画同步                      │
│  S5 成片：黑帧/静帧/字幕溢出                      │
└───────────────────────────────────────────────┘
              ↓
┌─ 评估层 Evaluate ──────────────────────────────┐
│  统一门面 `governance.evaluate(stage, artifact)` │
│  复用现有零件（五维/代理分/路由），不重写算法       │
│  输出：{verdict: pass|warn|block, dims, reasons} │
└───────────────────────────────────────────────┘
              ↓
┌─ 闸门层 Gate ──────────────────────────────────┐
│  S3→S4：崩图率 > 阈值 ⇒ 不许入轨（block）        │
│  S4→S5：黑帧/静默超阈值 ⇒ 不许导出（block）      │
│  warn 级：允许但必须在 UI 显示（不静默）          │
└───────────────────────────────────────────────┘
```

**四条铁律**：
1. **代理分不冒充审美**——`is_proxy=True` 的分数只能用于"筛坏"，不能用于"评优"
2. **闸门必须硬**——block 就是 block，不给"这次算了"的口子（要放行必须显式 `force` + 记录）
3. **估算必须标注**——`estimated_dims` 的维度在报告里打星号
4. **治理不生产**——治理层只判不修，修交由各阶段

### 7.6 验收标准

- 任一阶段的产物能拿到 `{verdict, dims, reasons}`
- block 能真正拦住（有测试反锁）
- 报告能追溯到具体维度（不是"综合分 72"）

## 第十章 概念词典（可执行定义）

> 每个词条都回答三个问题：**是什么 / 不是什么 / 代码在哪**。避免"各说各话"。

### 10.1 抽卡（Draw）
- **是**：一次生成 n 个候选 → 逐张评分 → 取最优 → 全量入账（`draw_orchestrator`）
- **不是**：随机出一张然后挑；也不是"多生成几张备用"
- **代码**：`ai/draw_orchestrator.py` + `ai/gen_critic.py` + `ai/draw_book.py`
- **红线**：代理分只筛坏不评优（`is_proxy=True`）

### 10.2 母版（Master）
- **是**：一个稳定 ID 指向的资产本体（角色/场景/道具/风格），下游只引用不复制；变体 = 继承 + 覆盖
- **不是**：一张参考图；也不是 prompt 模板
- **应有**：`AssetMaster{id, kind, master, variants[], version, usage[]}`（**尚未实现**）
- **红线**：改母版必须让引用方 `stale`，但不自动重生成

### 10.3 审美治理（Aesthetic Governance）
- **是**：标准（评分卡）+ 闸门（block）+ 追溯（维度归因）三件套
- **不是**：多打几个分；也不是"AI 判断好不好看"
- **现状**：有零件无管辖（`five_dimension_scorer` / `gen_critic` / `problem_router`）
- **红线**：估算维度必须标星；block 必须硬

### 10.4 诚实失败（Honest Failure）
- **是**：做不到就明说（空串/错误码/降级标注），绝不放假结果
- **不是**：静默降级、填默认值、返回占位图
- **代码**：`fallback=True` 标注、`is_proxy=True`、景别/运镜空串

### 10.5 血缘（Lineage）
- **是**：clip → asset → task → canvas_node 的可追溯链
- **不是**：简单的 `canvas_node_id` 弱映射
- **代码**：`clip["generation"]` 血缘块 + `/host/clip-lineage` + `resolve_lineage`

### 10.6 棘轮（Ratchet）
- **是**：存量债务冻结基线，只许减不许增（ruff / stability / file_size）
- **不是**：允许"这次先超一点"

### 10.7 双模式（小白 / 专业）
- **是**：同一份 `node.data` 的两种视图渲染（不是两套数据、不是转换层）
- **不是**：需要"转换逻辑"的两套模型（2026-10-18 已评估为伪需求）

### 10.8 阶段契约（Stage Contract）★本版新增
- **是**：每阶段必须填满「输入/输出/责任人/验收/失败语义」五格
- **不是**：文档里的愿景描述
- **用途**：填不满的格子 = 缺口；填满但两端字段不一致 = 漂移
