## 2. 差距与损失分析（若强行做「图→队列」转换）

1. **非线性图不可无损线性化**：多分支（同 prompt 出多候选）、并行链、菱形汇聚
   的 DAG 拓扑序不唯一，投影成单列队列必然丢结构信息；
2. **反向（队列→图）更简单**：队列本质是链式 DAG，加边即成图——但现状两档
   已共数据，这个方向没有存在必要；
3. 结论：**「转换」是伪需求（已被架构消解），「队列视图」是真差距**
   （蓝图「小白=线性、队列、任务级」的交互形态尚未落地）。

## 3. 若立项：最小方案（供未来拍板，不含本次实施）

- 形态：novice 档新增**只读队列面板**（任务卡片列表 = 拓扑序投影 + 状态灯 +
  「确认执行」按钮），图视图保留可切换；
- 数据：零新模型——投影函数 `nodes/edges → 有序卡片`，纯前端（复用 runner
  的拓扑序口径，或后端只读端点回传执行序）；
- 分支降级策略：不可线性化的图 → 按分支分段显示（诚实提示「此处有 N 个并行分支」），
  不硬排成一条；
- 红线：不动 `_clips` 真相源、不新增 node.data 必填字段（NoviceCard 纪律）；
- 工作量画像：前端一个面板组件 + 一个纯函数投影 + 守卫；无后端改造。
