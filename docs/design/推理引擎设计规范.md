# 推理引擎设计规范（Spec · v1.0）

> 建立：2026-10-27 ｜ 状态：生效
> 文档关系：**`推理引擎架构设计.md`（为什么长这样 / 一次请求怎么流 / 分几期）→ 本文件（契约与纪律）→ `推理引擎开发指南.md`（手怎么动）**

> 上位约束：`docs/现行技术文档.md` §2b 依赖升级纪律、§5 冻结区、§16 自研引擎注册表口径。

## 1. 目的：我们说的"自主可控"到底指什么

**不指**把 diffusers / diffsynth 的代码抄进仓库——那是维护负担，不是控制权。

**指这四件事**：

| # | 可控点 | 判定标准（可验证） |
|---|---|---|
| C1 | **执行控制权** | 去噪循环、步间决策、条件编码的调用顺序由本仓库代码决定，不在第三方 `__call__` 里 |
| C2 | **契约所有权** | 输入/输出/能力声明由本仓库定义并版本化；上游 API 变更只影响 adapter，不影响内核 |
| C3 | **上游可替换性** | 任一份上游（diffusers / diffsynth）停更或不可用，引擎仍能服务已验收的族 |
| C4 | **行为可证明** | 每一项优化都有同条件实测数据（PSNR / 时延 / 显存），负收益也如实登记 |

**当前状态（2026-10-27 实测）**：C1 ❌（L0：全仓 `scheduler.step`/`unet(` 命中数 0，循环在 `diffusers/pipelines/stable_diffusion/pipeline_stable_diffusion.py:1032`）、C2 ❌、C3 ❌、C4 🟡（有 `quant_descriptor` 台账，缺时延/显存账本）。
→ 本规范的全部内容，就是把 C1~C4 从 ❌ 推到 ✅ 的定义与验收标准。

## 2. 口径（不得越过）

1. 对外只能说「**自研去噪执行内核**」。模型权重、scheduler 数学、VAE 算子来自上游 ⇒ **不得称「自研推理引擎」**（`docs/CHANGELOG.md` 口径段、`现行技术文档.md` §28）。
2. **不承诺"重写变快"**。已有实测：Python 层重写收益 <5%（`_reports/2026-10-24-统一推理引擎架构设计稿.md` §5）、CUDA Graph 0.33×（`accel_status.py:36-37`）。性能承诺只有两个字：**不降速**。
3. **不做 L4**：不自写 UNet/DiT 前向、不自写 CUDA kernel。理由是 ABI 连锁（numpy/torch/CUDA 三者耦合的教训见 §2b）与项目既定边界「自研聚焦 = 映射/一致性/路由」。
4. 每个"创新点"必须先有上游做不到的证据，再写进文档；写"领先"必须先有对照数据。

## 3. 分层与依赖方向

```
┌──────────────────────────────────────────────────────────┐
│ 入口层   diffusers_image.generate() / video_gen.generate() │  薄切换，只做二选一
├──────────────────────────────────────────────────────────┤
│ 后端层   backends/{diffusers_kernel, diffusers_pipe,       │  统一 GenRequest → DenoiseResult
│                   diffsynth_pipe}                          │  声明 loop_owner
├──────────────────────────────────────────────────────────┤
│ 内核层   kernel/{loop, schedule, cfg, latents, hooks,      │  ★ 唯一出现 for-step 的地方
│                  instrument, engine}                       │  不认识任何族名/组件名
├──────────────────────────────────────────────────────────┤
│ 适配层   kernel/adapters/{sd15, sdxl, svd, wan, dit_misc}  │  族语义全部在这里
├──────────────────────────────────────────────────────────┤
│ 组件层   ComponentBag.from_pipe(pipe)                      │  把 pipeline 当零件箱，绝不调 pipe()
└──────────────────────────────────────────────────────────┘
```

**依赖方向单向向下**，且有三条硬线（写成守卫断言 + 反例自证）：

| # | 硬线 | 反例（必须报红） |
|---|---|---|
| H1 | `kernel/loop.py` 不含任何族名/组件名（`unet`/`transformer`/`vae`/`text_encoder`/`sdxl`/`wan`/`svd`） | 在 loop 里写 `model = bag.unet` |
| H2 | `kernel/adapters/*.py` 不含 `for ... in timesteps`（循环只有一处） | 在 adapter 里自己 for 一遍 |
| H3 | `kernel/engine.py` 之外，内核层顶层不 import torch | 在 `contracts.py` 顶层 `import torch` |

**为什么必须这样分**：C3（上游可替换）只有在"内核不认识上游"时才能成立。任何一处漏进来的族名，都会把上游语义钉死在内核里。

## 4. 契约定义（本仓库所有，版本化）

### 4.1 版本规则

- `CONTRACT_VERSION = "1.0"`，定义在 `kernel/contracts.py`。
- 破坏性变更（删字段、改语义、改必填）⇒ 升 MAJOR，并在 `docs/CHANGELOG.md` 写迁移说明。
- 新增可选字段 ⇒ 升 MINOR，不写迁移。

### 4.2 GenRequest（一次生成请求，族无关）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `family` | str | ✅ | `sd15` / `sdxl` / `svd` / `wan` …，决定选哪个 adapter |
| `model_id` | str | ✅ | 引擎注册表里的 id，如 `sd15-t2i` |
| `prompt` / `negative_prompt` | str | — | SVD 无 prompt，允许空 |
| `image_path` | str | — | i2i / SVD 首帧 |
| `width` / `height` | int | — | 0 = 取注册表 native_size |
| `steps` / `cfg` | int / float | — | 0 = 取注册表默认 |
| `seed` | int | — | 0 = 随机；**沿用调用方既有 generator 语义**（见 5.3） |
| `preset` | str | — | 质量档（fast/high/final），由 adapter 翻译，内核不解释 |
| `strength` | float | — | i2i 专属 |
| `frames` / `fps` / `motion_bucket_id` / `noise_aug_strength` | — | — | 视频族专属 |
| `precision` | str | — | `fp16`/`fp8`/…，必须过 `quant_descriptor.is_admissible()` |
| `output_dir` / `out_path` | str | — | 落盘位置 |

**纪律**：`GenRequest` 只放"请求事实"，不放"实现参数"（如 `decode_chunk_size`、`branch_id`）——那些由策略层算完写进 `RunPlan`。

### 4.3 AdapterCaps（族能力声明，声明式）

| 字段 | 取值 | 用途 |
|---|---|---|
| `cfg_mode` | `cat` / `two_pass` / `none` | SD/SDXL=`cat`，Wan=`two_pass`，SVD=`cat`（逐帧） |
| `cfg_batch_multiplier` | 1 / 2 | 内核据此决定 batch 维度 |
| `allow_cfg_merge` | bool | `two_pass` 能否合并成 `cat`（默认 False，要显存余量才算） |
| `cond_keys` | tuple[str] | `("prompt_embeds","pooled","time_ids")` 等，声明式 |
| `timestep_kind` | `scalar` / `per_token` | Wan2.2 的 `expand_timesteps` |
| `latent_rank` | 4 / 5 | 图像 4，视频 5 |
| `latent_scale` | `init_noise_sigma` / `none` / `add_noise(strength)` | **Wan 不乘 init_noise_sigma** |
| `vae_decode` | `scalar_factor` / `per_channel_mean_std` / `chunked_temporal` | Wan 是逐通道 |
| `scheduler_family` | `eps` / `v_prediction` / `edm` / `flow_match` | 决定能否做调度表预计算 |
| `verified` | `verified` / `unverified` / `blocked` | 未 verified 的族，内核**默认拒绝** |

### 4.4 ParityContract（等价性契约）

每族必须显式声明"哪些语义漏了会掉 PSNR 但不报错"，并给容差：

```python
ParityContract(
    fields={"scale_model_input": True, "init_noise_sigma_once": True,
            "cfg_order": "neg_pos", "clip_skip": 1, ...},
    tensor_rtol=1e-3,      # 逐 step latents 张量对照
    psnr_min_db=35.0,      # 图像出图对照
)
```

**这张表就是验收的判据来源**，不是注释。新族准入必须填完它。

### 4.5 DenoiseResult（一次生成结果）

返回键与既有 `diffusers_image.generate()` / `video_gen.generate()` **逐键对齐**，只新增一个子字典：

```python
"kernel": {
    "used": bool, "family": str, "loop_owner": "shiguang"|"upstream",
    "steps": int, "rejected_reason": str,        # 未用内核时必填原因
    "breakdown": {"encode_ms":…, "loop_ms":…, "decode_ms":…,
                  "weight_gb":…, "peak_gb":…}   # 来自 vram_ledger
}
```

**纪律**：`used=False` 时必须写 `rejected_reason`（诚实失败，禁止静默回退）。

## 5. 族适配器规范

### 5.1 必须实现（缺一个就不算接入）

| 方法 | 职责 | 禁止事项 |
|---|---|---|
| `bind(bag)` | 绑定组件袋 | 不得在这里加载权重（加载归引擎） |
| `validate()` | 返回 `List[str]`，空 = 可跑 | 不得抛异常代替返回原因 |
| `encode(req)` | 条件编码 | 不得读 `req.steps`（与编码无关） |
| `make_timesteps(req, cond)` | 时间轴（strength 切片 / fps / begin_index） | 不得自己 for 循环 |
| `init_latents(req, cond)` | 初始潜变量（含 noise_aug / add_noise） | 不得在这里碰 CFG |
| `prepare_step / forward / guide / step` | 每步四件事 | `guide` 不得自己猜 chunk 顺序（由 `cfg.py` 给） |
| `decode(latents)` | VAE 解码（含反缩放、分块、force_upcast） | 不得在这里落盘 |
| `cache_key(req)` | 条件缓存键 | 不得漏族字段（SVD 要 `fps`/`noise_aug`） |

### 5.2 新族准入清单（Gate，全部满足才算 `verified`）

1. `AdapterCaps` 填全且自洽（如 `latent_rank=5` 必须 `vae_decode=chunked_temporal`）
2. `ParityContract` 填全，且每条字段有对应单测
3. 逐 step 张量对照 `max|Δ| ≤ 1e-3`（对照对象：stock pipeline）
4. 出图/出片 PSNR ≥ 35dB（同 prompt / seed / 步数）
5. 时延 ≤ stock × 1.00（1.00~1.03 只能写"持平"）
6. 峰值显存 ≤ stock × 1.05（视频 ×1.10）
7. 中断/取消可用（`cancel_token` 生效，返回 `ok:False, cancelled:True`）
8. 登记进 `kernel/evidence.py`（数字 + 来源脚本 + 日期）

### 5.3 generator 语义不得统一改写

- 图像路径用 **CPU Generator**（`diffusers_image.py:686` 既定）；视频路径用全局 `torch.manual_seed`（`video_gen.py:720` 既定）。
- 内核**必须沿用调用方既有语义**，不许"顺手统一"。原因：改一处，所有历史种子的可复现性全废。

## 6. 后端兼容与双栈策略

### 6.1 三态 `loop_owner`

| 值 | 含义 | 现状 |
|---|---|---|
| `shiguang` | 本仓库拥有循环 | 目标：sd15 / sdxl / svd / wan |
| `upstream` | 第三方 `__call__` 内跑，我们只包契约 | diffsynth_pipe、diffusers_pipe（兜底）、MiniMax-H3 |

**同一 engine id 允许两条腿并存**（pipe 兜底 + kernel 主路径），但必须在 `capability_manifest` 里**分别声明能力**，否则 UI 会"显示支持、实际静默回退"——这正是项目最反感的降级。

### 6.2 DiffSynth：兼容 + 有触发条件的接管预案（2026-10-27 决策）

**数据依据**：`diffsynth-engine` 正式版停在 **0.7.0**，dev 流最后一次 `0.7.1.dev11` 是 **2026-05-27**（停 5 个月）；同期 diffusers 两个月发了 0.41 / 0.42 / 0.42.1。⇒ **DiffSynth 是真正有停更风险的一方。**

| 层级 | 内容 | 状态 |
|---|---|---|
| 契约兼容（必做） | 统一 `GenRequest`/`DenoiseResult`，逐键对齐，共享账本与证据台账 | 立即 |
| 组件级接管（预案） | 用它的 `model` + `EulerSampler.initialize/step`（`pipelines/sdxl_image.py:448/469/492`）自建循环 | **触发条件满足才做** |

**触发条件（满足任一即启动接管，不必等开会）**：
1. 连续 **6 个月**无新正式版（非 dev）；
2. 出现影响出图的 open bug 且 **90 天**无维护者响应；
3. PyPI 包被下架/归档，或安装在新环境下失败。

**接管时的最小改动面**：只新增 `adapters/diffsynth_sdxl.py` + 一个 `backends` 实现，内核零改动——这是 H1/H2 硬线的直接兑现。

### 6.3 双栈不兼容的四个事实差异（必须进 `AdapterCaps`，不许假设统一）

| 差异 | diffusers | diffsynth | 后果 |
|---|---|---|---|
| 采样器 | DDIM/Euler/UniPC/LCM 可切 | 固定 `EulerSampler` | 同 seed 出图本就不同 |
| 时间轴 | `timesteps` | `timesteps` + `sigmas` 双轨 | 抽象不能只传 timesteps |
| CFG | `__call__` 内 cat/两遍 | pipeline 内 | `cfg_mode` 必须可声明 |
| 组件命名 | `unet`/`transformer` | `unet` + `vae_decoder`/`vae_encoder` 分离 | 缓存/卸载不能按名字硬编 |

### 6.4 验收口径（防止假结论）

**PSNR ≥ 35dB 只在同一后端内比较**：`kernel(diffusers)` vs `pipe(diffusers)` ✅；`kernel(diffusers)` vs `pipe(diffsynth)` ❌（采样器不同，必然低分，但两者都对）。
跨栈只做人眼 + 质量档位对标，报告里必须写「跨栈不设 PSNR 判据」。

## 7. 版本策略

### 7.1 钉版（2026-10-27 决策）

| 依赖 | 钉住 | 理由 |
|---|---|---|
| `diffusers` | **0.40.0** | 全部既有标定基线（SDXL 5.21GB/27.9s、SVD 40s、块池四档）都在它上面测得；上游已到 0.42.1，跟版 = 基线全废 + 重标定 |
| `torchao` | **0.16.0** | 0.17+ 要求 `torch ≥ 2.11`，而 Windows 上 torch ≥2.11 只有 cu130 轮子 ⇒ 装 0.16.0 是不动 torch 的唯一解 |
| `torch` | **2.6.0+cu124** | 项目基线；升 torch 会连带 torchvision/torchaudio/transformers 全动 |

**前置动作**：`requirements.txt` 目前**没有** diffusers、也没有 torch（只有 `numpy>=1.24.0`）。钉版 = 先把这两个显式写进去，否则"钉"只是口头。

### 7.2 季度评估清单（每季度一次，产出结论写 CHANGELOG）

1. 上游最新版 vs 钉住版差几个 minor，是否有**影响本仓库 4 个族**的变更
2. `kernel_semantics_snapshot` 是否红（循环体 AST 变了没）
3. 新版本是否带来**可测收益**（不是"有新特性"，而是"在我们机型上有数字"）
4. 升级成本 = 重跑全部标定（估计 4 项基准 × n≥5）
5. 结论三选一：**保持 / 升级 / 内嵌 fork**

## 8. 上游断供分级（回答"不知道什么时候会停"）

| 级 | 触发信号（客观可观测） | 动作 | 影响面 |
|---|---|---|---|
| **G0 正常** | 6 个月内有 release | 跟钉版，只跑快照守卫 | 无 |
| **G1 漂移** | 上游改名/改签名，快照守卫红 | **只改 adapter**，内核零改动；更新快照基线 | 1~2 个文件 |
| **G2 停更** | 连续 6 个月无正式版，或关键 bug 90 天不修 | 冻结版本（内嵌 fork 到 `vendor/`）+ 自修关键 bug；同时启动接管预案（§6.2） | 新增一个 adapter |
| **G3 断供** | 包下架/归档/装不上 | 用快照 + `safetensors` + `config.json` 自建最小实现；已 `verified` 的族优先恢复 | 新增一个 backends 实现 |

**G3 能成立的前提**（现在就该守住）：
1. **权重格式是事实标准**——`safetensors` + `config.json` 不依赖 diffusers 存活；
2. **语义快照在库**——`docs/knowledge/kernel_semantics_snapshot.json` 固化了"我们依赖上游的哪几行语义"，断供后可照它重写；
3. **组件袋隔离**——不调 `pipe()`，只取组件，天然可替换。

## 9. 创新点（本规范只认一个招牌）

**招牌：视频帧间控制（B）** —— 上游做不到，且是产品差异点。

| 能力 | 定义 | 诚实边界 |
|---|---|---|
| **生成期时长约束** | `n_frames = round(seconds × fps)` 在生成前确定，生成后 `probe_duration` 复核，四态 `trimmed/padded/mismatch/exact` 语义不变 | 这是"预测 + 复核"，不是"凭空精确" |
| **链式续生** | 段 k 的尾帧作为段 k+1 的条件首帧，多段串成"前后衔接" | **SVD 只有首帧条件、没有尾帧条件**（条件仅 `image` + `image_embeds`）⇒ 必须标注"链式"，**不得宣称"双帧约束"** |

**不作为招牌的两项**（写进文档但降级为"地基/副产品"）：
- **等价性验证体系（A）**：是 C4 的证明手段，上游确实没有，但用户感知不到 ⇒ 当地基。
- **显存账本 + 能力选路（C）**：工程价值高，但属于治理层 ⇒ 当副产品。

## 10. 显存账本规范（新增，补现有空白）

现状：`generate()` 只返回 `memory_mode/precision/seconds_elapsed`，**没有任何 GB 分项**；`engine_telemetry.record()` 签名无显存字段；步缓存 `stats()` 只被 `logger.info` 掉。所有显存数字都来自人工登记表。

规范：
1. 每次 load/generate 必须记 **5 个分项**：`weight_gb` / `activation_peak_gb` / `cache_gb` / `vae_decode_peak_gb` / `encoder_resident_gb`。
2. 来源三分：`measured`（`memory_allocated`/`mem_get_info` 差值）/ `estimated`（公式 + 方法写在 evidence）/ `registered`（注册表值）——**三者不许混用**，沿用 `vram_budget` 的 `basis` 口径。
3. **超预算在加载前诚实失败**，不等 OOM。
4. 所有优化（量化/卸载档/步缓存/块池）挂同一账本 ⇒ 节省可加、可归因、可复核。这是「-43% 凭什么可信」的制度答案。

## 11. 验收协议（每族、每次变更）

| 门 | 判据 | 不满足时 |
|---|---|---|
| 张量门 | 初始 latents 比特一致；每步 `max|Δ| ≤ 1e-3` | **阻断**，不许往下 |
| 画质门 | 同后端对照 PSNR ≥ 35dB（n≥3 seed） | 回退，记 `rejected` |
| 速度门 | `≤ stock × 1.00` 通过；`1.00~1.03` 写"持平"；`>1.03` 不通过 | 回退 |
| 显存门 | `≤ stock × 1.05`（视频 ×1.10） | 回退 |
| 可观测门 | 中断生效（`cancelled:True`）、逐 step 进度真实 | 回退 |
| 守卫门 | 三条硬线 + 快照 + EngineSpec 一致性全绿 | 阻断提交 |

测量协议（写进 `kernel/instrument.py`，禁止口头约定）：预热 1 次丢弃；权重只加载一次 A/B 共用同一组件袋；`cuda.Event` 分段；n=5 取 median；**A/B 交错执行**抵消降频；每次前 `reset_peak_memory_stats()`。

## 12. 变更管理

1. 契约改动 ⇒ 升 `CONTRACT_VERSION`，在 CHANGELOG 写**迁移说明**（谁要改、改哪行）。
2. 新增族/后端 ⇒ 先登记 `AdapterCaps` + `ParityContract`，再写实现（先契约后细胞）。
3. 任何"更快"的结论 ⇒ 必须附对照数据（同条件、n≥5、含反例）。
4. 文档同步三件套：本规范（决策变化）、开发指南（操作变化）、CHANGELOG（结果与理由）。
5. 与本规范冲突的实现，一律以本规范为准；要改规范，先改文档再改代码。
