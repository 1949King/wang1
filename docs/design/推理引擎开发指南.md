## 2. 动工前三条纪律（违反会返工）

1. **分支只允许存在一处**：新老路径切换只写在 `diffusers_image.generate()` / `video_gen.generate()` 各一个三元判断，不做平行双链路（§5 反模式红线）。
2. **探测纪律**：`is_available()` 只 `find_spec`；真 import 只在 `load()` 里（两次组合场景硬崩的血泪）。
3. **新逻辑另开文件**：主文件只加薄接线（≤60 行净增）；单文件 <500 行（`check_file_size.py` 会拦）。

## 6. 踩过的坑（都是真金白银，别再踩）

### 6.1 量化相关

- **`Int8Tensor` 会把 `.dtype` 和 `.data` 都伪装成 fp16**。按 `sum(p.numel()*p.element_size())` 算会得出"零压缩"的假结论。真实存储在 `qdata`(int8) + `scale`；正确测法是 `torch.cuda.memory_allocated()` 差值。
- **torchao 0.16 断言 `version=2` 只支持 `group_size=None`**；传 `group_size=32` 直接 `AssertionError`。
- **mslk 的 Windows 轮子是空壳**（`mslk-1.3.0+cu130-py3-none-win_amd64.whl` 351KB、0 个 `.pyd`），且强制 `import triton` ⇒ 装上会让 **torchao 整体 import 失败**。别装。
- **int8 已实测否决**（SDXL 输出全黑，PSNR 5.29）。要启用任何量化，先过 `quant_descriptor.is_admissible()`。

### 6.2 路径与环境

- **`diffusers_image.local_dir()` 返回相对路径**（`app/models/cache/...`），外部脚本必须先 `os.chdir(r"D:/拾光剪影")`，否则误报"模型未下载"。
- **`requirements.txt` 里没有 diffusers，也没有 torch**（只有 `numpy>=1.24.0`）。别以为"已经钉了版本"。
- **项目 venv 跑 `pip install` 可能报 `No usable temporary directory found`**（受限环境）。纯 Python 包可以绕过：用另一个解释器把 wheel 解压进 `site-packages`，`dist-info` 完整即等效安装，`pip show/uninstall` 都认。

### 6.3 循环语义（接管时必查）

- **CFG 拆成两次前向会让 `StepFeatureCache` 的步号整体偏移一倍**（它靠 `unet` pre-hook 调用次数推断步，`inference_cache.py:294-304`）。用 `cat` 一次 batch=2 前向才保持语义。
- **SDXL 的 VAE 反缩放是 0.13025，不是 0.18215**；`add_time_ids` 必须先 `cat([neg,pos])` 再 `repeat`。
- **SVD 的 `fps = fps - 1` 才进 `added_time_ids`**；`image_latents` 用 `latent_dist.mode()` 且**不乘** scaling；`noise_aug` 加噪**先于** latent 噪声。
- **Wan 的 latent 不乘 `init_noise_sigma`**，解码是**逐通道** `latents/(1/std)+mean`（当标量缩放用会静默花屏）。
- **generator 语义不许统一**：图像用 CPU Generator（`diffusers_image.py:686`），视频用全局 `torch.manual_seed`（`video_gen.py:720`）。改一处，历史种子全废。
- **`@torch.no_grad()` 漏了不是慢，是 OOM**。

### 6.4 测量

- 首次调用含 lazy init / cudnn autotune，**必须预热 1 次再计时**。
- 不预热就测，会得到"int4 比 fp16 快 100 倍"这种假数据（真实是 5~7 倍）。
- A/B 要**交错执行**，不要跑完 A 再跑 B（GPU 降频会让第二组系统性偏慢）。
- SVD `decode_chunk_size=1` 是定稿（chunk=2 慢 6 倍），别"优化"它。

## 7. 调试手段

| 手段 | 用法 | 看什么 |
|---|---|---|
| shadow 双跑 | `SHIGUANG_KERNEL=shadow` | 同一次请求跑 pipe + kernel，落两套结果与 PSNR |
| 语义快照 | `check_kernel_semantics_snapshot.py` | 上游循环体 AST 哈希变了没（升版后第一件事） |
| 逐 step 打点 | `kernel/instrument.py`（默认关） | 每步 `wall_ms` / 显存，定位是"哪一步开始漂" |
| 显存账本 | `vram_ledger` | 5 个分项，归因"省的是权重还是激活" |
| 降级日志 | `result["kernel"]["rejected_reason"]` | 没用内核时**必须**有原因，没有就是 bug |

## 8. 回退

```bash
SHIGUANG_KERNEL=off                 # 全局回退 pipe 路径
SHIGUANG_KERNEL_FAMILIES=sd15,sdxl  # 只让指定族走内核，其余回退
```

回退时必须满足：`result["warnings"]` 里写明「本次未用内核：<原因>」。
**静默回退 = 缺陷**，按 §11 可观测门算不通过。
