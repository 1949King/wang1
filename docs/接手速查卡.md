## 一、三条红线（背下来，违反会出不可逆的损失）

| 红线 | 具体禁令 | 正确做法 |
|---|---|---|
| 🚫 **不碰冻结区** | 未获授权不改 `docs/knowledge/frozen_zones.json` 列出的符号（107 把锁） | 需要改 → 先问：「这个属于冻结区吗？要走解冻流程吗？」 |
| 🚫 **不用通配符删文件** | 禁用 `rm *.tmp` / `del /S /Q` 这类批量删 | 让 AI **列清单**删除；删前先 `git ls-files <文件>` 确认是项目自有还是本次新建 |
| 🚫 **不动 git 历史** | 禁用 `git reset --hard` / `git push --force` / 删 `.git` | 回退单个文件用 `git checkout -- <文件>`；历史问题交给 AI |

> 项目真实血泪：一次 `_*` 通配清理曾误删 6 个项目自有文件，3 个永久丢失。
> 沙箱环境另有「每轮最多 50 次删除」的限制，超了连移动文件都会被拦。

## 三、九道提交卡点（提交时自动跑，红了就提交不了）

| # | 卡点 | 拦什么 |
|---|---|---|
| ① | ruff check | 语法错误、未用导入、重复定义 |
| ② | ruff format | 格式不统一（只警告不拦） |
| ③ | 冻结区守护 | 偷改冻结区 |
| ④ | 稳定性门禁 | 新增 `except: pass`、`print`、未定义名（棘轮：只减不增） |
| ⑤ | 粘合层契约 | 跨层乱调用 |
| ⑥ | 架构守护 + 双库一致性 | 架构违规、双库漂移 |
| ⑦ | 前端三卡点 | 类型错误超基线、单测失败、质量指标超标 |
| ⑧ | 单文件规模守卫 | 文件超 2000 行（存量冻结只减不增） |
| ⑨ | 路由属性检查 | 画布路由写法不合规 |

**被卡住怎么办**：把**完整报错原文**贴给 AI，说「提交被卡在哪道了，修一下」。
**绝对不要**用 `git commit --no-verify` 跳过——那等于拆掉安全带。

## 四、报错自救流程（四步，按顺序）

```
1. 看红在哪        → 看清是哪一项 FAILED / 哪个文件哪一行
2. 贴给 AI         → 完整报错 + 你刚做了什么改动
3. 判断真假        → 先看第五节「常见假警报」，别急着改代码
4. 改完重跑        → 门禁全绿才算完
```

### 问 AI 的模板（照抄）
```
现状：<我在做什么>
现象：<完整报错/异常表现>
期望：<我想要的结果>
约束：<别动冻结区 / 先给方案别动手 / 附文件行号证据>
```

## 五、常见「假警报」对照表（看着像故障，其实不是）

| 现象 | 真相 | 要不要处理 |
|---|---|---|
| 「未检测到 GPU，将使用 CPU 运行」 | 假告警：该函数只在日志处被调用，**不参与编码器选择** | ❌ 别重启、别改编码逻辑 |
| 「硬件检测失败: No module named 'psutil'」 | 用系统 Python 启动导致；`.venv312` 依赖是全的 | ⭕ 用 bat 或 `.venv312` 启动即可 |
| `Error in sitecustomize; PermissionError` | 外部环境的噪音，项目代码里没有 `sitecustomize.py` | ❌ 忽略 |
| 「Ollama 未找到」/「ComfyUI 连接失败」 | 外部程序没启动（不是本项目故障） | ❌ 需要时再启动对应程序 |
| 双库检查报某文件「分叉」 | 先查是不是**行尾假分叉**（CRLF vs LF）：`git diff` 为空就是假的 | ⭕ 让 AI 转行尾即可 |
| 沙箱里生成图片报「inbox 失败」 | 沙箱权限问题，不是代码缺陷 | ⭕ 真实环境（.bat 启动）正常 |
| 测试运行时冒出 `sg_*` / `cover_*` 垃圾目录 | 临时目录回退到项目根的已知问题 | ⭕ 让 AI 按名单清理 |

## 六、需要动冻结区怎么办（流程，不可跳步）

```
1. 先问清楚：这个改动的「为什么」值不值得动冻结区？
2. 取得明确授权（口头/文字都行，但必须是明确的）
3. 备份该文件
4. 改
5. 跑全部门禁 + 相关测试
6. 重锁基线：python scripts/frozen_zone_guard.py --update
7. 同步 4 处记录：frozen_zones.json / docs/现行技术文档.md §5 /
   .cursor/rules/frozen-zones.mdc / CHANGELOG
```
**守卫只有两种模式**：无参数 = 校验；`--update` = 重写基线。**没有 `--check` 参数**。

## 八、每次改动的最小闭环（照这个做，不会出错）

```
① 说清需求（现象 + 期望 + 约束）
   ↓
② 让 AI 先出方案（别让它直接动手）
   ↓
③ 你拍板 → AI 改
   ↓
④ 跑全量体检 + 全量测试（两条命令，见第二节）
   ↓
⑤ git 提交存档（写清改了什么）
   ↓
⑥ 让 AI 更新版本号 + CHANGELOG + 记忆日志（项目规矩）
```

## 九、术语快速对照（10 个词）

| 术语 | 一句话 |
|---|---|
| 真相源 | 唯一说了算的数据（剪辑里是 `_clips`） |
| 冻结区 | 不许随便碰的区域（107 把锁） |
| 守卫/门禁 | 自动体检（107 项 + 14 道提交卡点） |
| 棘轮 | 旧问题冻结，只许减不许增 |
| 回归测试 | 改完必跑的全部测试（1,765 例） |
| bench | 性能实测脚本，用数字说话 |
| offload（卸载） | 模型太大时分块换进显存 |
| 诚实失败 | 做不到就明说，绝不放假结果 |
| 双库 | 两套前端源码要保持同步 |
| 缺口记账 | 没做完的记在案，不假装做完 |
