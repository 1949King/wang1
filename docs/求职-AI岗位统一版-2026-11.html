1-A 的缺口：不是「不会 ComfyUI」，是「没亲手连过节点」

三条 JD 的共同要求是：节点式工作流搭得出、LoRA 训得动、能把管线复用起来。2026-11-15 复查代码后，你已有的部分比原先估计的多一项：

  • 你写过 ComfyUI 的工作流格式转换器 —— app/core/ai/workflow_importer.py，注释原文：「把用户从 ComfyUI 复制的 workflow JSON 规范成可直接提交给内置引擎 /prompt 接口的 graph prompt。核心思想是透传而非复刻——只做格式识别、UI→graph 转换与结构校验」。
    ⇒ 这意味着你认得 UI workflow 的 nodes / links 结构、知道 graph prompt 与 UI 格式的差异、知道 widgets_values 要按节点定义顺序对齐、会调 /object_info 做 schema 校验。这是「懂节点为什么这么连」，比「会拖节点」高一层。
  • 你写过 ComfyUI 的引擎接入层 —— comfy_client.py 覆盖 /system_stats /object_info /prompt /history /view /upload/image；comfy_provider.py:90 ensure_engine() + :118 subprocess.Popen(main.py) 会自拉起内置引擎。
  • 参数化不稳定生成 —— 灯光预设 24 槽位、提示词块编辑模式，本质就是「把生成参数固化成可复用结构」，和节点图同一思路。
  • 多模态串联 —— 图 · 视频 · 3D · 成片四条链路，而博彦那条 JD 直接写「支持图像、视频、3D 等多模态内容生成」。
  • 成本与约束意识 —— 显存约束下做模型选型、量化、按输入比例算输出尺寸，这就是「核算单次生成成本」的实操版。自检里 peft + accelerate + safetensors 齐备（ai_runtime_selftest.py:127），LoRA 微调栈是通的。

所以缺口只剩一件：亲手把节点连一遍，把「我懂结构」变成「我搭得出」。按每周 10 小时算 2–3 周（约 25 小时），能补到「拿得出 2 套自建工作流 + 讲得清每个节点为什么这么连」。

但有一处必须诚实：有代码 ≠ 跑通过

ensure_engine() 和 Popen 都在，但没有证据证明本机真拉起过内置引擎。面试被问「你实际跑通过吗」，不能说「架构上支持」。补 ComfyUI 的第一件事就是把这个跑通一次——跑通了，这条经历才从「我写过」变成「我用过」。

「AI 原生」的真凭据不是功能，是架构

app/core/agent_capability_catalog.py 注册了 110 个 capability，而且不是聊天玩具——是让 AI 直接操作时间线和画布：

  • 时间线：editor.split_clip editor.ripple_delete_range editor.rough_cut_plan editor.precision_align_plan editor.suggest_beat_cut editor.suggest_scene_cut editor.suggest_silence_trim
  • 画布：canvas.generate_image canvas.local_generate_image canvas.image_to_video canvas.ai_upscale canvas.ai_matte canvas.ai_face_restore canvas.comfyui_run canvas.segment_retake
  • 权限模型：每个 capability 带 effect（read / canvas_write / file_write / media_write / memory_write）+ paid 标记，由 agent_policy 统一裁决
  • 左右脑分类：agent_brain 的 right（创意）/ left（逻辑）/ cc（胼胝体）

这才是「AI 原生」的本义：AI 不是产品的附属按钮，而是能直接改工程文件的执行者，且每步都有权限边界。绝大多数所谓「AI 功能」做不到这一层。

三处必须诚实对待的边界

  • 内置引擎「有代码」≠「跑通过」：ensure_engine() 与 Popen 都在，但没有本机真拉起的证据。这条决定你是「我写过接入层」还是「我用过它」——90 天路线第一件事就是把它跑通。
  • 音乐（YuE）跑不动：只有计划层，执行端不可用。这条要主动排除，别当能力讲。
  • ③ 那层占比不小：第三方生成与自研本地推理并存，说「全本地」会被追问穿。准确说法是「本地优先，外部兜底」。

所以面试该怎么说

场景话术
能说 「我做过一个 AI 原生的创意生产工具，AI 能直接操作时间线和画布——110 个能力，每个都带读/写权限和计费标记。生成侧本地优先，我自己写过 ComfyUI 的引擎接入和工作流格式转换。」
不能说 「我训练了模型」「我实现了扩散模型」「全本地运行」——这三句都会被一句追问拆掉。
被追问时 「模型是开源权重，我做的是加载、量化、显存调度和调用；工作流格式转换和引擎接入是我自己写的。」

1-B 客户端 时间轴多轨编辑、画布交互、构建与发布流程 「我做过完整的产品闭环，包括打包交付和回归验收。」
3 建筑 只演示建筑漫游那一条链路 「我懂建筑，也能把空间变成可看的东西。」
一个必答题，有数字和没数字差一个职级

客户端/工具类岗位面试必问：「你的时间轴在多少轨道、多长素材下还能流畅预览？」
如果你有实测数据（帧率、内存占用、首帧耗时），写进演示说明。没有就现在测一遍——这是你唯一能拿出的、别人无法反驳的硬指标。

九、90 天路线（约 125 小时 · 已按 2026-11-15 复查重算）

先说清账：每周 10 小时（工作日体力劳动后有效约 6h + 休息日约 5h），90 天 ≈ 125 小时。

为什么从 120 天缩回 90 天：2026-11-15 复查代码发现你已有 workflow_importer.py（ComfyUI 工作流格式转换）+ comfy_client.py（REST 接口层）， 所以「学 ComfyUI」这一段从 60 小时降到 30 小时。另一个版本的 90 天因此重新变得可行——但前提是只做主线，建筑 demo 算可选项（见下方砍项顺序）。

阶段约几周做什么产出
第 1–3 周 30h 先跑通一件事：把你已有的 ensure_engine() + workflow_importer 真跑起来一次，让内置引擎拉起、工作流提交成功。 然后复刻 3 个官方示例、自己搭 2 套工作流（一套角色一致性、一套图生视频）。目标不是「会点」，是「能讲清每个节点为什么这么连」 「跑通过」的证据 + 2 套自建工作流 + 每套一页节点说明
第 4–7 周 40h LoRA 训练一次（哪怕效果一般，peft + accelerate 环境已通）+ 剪出 1-A 的那支 3 分钟切片 1 支工作流演示片 + 1 个 LoRA
第 8–10 周 25h 建筑漫游变体 demo（复用灯光预设，别重做）—— 可选项，时间不够就砍 1 支漫游片
第 11–13 周 30h 定向投递：先投博彦、钰冠、云境清禾这三条大专可投的；同步投 5 家 1-C 当保底。内推优先，不海投 投递记录表
如果时间不够，按这个顺序砍（不要反过来砍）
  1. 先砍建筑漫游 demo（方向三是备选，不是主线）
  2. 再砍LoRA 训练深度（能跑通一次就够，不追求效果）
  3. 最后才砍ComfyUI 的两套工作流——这一项砍了，1-A 就没了

十、红线与话术（背下来）

  • 不能说「我写了 29 万行代码」。面试官打开就崩，且构成虚假陈述。
    改说：「我一个人用 AI 工具把这个系统从需求拆到跑通。代码是 AI 辅助生成的，我负责架构设计、链路打通和验收，我能读懂并定位问题。」
  • 把「非科班」说在最前面。主动说「我是建筑工程技术专科，没系统学过编程，我是靠 AI 工具做出来的」——先说，面试官就不再拿它卡你；藏着被问出来就是减分。
  • 禁用形容词：精通 / 熟练掌握 / 深入研究。改成「用过、做过、跑通过、能定位」。
  • 别讲术语自嗨。「冻结区」「体积守卫」「棘轮」这些词面试官听不懂。要翻译成人话：
    「改高风险模块之前我先把不该动的接口锁住定好契约，改完跑一轮回归，所以我一个人改 20 多万行没把原功能改坏。」讲结果和纪律，不讲名词。
  • 别说它是「短剧剪辑工具」。它是通用创意生产工具，绘图·视频·3D·成片四条链路。说成短剧工具，等于自己把护城河讲小。
  • GitHub 别整库开源。私有仓库保提交记录，另开一个脱敏的最小 demo 放公开库。
  • 薪资按下沿 +20% 谈。挂牌区间取低值再往上谈，不要按上限预期。
