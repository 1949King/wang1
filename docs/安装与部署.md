# 安装与部署

> 适用版本：4.47.0 及以后（版本真源 `app/version.py`）
> 本文记录**终端用户怎么装**，以及**出包机器怎么打出安装包**。
> 打包内部机制（PYZ / runtime_pack / 差集同步）见 `docs/现行技术文档.md` 与 `topics/packaging.md`。

## 二、安装包

### 2.1 怎么产出

**当前主路径：Inno Setup 完整包**

```bash
# 完整链路（PyInstaller → 装 AI 内核 → 自检 → Inno 分卷安装包）
.venv312\Scripts\python.exe scripts\build_release.py --inno-installer --disk-spanning

# 复用已有 dist，只重出 Inno 安装包
.venv312\Scripts\python.exe scripts\build_release.py --skip-pyinstaller --inno-installer --disk-spanning

# 内容降到单文件上限内时，可去掉 --disk-spanning 尝试单文件
.venv312\Scripts\python.exe scripts\build_release.py --skip-pyinstaller --inno-installer
```

前置：Inno Setup 6.x（`winget install --id JRSoftware.InnoSetup --exact`）。编译器缺失时构建会明确报错；脚本也会检测 `%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe`。

**保留的 NSIS 回退路径**

```bash
.venv312\Scripts\python.exe scripts\build_release.py --installer
.venv312\Scripts\python.exe scripts\build_release.py --installer --skip-pyinstaller --skip-selftest
.venv312\Scripts\python.exe scripts\build_release.py --installer --fast-compress
```

NSIS 回退前置：`winget install NSIS.NSIS`。该路径不能承载当前完整体积，原因见 2.7。

两条路径都由 `build_release.py` 读取 `app/version.py` 的 `__version__`：Inno 通过 `/DAPP_VERSION` 注入 `scripts\installer.iss`，NSIS 通过 `dist\build_info.nsh` 注入 `scripts\installer.nsi`。**安装脚本里没有写死任何版本号**。

### 2.2 当前 Inno 安装包内容与安装方式

当前 Inno 包不再拆分“程序本体 / AI 内核”可选组件，而是一次完整安装：

| 内容 | 是否随包 | 说明 |
|---|---|---|
| 主程序与 `_internal` | ✅ | Python 3.12、PySide6 / Qt6、插件、技能及桌面依赖 |
| `runtime` 本地 AI 推理运行时 | ✅ | 安装副本实测 206 个包、4477.7 MB |
| 模型权重 | ❌ | 需另行获取，未配置权重的本地生成功能不能视为可用 |
| 本机作品、输出与日志 | ❌ | 安装源排除 `短剧AI剪辑输出`、`output`、`logs`、`debug.log` |

**评委 / 用户安装步骤**：

1. 将 `拾光剪影-Setup-4.47.0.exe` 与 `拾光剪影-Setup-4.47.0-1.bin`、`-2.bin`、`-3.bin` 放在**同一个普通本地目录**。
2. 双击 Setup.exe，同意许可并选择安装目录；默认是 64 位 Program Files 下的 `拾光剪影`。
3. 安装目录保持简短，例如 `C:\拾光剪影`。安装完成后从开始菜单或桌面入口启动。

安装器包含许可页、目录选择、开始菜单与桌面快捷方式；不支持只装主程序而裁掉 `runtime`。旧 NSIS 脚本中的可选组件设计仅属于回退路径，不是当前 Inno 包的界面。

向导语言为**简体中文**：`installer.iss` 的 `[Languages]` 显式指定随仓库携带的 `scripts\ChineseSimplified.isl`（官方 6.5.0+ 翻译，LanguageID=$0804）。缺该段时 Inno 退回内置英文 Default.isl——**编译不报错、装完才发现向导全是 Next/Cancel/Install**，已由契约测试 `test_inno_wizard_language_is_chinese` 钉死。只配一种语言时不弹语言选择框，卸载器同样跟随中文。

### 2.3 NSIS 回退路径的安装前三道检查

以下检查属于旧 `installer.nsi`，不要与当前 Inno 包混为一谈。NSIS 脚本在 `.onInit` 里依次执行，命中任一条都会中止：

1. **64 位系统** —— 产物是 64 位解释器打的，32 位系统装了也起不来。
2. **已安装检测** —— 读注册表 `DisplayVersion` / `InstallDir`，弹窗告知「将覆盖该位置」，可取消。不是静默覆盖。
3. **结束正在运行的实例** —— `taskkill /F /T /IM 拾光剪影.exe`。

第 3 条不是洁癖：程序跑着的时候 `_internal\` 下的 `.dll` / `.pyd` 被加载，NSIS 覆盖写入**失败但不中断安装**，用户最后拿到的是「装完打不开 / 功能缺失」的残缺版，且没有任何报错。

### 2.4 卸载与用户作品保护

控制面板「应用和功能」→ 拾光剪影 → 卸载，或运行安装目录里的 `unins000.exe`。

**当前 Inno 包的契约**：

- 交互卸载会询问是否同时删除用户数据；选择“否”保留作品。
- 静默卸载（`/VERYSILENT /SUPPRESSMSGBOXES /NORESTART`）**不询问、始终保留后产生的用户数据**。
- 只有用户明确同意时，才删除 `{app}\短剧AI剪辑输出`、`{app}\output`、`{app}\素材库` 三个明确目录；禁止递归删除整个 `{app}`。
- 2026-11-18 实测：静默卸载退出码 0，主 exe、`runtime` 和卸载器被移除，`短剧AI剪辑输出\卸载保护验收.txt` 保留。

旧 NSIS 回退脚本也保留了卸载询问与注册表清理逻辑，但其 `/S` 等命令行参数不属于 Inno 包的使用说明。

### 2.5 一条硬约束：版本号只有一个真源

安装脚本里**禁止**出现写死的版本字符串。

历史教训：`installer.nsi` 曾写着 `!define APP_VERSION "4.10.3"`，而代码已到 4.47.0 —— 脱节 37 个次版本，一直没人发现。后果不只是文件名错，`DisplayVersion` 也写的是 4.10.3，**用户在控制面板看到的版本是假的**，排查问题时按版本对不上号。

现在的链路是单向的：

```
app/version.py __version__
   → build_release.read_app_version()      # 正则读，不 import 主程序
   ├─ /DAPP_VERSION → installer.iss        # 当前 Inno 主路径
   └─ dist/build_info.nsh → installer.nsi  # 保留的 NSIS 回退路径
   → 产物文件名 + 控制面板 DisplayVersion
```

`build_release.py` 出包后还会**按版本号精确校验**产物是否存在。原先的写法是「取 dist 里最新的一个 `拾光剪影-Setup-*`」，很容易拿到上一次的旧包，报出来的文件名和实际内容对不上。

### 2.6 NSIS 回退路径编码：`.nsi` 与 `LICENSE.txt` 必须是 UTF-8 **with BOM**

NSIS 3 在 `Unicode true` 下靠 BOM 判断编码。**无 BOM** 的 UTF-8 文件会被按本地 ANSI(GBK) 解释字节流 ⇒ 安装包里所有中文变成乱码，而且**编译不报错**，装完才看得见。

实测反例（同一份脚本，只删掉前三个字节 BOM）：

| 文件状态 | makensis 预处理输出里的中文 |
|---|---|
| UTF-8 with BOM | 全部正常 |
| UTF-8 无 BOM | 全部乱码 |

所以改这两个文件时，编辑器别开「保存为 UTF-8 无 BOM」。makensis 编译时会打印 `Processing script file: "...installer.nsi" (UTF8)`，这句里带 `(UTF8)` 才算对。

### 2.7 体积硬约束：makensis 装不下大包（实测）

这是旧 NSIS 路径**无法打出完整安装包**的真正原因，不是脚本写错，也不是没装 NSIS；当前交付已改走 Inno。

makensis 是 32 位程序，安装包数据块要 mmap 进 2 GB 用户态地址空间。本机实测（NSIS 3.13 / Windows）：

| 数据量 | 结果 |
|---|---|
| 900 MB | ✅ 成功 |
| 1.4 GB | ✅ 成功 |
| 1.6 GB | ✅ 成功（1 分 12 秒） |
| 1.8 GB | ✅ 成功 |
| **1.96 GB**（真实 `_internal`） | ❌ `Internal compiler error #12345: error mmapping file (1992247082, 33554432) is out of range` |
| **6.35 GB**（含 runtime） | ❌ 同上 |

失败发生在**打包开始后几秒内的预分配阶段**，与压缩率无关；换成 zlib / lzma 都一样。所以这是地址空间上限，不是配置问题。

本项目当前体积：

| 部分 | 体积 | 文件数 |
|---|---|---|
| `_internal`（程序本体） | **1.96 GB** | 5826 |
| `runtime`（AI 内核） | **4.37 GB** | 19963 |
| 合计 | 6.35 GB | 25791 |

⇒ **本体的 1.96 GB 就已经越过 NSIS 上限**，旧路径连「只装本体」都做不到。

`scripts/build_release.py` 里的 `NSIS_DATABLOCK_LIMIT = 2 GiB` 就是按这个实测设的：总体积超线时**不**把内核并入，并打印明确警告。这个判断只能靠体积算，不能想当然。

**历史候选出路，现已选择第 2 条的 Inno Setup**：

1. 瘦身到 1.8 GB 以下：会改变 PyInstaller 收集内容，需额外运行时回归，本轮没有采用。
2. **换打包器：已落地 Inno Setup 6.7.3**，保留完整桌面环境和 `runtime`，以 1 GiB 固定分卷交付。
3. 只做绿色版：仍保留为免管理员分发的备选形态。

> **在保持 6.35 GB 完整内容的前提下无法得到 NSIS 安装包**。这是工具限制；Inno 是当前主路径，NSIS 脚本仅作回退保留。

### 2.8 NSIS 回退路径压缩耗时

`SetCompressor /SOLID lzma` 对 GB 级目录很慢（1.8 GB 零字节数据实测 1 分 12 秒；真实 dll 数据压缩率低、更慢）。赶时间用 `--fast-compress`（zlib），代价是产物体积更大 —— 但注意 zlib 在接近上限时更容易失败（它需要更多同时驻留的数据）。

## 四、模型权重不随包分发

安装包和绿色版**都不含社区 AI 模型权重**。完整安装包包含本地推理运行时，但未配置相应权重时，本地生图、生视频、形象驱动口型成片等功能不能视为可用；剪辑、画布、数字人节点及已配置的云端能力不受此限制。

本地生成的权重需要自己从社区获取（ModelScope / Hugging Face / GitHub），入口在程序内：本地模型面板每一行都有「魔搭 / GitHub」链接。详见 `docs/现行技术文档.md §40.20`，以及 `python scripts/check_models.py --missing` 看缺什么、怎么拿。

单文件工具权重同样不随包、**绝不自动下载**：RIFE 补帧权重（`rife49.pth`）缺失时，「神经补帧」按钮会给出资源地址与放置步骤；ESPCN 超分权重（`.pb`）缺失时诚实降级为双三次插值并如实标注。

**为什么不打包权重**：单个模型动辄 12~85 GB，且各有各的许可条款，随包分发既不可行也不合规。

## 五、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `Internal compiler error #12345: error mmapping file ... is out of range` | 数据量超过 makensis 的地址空间上限（约 1.8 GB）。见 2.7，不是脚本错 |
| `error creating mmap the size of 41353472` | 同上，换了个报法（剩余地址空间比单个块还小） |
| 安装包界面中文是乱码 | 编译时 `.nsi` 或 `LICENSE.txt` 丢了 BOM。见 2.6 |
| Inno 安装向导是英文（Next/Cancel/Install） | `installer.iss` 缺 `[Languages]` 会退回内置英文 Default.isl。现行版本已显式指定随仓库携带的 `scripts\ChineseSimplified.isl`（简体中文），契约钉死；旧包复现请用新脚本重出。见 2.9 第 9 条 |
| `build_release.py` 报「找不到 makensis.exe」 | 没装 NSIS：`winget install NSIS.NSIS` |
| 装完打不开 / 功能缺失 | 装的时候程序还在运行，`_internal` 下有文件没覆盖成功。关掉程序重装 |
| 提示缺 `VCRUNTIME140.dll` / `MSVCP140.dll` | 2026-11-20 重建版起 CRT 已随包（exe 根 + `_internal` 双份），正常不应再出现；若仍出现，说明装的是旧包或四文件不全，用新四文件重装。旧包救急可装 [VC++ 2015-2022 x64](https://aka.ms/vs/17/release/vc_redist.x64.exe) |
| 控制面板里版本号是 4.10.3 | 那是旧版本安装包的错版本（版本号曾写死在 nsi 里）。用新脚本重出包 |
| Inno 安装提示找不到 `.bin` / 无法继续 | Setup.exe 与 3 个分卷没有放在同一目录，或只下载了 Setup.exe |
| Inno 创建技能 SVG 时提示找不到路径并回滚 | 目标路径过长；改用 `C:\拾光剪影` 等短目录重新安装 |
| 本机从原始 D 盘 dist 启动 Setup.exe 返回 1 | 残余环境异常尚未定位；将四个文件复制到 C 盘短的普通本地目录后运行 |
| Lite 版本地生图 / 生视频 / 神经补帧不可用 | Lite 不含 `runtime` AI 内核，属预期边界（诚实降级）；需要本地 AI 请装全量四文件 |
