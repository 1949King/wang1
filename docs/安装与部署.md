# 安装与部署

> 适用版本：4.47.0 及以后（版本真源 `app/version.py`）
> 本文记录**终端用户怎么装**，以及**出包机器怎么打出安装包**。
> 打包内部机制（PYZ / runtime_pack / 差集同步）见 `docs/现行技术文档.md` 与 `topics/packaging.md`。

---

## 一、两种交付形态

| 形态 | 产物 | 面向 | 有安装向导 | 有卸载入口 | 能升级覆盖 |
|---|---|---|---|---|---|
| **安装包** | `dist\拾光剪影-Setup-<版本>.exe` | 普通用户 | ✅ 6 页向导 | ✅ 控制面板 / 开始菜单 | ✅ 记住上次目录 |
| **绿色版** | `拾光剪影-<版本>-portable.zip` | 自用 / 内测 / 免管理员 | ❌ 解压即用 | ❌ 手动删目录 | 手动覆盖 |

两者内容**完全一样**（都来自 `dist\拾光剪影\`），区别只在外壳。

> 🔴 **当前状态（2026-11-15）：安装包这条路径被体积卡住，还没有可用的 Setup.exe。**
> 安装脚本本身已经写好并测过（6 页向导 / 编码 / 卸载保护 / 15 个契约测试全绿），
> 但 `_internal` 有 1.96 GB，超过 makensis 32 位地址空间的实测上限（约 1.8 GB）。
> 详见 **2.7**。**现在能用的交付形态是绿色版（第三节）。**

## 二、安装包

### 2.1 怎么产出

```bash
# 完整链路（PyInstaller → 装 AI 内核 → 自检 → NSIS）
.venv312\Scripts\python.exe scripts\build_release.py --installer

# 已打过 PyInstaller，只重出安装包（改安装脚本后调这个）
.venv312\Scripts\python.exe scripts\build_release.py --installer --skip-pyinstaller --skip-selftest

# 赶时间：用 zlib 替代 solid lzma
.venv312\Scripts\python.exe scripts\build_release.py --installer --fast-compress
```

**前置**：装 NSIS 3.x（`winget install NSIS.NSIS`）。没有它第 ④ 步会明确报错，不会静默跳过。

`build_release.py` 会先读 `app/version.py` 的 `__version__`，生成 `dist\build_info.nsh`，再交给 `scripts\installer.nsi`。**安装脚本里没有写死任何版本号**——这一点是硬约束，原因见 2.5。

### 2.2 向导的 6 个页面

| # | 页面 | 说明 |
|---|---|---|
| 1 | 欢迎 | 显示版本号（来自 `app/version.py`），声明模型权重不含在包内 |
| 2 | 许可协议 | 读根目录 `LICENSE.txt`，必须同意才能继续 |
| 3 | 组件选择 | 见下表 |
| 4 | 安装目录 | 默认 `C:\Program Files\拾光剪影`，记住上次位置 |
| 5 | 进度 | 显示详细解压日志 |
| 6 | 完成 | 可勾选「立即启动」 |

**组件**：

| 组件 | 默认 | 体积 | 不装会怎样 |
|---|---|---|---|
| 程序本体 | **必装**（不可取消） | `_internal` + 主程序 | — |
| 本地 AI 内核 | 装 | `runtime\`，约 6 GB 量级 | 只能用云端模型，本地生图/生视频不可用 |
| 桌面快捷方式 | 装 | 0 | 只有开始菜单入口 |

> **当前实际状态（2026-11-15 实测）**：AI 内核**不会**被并入安装包。原因见 2.7 的体积硬约束 —— `runtime` 有 4.37 GB，而 makensis 是 32 位程序，装不下。
> 上表那一行描述的是「内核本来设计为可选组件」和「体积允许时脚本会怎么做」，不是当前产物里能看到的选项。
> 组件机制本身保留着：`dist` 总体积降到 1.8 GB 以下时，`build_release.py` 会自动把内核并进安装包（`HAS_RUNTIME` 开关）。
> 若打包时 `dist\拾光剪影\runtime\` 不存在，这一项会**整个消失**（不是灰掉，是不出现），因为 `File /r` 是编译期指令，源目录缺失会让 makensis 直接失败，所以「有没有」必须在编译期确定。

### 2.3 安装前的三道检查

脚本在 `.onInit` 里依次执行，命中任一条都会中止：

1. **64 位系统** —— 产物是 64 位解释器打的，32 位系统装了也起不来。
2. **已安装检测** —— 读注册表 `DisplayVersion` / `InstallDir`，弹窗告知「将覆盖该位置」，可取消。不是静默覆盖。
3. **结束正在运行的实例** —— `taskkill /F /T /IM 拾光剪影.exe`。

第 3 条不是洁癖：程序跑着的时候 `_internal\` 下的 `.dll` / `.pyd` 被加载，NSIS 覆盖写入**失败但不中断安装**，用户最后拿到的是「装完打不开 / 功能缺失」的残缺版，且没有任何报错。

### 2.4 卸载

控制面板「应用和功能」→ 拾光剪影 → 卸载，或开始菜单里的「卸载 拾光剪影」。

卸载会**先问一句**：

```
是否同时删除安装目录下的用户数据？
包括：作品输出、素材库、项目文件、日志与配置。
选择「否」将保留这些文件（推荐，便于重装后继续使用）。
```

为什么必须问：这个程序会把作品写在自己的目录下（`短剧AI剪辑输出\`、`output\`、`素材库\` 等）。无条件 `RMDir /r "$INSTDIR"` 等于**卸载即删光用户全部作品**，而且原脚本就是这样写的、没有任何提示。

选「否」时，只删 `_internal\`、`runtime\`、主 exe 和顶层 dll/log，然后用不带 `/r` 的 `RMDir` 尝试删目录——目录非空就自动失败，数据正好保住。

**注册表项**（卸载干净，不留残渣）：

```
HKLM\Software\ShiguangJianying                                     InstallDir / Version
HKLM\Software\Microsoft\Windows\CurrentVersion\Uninstall\ShiguangJianying
  DisplayName / DisplayVersion / Publisher / DisplayIcon / InstallLocation
  UninstallString / QuietUninstallString / NoModify / NoRepair / EstimatedSize
```

含 `QuietUninstallString`（支持 `/S` 静默卸载）和 `EstimatedSize`（控制面板显示真实占用）。

### 2.5 一条硬约束：版本号只有一个真源

安装脚本里**禁止**出现写死的版本字符串。

历史教训：`installer.nsi` 曾写着 `!define APP_VERSION "4.10.3"`，而代码已到 4.47.0 —— 脱节 37 个次版本，一直没人发现。后果不只是文件名错，`DisplayVersion` 也写的是 4.10.3，**用户在控制面板看到的版本是假的**，排查问题时按版本对不上号。

现在的链路是单向的：

```
app/version.py __version__
   → build_release.read_app_version()      # 正则读，不 import（import app 会拖起 PyQt6/torch）
   → dist/build_info.nsh                   # !ifndef 包住，可被 /D 覆盖
   → installer.nsi                         # 只 !include，不自己 define
   → 产物文件名 + DisplayVersion
```

`build_release.py` 出包后还会**按版本号精确校验**产物是否存在。原先的写法是「取 dist 里最新的一个 `拾光剪影-Setup-*`」，很容易拿到上一次的旧包，报出来的文件名和实际内容对不上。

### 2.6 编码：`.nsi` 与 `LICENSE.txt` 必须是 UTF-8 **with BOM**

NSIS 3 在 `Unicode true` 下靠 BOM 判断编码。**无 BOM** 的 UTF-8 文件会被按本地 ANSI(GBK) 解释字节流 ⇒ 安装包里所有中文变成乱码，而且**编译不报错**，装完才看得见。

实测反例（同一份脚本，只删掉前三个字节 BOM）：

| 文件状态 | makensis 预处理输出里的中文 |
|---|---|
| UTF-8 with BOM | 全部正常 |
| UTF-8 无 BOM | 全部乱码 |

所以改这两个文件时，编辑器别开「保存为 UTF-8 无 BOM」。makensis 编译时会打印 `Processing script file: "...installer.nsi" (UTF8)`，这句里带 `(UTF8)` 才算对。

### 2.7 体积硬约束：makensis 装不下大包（实测）

这是当前**出不了安装包**的真正原因，不是脚本写错，也不是没装 NSIS。

makensis 是 32 位程序，安装包数据块要 mmap 进 2 GB 用户态地址空间。本机实测（NSIS 3.13 / Windows）：

| 数据量 | 结果 |
|---|---|
| 900 MB | ✅ 成功 |
| 1.4 GB | ✅ 成功 |
| 1.6 GB | ✅ 成功（1 分 12 秒） |
| 1.8 GB | ✅ 成功 |
| **1.96 GB**（真实 `_internal`） | ❌ `Internal compiler error #12345: error mmapping file (1992247082, 33554432) is out of range` |
| **6.35 GB**（含 runtime） | ❌ 同上 |

失败发生在**打包开始后几秒内的预分配阶段**，与压缩率无关；换成 zlib / lzma 都一样。所以这是地址空间上限，不是配置问题。

本项目当前体积：

| 部分 | 体积 | 文件数 |
|---|---|---|
| `_internal`（程序本体） | **1.96 GB** | 5826 |
| `runtime`（AI 内核） | **4.37 GB** | 19963 |
| 合计 | 6.35 GB | 25791 |

⇒ **本体的 1.96 GB 就已经越过上限**，安装包连「只装本体」都做不到。

`scripts/build_release.py` 里的 `NSIS_DATABLOCK_LIMIT = 2 GiB` 就是按这个实测设的：总体积超线时**不**把内核并入，并打印明确警告。这个判断只能靠体积算，不能想当然。

**出路（三选一，尚未决定）**：

1. **瘦身到 1.8 GB 以下** —— `_internal` 里有确定性冗余：`avfilter-11.dll` 104.5 MB 存了两份、`avcodec-62.dll` 92.8 MB 两份、`ffplay.exe` 96.1 MB（程序不用）、`qtwebengine_devtools_resources.debug.pak` 77.8 MB（DevTools 调试资源）。合计可省约 370 MB。**风险**：改的是 PyInstaller 的收集内容，动错就是运行时缺 DLL，必须打包后跑 `--selftest` 验证。
2. **换打包器** —— 7-Zip SFX（7z 格式无此限制，但只有「选目录 + 解压」的简单对话框，没有许可页/组件页/卸载注册）；或 Inno Setup（需实测是否也受 2 GB 限制）。
3. **只做绿色版** —— 即本文第三节，解压即用，无安装向导。

> 无论走哪条，**都没法在保持 6.35 GB 完整内容的前提下得到 NSIS 安装包**。这是工具限制，不是修脚本能解决的。

### 2.8 压缩耗时

`SetCompressor /SOLID lzma` 对 GB 级目录很慢（1.8 GB 零字节数据实测 1 分 12 秒；真实 dll 数据压缩率低、更慢）。赶时间用 `--fast-compress`（zlib），代价是产物体积更大 —— 但注意 zlib 在接近上限时更容易失败（它需要更多同时驻留的数据）。

## 三、绿色版（免安装）

### 3.1 怎么产出

```bash
# 先走完 PyInstaller + 装内核 + 自检
.venv312\Scripts\python.exe scripts\build_release.py

# 再整目录压缩（PowerShell）
Compress-Archive -Path dist\拾光剪影\* -DestinationPath 拾光剪影-4.47.0-portable.zip
```

### 3.2 怎么用

1. 解压到**一个固定目录**（例如 `D:\拾光剪影`）。不要解压到桌面再剪切——程序把配置和作品存在自己目录下，挪位置等于换了个程序。
2. 双击 `拾光剪影.exe`。
3. 首次启动会做一次自检并初始化目录（`output\`、`logs\`、`短剧AI剪辑输出\` 等），比后续启动慢，属正常。

绿色版**没有卸载器**。不想要了直接删整个目录——注意那里面**有你的作品**，先确认 `短剧AI剪辑输出\`、`output\`、`素材库\` 里的东西不需要了。

### 3.3 与安装包的取舍

| | 安装包 | 绿色版 |
|---|---|---|
| 需要管理员权限 | 是（装 Program Files） | 否 |
| 开始菜单/桌面入口 | 自动 | 手动建 |
| 升级 | 覆盖安装，记住目录 | 手动覆盖（先备份用户数据目录） |
| 卸载 | 有入口，问你要不要留数据 | 手动删 |
| 适合 | 给别人用 | 自己用 / U 盘带走 / 内测 |

## 四、模型权重不随包分发

安装包和绿色版**都不含任何 AI 模型权重**。装完只能跑云端模型和纯剪辑功能。

本地生成的权重需要自己从社区获取（ModelScope / Hugging Face / GitHub），入口在程序内：本地模型面板每一行都有「魔搭 / GitHub」链接。详见 `docs/现行技术文档.md §40.20`，以及 `python scripts/check_models.py --missing` 看缺什么、怎么拿。

**为什么不打包权重**：单个模型动辄 12~85 GB，且各有各的许可条款，随包分发既不可行也不合规。

## 五、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `Internal compiler error #12345: error mmapping file ... is out of range` | 数据量超过 makensis 的地址空间上限（约 1.8 GB）。见 2.7，不是脚本错 |
| `error creating mmap the size of 41353472` | 同上，换了个报法（剩余地址空间比单个块还小） |
| 安装包界面中文是乱码 | 编译时 `.nsi` 或 `LICENSE.txt` 丢了 BOM。见 2.6 |
| `build_release.py` 报「找不到 makensis.exe」 | 没装 NSIS：`winget install NSIS.NSIS` |
| 装完打不开 / 功能缺失 | 装的时候程序还在运行，`_internal` 下有文件没覆盖成功。关掉程序重装 |
| 提示缺 `VCRUNTIME140.dll` | 缺 VC++ 运行库，装 [VC++ 2015-2022 x64](https://aka.ms/vs/17/release/vc_redist.x64.exe) |
| 控制面板里版本号是 4.10.3 | 那是旧版本安装包的错版本（版本号曾写死在 nsi 里）。用新脚本重出包 |
