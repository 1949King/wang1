# 虚拟形象体系全景（拾光剪影）

> 快照日期：2026-10-20 · 主程序 V4.46.2 · 画布 0.3.33
> 性质：**跨子系统专题综述**（非单一事实源；架构/活路径仍以 [`现行技术文档.md`](现行技术文档.md) 为准）。
> 取证方式：逐文件 `read`/`grep` 实测 + 3 份深度调研交叉复核；每条结论带 `文件:行`。数字标「门禁输出」的以 `_verify` 脚本为准。

「虚拟形象」在本项目不是一个模块，而是**六条彼此交汇的线**：角色库（身份真相源）→ 捏脸 FaceCard（视觉参数）→ 3D 导演台人偶（体型/姿势）→ 数字人节点（配音/成片）→ 口型双引擎 → 角色一致性守护。本文逐条讲清「是什么、数据怎么走、接上了没、缺什么」。

## 1. 角色库 —— 虚拟形象的身份真相源

### 1.1 数据模型
`CHARACTER_FIELD_SCHEMA`（[character_management_module.py:85-116](../app/modules/lego/character_management_module.py)）按 `(key, 中文标签, 类型, 必填, 分组)` 定义，**分组决定字段流向哪里**：

| 分组 | 字段 | 去向 |
|---|---|---|
| `base`（基础身份，头部单行控件） | name* / gender / age_range / role_type / tags | 面板头部，不进滚动表单 |
| `visual`（影响出图） | appearance / temperament / memory_anchors / personality / **face_params** | **仅此组进生图提示词** |
| `inner`（内在人格） | values / core_desire / relations / backstory_events / sensory_triggers / thinking_pattern / feedback_pattern / speech_style | 剧本一致性，**刻意不进提示词**（画面塞「核心欲望」会污染出图）|
| `other` | representative_line / background / notes / **human_variant** | 长文本 + 3D 体型预设 |

- 门禁口径：**fields=22 / visual=5 / groups=4 / enum=1 / variants=5**（`SCHEMA` 守卫实测）。
- `face_params` 归 **visual**（捏脸结果进提示词）；`human_variant` 归 **other**（只驱动 3D，不进提示词）—— 二者刻意分组。

### 1.2 存储与六处同步
- 落盘：`~/.video_editor_cache/characters/library.json`（`CharacterStore`，[character_management_module.py:167-211](../app/modules/lego/character_management_module.py)）。
- **单一真源纪律**：新增一个角色字段，必须同步六处，否则「填了不生效 / 前端看不到 / 生图丢字段」：
  ① `CHARACTER_FIELD_SCHEMA` ② `canvas_bridge.build_character_prompt`（仅 visual）③ `/host/characters`（已改为按 schema 派生，免手工）④ `node-factory.ts::CharacterEntry` ⑤ `check_character_schema.py` ⑥ 色板/枚举镜像。
- 校验：`SCHEMA` 门禁（角色字段六处同步）+ `PROMPT` 门禁（`build_character_prompt` 字段流向）。

### 1.3 前端读/写通道
- 读：GET `/host/characters`（[canvas_routes_get.py:112-141](../app/core/canvas_routes_get.py)）裁剪为 `CharacterEntry`，字段白名单由 `CHARACTER_FIELD_SCHEMA` 派生，并**在 Python 侧拼好 `prompt = build_character_prompt(c)` 下发**（前端禁止自己拼字段——两份拼装逻辑必然漂移）。
- 写：POST `/host/character-update`（[canvas_routes_post.py:1394-1429](../app/core/canvas_routes_post.py)），host token 校验 + 只吃 `CHARACTER_FIELD_SCHEMA ∪ {avatar_url}` 白名单，其余键静默忽略。
- 画布节点：`CharacterNode`（[mediaExtraNodes.tsx:955-1029](../vendor/packages/canvas-core/src/mediaExtraNodes.tsx)）绑定 `characterId`，下拉选角色库条目，「🎨 捏脸」按钮派发窗口事件 `sg-open-face-card`（模态须在 React Flow viewport 之外）。

## 2. 生图提示词链路 —— 跨镜一致的脸（文字通道）

`build_character_prompt`（[canvas_bridge.py:447-485](../app/core/canvas_bridge.py)）把角色字段压成一段提示词片段，顺序：
`角色「名」→ 性别 → 年龄感 → 标签 → 外貌: → 捏脸:（face_params 译文）→ 气质倾向: → 标志性符号: → 性格:`

- `face_params` → 文字：`_face_params_to_text`（[canvas_bridge.py:354-444](../app/core/canvas_bridge.py)）只取**静态身份特征**（头型 / 五官形状 / 瞳色 / 肤色 / 发饰 / 妆容）。
- **刻意不取**：`emotion` / `emotionIntensity` / 4 表情滑杆（表情是「每镜可变」的表演参数，写进跨镜一致性提示会与分镜冲突）。
- 妆容只报「有没有」不报色与浓度；头型 `|Δ|≤0.15` 不写、最多 3 项。
- 幂等回灌：`store.ts` 的 `charPromptBlock` + `applyCharBlock` 把该块幂等写入分镜节点 prompt，`CanvasShell` 对绑定角色的节点重跑 `syncCharacterToShot`。

**这就是「同一角色每镜长一样」的文字机制** —— 目前对出图**已生效**。

## 3. 捏脸 FaceCard —— 视觉参数与 3D 预览

### 3.1 数据结构（唯一真源 `faceParams.ts`）
扁平对象 **27 字段 + `v:1`** 版本号（只加不删），5 大类：表情 / 五官样式 / 头型(Ruth2 shape sliders) / 发饰 / 妆容肤色。
- 铁律：**零随机**（随机只走 `mulberry32(hashSeed(id))` 确定性种子，禁 `Math.random()`）；**缺省即合法**（`normalizeFaceParams(undefined)` 返回完整合法对象，旧工程零改动加载）。
- 程序化五官驱动，**非 morph target**（GLB 素体没有表情骨骼）。

### 3.2 三条链路：共享同一结构，但只打通两条半
| 链路 | 状态 |
|---|---|
| 卡片 UI ↔ 卡片自带 3D mini-scene | ✅ 同一 `FaceParams` → `buildFaceLayer` |
| **3D 导演台人偶** | ⚠️ **半通**：`Stage3D.tsx`/`riggedHumanoid.ts`/`store.ts` 对 `faceHeadParts` **零引用**（grep 复核 + faceParams.ts:6-8 自述）⇒ **人偶身上不长脸** |
| 生图提示词 | ✅ 已打通（§2），但有损文字翻译 |

结论：**「卡片所见 ≠ 导演台所得」成立**；「卡片所见 → 模型出图」已通（2026-10-13 用户裁定「文字 + 参考图两者都要」）。

### 3.3 写回闭环（6 步）
应用/Ctrl+Enter → `onConfirm(serializeFaceParams)` → `CanvasShell.onFaceConfirm` 双通道（face_params JSON 串 + 3D 头快照 dataURL→`persistMediaUrl`→仅回 `/inbox_file/` 才写 `avatar_url`）→ POST `/host/character-update` → `CharacterStore().update()` → GET `/host/characters` 重派生 prompt → 分镜节点幂等回灌。入口 3 处（角色节点🎨 / 小白卡🎨 / 分镜卡头栏🎨），由 CanvasShell 唯一懒加载 host 承接。

## 4. 3D 人偶 / 导演台 —— 体型、姿势、投递

### 4.1 身体（bodykun / bodychan GLB，冻结区 stage3d-core）
- **来历**：vinchau「BodyKun(男) / BodyChan(女) Posable」素模（BlendSwap 23521，CC0），经 `scripts/export_vinchau_glb.py` 导出，`TARGET_HEIGHT=1.70`，骨名从 Rigify `DEF-*` 重映射为 Mixamo。
- **实测文件事实**（解析 glTF chunk）：bodykun 1,446,216 B / bodychan 1,357,680 B；**单材质、0 动画、0 morph target**；头部 mesh 节点名 —— bodykun 为小写 `head`（mesh `body-kun.000`）、bodychan 为大写 `Head`（mesh `Mesh.018`）。`DEF-toe.L/R` 脚趾骨存在 ⇒ 这就是「脚趾朝 +Z ⇒ +Z 为前方」约定的实测判据来源。
- `HumanVariant`（[riggedHumanoid.ts:124-129](../vendor/packages/canvas-core/src/riggedHumanoid.ts)）：**5 种** male_std / female_std / male_thin / male_heavy / child。
- `bodyFigureUrl`（:118）：**仅 `female_std` → bodychan**，其余四个体型 → bodykun（靠体型预设 + 发型区分，不换模型）；URL 带 `?v=RIG_MESH_STYLE`（`bodykun-v6-20260907`，改它强制重建 + 绕 WebView 长缓存）。
- ⚠️ `HUMAN_PRESETS[].heightScale`（男标1.0/女0.94/瘦1.03/胖0.96/儿童0.74）在导演台是**失效值**：`makeRiggedHumanoid` 内部 `root.scale.setScalar(P.heightScale)` 会被 `Stage3D.tsx` 的 `obj.scale.setScalar(safeScale)` 覆盖 ⇒ 投递侧改用 `VARIANT_SCALE`（`stage3dCast.tsx:83-89`，单测锁死），**明令不得用 heightScale**。
- GLB 素体**无五官、无 face 骨骼、单个无贴图 default 材质** ⇒ 五官只能程序化附件、肤色走独立叠加层。
- 材质冻结红线（`frozen_zones.json` zone `stage3d-core`）三条 invariant：`bodyFigureUrl` 只出两具 GLB；`prepareBodyFigureMeshes`/`loadGLBRiggedHumanoid` **不得覆盖 GLB 原始材质**（bodykun 12 mesh / bodychan 25 mesh 共用一个材质实例，改一处=全身串色）。测试锁：`faceParams.test.ts:260-283` 探针材质逐字未变。

### 4.2 姿势系统
- **33 个静态姿势**（`POSE_PRESETS`，[stage3dPoseLibrary.ts](../vendor/packages/canvas-core/src/stage3dPoseLibrary.ts)；含 2026-10-05 补内旋轴后才数学成立的 `stand_natural / hands_behind / hold_phone / handshake`）。坐标约定：**脚趾朝 +Z ⇒ +Z = 人体前方**（GLB DEF-toe 实测）。
- **8 个循环动作轨迹**（`MOTION_PRESETS`：走姿/呼吸/摆臂/环顾/微晃/挥手/深蹲/侧倚，可叠加，root 位移独立采样）。
- 自由度：**31 个关节角 / 15 根可动骨**，其中 6 个 Y 轴（shoulder/elbow/hip 左右）是 2026-10-05 补的内旋/旋前轴；静止态（全 0）是 **A 字型** ⇒ `lShoulderZ` 下限放宽到 -60，`stand_natural` 用 -48 才「手贴大腿」。
- DoF 验证方式：`check_stage3d_pose_dof.mjs` 用**真 bodykun.glb + 与渲染层逐行等价的数学副本**算关节世界坐标做 27 项几何不变式（鞠躬头前移、叉腰肘在身后、抱臂不穿脖、YXZ 无万向节回归…）+ 8 项源级 regex 防副本漂移。
- 缩略图缓存：`magnetic/poseThumbCache.ts` = Map-LRU，key=`${poseId}@${characterId}`，容量 64。⚠️ **该模块目前无任何生产 import 方** —— 属「壳 + 元数据 + 自检」，等待数字人节点接线（实为未投产）。

### 4.3 角色库 → 导演台投递（`stage3dCast.tsx`，唯一通道，有单测）
链路：角色/镜头节点 🎭 按钮 → `store.requestStage3dCast`（写 pending + `stage3dCastSeq+1`）→ `Stage3D.tsx::useStage3dCast`（先 consume 再 apply，抛错不重复投递）→ `castActorFromCharacter()` 造 `StageActor` 追加/选中/切 group 模式。
- 零随机确定性规则：体型 = 显式 `human_variant` 优先 → 年龄段命中「儿童|幼|少|小|孩」→child → gender 女→female_std → male_std（脏值退回推断）；发型 child→round / 女→long / 其余 short；配色 `CAST_COLORS` 8 色 + `stableHash(id‖name)` 取模（同角色恒定同色）；缩放走 `VARIANT_SCALE`。
- ⚠️ **投递携带的信息只有** name/variant/hairStyle/color/scale/默认姿势/初始位置 —— 角色库的 `face_params`、`appearance`、`prompt` **不进 3D 人偶**（§3.2 最大缺口的具体表现）；且本模块不新建 Mesh（几何/材质一律走 `makeRiggedHumanoid`，不绕材质不变量）。

### 4.4 导演台截图回写
1. 绑定：`store.openDirectorForNode(nodeId)` 校验 `kind==="director"`，写 `directorTargetNodeId` 并切 stage3d 视图。
2. 截图：主 renderer 不保留 drawing buffer（Qt WebEngine 省显存纪律）⇒ 统一走**离屏 `WebGLRenderTarget` + `readRenderTargetPixels`**（`stage3dGlUtils.ts`，含逐行垂直翻转）；拍前摘掉机位视锥/标签/坐标轴等编辑辅助物。
3. 元数据：cameraName/fov/focalLength/shotSize/aspect/aperture；`fovToFocalLength`（gizmo 标签 mm 与截图元数据**同源唯一实现**）。
4. 回写：`addCaptureToCanvas` 同时①写回 director 主图 + `captureUrls`（裁最近 24 张）②**另存一张 shot 镜头卡**（机位名/景别/焦段/prompt 参考）③>4KB dataURL 异步落 inbox 换回 `/inbox_file/` URL。批量=逐机位 120ms 错开；三视图（前/侧/背）同机制。
5. 产物入轨唯一入口 `stage3dArtifacts::sendArtifactToTimeline`（复用 `POST /ingest_path`；实测仅 ControlNet 三通道登记入库，首尾帧/BVH/三视图各有去向并逐条论证）。

### 4.5 冻结不变量摘要（`stage3d-core`，只读，勿改）
- 端口锁定：桥 `18765` / 静态 `3011` / dev `3010`（`canvas_bridge.py:33`·`canvas_runtime.py:42-43`·`canvas_aigc.py:46` 为镜像）。
- 材质单通道：`bodyFigureUrl` 只出两具 GLB；`prepareBodyFigureMeshes`/`loadGLBRiggedHumanoid` 不覆盖/替换 GLB 原始材质；角色色只染胶囊 `clothes` 层，GLB 树不吃色。
- `applyBoneDelta` 必须 `Number.isFinite` 守卫；`SkeletonUtils.clone()` 后必须 `updateMatrixWorld(true)` 再量包围盒、SkinnedMesh 一律 precise、兜底 k 除以 `root.scale.y`。
- 单通道 store 范式（投递/机位/灯位各一条 `seq` 通道）；灯位单主光 + ≤2 轮廓光，`lightingSeq>0` 后 lightPreset 不得覆盖 hemi/dir。
- 规模棘轮：`Stage3D.tsx` 基线 4,623（实测 4,652）、`riggedHumanoid.ts` 3,159（实测 3,164）；`tsc` 存量 37 处**全在冻结区**。

> ⚠️ 3D 灯光物理面窄：场景实际只有 HemisphereLight + DirectionalLight（+≤2 轮廓 dir），`shadowMap` 关闭，无多点布光/聚光/面积光；「24 灯位」是单主光 + 轮廓的投影。包围盒自检只报 >4m（超大），注释「500ms 节流」与代码 `>1000` 不一致（次要）。

## 5. 数字人节点 —— 配音 + 口型成片

`DigitalHumanNode`（[mediaExtraNodes.tsx:246+](../vendor/packages/canvas-core/src/mediaExtraNodes.tsx)），`digitalHuman` 端口模型 accepts `{text:1, image:1, audio:1}` produces `{audio:1, image:1}`。
- **已接**：形象图绑定 + 台词 → TTS 配音（`generateAudioViaHost`）→ 配音可入轨。
- **未接（诚实失败）**：口型成片。原文常量：
  > 「未配置形象驱动模型，口型成片未接入。请先生成配音并上传形象图入轨。」
- 符合红线纪律：**无模型不假成功**（现行技术文档 §6.5 / D 数字人 ~10% 权重）。

## 6. 角色一致性三守护（只读能力，治漂移）

三个 `pipeline.*` 只读能力（`read`，不花钱，`capability_handlers.py:1885-1892` 注册）：
| 能力 | 治什么 | 核心 |
|---|---|---|
| `pipeline.character_anchor` | 人物形象跨镜漂移 | `ai/character_anchor.py::plan_anchor`：特征卡 + 稳定指纹 + 漏拼校验 + `anchor_negative` 防漂移负面词 |
| `pipeline.expression_clamp` | 表情夸张 | ARKit blendshape 名权重钳制 + 帧间限幅 + 幅度质检 |
| `pipeline.prop_consistency` | 道具/武器结构畸形 | 结构约束 + 握持描述 + 道具漂移检测 |
| （总入口）`guard_all` | 上三者 + `tts_polish` | 守护门面 |

定位：**这是「生成后判漂移」的守门能力，与 §1–§3 的「生成前锚同一张脸」互补**。`character_anchor` 与角色库 `face_params`/`appearance` 共享视觉意图，但各自独立（锚定是运行时比对，捏脸是静态定义）。

## 7. 已知缺口与风险（不掩盖）

1. **捏脸不进 3D 人偶（最大）**：`buildFaceLayer` 生产路径零调用者；且挂载后需处理与 `makeRiggedHumanoid` 胶囊头自带眼/鼻/发（[riggedHumanoid.ts:1382-1410](../vendor/packages/canvas-core/src/riggedHumanoid.ts)）的**双份五官冲突**。解冻 `stage3d-core` 才能补那一行 `headBone.add(...)`。
2. **TS↔Python 枚举镜像漂移（本次独立复实为真；V4.46.2 已上新守卫 `FACEENUM` 拦截）**：[canvas_bridge.py:287-307](../app/core/canvas_bridge.py) 的眉/眼/唇/发饰中文表比 [faceParams.ts](../vendor/packages/canvas-core/src/faceParams.ts) 少 **8 个 2026-10-13「A 类扩展」值**：
   - 眉缺 `round` / `short`；眼缺 `cat` / `sleepy`；唇缺 `pouty` / `sharp`；发饰缺 `glasses` / `flower_crown`。

## 8. 与「Agent 能否完全调用」的关系（承接上轮问答）

虚拟形象这条线在 **dispatcher 侧全部注册为能力、可被程序化调用**；但对**对话中的 LLM**，其可达性受上轮结论约束（白名单 ~45 action，126 能力仅部分可见）。形象相关能力落点：

| 能力 | 前缀 | 模型可达性（当前）|
|---|---|---|
| `canvas.generate_image`（带角色 prompt）| canvas | ✅ 画布节点 action 覆盖 |
| `canvas.dub_orchestrate`（剧本→多角色配音→落轨）| canvas | ✅ 已在画布工具清单点名 |
| `pipeline.character_anchor` / `expression_clamp` / `prop_consistency` | pipeline | ❌ 休眠原生 tools + 不在 45 白名单 ⇒ 模型看不见（上轮 §三缺口）|
| 角色库读写 | 非 capability（HTTP `/host/character*`）| ✅ 前端 CharacterNode 直连 |

> 即：**虚拟形象的「执行层」是齐的，断点曾在「模型选择层」**——一致性守护（`pipeline.character_anchor` 等）这类最能体现「懂形象」的能力，此前 Agent 反而最调不到。V4.46.2 的「Agent 全能力可达」已在对话面列出全 126 capability_id + 执行闸放行直通，补齐了这个断点（原生 function calling Track C 的 `limit=60` 另刀处理）。
