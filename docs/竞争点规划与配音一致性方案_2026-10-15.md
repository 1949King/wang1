## 二、我们的优先竞争点（按打击力排序）

> 核心论点：**不和云厂拼"生成能力"，拼"预演确定性"——他们出视频，我们出"能开机拍的预演结论"。**

| # | 竞争点 | 一句话卖点 | 竞品为何做不了 | 落点 |
|---|---|---|---|---|
| 1 | **复刻质量校验闭环** | 别人复刻靠猜，我们复刻打分 | 逐帧比对烧本地算力，云按 GPU 时计费必亏；桌面端零边际成本 | 规划 #4(L3)+#3 合并升级：参考镜头 vs i2v 复刻 vs 3D 预演 三方对比，输出「复刻相似度分」 |
| 2 | **角色一致性三件套** | 换镜不换脸 | 竞品只有资产库；我们有 主仓+多图参考+锚定守护 三件齐 | 规划 #1+#2（Wave 1），叠加已有 character_anchor |
| 3 | **指令式编辑多渠道调度** | 一键换渠道，不被绑架 | 云用户被单渠道锁定；我们 provider_caps 双渠道+容灾+比价（QUOTEHEALTH 已有） | P1-2，Seedance+Kling Omni 两家（已拍板） |
| 4 | **隐私安全模式** | 素材不出域，全链路本地 | 云竞品结构性做不到 | 零新功能：EGRESS 硬开关已有，做成产品开关+对外话术 |

**明确不做**（防插队）：实时生成、多人协作、无限画布、发布矩阵。

## 三、配音「咬文嚼字与字幕不一致」：根因与方案

### 3.1 问题根因（四类不一致）

| 类型 | 表现 | 现有覆盖 |
|---|---|---|
| ① 文本归一化（TN） | 念"二零二四" vs 字幕显示"2024"；"1.5米"念"一米五" | ❌ 未覆盖 |
| ② 多音字念错 | "银行/行走"、"重量/重复" | ✅ tts_guard + pinyin_dict（V4.39.0） |
| ③ 时间轴错位 | 字幕时间按文案估算，配音实际语速不同 → 音画漂移 | 🟡 subtitle_generator 有 Whisper 转写，但 TTS 路径未对齐 |
| ④ 生成模型即兴 | 原生音频模型改词/吞字/加语气词 | ❌ 未覆盖 |

**本质**：配音是"音频真相"，字幕是"文本真相"，两条链各走各的，缺一个**回环校验**把它们钉在一起。

### 3.2 现有能力盘点（不重复造）

| 模块 | 能力 | 与本问题的关系 |
|---|---|---|
| voice_generator.py | Piper 本地 TTS → Coqui → gTTS → edge-tts，诚实失败纪律 | 配音引擎链 |
| ai/tts_guard.py + pinyin_dict.py | 多音字注音守护（离线确定性） | 根因② 已解 |
| ai/whisper_asr.py | 本地 ASR（含词级时间戳） | **回环校验的关键件，已有未用于配音验证** |
| subtitle_generator.py | Whisper 语音转字幕 + 错别字纠错 | "音→字"方向已有 |
| redub_orchestrator.py | 换词重配链（说话人分离+音色克隆+对口型） | 配音卡的后端引擎已有 |
| video_lipsync.py / lip_sync.py | 对口型三级降级 | 口型层 |
| /host/redub-preflight + execute | 重配端点 | **孤儿端点，前端未接线（规划 #13）** |

### 3.3 三条路线对比

#### 路线 A：工程闭环「双轨文本 + 听写回环」（推荐，核心旁白用）

```
台词原文 ──┬── 朗读版（TN 展开：数字→读法、单位→口语）→ TTS 合成
           └── 显示版（字幕用，保持原文观感）
TTS 产物 → whisper 本地听写 → 归一化比对（朗读版 vs 听写稿）
  ├─ 相似度 ≥ 阈值 → 出「已验证配音 + 对齐字幕（ASR 词级时间戳）」
  └─ 相似度 < 阈值 → 诚实失败/标记不一致 → 触发重配（redub 链）
```

- **优点**：确定性、零成本、素材不出域（whisper 本地）；"所听即所见"变成**可验证的验收指标**而非愿望
- **成本**：新增一个纯函数 `verify_dubbing(audio, expected_text)`（复用 whisper_asr + 归一化），TTS 结果加验证标记；时间轴从"估算"改"ASR 强制对齐"
- **关键设计**：字幕**从音频生成**（音→字），不是从文案回填（字→音）——这是"所听即所见"的唯一可靠方向

#### 路线 B：配音卡片（画布节点）——做，但定位为薄前端

- **不是新引擎**：卡片 = 路线 A 闭环的 UI 承载 + 已有 `/host/redub-*` 孤儿端点的前端接线（正好并入规划 #13）
- 卡片流程：台词输入 → 发音标注（多音字选择/数字读法，复用 tts_guard 词表）→ TTS → 听写验证 → 输出「音频 + 已验证字幕」，验证不通过红标提示
- 价值：把"发音决策"变成画布上可见、可改、可重跑的节点（对齐 segment_retake 的局部返工哲学）

#### 路线 C：视频生成模型原生音频（Kling/Sora2/Veo3/Seedance 音画同出）

- **优点**：口型与音画同步天然正确，省掉对口型环节
- **缺点**：中文台词保真度低——数字/多音字/专有名词最容易被"即兴"；不可控、不可本地验证前无法信任
- **优化手段**（若用）：
  1. prompt 逐字引用台词 + 显式约束"准确念出以下台词，不改写不加词"
  2. 生成后**同样走路线 A 的听写验证**（whisper 对成片音轨转写比对）
  3. 不一致 → segment_retake / redub 重做该镜
  4. 字幕**必须从生成音频 ASR 出**，不许用原剧本回填（原剧本只是"意图"，不是"真相"）
- **定位**：适合出镜角色对白（口型收益大）；不适合核心旁白/口播（保真要求高）

### 3.4 推荐组合

| 场景 | 路线 | 理由 |
|---|---|---|
| 核心旁白 / 口播 | A（双轨+听写闭环） | 确定性优先，本地零成本 |
| 出镜角色对白 | C + A 的听写验证兜底 | 口型收益大，验证保底线 |
| 改词返工 | B 卡片（redub 链前端化） | 已有引擎，只欠接线 |

**统一验收标准**：任何交付的配音，必须携带 `verified_similarity` 与 `subtitle_source=asr` 标记；
听写相似度低于阈值一律红标——**宁可红标，不可静默不一致**（与诚实边界红线同构）。

### 3.5 落地步骤（最小侵入，按序）

1. `app/core/ai/` 新增纯函数 `verify_dubbing()`（复用 whisper_asr + 归一化 + 相似度），带自包含测试
2. voice_generator 结果对象加验证标记（不动引擎链本身）
3. subtitle_generator：TTS 路径字幕时间轴改用 ASR 词级对齐（若现状为估算）
4. 配音卡片：接线 `/host/redub-preflight/execute` + 验证结果展示（并入规划 #13 孤儿端点清单）
5. `_verify/` 加一条守卫：配音交付必须带验证标记（防静默假成功，同 YuE 纪律第 35 条）

## 四、多 Agent 协作画布（政策升级：从「不做」到「排期」）

> 政策澄清：原 #12「多 Agent 并发」被推后（判语：连 Agent 改单节点都没做到，先做是空中楼阁）；
> 战略基线「不做协作」指的是**多人实时协作**（if画布式 B 端 SaaS，结构性不做，维持不变）。
> 本节升级的是另一件事：**多 Agent 分工**（机器协作，不是人协作）——用户 2026-10-15 明确要纳入。

### 4.1 形态定义

画布节点 = Agent 任务卡，五个专业 Agent 各管一段，**人是唯一批准者**：

| Agent | 职责 | 复用的现有件 |
|---|---|---|
| 编剧 Agent | 大纲→剧本→台词 | `/host/script-write` + editing_script_generator |
| 分镜 Agent | 剧本→镜头表→分镜节点 | video_storyboard + 拉片 L1/L2 |
| 运镜 Agent | 镜头表→机位/运镜参数→3D 预演 | Stage3D + L2 深度运镜 |
| 配音 Agent | 台词→TTS→听写验证→字幕 | voice_generator + whisper_asr（§三闭环） |
| QC Agent | 复刻相似度/合规/一致性打分 | 光流 QC(#3) + compliance-check + character_anchor |

### 4.2 与「空中楼阁」判语的和解

#12 原本意是**多镜并发生成的调度**（一台机器同时跑 N 个生成任务）。它依然需要前置：
- **#4 幂等键**（并发不重复烧钱）+ **#5 生成任务表**（异步/进度/取消/并发上限）——都在 Wave 1
- 调度底座已有：module_scheduler DAG（MSCHED 守卫在位）+ agent_pipeline_orchestrator + 事件总线

**结论**：多 Agent 分工画布排在 Wave 1（#4/#5）之后启动；Wave 1 之前依然是空中楼阁，判语不变。

### 4.3 差异化（vs if画布/竞品）

竞品做多 Agent 是为了**卖团队席位**；我们做多 Agent 是为了**单人导演的流水线**——
一个导演 + 五个 Agent = 剧组。配合竞争点 4（素材不出域），这是「本地 AI 剧组」品类，云厂没有对应物。

## 五、音韵问题完整清单（「所听即所见」的全部坑）

§三列了四类根因，这里给全量清单——做配音卡/听写验证时的**测试用例来源**：

| # | 音韵坑 | 例子 | 现状 | 对策 |
|---|---|---|---|---|
| 1 | 多音字 | 银行/行走、重量/重复 | ✅ tts_guard + pinyin_dict | 已有，配音卡暴露人工改音入口 |
| 2 | 数字读法 | 2024（二零二四/两千零二十四）、100万、电话号码逐位 | ❌ | TN 规则表 + 配音卡可选读法 |
| 3 | 单位符号 | m/kg/%/℃/km/h | ❌ | TN 规则表（"米/千克/百分之"） |
| 4 | 中英混合 | AI、GDP、品牌名 | ❌ | 词表（字母逐读 vs 整词读） |
| 5 | 专名姓氏 | 单 shàn、曾 zēng、地名堡/巷 | 🟡 部分在 pinyin_dict | 姓氏/地名补丁表 |
| 6 | 变调 | 三三变调、"一/不"变调 | 🟡 引擎自带（Piper/edge-tts 部分处理） | 引擎层，不重造 |
| 7 | 儿化/口音 | 头儿、哪儿 | ❌ | 引擎音色决定，标注即可 |
| 8 | 韵律停顿 | 标点→停顿时长、长句被切碎 | ❌ | 断句预处理 + ASR 对齐后移标点 |
| 9 | **同音歧义** | 听写"全补"vs 字幕"全部"——字不同音同 | ❌ | **听写比对必须走拼音级比对，不走字符级**（复用 pinyin_dict，这是本项目的独有正确工具） |
| 10 | 情绪语速 | 字对但念得平/过快 | 🟡 voice_clone 有情感解耦 | 配音卡情绪参数 |
| 11 | 多人对白归属 | 不知道给谁配 | ✅ redub 诚实边界（不瞎猜） | 维持：未指定则 plan 失败 |
| 12 | 字幕断行 | 音对但字幕丑 | 🟡 subtitle_manager | 显示规则（每行字数/标点） |

**关键洞察（#9）**：第 9 条决定整个听写闭环的成败——字符级比对会把正确配音判成不一致（假阳性），
拼音级比对（声母+韵母，声调可加权）才能既放过同音、又抓住真错字。pinyin_dict 已存在，闭环成本再降一档。

## 六、运镜控制（三层对齐打法）

预测：显式运镜参数 6-12 个月内成竞品标配（可灵 camera_video_control、即梦导演模式已有苗头）。
我们的位置不是跟进，是**三层对齐**——竞品只有第 1 层：

| 层 | 干什么 | 现有件 | 缺口 |
|---|---|---|---|
| ① 分析层 | 从参考片**反推**运镜参数 | L2 深度运镜（已通电，P0 已接线）+ 视觉模型兜底 | 无——P0 刚做完 |
| ② 预演层 | 运镜参数**驱动 3D 机位**出确定性预演片 | Stage3D 24 位灯位/机位、POSEDOF | 镜头表→机位参数的映射器（小纯函数） |
| ③ 生成层 | 运镜参数**写进 prompt** 指挥生成模型 | CAMERA_MOVE_ZH 词表、i2v prompt 模板 | 参数化模板：`{景别}{角度}{运镜}{速度}` 结构化槽位 |

**闭环**：①反推 → ②预演（ground truth 渲染）→ ③生成 → 竞争点 1 三方对比（参考 vs 预演 vs 生成）→
不一致就调 ③ 的 prompt 或换渠道重跑。**竞品的运镜控制是"猜模型"，我们的是"有标准答案的考试"。**

**落点**：②③ 合入 L3 复刻闭环（P1-1）一起做，镜头表节点携带结构化运镜字段（不另造协议）。

## 七、指令式视频编辑（确认要做，方案已备）

调研已完成（2026-10-14 交付），用户裁决：**Seedance + Kling Omni 两家都接**。本节把"怎么做"落定：

### 7.1 渠道分工

| 渠道 | 形态 | 关键约束 | 角色 |
|---|---|---|---|
| 火山 Seedance 2.0/2.5 | 官方"编辑视频"任务 + 句式模板 | `video_url` **支持 Base64**（素材可不出域）；mini 档 14 元/M token 最低 | **主编辑** |
| 可灵 3.0 Omni | `contents[].type=base_video` | 视频**必须公网 URL**（出域，需显式开启）；720p ≈0.63 元/5s；base_video 与首尾帧互斥 | **主编辑 + 补尾帧** |
| MiniMax H3 | `reference_video` role | 语义待实测；双向计费 ≈5 元/5s | 容灾 |

### 7.2 接入步骤（provider_caps 表驱动，路由零改动）

2. 新建 `app/core/ai/video_edit_client.py`（✅ 用户已拍板：canvas_aigc.py 顶基线 2905 行不动，按 dashscope_video.py 纯模块风格另建新文件，双渠道+失败保原镜+no_egress 拦截）
3. `/host/video-edit` 端点：入参 `{clip_path, instruction, channel?, video_url?, model?, out_dir?}`，出参 `{ok, clip_path, url, original_kept, channel_used, cost_note, errors, message}`（✅ 2026-10-15 已接线：端点 + canvas.video_edit 能力 handler + 能力目录条目，守卫 VIDEOEDIT 20 项全过；步骤 4 接线时补 `url`——成功时结果**复制**进画布 inbox 回 `/inbox_file/` 可播放地址，原文件不删，复制失败如实进 errors）

5. 与 segment_retake 的边界：**重拍=重新生成，编辑=改原片**；两张卡互补，共享"局部返工"哲学

### 7.3 差异化卖点

竞品是单渠道闭环（生成什么收什么钱）；我们是**多渠道比价 + 自动容灾 + 本地留档**——
"同一句指令，三家报价摆在你面前，选谁都不被绑架"。叠加 EGRESS 纪律：默认走 Base64 不出域渠道。
