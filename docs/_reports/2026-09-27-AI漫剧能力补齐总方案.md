> 定位：把「拾光剪影」按 **AI 漫剧 / AI 短剧**生产链补成完整闭环
> 用户已定顺序：**④ 生成·抽卡 → ① 策划/编剧 → ② 导演·节奏 + ③ 美术·母版**

## 〇、总览：架构映射与现状修正

```
主链：① 策划/编剧 → ② 导演·节奏 → ③ 美术·母版 → ④ 生成·抽卡 → ⑤ 配音配乐 → ⑥ 合成剪辑 → ⑦ 分发回流
横向 A：资产母版与一致性锁定（每环都调用）
横向 B：治理层（一致性硬约束 + 审美软判断 + 平台规格校验）
```

### 现状实测（**本次核实后修正**，比首轮判断更精确）

| 环 | 首轮判断 | **修正后（实测）** | 证据 |
|---|---|---|---|
| ① 策划/编剧 | 缺 | **缺**（唯一完全空白） | 全库"剧本"相关只有**消费**：`pipeline.director_breakdown`（剧本→分镜表）、`canvas.breakdown`、剧本合规守护；`pipeline.generate_script` 是**剪辑**脚本（关键词 镜头顺序/配乐）非剧集剧本 |
| ② 导演·节奏 | 部分 | **强于预期**：分镜 + 机位 + **记忆衰减时长分配**已有；**只缺钩子/节奏校验** | `pipeline.director_breakdown` / `director_camera_plan`；`app/core/ai/storyboard_memory.py:76 retention()` + `:92 _allocate()`（细节<意义<情绪 的时长分配，已有一致性回归） |
| ③ 美术·母版 | 缺 | **强于预期**：**22 字段设定模型 + 锚定算法 + 垫图机制全在**，只缺「**图资产本体**」与接线 | `character_management_module.py:55 CHARACTER_FIELD_SCHEMA`（base/visual/inner 三组，含 `memory_anchors` 跨集视觉符号）；`app/core/ai/character_anchor.py`：`extract_traits/fingerprint/build_anchor/render_anchor_prompt/diff_anchor/check_shot_alignment/plan_anchor`；`canvas_aigc.py:608` `reference_image` 支持图生图（失败降级文生图） |

| ⑥ 合成剪辑 | 有 | **项目最强项**（波纹删除带音画联动、墙钟播放、LUT、19 转场） | — |
| ⑦ 分发回流 | 已下线 | **不做**（用户决定） | — |

**关键结论：工作量比首轮估计小。** ②③ 不是"从零建"，而是"补最后一段 + 接线"；真正空白只有 ①。

### 排序理由（依赖关系，用户顺序正确）

```
④ 生成·抽卡  ──独立，且是唯一"影响所有后续环节效率"的环（抽卡效率决定 ①②③ 的试错速度）
① 策划/编剧  ──入口，独立；产出剧本结构 = ② 的输入
② 导演·节奏  ──依赖 ①（剧本结构是节奏/钩子校验的输入）
③ 美术·母版  ──依赖 ②（分镜表决定"哪些角色/场景需要母版"）+ ④（母版本身靠生成产出）
```

## 阶段二 ① 策划/编剧（唯一的完全空白环）

### 目标

把「用户有想法」→「站得住的剧本站得住」这一段补上。**分三层，从零成本到有成本**：

### 2.1 剧本结构层（纯启发式，零 API 成本，先做）

新增 `app/core/ai/script_structure.py`：

```
解析输入：剧本文本（md/txt）
输出：{
  "episodes": [{"no":1, "scenes":[...], "chars":[...], "dur_est":..}],
  "cast_balance": {角色: 出场场次/台词数},               # 出场失衡
  "hooks": [{"ep":1,"pos":"00:08","type":"冲突","text_head":...}],   # 钩子定位
  "hook_gaps": [{"ep":3,"gap":"前 40 秒无冲突"}],         # 违规项
  "arc": {角色: {"setup","turn","payoff"}},               # 弧光三段
  "warnings": [...]
}
```

**校验规则直接来自漫剧行业规格**（已联网核实）：

| 规则 | 阈值 | 依据 |
|---|---|---|
| 开篇冲突 | 前 10 秒必抛冲突（硬） | 行业实操文一致口径 |
| 反转密度 | 每 30 秒一个反转/悬念 | 同上 |
| 集末钩子 | 每集结尾留悬念 | 同上 |
| 单集时长 | 1~3 分钟（可配置，默认 90 秒） | 同上 |
| 角色出场平衡 | 主角缺席集数 ≤ N / 反派与主角场次比 | 项目自定 |

**成本**：纯正则 + 规则，零 API ✅ 可立刻拿用户的 105 章剧本验证。

### 2.2 剧本站得住层（结构 → 问题定位）

在 2.1 基础上加**结构诊断**：

- 三幕/七节点定位（每集落在哪个位置）
- 人物弧光完整性（setup/turn/payoff 是否都有）
- 伏笔-回收配对（埋了没收 / 收了没埋）
- 集间因果链（上一集结尾钩子 → 下一集是否接上）

**输出为"诊断报告"而非"改写建议"**——AI 只定位问题，你决定怎么改（呼应「AI 打分禁当真值」红线）。

### 2.3 想法 → 剧本（LLM 层，后做）

- 新增能力 `pipeline.script_draft`：**一句话想法 → 集纲 → 分场大纲 → 对白草案**
- 复用现有 LLM 通道（`agent_chat_proxy` / provider 体系）+ 角色库 `inner` 组字段作为人格约束（**这是项目的独特优势**：角色库的 8 个 inner 字段天生就是给剧本用的）
- 产物落盘为项目资产管理（集纲 json + 剧本 md）

### 2.4 与既有能力的对齐校验

- 剧本改动 → 哪些分镜失效（`director_breakdown` 的产物对不上）→ 关联检查
- 与剧本合规守护（`/host/compliance-check`）的衔接

**交付顺序**：2.1 → 2.2 →（用户确认效果后）2.3 → 2.4
**不碰冻结区** ✅

## 阶段三 ② 导演·节奏 + ③ 美术·母版

（合并为一个阶段，因为互为输入输出）

### 3.1 ② 导演·节奏：补"钩子与节奏校验"（不重建）

已有：`director_breakdown`（剧本→分镜表）+ `director_camera_plan`（→机位）+ `storyboard_memory`（记忆点时长分配）

新增 `pipeline.pacing_check`（或扩 `director_breakdown`）：

| 检查项 | 方法 | 输出 |
|---|---|---|
| 镜头时长分布 | 分镜表 duration 直方图 vs 行业区间（单段 5~10 秒，≤15 秒） | 超长镜头清单 |
| 节奏曲线 | 每 30 秒的"信息密度"（台词字数/镜头切换数） | 平淡段定位 |
| 钩子落位 | 与阶段二 hooks 对齐：钩子处是否有足够镜头时长承载 | 错位清单 |
| 情绪曲线 | 复用 `storyboard_memory.retention()` 的记忆权重 | 与情绪预期偏差 |

**注意**：这些是**校验器**，不自动改分镜——输出诊断，人改（同红线）。

### 3.2 ③ 美术·母版：补"图资产本体 + 接线"（不重建）

**已有（无需重做）**：
- 22 字段设定模型（`CHARACTER_FIELD_SCHEMA`）
- 锚定算法全家桶（`character_anchor.py`：traits/fingerprint/anchor/negative/diff/alignment）
- 垫图机制（`reference_image` 图生图）、提示词拼装（`build_character_prompt`）

**要补的**（精确）：

| 缺口 | 做法 | 依赖 |
|---|---|---|
| **母版图资产本体** | 角色新增资产位：`ref_sheet`（三视图/定妆照）+ `ref_seed`（种子）+ `ref_model`；落盘 `media_dir`；由 ④ 的生成链路产出（**正好接阶段一的抽卡账本选最优**） | ④ 完成 |
| **生成即锁定** | 生图时自动带 `reference_image=ref_sheet` + 固定 seed（已有参数支持，只需接线） | ④③ 配合 |
| **漂移硬拦截** | `diff_anchor` 已有漂移检测 → 接 `sampling_review` 的 0.30 freeze 阈值，超限**阻断出片** | 横向 B |
| **场景/风格母版** | 同角色逻辑扩展到场景与风格（同一套资产位模式） | 可选，后期 |

⚠️ **资产位新增涉及 `character_management_module.py` = stage3d-core 冻结区**（整文件锁）
⇒ 3.2 的"新增字段"部分**需解冻**；但**用现有字段（`appearance` + `media_dir` + `avatar_url`）先跑通**是可行的 → 建议**先用现有字段落地，字段扩展放解冻批次**。

### 3.3 横向 B 治理层（在本阶段成型）

- **一致性硬约束**：`diff_anchor` + `sampling_review` 阈值 → 拦截
- **审美软判断**：`gen_critic` 代理分（阶段一产出）→ 提示，不拦截
- **平台规格校验**：竖屏 9:16 / 1080P / 单集时长 / 片段 ≤15 秒 → 硬校验（可扩 `pipeline.preview_validate`）

## 五、贯穿原则（三条红线）

1. **AI 只诊断，不改判** —— 所有评分/建议标注为代理或建议，终裁权在用户（项目既有红线「AI 打分禁当真值」）
2. **建好就接线** —— 本项目反复踩的坑（三校验没挂载 / 异步底座没插电 / 质量真值通道没接），每批**必须有实际调用点 + 回归守卫**
3. **不确定的先只观察** —— 代理分先只写入，不改路由行为；观察 ≥50 次再放开
