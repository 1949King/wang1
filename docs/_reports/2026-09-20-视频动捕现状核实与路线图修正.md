## 三、下一刀：第 4 刀「录制白模视频 → reference_video」

### 3.1 目标

把「白模按 poseTrack 逐帧动起来」的过程录成一段视频，作为 `reference_video`
走**已有**的第 1 刀通道送生成模型。

—— 注意：第 1 刀通道**已经就位**，刀 4 只需要「生产出这段视频」。

### 3.2 技术路径（三选一，推荐 B）

| 路径 | 做法 | 评价 |
|---|---|---|
| A · 前端实时录制 | `MediaRecorder` 录 WebGL canvas | ❌ **会掉帧**（录到的是"实时发生"的，不是"逐帧渲染"的）；且 WebGL canvas 需 `preserveDrawingBuffer` 才能被录，改动面大 |
| **B · 逐帧导出帧序列 → 后端 FFmpeg 合成** | 前端逐帧 `poseFrameIdx++` → `applyPoseFrameToActor` → 渲染 → 取 canvas 帧 → 攒成序列 → 交后端 FFmpeg 合成 mp4 | ✅ **推荐**：帧率精确、不掉帧、可控分辨率；**复用既有能力**（`exportFirstLastFrames` 的单帧导出 → 扩展成逐帧；FFmpeg 是项目既有能力）；产出 mp4 落 inbox 即接上已有通道 |
| C · 后端离屏渲染 3D | Python 侧跑 3D 引擎 | ❌ 项目没有 Python 侧 3D 渲染，等于从零造，不现实 |

### 3.3 路径 B 的落地要点

```
逐帧循环（i = 0..frameCount-1）
  → setPoseFrameIdx(i) → applyPoseFrameToActor(i, actorId)
  → 等一帧渲染完成（requestAnimationFrame）
  → 读 canvas 像素 → PNG
攒齐后 → POST 到后端（复用 /host/upload-asset 或新增端点）
  → 后端 FFmpeg: -framerate {fps} -i frame_%05d.png → mp4 → 落 canvas inbox
  → 返回 /inbox_file/ URL → 挂载为 reference_video
```

**必须注意的三件事**：

1. **诚实失败**（沿用本功能全链的既有铁律）：
   帧数 0 / canvas 读到空白 / FFmpeg 缺失 / 合成超时 → 返回明确 message，**绝不产假视频**
2. **帧数上限**：刀 2 的 `pose_worker` 已有 `--max-frames 900` 硬上限（`17-motion-ref-design.md` §5.1）。
   录制侧应对齐同一上限，避免内存爆（900 张 PNG 已是可观占用）
3. **`reference_video` 对模型无能力时仍会诚实失败** —— 这与刀 5 未完成是**两件事**：
   刀 4 做完能拿到「白模视频」这个产物本身（可人工核对动作对不对），
   但要真正喂给生成模型，仍需刀 5 接上支持 `video_motion` 的模型。

### 3.4 冻结区影响评估（关键）

`stage3d-core` zone 锁 **7 个整文件**（`frozen_zones.json:286-308`）：

| 锁定文件 | 刀 4 是否必须改 |
|---|---|
| **`vendor/shiguang-canvas/src/Stage3D.tsx`** | ✅ **必须**（录制的 UI 与逐帧循环都在这里） |
| `vendor/shiguang-canvas/src/riggedHumanoid.ts` | ⚠️ 大概率**不用**（`applyPoseResolved` 已够用） |
| `vendor/shiguang-canvas/src/stage3dControlNet.ts` | ❌ 不用 |
| `app/core/canvas_bridge.py` / `canvas_runtime.py` | ⚠️ 仅当新增后端端点时才要碰 |
| `app/modules/lego/character_management_module.py` | ❌ 不用 |
| `scripts/export_vinchau_glb.py` | ❌ 不用 |

⇒ **改动面可收在 `Stage3D.tsx` 一个文件**（外加后端一个端点或复用既有上传）。
走既有解冻流程：**解冻 → 改 → 复跑守卫 → `--update` 重锁 → 补记录**
（刀 1 已有先例：§4.4 记「`frozen_zone_guard` 已 `--update` 固化，含 Stage3D.tsx 本次授权改动」）。

**必须守住的不变量**（`frozen_zones.json:290-297`，与录制直接相关的两条）：
- `loadGLBRiggedHumanoid 加载 GLB 后不做材质替换或颜色覆盖`
- `export_vinchau_glb.py 导出时不得修改骨名映射或材质设置`

⇒ 录制只做「**读渲染结果**」，**不得改动任何材质 / 骨名 / GLB 加载逻辑**。
