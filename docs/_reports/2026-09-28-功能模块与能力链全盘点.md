## 第 0 章 · 一页结论

### 一句话判断

> **这不是「功能缺失」型项目，而是「零件很全、连线不全」型项目。**
> 真正需要新造的零件很少；缺的是**把已有零件串起来的那几根线**。

### 四条最重要的结论

| # | 结论 | 依据 |
|---|---|---|
| **①** | **绝大多数模块是「真实现」，空壳极少** | 12 个模块里 ✅6 / 🟡6 / 🔴0；全库 `TODO/FIXME` 仅 **7 处** |
| **②** | **「链」在项目里有两套世界观，且没打通** | 画布的**边只是视觉**（美观）；真正的链执行**硬编码**在 `agent_pipeline_orchestrator.py` 的 Python 序列里 |
| **③** | **项目写过一个通用 DAG 执行器，但它是孤儿** | `flow_orchestrator.py`（597 行，含拓扑排序/并行/条件/循环）**全库零接线** |
| **④** | **最典型的失败形态不是「假成功」，而是「写了没接线」** | 口型引擎 `lip_sync.py`（704 行）**零 import**；画布边**零校验** |

### 闭环成熟度排行（谁真的能闭环）

```
✅ 真正闭环：
   抽卡质量链      生成 → 代理评分 → 账本 → 推荐 → 局部重绘
   Agent 编排链    指令 → 能力 → 执行 → 时间线（有确认门）

   成片精修链                  缺「片头连接器」

🔴 断链：
   图执行（整图跑）            执行引擎写好了，但是孤儿模块
```

## 第 3 章 · 画布能组合出哪些「链」—— 10 条链逐条判闭环

### 3.0 先讲清一件关键事：这个画布的「边」不干活

**实测结论：画布的连线只是视觉装饰，不参与执行、不校验合法性。**

| 事实 | 证据 |
|---|---|
| 连线类型只决定**颜色/虚线/动画** | `EDGE_STYLE_BY_TYPE`（`node-factory.ts:571-578`） |
| `onConnect` **无条件** `addEdge` | `store.ts:637-656`，只写一句 state 文案「已连接（X 流）」 |
| **全仓库不存在 `isValidConnection`** | Grep **零命中** ⇒ `video → prompt`、`note → anything` 都能连 |
| 上游文本只有 5 类进 prompt | `collectUpstreamContext` 只拼 `script/prompt/text/config/shot`（`bridge.ts:1403-1410`）⇒ image/video/audio 上游**不参与** prompt |
| `digitalHuman` 的 audio 流**不可达** | 它在 IMAGE_PRODUCERS 和 AUDIO_PRODUCERS 都在，但 `:558` 先判 image ⇒ 恒输出 image 流 |

> **这是理解全部「链」的前提**：链的合法性**由人脑保证**，不由系统保证；链的执行**靠人手点**，不由引擎驱动。

### 3.1 十条链的闭环判定

#### 链 ① 剧本 → 分镜（文本拆解链）
```
script ──[breakdownStoryboard]──> shot × N
```
- ✅ 拆解真实现（`/host/storyboard-breakdown`，LLM/启发式双路）
- 🔴 **缺「从想法生成剧本」入口** —— `ScriptNode` 是纯文本框（`nodes.tsx:345-354`），placeholder「双击撰写剧本大纲…」
- 🔴 **缺题材层模板** —— `shiguang-drama.json` 仅 8 条且全是**分镜/风格层**；题材层（世界观/主线/人设/禁忌）为**零**
- **闭环**：🟡 能拆，但**起点必须是人写的剧本**

#### 链 ② 分镜 → 图（图像生成链）★ 核心
```
shot ──[generateImageViaHost]──> image
```
- ✅ 真实现，全链路通
- ✅ 可挂角色（`bindCharacterToShot`）
- 🔴 **角色库无形象图字段** —— `CHARACTER_FIELD_SCHEMA` 20 字段**无任何 image/立绘/参考图**；`CharacterStore` 只读写 JSON
- 🔴 **画布绑角色丢字段** —— `store.ts::bindCharacterToShot` **只拼 `[角色外貌: appearance]`**，`temperament`/`memory_anchors`/`personality` 被丢弃（`memory_anchors` 恰是跨集一致性关键锚点）
- **闭环**：🟡 出图能闭环，但**角色一致性有洞**

#### 链 ③ 图 → 视频（视频生成链）
```
image ──[generateVideoViaHost]──> video
```
- 🟡 **图生视频能力未接** —— `provider_caps.py:42-43` 里 dashscope 自标 `image_to_video: False` / `first_last_frame: False`（注释「后续接线后改 True」）
- 🔴 `seedance`/`cogvideo` **无客户端模块**（`video_generation_client.py:547-560` 加载失败**静默返回 None**）
- **闭环**：🟡 文生视频可用，**图生视频/首尾帧断链**

#### 链 ④ 视频 → 成片（入轨链）★ 项目独有的强项
```
video ──[MATERIAL_TO_TIMELINE]──> timeline(_clips)
```
- ✅ 通路真实存在：`canvas_bridge.py:866` 发 EventBus；`/host/batch-to-timeline`（`canvas_routes_post.py:1036`）；`/ingest`
- ✅ 带 `canvas_node_id` 可**反向溯源**（round-trip）
- 🟡 **人工触发**，不是上游一变自动传播
- **闭环**：✅ **这是项目最完整的链之一**

#### 链 ⑤ 3D 导演台 → 参考 → 生成（3D 链）
```
director ──[姿势/ControlNet/BVH]──> reference ──> generate
```
- ✅ 3D 台真实现（5 体型人偶 / 15 关节 / 循环动作库 / ControlNet 三通道 / BVH 导出）
- 🔴 **体型预设 ↔ 角色库未通** —— `HUMAN_PRESETS` 5 个通用体型与角色库无关联，角色库也无体型/发型字段
- 🟡 **白模视频只挂 `reference_video` 通道**（`Stage3D.tsx:3429`），**不进时间线**
- **闭环**：🟡 3D 能产参考，**不能直通成片**

#### 链 ⑥ 声音链（TTS / 音乐 / 口型）
```
digitalHuman ──[TTS]──> audio ──> timeline        ✅
歌词+风格 ──[YuE plan]──> ABC ──[render]──> music  🟡
digitalHuman ──[口型]──> talking-head-video       🔴
```
- ✅ TTS 真实现（4 守护里 `tts_guard` 25.8KB，正音+分段+回读）

用户指令 ──[capability]──> 执行（含确认门）──> timeline

- ✅ 能力目录 72 条 · 四路接线（含守卫不覆盖的第 3/4 处）

## 第 4 章 · 结构性缺口：这个画布没有「执行引擎」

这是**最深的一处差距**，也是理解"为什么链不闭环"的总根因。

### 4.1 现状：两套世界观，没打通

| | 画布（React Flow） | 真实执行 |
|---|---|---|
| 载体 | 节点 + 边 | `agent_pipeline_orchestrator.py`（778 行） |
| 边的角色 | **视觉装饰**（颜色/虚线） | 无 |
| 执行单元 | **人手点"生成选中"** | Python 硬编码方法序列 |
| 顺序 | 无（人自由点） | `_run_generation_line → _run_editing_line → _run_preview_validation → _consult_brain → _try_regenerate_failed → _run_scoring → _run_script_generation → _run_editing` |
| 校验 | **无** | 无 |

**即：画布图 ≠ 程序。程序是 Python 里写死的流水线，画布只是它的「可视化面板」。**

### 4.3 对比 ComfyUI：差在「五层」

| 层 | ComfyUI | 拾光剪影 | 差距定性 |
|---|---|---|---|
| **① 类型化插座** | 强类型（IMAGE/LATENT/MODEL/CONDITIONING），连接即校验 | 边只上了个**颜色**；`isValidConnection` **零存在** | 🔴 **缺校验** |
| **② 图执行** | 点 Queue → 服务端跑**整图**（拓扑顺序） | 人工逐节点点；真实顺序写死在 Python | 🔴 **缺引擎**（但 `flow_orchestrator` 已写好待接） |
| **③ 缓存/增量** | 按节点 hash 缓存，改一处只重跑下游 | 每次重抽，**无缓存概念** | 🔴 **缺增量执行** |
| **④ 自定义节点生态** | 数千社区节点 | 插件框架 3,413 行 ✅，但 `install_plugin` **是桩**，`external/` **空目录** | 🟡 **框架有、生态无** |
| **⑤ 模型管理** | 统一模型目录 + 加载器 | `comfy_provider` 能探能拉起（本机秋叶包可用）✅，但**只 1 个真客户端** | 🟡 **能跑、选择少** |

**一句话**：ComfyUI 是「**图即程序**」；拾光剪影目前是「**图是仪表盘，程序在别处**」。

### 4.4 这是缺陷还是选择？——**一半一半**

- **是选择的部分**：北极星明写「智能体只做**确认后执行**的遥控器，**不默认一键成片**」⇒ 刻意不让人失去控制权
- **是缺陷的部分**：
  - 「改上游 → 下游自动标脏重跑」**没有**（ComfyUI 有）
  - 「同参数不重复抽卡」**没有**（正是 `draw_book` 想解决的，但只在**推荐建议**层面，不在**执行层**）
  - 「非法连接给出提示」**没有** —— 用户连错了**不会有任何反馈**

> **判断**：不追求「一键成片」是对的；但**连"合法性提示"都不给**、**已有 DAG 执行器不接**，属**可修的欠债**，不是价值观。
