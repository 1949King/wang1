# 统一推理引擎架构 · 设计稿 v1（goal：三条线合一）

> 日期：2026-10-24 ｜ 状态：待用户评审 ｜ 前置：V4.46.5~13 已交付执行层决策器 / 可移植底座 / 遥测选栈 / 质量档位 / 显存策略
> 目标（用户原话）：「同时支持市面上已有的视频类生成模型和其他大模型、多模态模型的引擎」+「解决现在三条线的问题，把它合并成一条」。

---

## 0. 一句话方案

**不重写任何模型执行代码**——建一张 `ModelFamily` 注册表（协议层）+ 把现有 4 条执行线各包成一个 `BackendAdapter`（适配层），选路统一走已建好的 `execution_planner`。新模型接入 = 登记一条描述 + （可选）指认后端，不再新写 `_infer_xxx`。

### 1.2 重叠与分裂点（要合并的病根）

- **SVD 有两个实现**：③ 的 `_infer_svd`（diffusers pipeline）与 ④ 的 `video_gen`（diffsynth）。两者共享 `video_gen.TUNED` 调优表但各跑各的——同一模型两条命，参数漂移只是时间问题（`local_video_infer.py:50` 注释自己承认"两套实现脱节"是补出来的）。
- **选路逻辑三处重复**：图像走 `resolve_local_image_engine`，视频 ③ 走 `decide_execution`，④ 走端点直连（不经任何决策器）。
- **能力宣称无准入校验**：③ 的 6 个未验证族在 UI 上"看起来可选"——违背项目"library-only 不得宣称可用"纪律（`engine_registry.py:14` 已把这条写成法条，但 ③ 没接）。
- **三个注册表并存**：`backend_registry`（4 后端×架构，本会话建）/ `engine_registry`（56 条登记+健康+用量，并行会话建）/ 能力目录。经核对**职责不冲突**（调度输入 / 观测视图 / Agent 面），但 `backend_registry` 与 ModelFamily 的边界必须今天划清，否则成第四个真源。

### 1.3 已有的好资产（保留，不推翻）

`LocalGenerationBackend` 抽象基类（`canvas_aigc.py:149`）、`execution_planner.plan()`、`engine_telemetry`（n≥3 证据选栈）、`device_profile`（能力位）、`memory_policy` + `promotion_fits`、`video_gen.TUNED`、109 项门禁 + 1967 测试。

## 2. 目标架构

```
                    ┌────────────────────────────────────────┐
 新模型接入 = 登记   │  model_family.py（新，协议层·单一真源）  │
                    │  ModelFamilySpec:                       │
                    │    family / capability(image|video|     │
                    │      audio|llm|vlm…) / archs /          │
                    │    backends:(按优先级) / weights 探测 /  │
                    │    min_vram / encode_cost / fps 语义 /  │
                    │    tuned 参数引用 / verification 状态    │
                    │  准入三态: verified | unverified | blocked│
                    └───────────────┬────────────────────────┘
                                    │ resolve(family, device, bias, 遥测)
                    ┌───────────────▼────────────────────────┐
                    │  execution_planner（已建，扩一个输入面）  │
                    │  选后端 = 注册表声明 ∩ device 能力 ∩ 遥测 │
                    └───────────────┬────────────────────────┘
              ┌──────────┬──────────┼──────────┬───────────┐
              ▼          ▼          ▼          ▼           ▼
        AdapterDiff  AdapterDif  AdapterVid  AdapterVid  (未来)
        synthImage   usersImage  genLocal    GenSvd      AdapterLLM/
        (①包装)      (②包装)     (③包装)     (④包装)     ONNX/TensorRT
                                    │
                                    ▼
                    旧入口全部保留 = 薄委托（canvas_aigc / 端点 / hybrid_dispatch 不改签名）
```

**关键裁决（写进协议，消灭 1.2 的病）**：

1. **SVD 只有一个家**：归 ④ `video_gen`（diffsynth 通道，有 TUNED 实测表、有守卫 `check_video_gen.py`）。③ 的 `_infer_svd` 标记为 `alias`，注册表把 svd 族的唯一后端指到 ④；③ 内 svd 分支保留但委托 ④，不再双轨。
2. **未验证族降级**：③ 的 wan/ltx/mochi/minimax/cogvideox/hunyuan 登记为 `verification=unverified`（权重不在盘、pipeline 类存在性未测）。UI/Agent 可选择，但 reasons 必须带"未在本机验证"——对齐 engine_registry 的 `library-only` 法条。**不删代码**（它们是对 diffusers 生态的合法适配），只是不再冒充"可用"。
3. **backend_registry 归位**：它继续管"后端进程内健康"（find_spec 级），ModelFamily 管"模型族→后端映射"。前者是后者的输入之一，两表字段不重叠（对照表见 §4）。
4. **engine_registry 收编**：新族注册表落 `family="inference"` 新条目 `model.family`（role=primary），56 条视图不动——它读得到用量/健康，调度读得到声明，各管各的。

## 4. 迁移计划（每阶段独立可交付、可回滚，旧签名全程不变）

| 阶段 | 内容 | 验收 | 风险 |
|---|---|---|---|
| **M1 协议层** | 新建 `model_family.py` + 单测（纯数据 + resolve 逻辑，不碰 GPU）+ 守卫入册 | 门禁全绿；resolve 对 9 族输出与现状四条线的实际行为一致（快照测试） | 低 |
| **M2 后端收编** | ①②③ 各注册为 adapter（`backend_id` 对齐 backend_registry）；`execution_planner._engine_probe` 改读 ModelFamily（保留旧探测兜底——svd 教训：查无≠不可用） | 现有 40+ 测试全过；video plan 不再依赖注册表兜底路径 | 低 |
| **M3 SVD 归一** | ~~③ `_infer_svd` 改为委托 ④~~ **实施时侦察修正（V4.46.16）**：委托方向会丢 ③ 的缓存资产（OOM 让位、实测复用 35.68s）。真实病灶是**双驻留**（顺序使用两条各持 4.2GB ⇒ 8.4GB，15GB 机压爆）与**参数双源**（③ 硬编码"抄自"TUNED）。改做「驻留合一 + 参数单源」：④ 的 load 走 ③ 的共享缓存（同 key，两侧目录解析实测相等）、④ unload/OOM 连带 evict、③ 参数实读 `tuned_for`。两份代码都保留，双轨病灶（驻留/参数）消灭 | 跨实例共享命中 + unload 真驱逐 + 改表传导（monkeypatch 证明）；SVD 真机回归；fps/CFG 守卫绿 | **中**（动生产路径，带遥测回退：委托失败→走原实现并记 reason） |
| **M4 入口合一** | `canvas_aigc` 视频分支与 `canvas_routes_local_video` 都改调 `resolve()`；未验证族在 reasons 带警示；`/host/execution-status` 增 families 视图 | 端点契约守卫 + E2E（真桥打 /host/local-video-generate 与 local/ 前缀各一次） | 中 |
| **M5 扩展验证** | 用**一个真实新模型**验收协议（候选：ModelScope 可下的 Wan2.1-T2V-1.3B，需 P0-2 编码器缓存/组件卸载先落地才可能在 15.3GB RAM 上跑——若 RAM 墙不过则改用更小的 CogVideoX-2b 或诚实记"本机不可行"） | 登记一条 spec + 零 `_infer_*` 新代码 = 可跑/或诚实 blocked | 高（硬件边界，失败也是有效结论） |

每阶段交付 = 代码 + 测试 + 门禁 + CHANGELOG + 提交。**M1–M4 不依赖任何未装库；M5 需要下载权重（另行请示）。**

## 5. 明确不做（防止范围蔓延）

- 不重写任何模型执行逻辑（性能在 CUDA kernel，实测 GPU 饱和 97.6%，Python 层重写收益 <5%——本会话已实测否决）；
- 不引入新框架（DiffSynth/diffusers 就是后端，不建第三生态）；
- 不合并 `engine_registry`（观测层）与 `model_family`（协议层）——两表字段正交，硬合会让 HTTP 线程探测拖上调度语义；
- C++/Rust 化：已实测否决（见 V4.46.13 后的探针记录）。
