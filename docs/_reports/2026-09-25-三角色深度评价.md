## 一、开发者视角：**远超个人项目平均，但被"摊大饼"拖住**

### 1.1 最突出的优点（罕见级）

**① 单一事实来源纪律被执行到底 —— 这是全项目最值钱的工程决策**

| 收敛对象 | 单一来源 | 派生处 |
|---|---|---|
| Agent 能力元数据 | `agent_capability_catalog.CAPABILITY_ROWS` | `agent_policy` 效果表 · `agent_brain` 神经元表 · `capability_handlers` 注册守卫 |
| Agent 常量 | `agent_constants.STATUS_*` | 全项目，禁裸字符串 |
| 画布版本号 | `canvasVersion.ts` | `package.json` + 导航栏（曾散在三处、停在 v0.1.0 十余轮） |
| 画布动作 | `agent_action_registry._CANVAS_ACTION_ROWS` | 能力目录行由它派生 |
| 冻结区基线 | `frozen_zones.json` | 4 处文档同步 |

配套**双向一致性守卫**（`verify_catalog_consistency`）：漏注册/漏登记都会告警。
⇒ 同类项目 90% 会在这上面腐烂，本项目把它变成了机器可验证的机制。

**② 验证文化（56 个检查脚本 + 52 项回归）**

不是"有测试"，而是**测试覆盖了独有风险面**：默认值行为（dry_run 不改数据）、
撤销栈条数（恰好 1 条 compound）、隔离性（不该动的零改动）、
四处接线静态断言（**守卫覆盖不到的第 3/4 处**）、漂移清单核对。
⇒ 这解释了为什么"同名方法重复定义导致撤销失效"这类缺陷能被抓住。

**③ 踩坑沉淀成技能库（8 个 user-level skill）**

`git-mass-deletion-triage`（删定性）· `ast-scope-nameerror-hunt`（NameError 扫描）·
`frozen-zone-release`（冻结区解冻七步 + 20 条陷阱）· `shared-state-locking-proof` ·
`serialization-field-symmetry` · `python-coldstart-profiling` · `qt-visual-change-verification` ·
`mjs-mirror-test`。
⇒ **把"经验"变成了"可复用流程"**，这是个人项目最难积累的资产。

**④ 诚实降级是一等公民**

`pinyin_dict` 库缺失→`ok=False`+人话原因；LLM 不可用→走字典兜底而不是"静默不注音"；
Unihan 未覆盖→标 `unknown` 且**明确写"不编造读音"**；tsc 存量错误→A/B 对比证明零新增。
⇒ 反"随机效果"的工程价值观落实到了代码层。

**⑤ 新引擎的架构质量明显高于存量**

V4.37.4~V4.39.2 新增的 12 个引擎模块：零外部依赖、RLock、原子写、异常不抛、
观察门控、抗卷绕、不变量断言、可复现仿真（`Simulator` 同种子同指纹）。
⇒ 说明**能力在成长**，且新代码质量高于旧代码 —— 这是罕见的好信号。

### 1.2 最突出的问题（按严重度）

| # | 问题 | 数据 | 影响 |
|---|---|---|---|
| 1 | **巨型文件持续增长** | `editor_module.py` 9,717 行，比 09-19 **涨了 238 行** | 单文件认知负荷极高；已有 mixin 拆分（editor_agent_runtime_mixin / editor_agent_panel_mixin）但主文件仍在长 |
| 2 | **双前端 + 副库三重维护** | Qt6（app/main_qt6）+ 画布（Tauri/React 3.9 万行）+ 副库（15.8 万行，22 处分叉 16 处缺失） | 同一功能要改 2~3 处；副库未被 git 跟踪 ⇒ **无法用 git 回滚**（曾因此无路可退） |
| 3 | **修正性债务 > 结构性重写** | 8 个 >2000 行文件；lego 目录 81 个模块无分层 | 新功能倾向于"再加一个文件"而非"重构现有" |
| 4 | **前端类型错误长期挂 37 处** | Stage3D.tsx 16 + riggedHumanoid.ts 21 | 多为 Three.js 类型问题，运行时无害，但**掩盖真实新错**（故强制 A/B 对比） |
| 5 | **验证脚本无 CI** | 52 项回归靠手动跑 `run_all_checks` | 缺少"提交即验证"的强制门（沙箱环境所限，但仍是缺口） |

### 1.3 一句话结论（开发者视角）

> **工程纪律是 A 级，模块划分是 C 级。**
> 项目最像"一个受过工程训练的人在一个没时间做架构的项目里拼命保持体面"——
> 纪律（守卫/不变量/验证/诚实降级）做到了大厂水平，
> 但**没有一个模块规模约束**（9,717 行单文件、81 个平铺模块），
> 导致"改一处要读一万行"。**继续加功能前必须先做拆分**，否则纪律会被规模压垮。

## 二、用户视角：**功能极多，但"能顺畅跑通的闭环"只有两条**

### 2.1 逐功能拆解（完成度 / 体验 / 缺口）

| # | 功能 | 完成度 | 用户体验 | 关键缺口 |
|---|---|---|---|---|
| 1 | **视频剪辑精剪**（editor_module 9,717 行） | ★★★★☆ | 时间线、撤销/重做、关键帧、变换、涟漪删除齐备；`_clips` 为真相源 | 无自动粗剪写回 `_clips`；工具栏曾因同名方法覆盖而调错实现（已修但说明历史欠账） |
| 2 | **AI 画布 · 磁吸意图卡片**（3.9 万行） | ★★★★☆ | 磁吸贴合、Bond 咬合、让位 reflow、空间记忆分层、小白/专业双模式 | 卡片信息密度与 240×200 硬约束冲突（本轮实测：四层内容装不下，需折叠提示语）；双库漂移 |
| 3 | **AI 视频生成 · 多渠道路由** | ★★★☆☆ | 12 引擎模块：收益函数选路、λ 双层预算、六级降级、D 双路融合、分歧探针 | **依赖渠道 key 开通**（用户尚未开通百炼 → 只能本地占位）；执行体（真实视频落盘）仍需逐个接通 |
| 4 | **Agent 大脑**（Neuron/Synapse/Hebbian） | ★★★★☆ | 左右脑 + 胼胝体、突触学习改变决策（`check_brain_routing` 证明真的在管"继续 vs 重生成"） | 学习只影响"调用习惯"，**不改变理解能力**（LLM 权重冻结）；48 个能力对 prompt 预算有压力 |
| 5 | **Agent 能力面**（48 条能力 + action 白名单） | ★★★★☆ | 目录单一来源 + 四处接线完整；effect 分级（read/write）+ paid 审批 | 能力多 → LLM 选错概率上升；部分能力 effect=read 但用户不知道"只出计划不改数据" |
| 6 | **配音 TTS 正音 + 口型** | ★★★★☆ | 长台词切段 + 多音字注音（字典确定性 + LLM 选候选 + 判卷）+ ASR 回读质检 + Viseme 口型 | 字典覆盖不到扩展区（实测与字幕相关仅 103 字）；口型与配音同源（本轮已统一） |
| 7 | **生成质量守护**（tts / 角色锚定 / 表情 / 道具） | ★★★★☆ | 四守护可单打也可 `guard_all` 总入口；负面词 + 结构化质检 | 守护依赖 LLM 时延迟高；规则层覆盖面有限 |
| 8 | **短剧筛选**（drama_finder_plugin） | ★★★☆☆ | Playwright 爬虫 + 内容分类 + 情绪向量 | 依赖外部站点结构；合规风险（爬虫） |
| 9 | **3D 数字人**（Stage3D + 骨骼 + 动捕） | ★★★☆☆ | GLB 渲染、姿势元数据、白模录制、姿态解析（刀1-3 完成） | **刀4（录制白模视频）未做**；通道就位但无模型支持 `video_motion` |
| 10 | **素材库 / 资产管理** | ★★★☆☆ | 本机素材库 + 网站直达（帮助页） | 仅本机、无云同步 |
| 11 | **插件系统** | ★★★☆☆ | 两层架构（`PLUGIN_STANDARD` + `IEffectPlugin`）+ 懒加载 | **两套并存**（ExtensionsRegistry + PluginManager）易混淆；lego→插件迁移未完成 |
| 12 | **宣传页 / 可视化**（byox_visualizer 等） | ★★☆☆☆ | 有产出但属一次性 | 与主链路无关，属探索性投入 |

### 2.2 用户侧三个结构性问题

1. **入口过多、活路径不清**：V4.19.0 已把闭环收敛为"剪辑精剪 + AI 画布"两条活路径，
   但**界面上仍能看到 8+ 个模块**（DramaFinder/AccountOps/Copywriting/Tasks/Materials/
   Plugins/Performance/Lego），用户不知道"从哪开始"。
   ⇒ 对小白用户直接是致命伤（产品定位却是"小白模式"！）。
2. **"能跑通"依赖外部条件**：AI 生成要 key、要开通模型、要网络；一旦缺就退到"本地占位"
   （色块视频）——用户看到的是"AI 功能没效果"，而不是"你没开通"。
3. **双版本困惑**：Qt6 桌面版 + Tauri 画布版两套前端，同一用户可能看到两处入口、
   两套版本号（主程序 4.39.x / 画布 0.3.1），需要解释成本。

### 2.3 一句话结论（用户视角）

> **这是"给创作者的重型工具"而不是"消费级产品"。**
> 功能广度足够覆盖短剧生产全流程，质量守护设计（注音/角色一致/口型）直击短剧痛点；
> 但**首次使用门槛高**：需要配置 key、理解两条活路径、容忍未完成模块。
> 适合"愿意折腾的创作者"，不适合"打开就能用"的用户。

## 三、投资者视角：**工程能力是 A，商业确定性是 C+**

### 3.1 赛道与定位

- **赛道**：AI 短剧 / 短视频自动化生产（2026 年高热，但竞争密集：大厂工具、SaaS、开源方案并存）
- **切入**：桌面端一体化（剪辑 + 生成 + 画布 + Agent），**非 SaaS**
- **差异化**：
  1. **磁吸意图画布**（人机交互创新，7 个月迭代，Bond 咬合/让位/空间记忆有完整不变量文档）
  2. **把"AI 生成质量不稳定"做成子系统**（占位选路 + 降级 + 质量守护 + 抽检冻结 + 人工红线）
     —— 这恰是行业内被普遍抱怨但少有系统化解决的问题

### 3.2 资产盘点（按可迁移性排序）

| 资产 | 可迁移性 | 估值逻辑 |
|---|---|---|
| **12 个异构引擎模块** | ★★★★★ **零 `app.*` 依赖，可整目录迁出**（已实测） | 唯一可**独立变现**的资产：可服务任何"多模型成本/质量调度"场景（含代码 Agent） |
| 验证体系（56 检查 + 52 回归 + 8 技能） | ★★★★☆ 概念可迁移 | 证明创始人**能交付可靠系统** —— AI 创业里最稀缺信号 |
| 磁吸画布交互 | ★★★☆☆ 需配套前端 | 交互设计可复用到其他画布类产品 |
| 48 条 Agent 能力 + 目录机制 | ★★★☆☆ 半可迁移 | 机制可迁移，业务能力不可 |
| 短剧领域规则（守护/情绪/文案锚定） | ★★☆☆☆ 强绑定 | 领域 know-how，形成小护城河 |
| 视频剪辑内核（9,717 行） | ★☆☆☆☆ 强绑定桌面 | 很难迁到云端/移动 |

### 3.3 风险清单（按致命度）

| # | 风险 | 说明 |
|---|---|---|
| 1 | **单人开发 + 无团队** | 17 万行主程序 + 3.9 万行前端 + 15.8 万行副库全由一人维护 ⇒ bus factor = 1 |
| 2 | **技术栈过重** | Qt6 + Tauri/React 双前端 + 3D/动捕 + FFmpeg + 本地 ML ⇒ 每扩一个平台成本翻倍 |
| 3 | **依赖闭源模型** | 收益函数与预算控制建立在"按次计费的第三方模型"上；模型方改计费/关 API 即冲击 |
| 4 | **无变现验证** | 全部为工程投入，未见付费/留存数据；"省配额/省成本"在订阅制下价值口径不清晰 |
| 5 | **内容合规** | 短剧题材 + 爬虫筛剧 + 生成内容 ⇒ 平台政策与版权风险 |
| 6 | **工程债传导** | 巨型文件 + 双库漂移 + 37 处类型错误 ⇒ 若融资后要扩团队，新人上手成本极高 |

### 3.4 估值视角的两种剧本

**剧本 A（工具化）**：作为"AI 短剧剪辑桌面工具"卖断/订阅
→ 天花板低（工具类 ARPU 有限），但现金流清晰；估值取决于用户量而非技术。

**剧本 B（引擎化）**：把 12 引擎模块提炼为"AI 生成的质量与成本控制层"（SDK/服务），
场景从短剧扩到任意"多模型生成"业务（含代码、文案、图像）
→ 天花板高得多（对标观测/评测/路由层），且**已验证可迁移**。
→ 前置条件：引擎需脱离视频语义（融合算子换介质、收益函数重定义单元边界），
并补服务端取舍（进程隔离、真并行）。

**判断**：当前资产**明显偏向剧本 B 的潜力**，但项目本身仍在按剧本 A 的形态投入（重桌面、重 UI）。

### 3.5 一句话结论（投资者视角）

> **"工程能力优秀、商业确定性不足"的典型早期项目。**
> 值得关注的理由不是"短剧工具"，而是**创始人把 AI 生成的不确定性做成了可控工程**——
> 这套方法论 + 可迁移引擎，是比产品本身更大的资产。
> 最大问题是**单人 + 三线并行（Qt/画布/副库）**，任何投资都应把"收敛技术栈、砍掉一条线"
> 作为前置条件。

## 五、给三条行动建议（按性价比排序）

1. **砍一条线**：Qt6 版与 Tauri 画布版二选一（保留哪条取决于目标用户）；
   副库要么纳入 git，要么明确"只读存档"。→ 直接释放 50%+ 维护成本。
2. **给最大文件设上限**：`editor_module.py` 9,717 行必须开始拆分（mixin 已有先例），
   并把"单文件 ≤2000 行"变成守卫可检查的规则（**用已有的守卫文化做这件事，成本最低**）。
3. **把 12 引擎模块做成独立包**（`pip install` 可装、脱离视频语义），
   同时立刻做两个最小验证：① 换一个非视频场景的端到端 demo；
   ② 写一份"引擎能省多少钱"的量化对照。→ 这是把"工程资产"变成"商业资产"的唯一路径。
