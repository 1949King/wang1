## 三、做得好的地方（有实证）

### 1. 单一事实来源（SSOT）落地得相当彻底 ★★★★★

`app/core/agent_capability_catalog.py` 是全项目**设计水平最高的一块**。

它把此前散落在 4 处的 capability 元数据收敛成一张表，其余三处全部**派生**：

```
CAPABILITY_ROWS（唯一手写处）
   ├── agent_policy._CAPABILITY_EFFECTS  = capability_effect_paid()
   ├── agent_brain._NEURON_TAXONOMY      = neuron_taxonomy()
   └── capability_handlers.register_builtin_handlers → verify_catalog_consistency()
```

难得的是**文件头 docstring 记录了动机与三个真实踩坑**（`editor.inspect_media` 因漏登记被策略引擎误判成 FILE_WRITE、`memory.suggest` 有 effect 无 handler、9 个能力无脑归属）。"问题—方案—证据"三段齐全，这是资深工程师才会留下的痕迹。

**实测佐证**：全库扫描「同类内重复定义 = **0**」。说明此前的重复定义缺陷没有复发，收敛策略生效了。

### 2. 安全默认值选的是 fail-closed（而非 fail-open）★ ★ ★ ★ ★

`agent_policy` 对**未登记工具一律返回 `FILE_WRITE`**——不认识的工具当作危险操作，而不是当作只读放过。

更细致的一处：

```python
# agent_policy.py:135
eff = effect if effect in WRITE_EFFECTS or effect == EFFECT_READ else registered_effect
```

调用方可以传 `effect`，但**只能提权不能降级**成 read。这说明作者认真想过越权路径。

配套还有 `can_auto_retry`（付费/写操作**永不**自动重试）与 `sanitize_for_log`（递归脱敏 + 绝对路径打码）。

**实测佐证**：全库「硬编码凭据 = **0**」（唯一 1 处在 `app/tests/test_security.py`，是测试用例本身）。

### 3. 「事故 → 工具化防御」的闭环 ★ ★ ★ ★ ★

`canvas_server.py:266` 有一条注释记录了真实事故：**新端点被追加到文件末尾，落进上一个函数的 `return` 之后，永远走不到**（语法合法、静默死代码）。

关键不是修了它，而是**为它写了 AST 检测脚本** `_verify/check_canvas_routes.py`，能识别四种路由写法。**把一次踩坑变成永久防线**——这是个人项目里罕见的工程自觉。

### 4. 诚实失败原则贯穿始终 ★ ★ ★ ★ ☆

`agent_loop.py:412-415`：预算耗尽但未获最终答复时，**明确标记失败**而不是包装成成功。多轮 Agent 最容易在这里偷懒。

`canvas_aigc.py:1299` 的 docstring 直接写「失败返回明确错误（不假成功占位）」；motion-ref 门禁不支持时，把已落盘的 `reference_video_path` 一并回传，**不丢用户资产**。

### 5. 性能细节专业 ★ ★ ★ ★ ☆

- 预览节流三层合并：`_preview_debounce`(60ms) + `_scrub_idle_timer`(220ms) + `_scrub_preview_timer`(80ms)，另有丢帧统计
- 缩略图**代际失效**：`_thumb_gen_token` 递增，防止旧异步任务回写覆盖新状态（Qt 里极易做错）
- 视口剔除带 120px 预取边距；滚轮缩放保持视口语义
- `_LazyModuleProxy` 用 `__slots__` + `object.__getattribute__` 规避 `__getattr__` 递归陷阱

## 四、核心缺陷（按严重度）

### P0-1：`_clips` 是全库事实来源，却**零锁保护**且无数据模型

| 证据 | 值 |
|---|---|
| `_clips` 在 `editor_module.py` 中被提及 | **212 次** |
| 该文件内 `threading.Lock` / `RLock` / `_clips_lock` 匹配数 | **0** |
| `editor_module.py` 总行数 | 9,479 |

**为什么是 P0**：

1. 它被 `_add_clip_to_timeline`（主线程）与画布后台线程路径同时触碰（`canvas_server.py:1644` 的 `_run_batch` 在后台跑生成任务）
2. `:3538` 的 `if clip not in self._clips` 是**「检查-再追加」竞态**，非原子
3. 列表元素是可变的 `dict`，跨线程改字段会产生**撕裂状态**
4. 字段无约束，靠各处 `clip.get("start_time", 0)` 拼装；`:8933` 构造一次 `clip_info`、`:8949` 又手工拼一次 `clip` —— **同一片段建两次**

存在 `_heal_linked_av_duration_mismatch`（:8834）这类"自愈函数"，本身就是数据模型缺失的自证。

**建议**：抽出 `TimelineModel` 类，把 `append/remove/update_fields` 变成唯一写入口，内部加 `RLock`。

### P1-1：调试代码留在主干，且**自身会崩**

`editor_module.py:22-52` 是一个向 `http://127.0.0.1:7777/event` 发 HTTP 的临时调试函数，注释标明 `#region debug-point`。

**实测调用点 5 处**：`:1340` `:1355` `:1378` `:8908` `:9026`。

**我发现一个子问题（原始分析未提及）**：

```python
 22  def _report_video_import_debug(...):     # ← 函数定义
 50      except Exception:
 51          logger.debug("video import debug report failed", exc_info=True)
 52      # #endregion
 53
 54  logger = logging.getLogger("AI短剧编辑器.editor_module")   # ← logger 在这里才定义
```

`logger` 在 **第 54 行**才创建，而**第 51 行**就引用了它。一旦 `except` 分支真的执行，会抛 **`NameError: name 'logger' is not defined`** —— **调试代码的异常处理本身会崩**，把原本想吞掉的错误变成新异常抛出去。

**危害**：
- 每次入片多一次 HTTP 尝试（`timeout=0.8`），服务器不在时**每次最坏多等 0.8 秒**
- 热路径上的出站请求属生产事故级反模式

**建议**：删除函数 + 5 个调用点。若要保留链路诊断能力，改为 `logger.debug` 本地打点。

### P1-3：守卫机制「有骨架没牙齿」

`capability_handlers.py:1130-1157` 有三处自检（目录一致性、action 映射、brain 同步），设计意图完全正确。但**三处全部只 `logger.warning`，且自身异常降级为 `logger.debug`**：

```python
# :1156
except Exception as e:
    logger.debug(f"[AgentBrain] 同步 dispatcher 失败: {e}")
```

**脑同步失败意味着 Agent 神经元表与实际能力脱节**——却只打 debug 级日志。更讽刺的是：**守卫自己挂了也无人知晓**，而这正是它要防的那类静默缺陷。

**建议**：问题清单汇总暴露到启动自检面板 + `_verify/` CI 门禁；守卫自身异常提到 `warning`。

### P1-5：`except Exception: pass` 集中在**最不该静默的地方**

全库静态匹配 **124 处**。但逐条核对后要**修正一个常见误读**——不是"全都是静默吞噬"，`clip_widget.py` 全文 26 处 `except` 中真 `pass` 约 12 处，其余带 `logger.debug`。

**真正有害的是状态/资源管理路径的密集 `pass`**：

| 位置 | 内容 | 风险 |
|---|---|---|
| `clip_widget.py:1209-1221` | `sleep_media_workers` 里连续 4 个 `try/except: pass` 包住 `_thumb_debounce.stop()`、`_media_worker_gate.cancel_owner()`、`_thumb_gen_token += 1` | **worker 泄漏**；token 自增失败 → 旧缩略图任务回写覆盖新状态，表现为"拖动后缩略图错帧"这类极难复现的 bug |
| `timeline_widget.py:1034-1057` | 框选结束路径 3 个连续 `pass`（marquee 清空、光标恢复） | 框选卡死 / 光标不还原 |
| `timeline_widget.py:398/1105/1330` | `except Exception: continue` 遍历时跳过 | 用户看不到"有 N 个片段刷新失败" |

**判定原则**：**UI 绘制类静默可接受，状态机与资源管理静默不可接受。**

## 七、一句话总结

> **这是一个"知道自己在做什么"的项目。** SSOT 收敛、fail-closed 默认值、事故工具化、诚实失败——这些不是"能跑就行"的项目会做的事，作者显然读过工程实践并真的在落实。
>
> **卡点是"防御有骨架没牙齿"**：守卫只告警、协议靠字符串、事实来源没锁。这几处补上，就能从"工程化中期偏上"跨到生产级——因为它们全都不需要重构，只需要**让已有的防线真正生效**。
