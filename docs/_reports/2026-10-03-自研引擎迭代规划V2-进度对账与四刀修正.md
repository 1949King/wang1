## 第 2 章 三处诚实性修正（先认错，再规划）

### 2.1 M3「视频 ≥7 族（已达）」是虚报

V1 把 `_guess_model_kind` 的**关键字识别面**（wan/cogvideox/hunyuan/ltx/mochi/minimax_h3/svd = 7 种）
当成了「已达」。实测（2026-10-03 子进程）：

| 口径 | 数量 |
|---|---|
| 关键字识别面 | 7 族 |
| `VIDEO_MODELS` 注册表 | **3 条** |
| 本机实有权重且可跑 | **1 条**（SVD；两个 Wan 均被 RAM 墙挡死） |

⇒ M3 修正为：**可跑视频 ≥2 族 + 可跑图像 ≥2 族**（自研侧，实测出片为准，「能认出」不算数）。

### 2.2 W1 验收「8GB 跑通 Wan1.3B」不可达

Wan 的墙是 **RAM 不是显存**：umt5-xxl T5 = 10.58GB 常驻（cpu_offload 要求全量权重在 pinned RAM），
DiT 2.6GB + VAE 0.5GB ≈ **13.7GB > 本机 15.3GB 减 OS**。
`layer_disk_offload` 解决显存，**解决不了 RAM 常驻**。此验收项与引擎能力无关，两个引擎同样撞墙。

⇒ 修正：`layer_disk_offload` 的验证场景改为 **SDXL 图像**（fp16 6.9GB 权重 + 激活 > 8GB）
与 **SVD 长帧**（25 帧 floor ≈10.85GB > 8GB×95%，现自动升 sequential 慢档）。

### 2.3 M1/M2「同模型对比 DiffSynth」基准缺失

- DiffSynth 11 管道里**没有 SVD**；Wan 两边都因 RAM 墙跑不动
- ⇒ 双栈**没有共同可跑的视频模型**，M1/M2 在视频侧无法落地

⇒ 修正：对比基准移到**图像侧** —— SD1.5 一体化 safetensors（3.97GB，**已下载**）
可同时被两栈加载：DiffSynth `SDImagePipeline`（已实装）vs diffusers
`StableDiffusionPipeline.from_single_file`（0.40.0，已验证可用）。
**同权重、同 prompt、同 seed、同步数** ⇒ M1（峰值显存比）/M2（耗时比）第一次有真实数字。

## 第 3 章 修正后的迭代方向：四刀

> 原则不变：R8 每档实测 · R9 降级可见 · 三条自有优势（治理 12 切片/渠道统一/深度集成）不许丢。
> 顺序逻辑：**先易后难、先有基准后有优化、每刀独立可回滚**。

### 刀1 —— 自研图像引擎（W3'，零下载 · 顺带立 M1/M2 基准）

| 项 | 内容 |
|---|---|
| 交付 | `app/core/neural/diffusers_image.py`（契约与 `diffsynth_image.py` **逐键对齐**） |
| 权重 | **复用** `app/models/cache/AI-ModelScope_stable-diffusion-v1-5/v1-5-pruned-emaonly.safetensors`（`from_single_file`，零新下载） |
| 探测 | `find_spec("diffusers")`，绝不真 import（组合场景崩教训 ×2） |
| 显存 | 接 `memory_policy`（SD1.5 fp16 ≈2GB 权重：whole_gpu / model_offload 双档实测） |
| 测试 | 对齐 `test_diffsynth_image.py` 17 用例规格 + AST 无真 import |
| 附产 | **双栈对比脚本**（同 prompt/seed/步数：显存峰值 + 耗时 + 出图）⇒ M1/M2 首批实测数字 |

**为什么是第一刀**：零下载、契约已定型（照抄对岸）、当天可收口；
且它一完成，M3 图像族 1/2、M1/M2 基准三个缺口同时松动。

### 刀2 —— SDXL 图像族 + `layer_disk_offload` 真实现（W1' + M3 图像 2/2）

| 项 | 内容 |
|---|---|
| 交付 | `memory_policy` 第四档 `layer_disk_offload` 从「预览」变「可返回」；hook 式逐层 `to(cpu/cuda)`，不改模型结构（参考 DiffSynth `AutoWrappedModule` 思路，只实现推理必需部分） |
| 验证场景 | SDXL fp16（6.9GB）在 8GB 卡上**必须 offload**；对比 model_offload vs layer_disk 的显存/速度 |
| 双栈 | DiffSynth 侧注册 `sdxl-t2i`（`SDXLImagePipeline`），自研侧同步 `from_single_file` |
| 下载 | SDXL 1.0 一体化（~6.9GB，ModelScope 直连接 `pull_sd15_http.py` 通道） |
| 验收 | 四档 mode 各有实测峰值显存记录（CHANGELOG）；layer_disk 场景下显存显著低于 model_offload |

### 刀3 —— 量化档（W2，顺带埋下 Wan 复活触发器）

| 项 | 内容 |
|---|---|
| 后端 | **torchao 优先**（宽松许可、与 torch 2.6 同厂维护），bitsandbytes 备选；冲突时保 torch 不动 |
| 交付 | `memory_policy` 增 `quant ∈ {none, int8, nf4, fp8}`；量化权重落 `app/models/cache`（不建第二套链路） |
| 验收 | 同模型出片 + **PSNR ≥ 30dB**（vs fp16 逐帧）+ 显存再降 ≥40%；不达标不上线 |
| 彩蛋 | 若 T5 量化（NF4 10.58GB→~3GB）实测可行 ⇒ **Wan RAM 墙自行瓦解**，P2 观察板触发器由自研主动造出 |

### 刀4 —— 跨 run 缓存 + 稳定性 + 切回验收（W4）

| 项 | 内容 |
|---|---|
| 缓存 | 进程内单模型缓存（已有）→ **LRU 双槽**（视频 1 + 图像 1 共存），跨进程不做（权重 mmap 本身不慢，SD1.5 首载 49s 主要在 cpu_offload 包装） |
| 稳定性 | `_verify/` 增 50 次连续生成脚本 + 显存曲线（M5） |
| 切回 | 验收报告逐条填 M1~M5 实测数；达标才动 `SHIGUANG_EXEC_ENGINE`；**先改开关不改常量**，双向可逆 |
