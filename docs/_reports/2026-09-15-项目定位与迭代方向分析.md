## 一、项目是什么（从代码推导，非愿景）

拾光剪影是一个**单机优先的 AI 短剧/漫剧生产工位**：PyQt6 桌面宿主 + 三条产品面。

| 产品面 | 载体 | 成熟度 |
|--------|------|--------|
| 剪辑 | `app/modules/lego/editor_module.py`（9,155 行）+ FFmpeg 管线 | 主力，写能力 8/8 达标 |
| 画布 | `vendor/shiguang-canvas`（自研磁吸四向卡片，React Flow v12） | 差异化核心，模板闭环已通 |
| Agent | `app/core/agent_*`（brain/loop/policy/catalog/console） | A→B→C→D 四轨已落地 |

**差异化战略**（决策文档，代码行为已印证）：不跟剪映拼剪辑、不跟 ComfyUI 拼节点、
不跟大厂拼模型；磁吸四向卡片（横向=时间叙事链，纵向=挂载关系）是唯一竖切；
一套骨架两层深度（折叠=小白 / 展开=专业）。ComfyUI 只做导入/导出逃生舱（已闭环）。

## 二、发展目标（北极星 7 阶段闭环的真实进度）

精剪 → 人工改 → 文案 → 发布 → 数据采集 → 优化建议 → 选题。

- C1 发布真回执 ✅ / C2 爆款建议进账号运营 UI ✅ / C3 剪辑 workflow_hint ✅
- **缺口**：选题自动导入时间线、一键粗剪写 `_clips` —— 闭环最后两公里在剪辑侧
- 优先级纪律：**先剪辑（稳→快→全→可维护），后 AI 闭环** —— 与代码投入分布一致

## 三、使用人群（按现有功能反推）

1. **个人短剧/漫剧创作者（主人群）**：小白模式「一句话→拆镜→卡片→生成→成片」
   （V4.17.4/5 已闭合）、模板起步（V4.17.7）。特征：不懂节点图，要的是"说人话出片"。
2. **小团队/自媒体运营**：账号运营插件 + 数据采集 + 爆款建议回灌选题。
3. **进阶创作者**：专业模式节点工作流、ComfyUI 导入、3D 导演台（单人/群像模板）。

## 四、迭代方向（优先级）

1. **剪辑稳定性**（P0）：修 2 处同类内重复定义真实缺陷（见 §五）→ 一键粗剪写 `_clips`
2. **画布生态收尾**（P1）：补②「四向语义动起来」（触碰磁吸冻结区，需解冻纪律）
3. **Agent 从"能干"到"有状态"**（P1，本轮 V4.18.0 已落内心状态层；后续把
   `affect` 门控接进 UI 主动建议的展示层）
4. **闭环缺口**（P2）：选题自动导入时间线
5. **工程债分期还**（持续）：测试整合、死代码清理、宿主拆分

## 五、不足点（诚实清单，全部代码实测）

1. **宿主过大**：`editor_module.py` 9,155 行，拆上帝类进行中
2. **同类内重复定义=静默覆盖**（最高频缺陷形态，已两次踩），现存 2 处待修：
   - `keyframe_animation.py get_value`（:283 生效/:363 死）→ BEZIER/STEP/SMOOTH 静默退化线性
   - `login_window.py _do_phone_register`（:414 生效/:499 死）→ 手机号注册 100% 失败
3. **测试资产分散 4 处**：307 收集 → 6 failed，3 个模块收集即失败（`from core.*` 陈旧路径）
4. **死代码 23 个 / 10,359 行**；`app/modules/plugins/*` 是零引用的第二套插件体系（与正文档 §9 冲突）
5. **存量坏味道高位**：`except: pass` 249、裸 print 729、超 50 行函数 561（红线"只许降不许升"）
6. **双库漂移**：副库 AI-Canvas-tauri 落后主库 7 个功能文件（已知状态，待 P0-1 抽包收敛）
7. **冻结区守卫文件级误报**：`files` 整文件登记 vs `invariants` 锁符号，合法增量也会报警（纪律成本高）
8. **Agent 的模型依赖**：多轮循环的决策质量受 provider 模型能力影响大（五写法解析兜底了格式，兜不住智力）
9. **单机架构**：无云协作/多端（有意取舍，短期不是缺点）

## 六、Agent 升级：小凌意识公式体系 → 内心状态层（V4.18.0）

**"到 libtv 水准"的解读**：画布引擎（libtv）是本项目工程标杆——纯函数内核 +
单例状态 + 回归脚本 + 冷启动不变量。本轮按同一标准给 Agent 补上缺失的
「内心状态/动机层」：`app/core/ai/affect_model.py`（约 470 行）。

手稿 10 组公式 → Agent 语境映射（全部夹紧 [0,1]）：

| 手稿公式 | 实现 | Agent 语境 |
|---|---|---|
| ② pain=S×I×C | `pain_signal` | S=失败占比，I=敏感度（写类>读类），C=疲劳（预算+连败） |
| ③ 冷/热感受 | `discomfort` | 冷=记忆稀薄/预算见底/无反馈；热=调用过密/重试/燃烧率 |
| ④ A=w1..w5 | `arousal` | 新颖性+需求+情绪+目标+记忆；≥0.6 进取 / 否则保守 |
| ⑤ Disappointment=E×I×(1−PE) | `disappointment` | 期望高×重要×预测意外 → 失望 |
| ⑥ Trust=αP+βCons−γV−δB | `trust_score` | α+β=1 保证中性=0.5；信任决定「学到的权重打几折用」 |
| ⑦⑨ SoulDrive=f(T,P,H,U,V,F,R) | `soul_drive` | ≥0.7 才允许主动建议（不打扰门控） |
| ⑧ Impact=P×H×U×D | `psych_impact` | 乘法结构：四者皆大才触发「习得性谨慎」 |
| ⑩ M_{t+1}=M_t+α(E−M_t) | `update_expectation` | 按决策分支 EWMA，M0=0.5 |

**三处接线（全部 try/except 静默降级）**：
1. `agent_brain.suggest_next(..., trust=)`：低信任 → 学到的权重向中性 0.5 收缩
   （因子=clamp(0.5+trust, 0.5, 1.0)，只减幅不反向）；None=不干预
2. `agent_loop._finalize`：每次 run 观察成败/调用密度/审批事件/重试压力
3. `agent_pipeline_orchestrator._consult_brain / _emit_done`：咨询带信任、会话结束更新分支期望
4. `agent_console` 新增 `affect` 块（pain/trust/arousal/drive/impact + 门控结论），UI 可直接消费

**红线保持**：冷启动行为与未接入时逐字节一致（空状态 mode=conservative、
proactive=False、trust=0.5→因子1.0）；不做 ε 随机探索；永不自动执行写操作；
诚实失败；零解冻（改动均不在冻结区）。

**回归**：`_verify/check_affect_model.py`（A~H 共 40+ 断言全绿）+
`check_brain_routing.py` 复跑全绿（suggest_next 改动零破坏）。
