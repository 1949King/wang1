## 二、五大面板的「业界共识」分工

调研 8 款产品后，主流画布对 **顶部 / 左侧 / 中央 / 右侧 / 底部** 五个区域的分工有高度共识：

| 区域 | 业界共识职责 | 出现频率 | 反例 |
|---|---|---|---|
| **顶部 toolbar / navbar** | 文件菜单 / 视图切换 / 分享 / 缩放 / 全局工具 / **AI 入口按钮** | 100%（8/8） | — |
| **左侧 sidebar** | **库 / 目录 / 层级**：Pages / Layers / Assets / Resources / Templates / 节点库 | 100%（8/8） | — |
| **中央画布** | 核心工作区，**永远独占中央** | 100%（8/8） | — |
| **右侧 panel** | **属性 / 详情 / AI 助手**：选中项属性 / Agent 对话 / 输出预览 | 100%（8/8） | — |
| **底部 dock** | 状态栏 / 缩放 / **小地图 / 导航 / 时间轴**（剪辑工具专属） | 87.5%（7/8） | Figma 无底部 dock |

**核心规律**：

1. **左侧 = 库**（资源、组件、节点、模板）
2. **右侧 = 详情**（属性、AI 助手、输出预览）
3. **顶部 = 全局动作**（文件、视图、分享、AI 单入口）
4. **底部 = 状态 / 时间**（缩放比例、小地图、时间轴）
5. **AI 暴露 = 单一入口**（Figma/MasterGo 顶部按钮、TapNow 右 Chat interface、剪映 Hub 独立 Agent）

## 三、8 款产品的「AI 功能暴露方式」横向对比

| 产品 | AI 暴露方式 | 强度 | 借鉴价值 |
|---|---|---|---|
| **Figma** | 顶部 toolbar 内集成 Figma AI 按钮 | 轻 | UI 单点（最不易乱） |
| **MasterGo** | 顶部 toolbar 内 AI 工具按钮 | 轻 | 同上 |
| **Miro** | "AI Canvas" 模式：toolbar 图标变化 + 额外工具入口 | 中 | 模式化切换 |
| **ComfyUI** | 右控制面板 + 顶部 Manager | 中 | 区分"对话"和"管理" |
| **TapNow** | 右侧 Chat interface（对话） + 侧栏 panel（outputs 列表） + 左下 Toolbar | 重 | **对话与产物分离** |
| **剪映** | 顶部 toolbar 集成 + 左侧文本 tab 含"智能字幕" | 轻-中 | 与功能分类耦合 |
| **剪映 Hub**（最新） | **独立 Agent 入口"小映"** + 无限画布 + 多轨道 | 重 | **AgentOS 雏形** |
| **Excalidraw** | 无 AI | — | 极简参考 |

**关键发现**：AI 越重的产品，**对话面板**和**功能执行面板**越分离（TapNow / 剪映 Hub 都遵循）；AI 越轻的产品，AI 按钮越藏在工具栏深处（Figma / MasterGo）。

## 五、优化方案（针对拾光剪影）

### 方案 A：按业界共识整理（≈3-4 小时，零冻结区改动）

**改 4 个区域**，遵循"左=库 / 右=详情 / 顶=全局 / 底=状态"：

| 区域 | 改动 | 文件 |
|---|---|---|
| 顶部 navbar | 合并去重：Agent 单一入口、引擎投影机单一入口；保留 Ollama/Qwen 状态徽章 | `CanvasShell.tsx` ⚠️ 解冻 |
| 顶部 toolbar | 与 navbar 合并（或收纳到 navbar 的"视图"菜单） | 同上 |
| 左侧 sidebar | **15+ 节点分类压缩到 6 大类** + `<details>` 折叠：创作（剧本/分镜/提示词/文本）/ 媒体（图片/视频/音频）/ 工具（生成器/编辑）/ 视图（Markdown/工作区）/ 调度（双击空白/搜索/临时） | `LeftSidebar.tsx`（待确认是否冻结） |
| 底部 dock | 只保留缩放比例 + 视图模式（画布/3D 导演台） | `LibTvChrome.tsx` ✅ |
| 右侧 Agent-IM | 对话 Tab 加 `<details>` 折叠分块（模型 / 快捷 / 引用 / 附件 / 输入） | `AgentPanel.tsx` ✅ |

**风险**：低；**触及冻结区**：CanvasShell + 可能 LeftSidebar

---

### 方案 B：分组重构 + Ctrl+K 搜索中枢（≈半天，顺带启动 AgentOS S5）

A 的全部 + 加搜索中枢：

| 增量改动 | 价值 |
|---|---|
| 顶部 navbar 加 `Ctrl+K` 搜索按钮 | **直接消解"功能多找不到"问题** |
| Ctrl+K 全屏搜索框：模糊匹配 capability / tool / 节点分类 / Agent 命令 | 让 80% 控件**不需要直接暴露** |
| 顶部 navbar AI 入口收窄为单一 `🚀 Agent` 按钮（合并 5 个入口） | **根治入口发散** |
| 左侧 sidebar 节点分类按"输入/处理/输出"重构 | 强化"分类=数据流"心智 |
| Agent-IM 的"工具"Tab 上限 80 行改**按 `extension_type` 自动分组 + 每组可折叠** | 治 80 行平铺 |
| 底部 dock 极简化：仅缩放 + 视图模式 + Agent-IM 折叠指示 | 状态信息单独留 |

**新增 Ctrl+K = AgentOS S5 命令中枢雏形**，与 S1 窗口管理联动。

**风险**：中；**触及冻结区**：CanvasShell + 部分 styles.css

---

### 方案 C：AgentOS 战略级重做（≈1-2 天）

B 的全部 + 借鉴 **剪映 Hub（无限画布 + Agent）** 与 **TapNow（对话与产物分离）**：

| 增量改动 | 价值 |
|---|---|
| 顶部 navbar 重构为"AI OS Launcher"：文件 / 视图 / 搜索 / 分享 / 用户 | 极致简洁 |
| 左侧 sidebar 升级为"能力库 nav tree"，按 `agent_capability_catalog.py` 的 6 category 分组（extension / model / canvas / editor / workflow / pipeline） | **与后端能力目录单一来源对齐** |
| 节点分类成为"可搜索的能力"，不再平铺 | 治本 |
| 顶部 navbar + 底部 dock + 右下 FAB + 桌宠**合并为单一 Agent nav** | 根治 5 入口发散 |
| 右侧 Agent-IM 抽屉保留为"当前任务对话"（对话 Tab） + 分离"输出预览"（侧栏 panel） | **借鉴 TapNow 双面板** |
| Ctrl+K 命令中枢升级为自然语言命令 | 完成 S5 |

**风险**：高；**触及冻结区**：CanvasShell + styles.css + 可能 LeftSidebar

## 六、我的推荐

**推荐方案 B + 顺带把"5 个 Agent 入口合并"做完**：

理由：

1. **A 太轻**：能治"分组缺失"，但治不了"入口发散"和"找不到功能"。
2. **C 太重**：1-2 天 + 多次解冻，与当前节奏不匹配。
3. **B 正好**：
   - 治"分组缺失"（左侧 6 类折叠 + 右侧对话 Tab 分块）
   - 治"入口发散"（顶部 5 入口合并为 1）
   - 治"功能太多找不到"（Ctrl+K 搜索）
   - **直接是 AgentOS S5 命令中枢**，未来推进时省一次重构
4. 工作量：~半天；触及：CanvasShell 解冻（一次性）+ 部分 styles.css

**配套建议**：
- **顶部 navbar 5 入口 → 1 入口** 的取舍：建议保留 PyQt6 `🎨 AI 画布` 主入口 + 画布顶栏 `🚀 Agent` 单一按钮 + 桌宠，其他全隐藏。
- **左侧 sidebar 6 大类**：建议用"创作 → 媒体 → 工具 → 视图 → 调度"五类（去掉冗余的"双击空白"、"搜索区域"等"操作提示"，它们是空类）。
- **Ctrl+K 触发**：建议用 `Cmd/Ctrl+K`，对齐 Figma/Linear 习惯。
