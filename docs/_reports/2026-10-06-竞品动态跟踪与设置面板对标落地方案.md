## 一、LibTV（**同赛道头号竞品**）

**身份核实**：LibTV = **LiblibAI（哩布哩布 AI）** 的 AI 短剧/视频平台，**2026-05-18 团队版上线**，
已孵化/发行 AI 短剧累计播放**突破百亿**（百度百科条目）。⇒ **这就是我们 AI 短剧赛道的正面对手。**

### 1.1 最近动态要点（2026-08 ~ 10）

| # | 要点 | 细节 | 对我们的含义 |
|---|---|---|---|
| 1 | **智能引用**（配 Seedance 2.5） | 一次最多 **50 份全模态参考素材**；自动识别画布内素材并**插入提示词对应位置** | ⚠️ 上游 AI Canvas 0.9.21 也有「连线后自动 @ 上游素材」⇒ **这是行业标配了**，我们**没有**，该跟 |
| 2 | **片段重拍** | 对已生成视频的**指定时间段**（如 00:19–00:24）局部重生成，**不必整条返工** | 我们有局部重绘（图像）；**视频侧没有** ⇒ 对「成片精修」是关键项 |
| 3 | **超长视频** | 多节点工作流把单次 **30 秒 → 5 分钟**连续直出；长片保留**分镜节点**可逐段编辑 | 我们有时间线/精剪底座（**这是我们的强项**）；但生成侧的"长片编排"没他们顺 |
| 4 | **角色造型室**（LibTV 1.5） | 捏脸式调五官/发型/身材/服装 + 预设形象库；**改完可把画布上所有与该角色相关的资产一键换新** | 我们记忆里就有「**角色造型**」列在 LibTV 1.5 对标差距里 ⇒ 仍未做。**"一键换新全画布"这个原子操作值得学** |
| 5 | **导演指导模式** | 挑选或**训练"导演 skill"**优化分镜，**一键应用到视频节点** | 我们已有导演分身的雏形（`director_skill`）⇒ 方向对，缺"可训练的导演 skill 库" |
| 6 | **深度视频提取** | 参考视频先转**灰度深度**再喂模型 ⇒ **只搬运运动/运镜/空间关系，不泄露人脸与风格** | ⭐ 低成本高质量技巧，**直接可做**（我们已有 ffmpeg + 姿势/深度链路） |
| 7 | **3D-BOX / 逐帧拉片 / 爆款复刻 Agent** | 3D 视角框；拉片拆解参考片 → 结构化脚本（时长/景别/机位/运镜/光线/声音 + 替换方案） | 我们有 3D 导演台 + 分镜拆解 ⇒ **形态差距大于能力差距** |
| 8 | **双入口（最该注意）** | 除 GUI 外，提供**面向 AI Agent 的 Skill 接口**，外部 Agent（如 OpenClaw）**一句话跑完剧本→分镜→视频** | ⚠️ 我们 Agent 只在**自家 UI 内**；LibTV 把能力**开放给外部 Agent** ⇒ 这是生态位差异 |
| 9 | 电影级灯光 | **24 种主光位 + 9 种轮廓光预设** | 我们 3D 台有灯光概念，但没这个预设库 |
| 10 | 商业/速度 | **0.4 元/秒**（2.5 与 2.0 折后同价，官方 API 涨价 50% 但用户端不涨）；团队版按席位+资源；**从拿到模型测试权限到功能上线仅 2 天** | 速度是他们的护城河 ⇒ **我们必须靠"本地 + 剪辑底座"差异化，不能比功能数量** |

### 1.2 一句话判断

LibTV 已经把「AI 短剧从想法到成片」做成了**结构化产品**（无限画布 + 节点 + 20+ 独家控制 + Agent Skill 接口），
**我们不可能在功能数量上追上**（他们模型一更新，功能 2 天上线）。
**我们仍然守得住的三条**：① **本地/私有**（素材不出机）；② **真剪辑底座**（时间线/精剪/LUT/撤销体系 —— 他们是"生成优先"，成片精修仍是弱项）；
③ **Agent 可编排 + 三档审批**（比他们的 Agent 更可控）。

## 三、「要不要建跟踪机制？」—— **要，但要有边界**

### 3.1 支持建的三个理由（都是可核对的）

1. **迭代速度不对称**：LibTV **2 天**把模型能力变成产品功能；上游 AI Canvas **10 天 3 个版本**（0.9.21→0.9.23）。
   我们若一季不跟踪，**刀序会排错**。
2. **成本极低、已被验证有效**：本轮调研约 10 分钟，直接改判了一件事 ——
   把「**输出历史**」从"看着不错"提到**最优先**（因为它是这类产品的标配，而我们**完全缺失**）。
3. **跟踪的产物是"校准"而不是"抄"**：我们已明确列出**不抄的项**（如"Agent 与人不互锁"、
   "把'本地'当卖点却不标出网环节"）⇒ 有边界，不会变成功能焦虑。

### 3.2 机制设计（建议：每周一次自动任务）

产出《竞品周报》，四段固定结构，**无更新就写"无更新"，绝不编内容**：

```
① 上游 AI-Canvas-tauri：新 Release（版本 + 要点）
② LibTV：新功能 / 新模型首发（含价格与速度信号）
③ TapNow：Agent OS / Skills / 社区动态
④ 影响判断（最重要）：每条注明「命中我们哪个缺口」+「是否影响当前刀序」+「不采纳的理由（若采纳则写代价）」
```

**存放**：`docs/_reports/竞品跟踪/YYYY-Www.md`（例：`2026-W41.md`）
**触发**：每周一早上；我们当前在跑的刀序完成后自动把"新出现的差距"并入下一刀候选。

### 3.3 我建议的"看门条款"

- **只跟踪不冲动**：周报**不产出**"要不要抄"的清单，只产出"与我们哪个缺口对齐"。
- **必须标来源**：每条要点附来源链接与获取日期（本项目报告惯例）。
- **禁止把竞品宣称当实测**：标注"官方宣称/媒体报道"，与"我们实测"分开写。

### 4.2 建议顺序（按"闭环价值 / 成本"排）

1. **插件面板（含开发规范 + 示例 + 校验）** —— 我们已经有两套系统与真实插件目录，**只差"可视化 + 规范"**；
   而且**插件生态是我们相对 LibTV 的差异化点**（他们没开插件）。
2. **MCP 控制面板**（顺带把服务端接线）—— 行业正在向 MCP 收敛（Comfy 官方 MCP 已 public beta）；
   我们客户端早就实现了，**面板 + 服务端**是欠账。
3. **外观预设系统** —— 价值在"换肤/交付观感"，非闭环；但成本低（主题变量已集中）。

⚠️ **两条纪律**（避免踩我们自己踩过的坑）：
- 面板若含 Qt 内联样式，**每个都必须回 `set_theme()` 补刷新**（不变量 #8）；能不用内联样式就不用。
- 插件市场/版本检查涉及**网络**⇒ 必须在界面上**如实标注"此操作会联网"**（诚实线，见第四节 #5 的教训）。

## 五、结论（三句话）

1. **跟踪机制要建**：理由不是"别人有我也要"，而是**LibTV 2 天一个功能 + 上游 10 天 3 版**，
   不跟踪我们的**刀序会排错**；成本 10 分钟/周，已在本轮验证有效（改判了"输出历史"优先级）。
2. **LibTV 是正面竞品、且功能数量上追不上**：我们守 **本地私有 + 剪辑底座 + 可控 Agent** 三条，
   但要尽快补三个"标配"：**连线/智能引用自动带素材**、**视频片段重拍**、**深度视频提取**（后者成本最低）。
3. **设置面板三块都能做，且都是"面板化 + 规范文档化"，不是新造系统**；
   建议顺序：**插件（含规范/示例/市场）→ MCP 控制 → 外观预设**。

## 六、两家更新总结（一页，供拍板）

### 6.1 他们共同的四个方向

1. **画布内 Agent 直接操作对象**（不是给建议/给 JSON）：Comfy Agent 计划-搭建-运行-调试；TapNow Agent OS **画布感知**；LibTV 侧边栏 Agent（爆款复刻/导演指导）。
2. **Agent 能力要能沉淀复用**：Comfy Agent 的 **skills**；TapNow 的**技能仓库 + 按偏好生成专属 Skill**。
3. **生成之后的"改"比"重抽"重要**：LibTV **片段重拍**（指定时间段局部重生成）、Comfy Agent「解释这张图/这个工作流哪里慢」。
4. **长片/多镜头编排到应用层**：LibTV **超长视频**（30s → 5 分钟，保留分镜节点）；TapNow 故事板 + Cinema Lab。

### 6.2 两家的差异

| 维度 | LibTV（LiblibAI） | TapNow |
|---|---|---|
| 定位 | **AI 短剧**垂直（与**我们同赛道**） | 商业视觉/影视创作 OS |
| 护城河 | **速度**（模型到手 2 天上线）+ 独家控制（角色三视图/主体库/灯光预设） | **生态**（TapTV 12 万可克隆工作流）+ 多模型自动匹配 |
| 入口 | GUI + **面向外部 Agent 的 Skill 接口** | GUI + Agent OS + 外部应用授权（飞书/Notion） |
| 价格 | 0.4 元/秒（用户端不随模型涨价） | 订阅 + Tapies 积分 |

### 6.3 对我们**最必要的 3 件**（本轮已完成 1 件）

| 序 | 项 | 为什么必要 | 状态 |
|---|---|---|---|
| 1 | **输出历史面板**（含复制配方/种子） | 抽卡/生成闭环**唯一缺失的复盘端**；账本/任务表/产物数据**都已存在** | ✅ **本轮已做**（V4.40.41） |
| 2 | **连线/智能引用自动带素材** | 已是行业标配（上游 0.9.21 也有），我们没有；直接影响出图质量 | 待做 |
| 3 | **深度视频提取**（只搬运动/运镜，不泄露人脸风格） | LibTV 的巧招，**成本最低**；我们已有 ffmpeg + 深度/姿势链路 | 待做 |

> 另有两条"值得跟但不紧急"：**技能沉淀/可分享配方**（对应 TapNow TapTV 与我们的 B-12 配方包）、
> **MCP 服务端接线**（Comfy 官方 MCP 已 public beta，行业在向 MCP 收敛；我们客户端早就实现了）。

### 6.4 明确**不照抄**的项

- **Agent 与用户同时改画布「不互锁」**：我们已有**三档审批（plan/collaborative/autonomous）+ dangerous 级**，比他们更可控；改回去等于削弱刚建好的闸门。
- **把「本地」当卖点却不标注出网环节**：Comfy 官方都写明「本地执行 ≠ 离线推理」，我们必须**如实列出哪些能力联网**（诚实红线）。
- **「模型一更新就堆功能」的军备竞赛**：我们守 **本地私有 + 真剪辑底座 + 可控 Agent** 三条，不在功能数量上比。
