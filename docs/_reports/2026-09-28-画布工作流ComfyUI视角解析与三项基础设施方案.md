## 1. ComfyUI 的「工作流」到底是什么

### 1.1 两边的模型对照

| 维度 | ComfyUI | 拾光剪影画布 | 差距 |
|---|---|---|---|
| **工作流的本体** | 节点图**就是程序** | 节点图是**面板**，程序在 `agent_pipeline_orchestrator.py`（778 行硬编码 Python 序列） | 🔴 |
| **端口模型** | 每节点声明 `inputs: [{name,type}]` / `outputs: [{name,type}]`，**可多入多出** | 每节点**恒 1 入 1 出**，无类型 —— `nodes.tsx:269` 一个 `<Handle type="target">`、`:308` 一个 `<Handle type="source">` | 🔴 |
| **连接校验** | 类型不匹配 → **拒绝连接** | **无校验**：`onConnect` 无条件 `addEdge`（`store.ts:637-656`）；全库 **无 `isValidConnection`**（Grep 零命中） | 🔴 |
| **边的语义** | 数据流（真的传值） | **只决定颜色/虚线**（`EDGE_STYLE_BY_TYPE`，`node-factory.ts:571-578`） | 🔴 |
| **执行** | 点 Queue → 服务端跑**整图**（拓扑序） | 人**逐节点点**"生成选中"；无 `runWorkflow` 动作（Grep 空） | 🔴 |
| **缓存** | 按节点 hash 缓存，改一处**只重跑下游** | **每次重抽**，无节点级缓存 | 🔴 |
| **节点生态** | 数千社区节点 | 插件框架 3,413 行 ✅，但 `install_plugin` 是桩、`external/` 空目录 | 🟡 |

### 1.2 关键：ComfyUI 的"工作流"= 一个有向无环图 + 类型契约 + 执行器

要用 ComfyUI 视角看拾光剪影，必须承认：
**拾光剪影当前的"链"是「语义链」**（人理解的先后关系），**不是「执行链」**（机器跑的 DAG）。

⇒ 因此本文的每个工作流，都会标注它**当前实际是怎么跑的**（人点 / 硬编码 / 还是根本没跑）。

## 3. 三项基础设施方案

### 3.1 类型化插座（typed sockets）

**目标**：从「节点级隐式类型」升级到「**端口级显式类型 + 连接校验**」。

**设计**：
```ts
// 新增 PortType
type PortType = "text" | "image" | "video" | "audio" | "music" | "scene3d" | "grid" | "any";

// 每 kind 声明端口（新增）
const NODE_PORTS: Record<Kind, { inputs: PortType[]; outputs: PortType[] }> = {
  script:      { inputs: [],            outputs: ["text"] },
  prompt:      { inputs: ["text"],       outputs: ["text"] },
  shot:        { inputs: ["text","image"], outputs: ["image"] },
  image:       { inputs: ["text","image"], outputs: ["image"] },
  video:       { inputs: ["image","text","audio"], outputs: ["video"] },
  music:       { inputs: ["text"],       outputs: ["music"] },
  audio:       { inputs: ["text"],       outputs: ["audio"] },
  digitalHuman:{ inputs: ["text"],       outputs: ["audio","image"] },  // 双输出
  director:    { inputs: [],             outputs: ["scene3d","image"] },
  generator:   { inputs: ["text","image","video","audio"], outputs: ["any"] },
  ...
};

// 兼容矩阵
function canConnect(from: PortType, to: PortType): boolean {
  if (from === "any" || to === "any") return true;
  return to === from || COMPAT[from]?.includes(to);
}
```

**落地三步**：
1. `NODE_PORTS` 表 + `canConnect()`（新代码，放 `node-factory.ts` 或新文件）
2. `store.ts::onConnect` 加校验：非法连接 → **拒绝 + 提示原因**
3. `CanvasShell.tsx` 给 `<ReactFlow>` 挂 `isValidConnection`
4. （可选）`nodes.tsx` 按 PortType 给手柄上色

**冻结影响**：`node-factory.ts` / `store.ts` / `CanvasShell.tsx` / `nodes.tsx` **全在 `canvas-magnetic-intent`** ⇒ **需解冻**

**风险控制**：
- **默认宽松**：`any ↔ any` 恒真；只拦"明确不兼容"（如 `video → text`）
- 提供**开关**：`SHIGUANG_STRICT_PORTS`（默认关）⇒ 不影响既有工程
- 保留 `inferEdgeType` 作为样式推断，不破坏现有视觉

### 3.2 图执行（graph execution）

**目标**：从「人逐节点点」升级到「**可选的一键运行整图**」——**但不违反北极星**（默认仍需确认）。

**设计（后端优先，零冻结）**：
```
新文件 app/core/canvas_workflow_runner.py
  ├─ run_graph(graph: {nodes, edges}, *, dry_run=False) -> RunResult
  │    ├─ 拓扑排序（复用 flow_orchestrator._topological_sort 的思路）
  │    ├─ 逐节点执行：按 kind 调用既有后端函数
  │    │    image/shot  → canvas_aigc.generate_image_via_host
  │    │    video       → generate_video_via_host
  │    │    audio       → generate_audio_via_host
  │    │    music       → yue/suno
  │    │    script      → chat（拆解/生成）
  │    │    其余        → 跳过（纯前端节点）
  │    ├─ 上游产物注入下游（关键！当前 collectUpstreamContext 只拼文本）
  │    └─ 进度回调（复用 SSE /host/agent/events）
  └─ 新增端点 POST /host/canvas-run + GET /host/canvas-run/{id}
```

**关键设计决策**：
| 决策 | 选择 | 理由 |
|---|---|---|
| 默认行为 | **只出计划（dry_run）**，确认后才跑 | 守北极星「确认后执行」 |
| 上游注入 | **文本**用 `collectUpstreamContext`；**图/视频/音频**新增"产物注入" | 补上当前的能力落差（见 §1.3） |
| 失败策略 | 单节点失败**不中断整图**，记录并继续（除非是硬依赖） | 与 `preview_validation_loop` 一致 |
| 复用 `flow_orchestrator`？ | **复用它的拓扑排序思路**，但不直接用它 | 它是通用 DAG（BLOCK/LOOP/CONDITION），`FlowNode` 结构与本项目节点不匹配；**直接接要写适配层**，不如新写薄运行器 |

**冻结影响**：**零冻结**（新文件 + `canvas_routes_post.py` 不在冻结区）✅

**前端（需解冻）**：一个「▶ 运行工作流」按钮 + 进度面板

### 3.3 增量缓存（incremental cache）

**目标**：同参数不重复抽卡；改一处只重跑下游。

**设计（后端，零冻结）**：
```
新文件 app/core/canvas_node_cache.py
  ├─ node_fingerprint(node, upstream_fingerprints) -> str
  │    = sha1(kind | 归一 params | 上游指纹拼接)[:16]
  │    （复用 draw_book.normalize_prompt 的归一化纪律）
  ├─ lookup(fp) -> Optional[output]      # 命中则跳过生成
  ├─ store(fp, output)
  └─ invalidate_downstream(changed_node_id)
```

**复用现有**：`draw_book.py` 的指纹/原子写/RLock 模式**直接可搬**（它的 `_fingerprint` 是 `sha1(kind|prompt|model|style|size)[:16]`）。

**关键**：fingerprint 必须**包含上游指纹**，否则改上游不会失效下游。

**冻结影响**：**零冻结** ✅

**UI**：命中缓存时节点显示「⚡ 缓存命中」徽标（需解冻）

>
> **答**：
> 1. **能组成 16 条工作流**：✅ 5 条已闭环 / 🟡 8 条半闭环 / 🔴 3 条断链（其中 1 条是外部模型依赖）。

> 4. **三项基础设施**：类型化插座（需解冻）· 图执行（**零冻结**，新模块+新端点）· 增量缓存（**零冻结**，可搬 `draw_book` 模式）。
> 5. **建议顺序**：先做零冻结的三项（图→视频对齐 / 增量缓存 / 图执行），再申请解冻做类型化插座与三条链的前端加固。
