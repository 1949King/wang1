# 小白模式优化方案 · 意图编译范式 2.0

> 版本：2026-10-11 · 状态：**方案稿（待拍板）**
> 前置：`docs/_reports/2026-10-11-意图类型契约设计稿.md`（E1 契约）
> 定位词：**小白模式 = 意图编译** · 专业模式 = 节点图（**并存，不废弃**）

---

## 0. 命题：为什么不能变成「中文版 ComfyUI」

ComfyUI 的门槛不在UI，在**心智模型**：用户必须先在脑中建立「数据流图」，再把图翻译成操作。门槛 = 抽象 + 记忆 + 排错。

| 维度 | ComfyUI | 目标形态 |
|---|---|---|
| 用户要产出什么 | 一张**图** | 一段**片子** |
| 前置知识 | 数据流、节点、连线语义 | **零** |
| 失败时怎么办 | 看图找断点 | 系统直接告诉下一步 |
| 学习曲线 | 陡（教程 + 试错） | 平（一句话开局，按需展开） |
| 扩展方式 | 写节点（要会编程） | **说配方**（会打字即可） |

**判定标准（写死，避免跑偏）**：任何新功能若要求用户「先理解数据流才能用」，一律不做。

## 1. 概念层：三个重新定义

### 1.1 卡片不是「节点」，是**一句待办**

现状问题：`shot` / `image` / `video` 这类命名与 22 种 `KIND_STYLE` 是**从专业模式继承来的**——小白看到「分镜板」「生成配置」不知道该干嘛。

**改法**：小白模式的卡片**按角色命名，不按技术类型命名**：

| 技术 kind | 小白看到的名字 | 一句话职责 |
|---|---|---|
| `directorCard` | **故事** | 「把你的想法拆成一组分镜」 |
| `shot` / `image` | **画面** | 「描述这一幕该长什么样」 |
| `video` | **镜头** | 「让画面动起来」 |
| `audio` / `music` | **声音** | 「配台词或配乐」 |
| `generator` | **批量出图** | 「一次多出几张，挑最好的」 |
| `director` | **摆姿势** | 「用 3D 摆人和机位」 |
| `markdown` / `note` | **笔记** | 「随手记」 |
| `config` / `source` | **素材** | 「把文件放进来」 |

> **不动 kind、不动数据模型**，只加一层 `noviceLabelFor(kind)` 映射。零迁移成本。

### 1.2 意图胶囊从「三层标签」升级为**唯一的信息架构**

现状问题：胶囊是**被动显示**（三个小圆点 + 悬停提示），小白看不到它有什么用。

**改法**：胶囊变成**卡片的唯一入口**——

```
        ┌─ 你看到的（表面层）：缩略图 / 状态灯
 卡片 ──┼─ 你要的（语义层）： ← 默认展开，就是你打字的地方
        └─ 系统的事（实现层）：默认折叠，需要时才看
```

- 默认只露**语义层**（提示词、画质、时长、画幅）
- 实现层收进「进阶」抽屉，**不进 L3 也要能过**（L3 只在需要复现/排错时用）
- 表面层的缩略图**必须可见**——它是「我做出来的东西」，正反馈的来源

### 1.3 关系从「连线」升级为**意图流**

现状问题：软连接只是「虚线提示」，用户不知道该固化还是该拖着。

**改法**：软连接**按意图类型命名+ 着色**（承接 E1 契约矩阵）：

| 边的意图 | 呈现 | 文案 |
|---|---|---|
| 结构 → | 紫色实线 | 「故事分成镜头」 |
| 画面 → | 蓝色实线 | 「画面喂给下一镜」 |
| 声音 → | 青色实线 | 「声音配到画面上」 |
| 冲突 | 琥珀虚线 | ⚠️「画面不能直接进声音，换张声音卡」 |

**这一步是小白模式的关键分水岭**：从「我连了个线」变成「系统看懂我的意图了」。

## 2. 操作逻辑层：从小白路径倒推（5 步，零学习成本）

### 现状 vs 目标

| 步 | 现状（用户要做什么） | 目标（系统要做什么） |
|---|---|---|
| 1 | 打开左侧面板找节点 | **空画布上直接打字**（一句话开局，已有 `runIntentBreakdown`） |
| 2 | 手动挑节点类型 | 系统从文字**猜类型**，猜错给 3 个候选让你点 |
| 3 | 想不出该连什么 | 系统**自动铺**好下游链（已有 `breakdownDirectorCard`） |
| 4 | 逐个点「生成」 | **一键按序跑**（E1.4 拓扑编排后可行） |
| 5 | 结果不满意 | **同卡片上给3 个具体出路**（换种子 / 改构图 / 换引擎），不教术语 |

### 2.1 「下一步建议」取代「错误提示」

这是**最重要的一条**。ComfyUI 报「Node 5 missing input」，小白要自己翻译；目标形态必须**直接给动作**：

| 场景 | ❌ 专业式提示 | ✅ 目标提示 |
|---|---|---|
| 卡片没有内容 | 「prompt is empty」 | 「写一句你要的画面，比如：雨夜街口，霓虹灯下站着一个人」 |
| 关系冲突 | 「type mismatch: frame → audio」 | 「画面卡不能直接接声音卡，中间隔一张声音卡就行」 |
| 生成失败 | 「HTTP 500」 | 「这个引擎连不上。换本地引擎试试（RTX 4060 可用）」 |
| 不知道下一步 | 空白 | 「还差一件事：给这张卡片写一句描述」 |

**落点**：宿主在每个失败分支附`nextAction: {label, action}`，UI 直接渲染成按钮。

### 2.2 空状态三选项已有，需要强化为「开局即服务」

现状空状态：① 从一句话开始 ② 直接生一张图 ③ 模板列表（5 个内置模板：竖屏短剧 3 场/ 产品展示/情绪板 / MV 节奏板/ 快速生图）。

**优化**：模板区从「列表」改为「**封面卡片网格**」，每个模板给一张预览图 + 一句话说明，**点一下直接铺满画布**（当前需先点再确认）。

## 3. 兼容专业模式：三条并存铁律

| # | 铁律 | 实现保证 |
|---|---|---|
| **1** | **同一份数据**：小白写的字段，专业模式原样可见 | 已满足（`KIND_TEXT_FIELD` 全部是 `node-factory` 真实字段） |
| **2** | **小白不写小白专属字段**：只做**视图降维**，不造影子数据 | `NoviceCard` 不写 `node.data`，只读；`intentDepth` 是唯一可选项且可省 |
| **3** | **专业模式永远是逃生舱**：任何卡住的地方，一键切档位看全图 | 顶部开关已有；建议补「卡住？切专业模式」引导条 |

> 关键：小白模式**不新增节点类型、不新增字段**。它是**同一数据的另一种读法**。这样专业模式永远不用追小白模式的功能债。

## 4. 生态层：让「不写代码的人也能贡献」

ComfyUI 生态靠**程序员写节点**；目标生态靠**会打字的人说配方**。这是生态量的分水岭。

### 4.1 三级贡献阶梯（门槛从高到低）

| 级别 | 贡献什么 | 需要会什么 | 举例 |
|---|---|---|---|
| **L1 配方**（主生态） | 一句话 + 参数 = 可复现流程 | **会打字** | 「古风女主雨夜独行·电影级·9:16」 |
| **L2 卡片** | 新卡片类型（外观 + 参数 + 一句话说明） | 会打字 + 填表单 | 「分镜表卡片」 |
| **L3 节点** | 真正的处理逻辑 | 会 TS | 插件 SDK（已有雏形） |

**结论：生态的主战场是 L1，不是 L3。** 这与 ComfyUI 正好相反，也正是本产品该抢的位。

### 4.2 配方包（L1 的载体）格式

```
配方包 = { 卡片序列 + 图 + 模型引用 + seed + 硬件档位要求 + 说明一句话 }
```

可行性前置条件**已全部就位**：

| 依赖 | 状态 |
|---|---|
| seed 可复现（结果一致） | ✅ P0a/P0b V4.41.10 |
| 硬件档位标注（哪台机器能跑） | ✅ H1 V4.41.11 `hw_tier` |
| 意图契约（关系可校验） | 🔵 E1 设计稿已出 |

**诚实提示**：本地生成**不保证跨机器一致**（DiffSynth/模型版本差异）。配方包必须带 `seed` + `model_id` + `engine`，否则「复现」是假的。

### 4.3 插件生态的契约缺口（承接 E1 设计稿）

现状：`CanvasPlugin` 已有 `{id, name, version, minAppVersion, nodes[], css?, setup?}`，但：
- **缺 `inputs/outputs` 声明** ⇒ 宿主无法校验、无法自动编排
- **示例只有 1 个**（`sticky-note.tsx`）⇒ 没有起跑示范

**最低成本起跑**：先补 3 个官方示例（便签已有一→ 再加「字幕卡」「色卡」），让作者照抄。

## 5. 明确不做的事（防止滑向 ComfyUI）

| ❌ 不做 | 原因 |
|---|---|
| 暴露端口/连线手柄给小白 | 回到显式图，门槛立刻升高 |
| 让用户填 seed / steps / cfg 就能出片 | L3 折叠是「逃生舱」不是「入口」 |
| 无限加节点类型 | 21 种已超小白认知负荷；**优先复用**而非新增 |
| 契约反过来决定吸附位置 | 等于退回显式连线，磁吸价值归零 |
| 把 `left/right` 重新绑成「输入/输出」 | 2026-09-18 已剥离，判定为过度设计 |

## 7. 成功判据（可量化）

| 指标 | 现状 | 目标 |
|---|---|---|
| 首次上手耗时 | 需读文档 | **一句话 → 出图 < 60 秒** |
| 小白完成首个镜头需点击数 | 未知 | **≤ 8 次** |
| 用户需要理解的专有名词 | 22 种 kind 名 | **≤ 5 个**（画面/镜头/声音/故事/素材） |
| 遇到错误时能自己解决比例 | 低 | **> 70%**（靠 `nextAction`） |
| 非程序员贡献的生态内容占比 | 0 | **> 60%**（L1 配方） |

## 8. 待拍板

1. **卡片改名**：是否采用「故事/画面/镜头/声音/批量出图」这套命名？专业模式保持原名不变（两边不同名是刻意的）。
2. **默认档位**：现在是 `pro`（`store.ts:148`）。是否改为**首次进入默认小白**？—— 我倾向**是**，但老用户需保留原档位（按localStorage 判断是否首次）。
3. **配方包起步范围**：先只做「导出/导入」不做市场，还是同步做最小市场？—— 我倾向**先做导出/导入**验证格式，市场等有真实配方再上。
