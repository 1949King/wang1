## 第 1 章 · 产品逻辑：它到底在解决什么问题

### 1.1 一句话定位

**拾光剪影 = PyQt6 桌面端的「短剧精剪 + AI 导演台画布」。**

活路径**只有两条**：
- **剪辑模块**——时间线编辑、预览/播放、导出
- **AI 画布**——导演台节点、生图/生视频、智能体、画布数字人

### 1.2 北极星（这句话是整套架构的源头）

> **竖切可重复：导演台（含数字人）→ 分镜图 → 入轨精剪。智能体只做「确认后执行」的遥控器，不默认一键成片。**

请把这句话拆成三个**刻意的拒绝**来讲——拒绝比承诺更能体现思考深度：

| 它拒绝了什么 | 为什么拒绝 |
|---|---|
| **不做「一键全链路成片」作主入口** | AI 一键成片的质量不可控，用户拿到一个"差不多但没法改"的成片，等于把返工成本转嫁给用户。改成「AI 干 80% 体力活 + 人做关键决策」 |
| **不重写时间线架构** | 真相源永远是 `EditorModule._clips`。推倒重来是新人最容易犯的错 |
| **不换壳**（Wails / tldraw / Dify） | 每个"更好的框架"都要重付一遍学习与迁移成本，而当前架构的瓶颈不在框架 |

**演讲金句**：「**我们不是在做『一键成片』，我们是在做『把 80% 的体力活交出去，把 20% 的决策权留住』。**」

### 1.3 三条主线 = 三种世界观（这是全项目最深的设计洞察）

项目实际有三条并行主线，而**它们的"世界观"是互相冲突的**：

| 主线 | 失败观 | 时间观 | 一致性观 |
|---|---|---|---|
| **剪辑线** | 失败必须**可见**（用户点了没反应 = bug） | 命令栈，帧级可撤销 | 音画 ≈280ms **强对齐** |
| **生成线** | 可以**静默降级**（出片优先） | 无历史 | 可降级出片 |
| **画布线** | 必须**诚实失败**（不假成功） | 图 undo/redo | —— |

**同一个 `except` 该不该 `pass`，三条线的答案完全不同。** 这是所有多人/多模块项目最终都会撞上的墙。

项目的解法**不是统一它们**，而是：

> **不统一三条线，只统一它们的交界处。**（`app/core/glue/policies.py:4-8`）

**演讲建议**：这是全场**最值得讲的一个洞察**。因为大多数工程师的本能反应是"统一它"——而统一三条线 = 三条线全部重写 = 触碰全部冻结区 = 单人带宽下必然烂尾。**"只统一交界处"是一个成熟的取舍，而不是妥协。**

### 亮点 ①　磁吸意图画布 —— 项目的皇冠

这是**整个项目最自研、最没有现成轮子可抄的部分**，也是最能体现"手感工程"的地方。

#### 实现真相

**判据是「边缘间隙（edge-gap）」，不是「中心距」** —— 这是**一次真实的踩坑修正**：

```
MagneticEngine.ts:51-60 注释（原文）：
  「若用中心距，240×200 的卡片并排贴合时中心距已达 240px，
    永远超出 80px 阈值 → 并排吸附根本无法触发。」
```

即：**用中心距做判据，整个磁吸功能会彻底失效**（因为卡片本身就 240 宽，中心距天然大于任何合理阈值）。改正为 `edgeGap()`——取各轴分离量的欧氏距离（`MagneticEngine.ts:61-70`）。

**四级吸附阈值**（`magnetic/types.ts:67-70`）：

| 档位 | 阈值 | 语义 |
|---|---|---|
| `instant` | **10px** | 边对边立刻贴齐（对齐 Win11 磁贴手感） |
| `strong` | **60px** | 强吸附（落座带过冲） |
| `medium` | **50px** | 中吸附 |
| `weak` | **120px** | 弱吸附 |

**咬合（Bond）由几何推导，不落盘**（`bonds.ts:3-5`）：
- 条件①：边距 ≤ `bondTolerance`(2px)
- 条件②：贴合边投影重叠 ≥ `MIN_OVERLAP`(40px)——「只搭一个角不算咬合」
- **不落盘的好处**：刷新 / 重开工程后**自动恢复**，无需序列化、无需迁移

**让位（reflow）三条红线**（`magnetic/reflow.ts:20-27`）：
1. 只推**同一行/列**（对侧轴投影 ≥ 40px，斜对角不推）
2. 链式**只推一格**，绝不递归放大
3. 推动后若撞上**链外紧贴卡** → **整条链放弃**（`blocked: true`）

**拖拽手感的三段式阻力**（`useMagneticDrag.ts:282-301`）：

```
拉力 < 30px  → 完全粘住（give = 0）
30 ~ 50px   → 只跟出 28%（bondGiveRatio = 0.28）
≥ 50px      → 断裂
```

**「跟手浮起」**：拖拽中**绝不覆写卡片位置**（不调 `writeNodePos`），卡片 1:1 跟指针走；松手才走 `animateNodeTo(200ms)` 平滑滑入，强吸附带 `overshootPx(5)` 过冲。设计动机是**消除每帧重建 nodes 数组的卡顿**（`useMagneticDrag.ts:326-343`）。

**意图卡片的分层**：
- `CARD_GEOMETRY` **固定 240×200**（`novice/types.ts:24-38`）——因为磁吸落位基准依赖实尺寸。改成 `minHeight` 后内容会把卡撑到 300px，**高矮不一 + 违反不变量**，故改回 fixed height + `overflow:hidden`
- **意图三层**：`intentDepth` 1/2/3 = 表面层 / 语义层 / 实现层，只允许**改颜色**（`filter` + 描边透明度），**不得改尺寸/加阴影/改圆角**
- **L1/L2/L3 参数分层**：L1 导演参数（常用）→ L2 进阶（折叠）→ L3 专业（再折叠）

#### 这里藏着三个"讲出来就能镇场"的真实 bug 故事

这是**演讲最值钱的部分**——因为细节无法伪造：

**故事 1 · 方向 180° 反转**
`getDirection()` 返回的是「**目标相对拖拽**」的方位，却被直接传给 `getSnapPosition()`——后者的语义是「**拖拽节点该放到目标的哪一侧**」。两者**恰好相反**。后果：目标在拖拽右侧时，卡片吸附到目标**右侧** → 用户反馈「**左右吸附跑到最右、左边吸不上**」。修复：调用前取反（`oppositeDirection`）。

**故事 2 · `levelRank` 漏了一个键**
`levelRank = { none:0, weak:1, medium:2, strong:3, instant:4 }`——某次新增 `instant` 档时**漏了这个映射**，导致 `instant` 被后遍历的 `strong/medium` **静默覆盖**。现象是「**instant snap 时灵时不灵**」——最难查的那类 bug。修复后补了回归测试。

**故事 3 · 守卫常红、git 说没事**
双库校验一直报 `canvasVersion.ts` 分叉，但两文件**逐行相同、解码后 md5 一致**。真因：副库 `core.autocrlf = true` 把索引里的 LF 写成工作区 CRLF，而 `git status` **比较前会归一化**，所以显示"干净"——于是出现「**守卫常红、git 说没事、看不出为什么**」的鬼故事。修复必须**先删文件再 checkout**（`git checkout -f` 无效，stat 缓存让它跳过重写）。

#### 演讲建议

> 「**磁吸这个东西，看起来是视觉效果，实际上是数学。**我们踩过一个坑：用『中心距』做吸附判据，结果**整个功能是死的**——因为卡片本身就 240 宽，并排时中心距天然 240，永远超阈值。改成『边缘间隙』才活过来。**很多时候功能不是没写，是判据错了。**」

### 亮点 ②　Agent 的能力治理 —— 「单一事实源」的工程化

#### 实现真相

**问题**：Agent 能干什么，散落在多处。加一个能力要改一堆地方，漏一处就**静默失效**。

**解法**：`app/core/agent_capability_catalog.py` 的 `CAPABILITY_ROWS` —— **一张表承载 8 列**：

| 列 | 含义 |
|---|---|
| `capability_id` | 能力唯一 id（如 `editor.split_clip`） |
| `category` | extension / model / canvas / editor / workflow / pipeline |
| `effect` | 副作用等级：`read / canvas_write / file_write / media_write / memory_write` |
| `paid` | 是否付费渠道 |
| `description` | 一句话说明（进提示词） |
| `hemisphere` | 脑归属：`right`（创意）/ `left`（逻辑）/ `cc`（胼胝体·混合） |
| `label` | 中文标签 |
| `keywords` | 关键词（左右脑匹配打分） |

**实测：72 条能力**（54 条手写 + 18 条由 `_canvas_node_catalog_rows()` 派生）。
- 分类分布：canvas 29 · pipeline 21 · editor 15 · model 3 · extension 3 · workflow 1
- 副作用分布：read 33 · canvas_write 26 · media_write 8 · file_write 5
- `paid=True` 共 9 条

**这张表是派生的源头**：
- `agent_policy._CAPABILITY_EFFECTS` ← 从表派生（`agent_policy.py:49`）
- `agent_brain._NEURON_TAXONOMY` ← 从表派生（`agent_brain.py:91`）

⇒ **新增能力的唯一入口 = 目录表加一行。**

**但有一个残酷的细节**——能力要真正能被 Agent 调用，需要接**四处**：

| # | 位置 | 职责 | 守卫覆盖？ |
|---|---|---|---|
| 1 | `agent_capability_catalog.CAPABILITY_ROWS` | 元数据单一事实源 | ✅ |
| 2 | `capability_handlers.py` + `dispatcher.register()` | 注册进运行时 | ✅ |
| 3 | `agent_action_registry._AGENT_ACTION_ROWS` | 对话 action 白名单 | ❌ **不覆盖** |
| 4 | `build_agent_actions_help_block()` | 注入 prompt 的参数文案 | ❌ **不覆盖** |

**第 3、4 处守卫不覆盖**（`docs/CHANGELOG.md:1451-1452` 原文标 `★ 守卫不覆盖，漏了 Agent 不会调`）——漏了**不报错、不崩溃，只是 Agent 永远不调它**。这种"静默失效"是工程上最贵的一类缺陷。

**AgentBrain 的神经架构**（`app/core/agent_brain.py`）：
- `Neuron` / `Synapse` 数据结构（`agent_brain.py:44-77`）
- **Hebbian 学习**：`reinforce_path()`——路径相邻对权重更新
  - 成功：`weight = min(1.0, weight + delta)`，`delta = 0.05`
  - 失败：`weight = max(0.0, weight - delta)`
  - 反馈桥按 severity 调 delta：low 0.02 / medium 0.04 / high 0.08
- 参数：`decay 0.7` / 激活阈值 `0.5` / 最多扩散 3 跳 / 上限 500 突触
- 持久化：`MemoryStore`，`category="brain_synapse"`
- **关键纪律**：`suggest_next()` 无数据时**回退 default，拒绝 ε 随机**（`agent_brain.py:398`）——**不搞随机效果**

#### 演讲建议

> 「**我给 Agent 建了一张能力表，72 个能力，加了 8 个字段。这张表是唯一的真相源——策略层的权限判断、脑网络的神经元，都从这张表派生。加一个能力只需要加一行。**
>
> 但我要诚实说一个细节：**光加这一行不够**。它还需要接四个地方，而**其中两个守卫覆盖不到**——漏了不报错，只是 Agent 永远不调它。这是我踩过的坑，所以现在我专门写了静态断言把这两处钉死。」

**这个"诚实说一个细节"的段落，恰恰是最专业的**——它证明你不是在讲 PPT，是在讲代码。

### 亮点 ③　抽卡闭环 —— 把"玄学"变成"账本"

#### 实现真相

**问题**：同一条提示词上次用哪个种子出了好图？**没有任何地方记得，每次都从零抽。**

**解法 A · 抽卡账本**（`app/core/ai/draw_book.py`，321 行）：
- **指纹**：`sha1(kind | 归一提示词 | model | style_tag | size)[:16]`
  - 提示词归一：NFKC + 小写 + 去全部空白
  - `kind` 入键是**有意扩充**——「同 prompt 的图/视频混在一桶会互相污染」
- **值**：分桶 EMA——`均分 mean + 方差 var + best_seed + 最近 20 条样本环形`
  - EMA 更新：`mean += a * delta`，`a = 0.3`
- **新鲜度**：`_STALE_DAYS = 60`——**过期只影响推荐，不删数据**
  > 注释原文：「模型版本、渠道能力、提示词写法都会漂移，60 天前的『这组参数出图 0.9 分』很可能已经不成立。**过期的推荐比没有推荐更糟。**」
- **纪律**：RLock + 原子写（临时文件 + `os.replace`）、**记录失败绝不抛出**、只记 `seed_sent=True` 的种子

**解法 B · 代理评分器**（`app/core/ai/gen_critic.py`，320 行）：
- **五项可测代理指标的加权和**：非崩图 0.35 / 清晰度 0.25 / 尺寸达标 0.20 / 构图中心度 0.10 / 成本信号 0.10
- **崩图闸门**：非崩图分 < 0.2 → 总分封顶 0.3
- **红线**：`is_proxy` **恒为 True**
  > 注释原文：「代理指标，**非审美真值**（项目红线）。任何下游都不得把它当审美真值；它只负责把『崩图/糊图/尺寸错』这类**可证伪的坏**筛出来。」

**闭环三个字段的回写链**：
```
画布发指令 → canvas_aigc.py:847 调 feed_draw_ledger()
   ├─ 先查推荐（recommendation）    ← 用旧数据，不含本次
   ├─ 再评代理分（proxy_score）     ← 本次结果
   └─ 顺带体检（repair_plan）       ← 免费出报告，只报不修
        ↓
App.tsx:789  snake→camel 回写节点数据
        ↓
NoviceInspector.tsx:718  「抽卡闭环」面板渲染
   ├─ 推荐种子 / 均分
   ├─ 代理分（标注「仅供参考」）
   ├─ 坏区数
   └─ 「只修坏区，不重抽整张」按钮（花额度，必须显式点击）
```

**⚠️ 这里有一处必须讲清的区分**（很多介绍会讲混）：

| | `gen_critic.proxy_score` | `five_dimension_scorer` |
|---|---|---|
| 对象 | **单张生成图** | **镜头 / 片段** |
| 量纲 | 0~1 | 100 分制 |
| 五维 | 非崩图/清晰/尺寸/构图/成本 | 画面 25 · 高光叙事 25 · 文案 20 · BGM 15 · 时长 15 |
| 分级 | —— | S≥90 / A≥80 / B≥70 / C≥60，D<60 剔除 |
| 关系 | **两套独立系统，无相互调用** | 同上 |

**`estimated_dims` 是什么**（这是用户曾经质疑的点，很值得讲）：
- 定义在 `five_dimension_scorer`（**不是** `gen_critic`）
- 当某个维度**没有真实评分数据**时，用**基线值 70.0**（C 级合格线）填上，并**登记进 `estimated_dims`**
- 设计动机：保证素材**不因元数据缺失被误判为 D 级**
- 输出 `is_fully_estimated`（当全部维度都是估算）= **诚实标注「这是估的，不是真审美判断」**

#### 演讲建议

> 「**过去抽卡是玄学。同一句提示词，上次哪个种子出了好图？没人记得。**
>
> 我们做了一个『抽卡账本』：把参数指纹和结果质量存下来，下一次给你推荐。而且有一条纪律——**过期的推荐比没有推荐更糟**，所以超过 60 天的记录只影响推荐、不删数据。
>
> 但最重要的一句话是：**我们的评分器恒等于『代理指标』，不是审美真值。** 它只负责筛掉『崩图、糊图、尺寸错』这类**能被证伪的坏**。**审美判断我们不做假。**」

### 亮点 ④　粘合层 —— 全场最有工程思想的一笔

这是我认为**最值得讲**的架构决策。

#### 实现真相

**问题**：三条主线靠**散落的字段字面量**互相看见——`canvas_node_id` / `canvas_kind` / `canvas_title` 在三处硬编码，**无 schema 版本、无校验、无溯源**。任一处的字段改名都会**静默失效**。

**做法**：建一个**纯标准库、零项目依赖**的契约层（`app/core/glue/`）：

| 模块 | 职责 |
|---|---|
| `schema.py` | 跨线字段集合 · 别名表 · 溯源 · `GLUE_SCHEMA_VERSION` |
| `convert.py` | 三向转换（clip ↔ glue ↔ canvas payload） |
| `validate.py` | 桥边界校验 |
| `policies.py` | **三条世界观冲突的显式策略** |

**三条铁律**：
1. **字段名保持原样**——`canvas_node_id` 等被前端与已有工程文件依赖，改名 = 破坏兼容。**契约层的价值在「收拢 + 校验 + 溯源」，不在「重命名」**
2. **只新增不改行为**——由 `_verify/check_glue_contract.py` 的**等价性断言**保证：契约层输出必须与既有实现**逐字段一致**，不等价即失败
3. **契约在桥边界强制**——`canvas_server.py` 的 `/ingest` 与 `/host/timeline-snapshot`（该文件**不在冻结区**，所以**不动前端一行代码**就能给跨线传输上约束）

**三条冲突的消解策略**（`glue/policies.py`）：

**冲突① 失败观** → 把判定线变成**可执行数据**：
```python
SILENT_EXCEPT_UI_WHITELIST       # UI 绘制类，pass 可接受（5 文件）
SILENT_EXCEPT_REVIEW_TARGETS     # 状态机/资源路径，须补日志（8 文件）
SILENT_EXCEPT_FROZEN_PENDING     # 冻结区内，暂不可改（2 文件）
```
`silent_except_verdict(path)` 按顺序判定 → 返回 `ok / needs_log / frozen / ui_heuristic`

**冲突② 时间观** → 声明**唯一合法写入入口**：
```python
TIMELINE_WRITE_ENTRYPOINTS = 6 个（agent_replace_timeline_clips / _apply_action /
                                   _add_clip_to_timeline / batch_add_clips /
                                   _delete_clip / set_clips_writer）
TIMELINE_ASSIGN_ALLOWED = ("app/modules/lego/editor_module.py",)
```
- 动机：跨线写入不收敛到这些入口 → **撤销栈会漏记 → 「画布改了，Ctrl+Z 撤不回」**

**冲突③ 一致性观** → 默认只收完整交付：
```python
ACCEPT_DEGRADED_MAX = 0   # degraded 超过此值一律拒绝（0 = 只收完整交付）
```
- 降级产物须带**显式 `degraded_ack=True`** 才准入，且准入后**自动打标**（`glue_degraded` / `glue_origin` / `glue_lane`）→ 可筛选、可回滚

#### 演讲建议

> 「**这个项目有三条并行的线：剪辑、生成、画布。它们的『世界观』是冲突的。**
>
> 剪辑线要求『失败必须可见』，生成线允许『静默降级』，画布线坚持『诚实失败』——**同一个 except，三条线的答案完全不同**。
>
> 大多数人的第一反应是『统一它们』。但统一三条线 = 三条线全部重写 = 触碰全部冻结区 = **在这个体量下必然烂尾**。
>
> 所以我们做了一个反直觉的决定：**不统一三条线，只统一它们的交界处。**把冲突变成可读、可测、可守卫的**数据**——让每条线保留自己的世界观，只在交叉的那一刻遵守共同规则。
>
> 比如『时间观』冲突：剪辑线用命令栈，画布线用图 undo。我们的解法不是统一撤销机制，而是**声明 6 个唯一合法的写入入口**——所有跨线写入都必须走它们，否则撤销栈会漏记。**这是契约，不是重构。**」

### 亮点 ⑤　「诚实失败」——贯穿全项目的价值观

这不是一个技术点，而是**一条贯穿整个代码库的价值观**，也是**演讲的精神内核**。

#### 实现真相 —— 它在代码里到处留下指纹

| 位置 | 表现 |
|---|---|
| `gen_critic.py:279` | `is_proxy` 恒为 True，「非审美真值（项目红线）」 |
| `five_dimension_scorer` | `estimated_dims` 诚实标注「哪些维度是估的」 |
| `draw_book.py:19-22` | 只记 `seed_sent=True` 的种子（**只记真发出去的**） |
| `agent_loop.py:424-427` | 预算耗尽 → 明说「已执行部分工具，但预算耗尽、未获最终答复」（**不假成功**） |
| `agent_loop.py:397-401` | 工具报错**如实记入** `LoopStep.error`（不包装为成功） |
| `capability_handlers.py`（YuE） | 执行端未配置 → 返回安装指引，「**如实转告用户，不要假装生成成功或改用 Suno 顶替**」 |
| `agent_persona.py:46` | 人格铁律「不说假拟人话」 |
| 数字人节点 | 「口型成片无模型**不假成功**」 |
| 插件接口壳 | `drama_finder` / `account_ops` 能力**诚实失败** |

**最典型的是 YuE 音乐生成**（最近一轮的工作）：
- 官方硬要求 **Linux + Python 3.12 + NVIDIA ≥24GB VRAM**
- 本机是 RTX 4060（8GB）——**跑不动 3B 模型**
- 项目的处理：执行端探测失败 → 返回 `unavailable: true` + **安装指引**
- **绝不**返回占位音频、静音文件，或**静默降级成 Suno**

这条纪律被写进冻结区不变量，并有回归测试钉死：
`test_yue_music.py::test_render_honest_failure_no_fake_audio`

#### 演讲建议

这是**最可能打动听众**的一段，因为它反常识：

> 「我想说一个**价值观**，它贯穿了整个项目。
>
> AI 项目最容易犯的错，是**装作成功**——模型跑不动，就返回一个占位图；音频生成失败，就静默换个云服务。用户拿到一个"看起来能用"的东西，然后在真正要用的时候才发现全是假的。
>
> 我们的规则很简单：**执行端不可用时，必须诚实失败。**
>
> 最近我们接了一个开源全曲生成模型。官方要求 24GB 显存，我的机器只有 8GB——**跑不动**。按很多项目的做法，这里应该『兜底』一个假音频。我们的做法是：**如实返回『执行端未配置』加安装指引**，并且写了一条回归测试，专门验证『绝不返回假音频』。
>
> 因为**『假成功』比『失败』贵得多**——失败你知道要修，假成功你不知道。」

## 第 3 章 · 工程纪律 —— 一个「反熵」系统

这一章是**可信度的来源**。听众会怀疑「这么多功能是不是堆出来的」——纪律体系就是回答。

### 3.1 提交前的六道卡点（`.pre-commit-config.yaml`）

| 卡点 | 拦什么 |
|---|---|
| `ruff` | 静态检查（F811 同名重复定义 / F401 未用导入） |
| **冻结区守护** | **9 zone / 85 锁点的哈希漂移** |
| **稳定性门禁** | 裸 except / 静默 except / product-print / 未定义名（**棘轮：存量入基线，只减不增**） |
| **粘合层契约** | 跨线字段与既有实现不等价 |
| **架构守护** | 分层纪律（UI 层不得写业务逻辑） |
| **双库一致性** | 副库副本漂移（防复漂） |

全量套件更狠：`_verify/run_all_checks.py` **一次跑 57 项检查**。

### 3.2 冻结区 —— 「修好的功能，别手贱改坏」

**9 个 zone / 85 个哈希锁点**：
- `playback-av`（音画同步，纠偏 ~280ms 是冻结值）
- `stage3d-core`（3D 导演台，7 个整文件锁）
- **`canvas-magnetic-intent`（磁吸意图系统，33 个整文件锁）**
- ……

改这些必须：**用户授权「解冻 \<zone-id\>」→ 备份 → 改 → 回归 → `--update` 重锁**。

**演讲建议**：这体现了「**对已修好的东西有敬畏**」。很多项目死在"重构热情"上。

### 3.3 棘轮机制 —— 技术债只减不增

`stability_gate.py` 的设计很聪明：**存量违规录入基线，只减不增**。
- 新违规 → 直接失败
- 存量违规 → 允许存在，但**只能变少**

单文件规模守卫同理：**阈值 2000 行，存量 12 个超标文件冻结为基线，只许减不许增**。

### 3.4 一个反例：守卫为什么会被忽视（这个坑极有讲的价值）

文档里记录了**三种"看起来有守卫、实际没守卫"**的病：

| 病 | 症状 | 真因 |
|---|---|---|
| **噪声淹没** | `stability_gate` 长期红、无人执行 | `SKIP_DIRS` 漏了草稿目录 → **631 项新增违规里 564 项来自草稿** |
| **空转** | `arch_guard.py` exit=0 但一次没扫 | **必须传 `--scan`**，无参只打印 usage |
| **幽灵分叉** | 双库守卫常红、git 说没事 | `autocrlf` 改行尾，`git status` 比较前归一化 |

> **共同点**：这三者都会让守卫**被忽视**——而一个被忽视的守卫，比没有守卫更糟（它给你虚假的安全感）。

**演讲建议**：这段特别能体现「**我不仅写了守卫，还验证了守卫本身有效**」。这是元层次的思考。

❌ 大多数 AI 剪辑工具：  一句话 → [黑盒] → 成片（没法改）
