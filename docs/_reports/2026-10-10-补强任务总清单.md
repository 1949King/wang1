## 2. 分系列明细

### P0 — 立即项（深潜复核新增，一切闭环工作的地基）

**P0a 首流量验收**：`data/draw_book.json` 当前 = `{}`（2 字节）——闭环「代码通电」≠「闭环工作」。
执行：真实跑一次云端抽卡（`canvas.best_of_draw` 或画布生图），亲验 ① `draw_book.json` 落笔
② `proxy_score/is_proxy/recommendation` 字段回传 ③ quality_prior proxy 桶有记录。
**验收**：账本出现首个桶（指纹+EMA+best_seed），推荐第二次抽同 prompt 时回传。

**P0b 本地生图入闭环**：`capability_handlers.py:222` `seed=int(p.get("seed") or 0)` 缺省 0、
不走 `normalize_seed`、不回显、不调 `feed_draw_ledger`——本地双栈是零成本抽卡主力却是账本盲区。
执行：seed 归一化（复用 `draw_ledger.normalize_seed`）+ 回显 + 生成收尾接 `feed_draw_ledger`。
**验收**：本地生图后 draw_book 落账、响应带 seed/proxy_score；`test_local_image_dispatch.py` 补断言。

### S — 编剧生产端（战略 G1：从代工厂到创作公司）

| 刀 | 模块 | 干什么 | 验收 |
|---|---|---|---|
| S1 | `app/core/ai/script_structure.py` | 启发式结构骨架：前 10 秒冲突位/每 30 秒钩子位/集末悬念位/时长预算；输入梗概+题材模板 → 场次大纲 JSON。**零 API 成本纯规则** | 一句话梗概 → 结构化大纲；能力 `pipeline.write_outline` 注册进目录表（唯一入口纪律） |
| S2 | `app/core/ai/screenwriter.py` | 分层生成：梗概→角色卡（**消费角色库 9 人格字段**——当前零消费）→分场→动作→台词；每层人审卡点；MC 排除防台词重复；过 compliance-check | 单集剧本（带台词）人工只改 ≤30% 即可用；「梦浮生」首语料 |
| S2b | `app/core/ai/story_bible.py` | 剧本圣经：世界观/角色档案/**伏笔账本**（埋设-回收-状态机）/连续性检查表；剧本资产入库供导演分解与抽卡 prompt 消费 | 伏笔账本回收率 100%（埋设必有回收记录）；角色库人格字段被真实消费（grep 可证） |
| S3 | 贯通 | S2 输出直喂 `/host/storyboard-breakdown`，剧本→分镜表→入轨全链打通 | **3 分钟单集全链 demo**（2027 Q1 交付物，兼求职作品集） |

**红线**：剧本生成不落 `_clips`（生产端只产文本资产）；Dramatron 教训——专业编剧用它做世界观探索而非一键全本，**人审卡点永远保留**。

### E — 真值裁判（战略 G2：让「哪个更好」说得出口）

- **E2**：真值分**并列一列，不改代理分语义**（`is_proxy` 红线不动）。首选 DiffSynth-Studio
  `diffsynth.metrics`（一站式 PickScore/ImageReward/HPSv2/CLIP/Aesthetic，统一 API）；
  视频侧先只接 VBench `motion_smoothness`/`temporal_flickering` 两维，实测速度如实记录。
  **验收**：验收台同一行能并排看到几何分与真值分；未评估显示「未评估」，绝不算假分。
- **E3**：验收台 UI 五列分（几何/技术/审美/平滑/闪烁）可排序可溯源；KPI 仪表三指标
  （首抽合格率/平均抽卡次数/重抽率）——draw_book 已有全部原料，只差 summary 出口。

### M — 资产母版层（缺口③：角色有档案没照片，场景道具整条空）

- **M1 定妆照**：沿 `voice_id` 先例走**非 schema 资产字段** `portrait_image`（不碰六处同步不变量，
  日后要进提示词派生再升 schema——Q7 决策点）。定妆照本身用 `best_of_draw` 抽卡产生、人选定稿。
  **闭环复用，不造新轮子**。
- **M2 配方包 + 场景/道具卡**：`gen_recipe.py` 把「模型+prompt+style+size+种子集+超参」冻结成
  可命名复用配方 JSON，血缘写进 draw_book——**这是我们对「ComfyUI 工作流」的正确等价物**
  （参考项目 saveOffer 机制同构，见附录）。场景卡/道具卡照角色库模式克隆；注意
  `pipeline.prop_consistency` 道具守护已经在等「握持描述」字段，道具卡一建立刻吃饱。
- **M3 一致性实测**：IP-Adapter（22M 适配器，SD1.5 可跑）第一候选；StoryDiffusion（NeurIPS 2024
  Spotlight）做连拍一致性——⚠️ 官方 low-VRAM 测试机 24GB，8GB 需实测，**不实测不进能力目录**。

### G — 审美治理（缺口④：把审美从玄学变成验收单）

- **G1 规则引擎 v0**：20 条可编程剪辑语法检查——Murch 六法则加权（情绪51/故事23/节奏10/视线7/
  平面5/空间4）、跳轴提示级检测、正反打覆盖检查（B0 词级绑定有原料）、镜头长度单调告警、
  BGM/对白响度冲突（音频 DSP 8 件套现成）、字幕行宽/驻留、黑场/静帧。**零成本纯规则，先做**。
  开工时出逐条清单过审（Q8 决策点）。
- **G2 成片体检报告**：每集导出自动生成——规则违规清单+评分雷达+**ASL 节奏曲线**+
  **moviebarcode 色彩条码**（百行实现：ffmpeg 抽帧+PIL 均值条，体检报告里最「像产品」的一页）+
  **桌宠「拾岚」审片播报**（状态机五态现成，报告出来换表情——用户点名采纳，差异化彩蛋）。
- **G3 ASL 基线**：用拉片 L1 批量统计真实爆款平均镜头长度分布，给「节奏」数据基线而非形容词。

### A1 它的生成架构：五通道 provider + ComfyUI 深度集成 + 本地 ONNX 后处理

**① 五条生成通道**（`src/services/ai/generateImage.ts:132-267` 的 provider 分支）：

| 通道 | 性质 | 说明 |
|---|---|---|
| `dreamina` | 云 | 即梦（字节系） |
| `general` | 云 | OpenAI 兼容通用渠道 |
| `volcengine` | 云 | 火山引擎 |
| `runninghub` | **云 ComfyUI** | 在云平台上跑 ComfyUI 工作流——**不用本地显卡** |
| `localllm` | 本地 | 本地 LLM（Ollama 类） |
| ComfyUI 工作流路径 | 本地/自建 | `generateImage.ts:145-148`：走 `executeComfyUIGenerate`，参考图由 ComfyUI 自己的 `/upload` 收 |

**② ComfyUI 深度集成四件套**（它的招牌，与我们的差别所在）：
- **工作流库**（`comfyWorkflowService.ts`，1289 行）：导入/校验/执行/IO 节点提取
  （`IO_TYPE_RULES` 正则识别 LoadImage/CLIPTextEncode 等入口）；
- **AI 助手动态生成工作流**（`comfyAgentService.ts:1-6`）：助手生成的工作流必须先按当前实例
  `/object_info` 完整校验，换**短期任务绑定的 validationId**（10 分钟 TTL）才能进执行工具——
  **「先校验再执行」的安全门设计**；
- **独立窗口编辑回传**（`comfyUIWindowService.ts:172-259`）：Tauri `open_comfyui_window` 把
  ComfyUI 开成独立 WebView 窗口，改完经 Tauri event 桥回传工作流库（含「缺节点提前报错」
  的防御：`findMissingNodeClasses`）；
- **轮询+关窗恢复**（`comfyPolling.ts` + `pollManager.ts`）：同一套轮询供实时生成与
  关窗后任务恢复复用。
- **内置工作流播种**（`builtinWorkflows.ts:41-78`）：内置的全是 **MiniMax H3 云模型**的
  ComfyUI 工作流（文生视频/图生视频/参考生视频，各带 Turbo 加速版）——即**云端模型也走
  ComfyUI 工作流形态**，ComfyUI 在它那里是「生成插座」而非「本地显卡专用」。

**③ 本地推理只有 ONNX 后处理**（`onnxService.ts:48-53`）：模型注册表仅两个——
Real-ESRGAN x4（超分）+ RMBG-1.4（抠图），Rust 侧 ONNX Runtime 跑；角色 8 向宫格是纯切图
不跑模型（`:201-208`）。**它本地不跑任何生成模型**。

### A2 与拾光剪影的对照（解释「咱们参考了什么、走了什么不同的路」）

| 维度 | AI-Canvas-tauri | 拾光剪影 |
|---|---|---|
| 生成主力 | **云 API**（五通道 provider） | **本地引擎主选**（DiffSynth 主备制，paid=False 零调用费）→ 云 16 家兜底加速 |
| ComfyUI 角色 | 产品形态核心（工作流库+动态生成+独立窗口） | 供给侧生成引擎之一（comfy_provider + `/host/comfyui/run`） |
| 本地推理 | 仅 ONNX 后处理（超分/抠图） | **双栈生图引擎**（DiffSynth+diffusers，SD1.5/SDXL）+ whisper 等 |
| 工作流复用 | 工作流库 + **saveOffer**（AI 生成后提供「保存为可复用工作流」的提议，`comfyAgentService.ts:71-83`） | 待建 `gen_recipe.py` 配方包（M2）——**saveOffer 就是它的产品形态参考** |
| 安全门 | validationId 短期任务绑定（10min TTL） | 三档审批 + 白名单 + dry_run 计划确认（异曲同工，我们的更保守） |

**结论**：两者是**同构的混合算力架构**（本地+云多通道+本地 LLM），但取向相反——
参考项目「云为主、ComfyUI 为工作流插座」；拾光剪影（用户裁定的定位起源）「**本地大模型为主
（ComfyUI 同思路）、云 API 兜底+加速**」，在图像域走得更激进（本地双栈零调用费是刻意设计）。
这与 ComfyUI 边界辨析（策划案 §3）互相印证：**拾光剪影与 ComfyUI 的根本差异不在算力路线
（同是本地优先），而在产品形态——面向结果的导演台 vs 面向过程的节点工具**。

### A3 值得抄的三件事（进任务清单的依据）

1. **saveOffer 机制** → M2 配方包的产品形态：AI 生成结果出来时，附一个「保存为可复用配方」
   的提议（60min TTL），用户点头才入库——**比自动入库克制，符合「确认后执行」哲学**。
2. **validationId 短期任务绑定** → 画布动态工作流（若未来做）的安全门范式：先按当前实例
   `/object_info` 校验、换短期 ID 才能执行，防「生成的工作流引用不存在的节点」。
3. **关窗任务恢复**（pollManager）→ 我们的异步任务体系（agent 异步任务已有）可对照：
   长任务的「UI 重启后还能找回结果」体验值得对齐。

### A4 顺带核实（诚实记录）

参考项目 **本地不跑生成模型**——它不是「本地大模型为主」的范本；拾光剪影「本地优先」定位
比它更彻底。用户印象中「参考项目 = 本地大模型跑」的部分，对应的是它的 **ComfyUI 深度集成
形态**（可接本地 ComfyUI 服务，`comfyUIUrl` 任意配置）与 **localllm 通道**，而非它的默认主力。
