# AI 生成质量守护方案

> 四个高频问题（配音漂移 / 表情夸张 / 人物漂移 / 武器畸形）的**统一解法**：
> 生成前 LLM 约束 + 生成后质检回读 —— 把「一次性生成」改造成「闭环生成」。
> 日期：2026-09-20 · 状态：**问题 1 已落地**（`pipeline.tts_polish`，V4.32.7），问题 2/3/4 待落地。
> 口径：所有「现状」结论均取自本地实际代码（file:line 已标注）。

---

## 0. 结论

四个问题**病根同一个**：**AI 生成是黑盒 —— 一次性吐出结果，中间插不上手，事后没人检查**。

解法也是同一套：**两道防线**（生成前约束 + 生成后质检回读），不合格就**定向重试**。

| 问题 | 生成前（LLM 约束） | 生成后（质检回读） | 落地 |
|---|---|---|---|
| **① 配音长文本漂移** | 语义切段 + 多音字注音 | ASR 回读比对字幕，不一致重试 | ✅ V4.32.7 |
| **② 脸部表情夸张** | 表情幅度约束 / 权重钳制 | 超限帧/维度/跳变质检 | ✅ V4.32.9 |
| **③ 人物形象漂移** | 角色提示词卡 + 参考图锚定 | 特征指纹漂移检测 + 镜头漏拼校验 | ✅ V4.32.8 |
| **④ 手持武器结构畸形** | 结构约束 + 握持描述 | 手部关键点规则 | ✅ V4.33.0 |

## 1. 四个问题诊断（证据）

### 1.1 配音长文本漂移（用户核心痛点）

**现象**（用户实测，指向性极强）：15 秒片段正常；时长一长，**前面正常、后面发音错 / 与字幕不符**。

**根因**（不是多音字随机错，而是两类长文本病）：
1. **长文本 TTS 注意力漂移** —— 自回归 TTS 在长序列上累积误差，前半段稳、后半段糊；
2. **文本-音频对齐错位** —— 长音频累积时间误差，使「字幕在第 N 句、音频播第 N-1 句」。

**项目现状**：
- `app/core/voice_generator.py` `_generate_tts_audio` —— 整段文本直喂 gTTS / edge-tts / Coqui，**零分段、零消歧**；
- `app/core/canvas_aigc.py:1035 generate_audio_via_host` —— 云端 TTS 同样 `"input": prompt` 整段直喂。

### 1.2 脸部表情夸张

**现象**：鼓腮生气时腮帮变化过于剧烈，不符合人体机能。

**根因**：AI 生成的表情权重失控（黑盒）。

**项目现状**：3D 角色无表情 blendshape ——
- 素模 `vendor/shiguang-canvas/src/riggedHumanoid.ts:1949` 头部 = skull + 双眼 + 鼻子 + 头发，**无嘴无腮**；
- GLB 路径 `loadGLBRiggedHumanoid` / `prepareBodyFigureMeshes` **无 morphTarget 处理**。

### 1.3 人物形象漂移（跨镜头角色不一致）

**现象**：同一角色在不同镜头/片段长相不一致。

**根因**：生成模型缺乏「角色身份保持」能力。

**项目现状**：已有**角色库**（`character_management_module.py` + `CHARACTER_FIELD_SCHEMA` + `canvas_bridge.build_character_prompt`），
且设计上**只让 `visual` 组字段进提示词** —— 这正是现成的「角色提示词卡」基础设施。Stage3D 演员还带 `promptHint`。

### 1.4 手持武器结构畸形

**现象**（用户实图诊断，**关键**）：手持长杆武器在握持处长出「**一横一竖**」的 **三通 / T 形交叉结构**，
本应是连续贯通、无分支的长杆。

**根因**：① **结构拓扑错误（主症）** —— 生成模型对道具结构缺乏约束，凭空长出多余分支；
② **手-道具接触畸形（次症）** —— 手指与武器融合、武器穿过手。

**项目现状**：生视频走云端 API（`generate_video_via_host`），**无结构约束、无手部关键点检测**。

## 2. 统一框架：两道防线

```
用户意图 → [生成守护] 生成前约束（LLM）→ AI 生成 → 生成后质检（LLM/ASR/视觉）
                    ↑                                      │
                    └────────── 不合格：定向重试 ←─────────┘
```

**为什么「大模型挂载」能解决**：
- 生成前约束 = **语义层**（LLM 的强项：切段、注音、写角色卡、约束表情幅度）；
- 生成后质检 = **回读比对**（ASR 文本比对、人脸相似度、手部关键点）—— 误差可定位到「哪一段」，只需重生成那一段。

## 3. 本轮落地：`pipeline.tts_polish`（问题 ①）

### 3.1 核心模块 `app/core/ai/tts_guard.py`（纯函数 + LLM 可注入）

| 函数 | 职责 |
|---|---|
| `segment_text(text, max_chars=40)` | 按句读边界切长台词；**不变量**：拼接去空白 == 原文去空白（不丢字） |
| `detect_polyphones(text, llm)` | LLM 多音字消歧；llm 缺失/抛错/返回非 JSON → 返回 `[]`（诚实降级，**绝不瞎猜读音**） |
| `build_ssml(text, polyphones)` | 转 SSML `<phoneme>` 标注 |
| `diff_readback(asr, original)` | ASR 回读比对；去标点后算相似度（ASR 不加标点） |
| `verify_segments(asr_texts, originals)` | 逐段质检，返回需**定向重生成**的段下标 |
| `plan_tts(text, max_chars, llm)` | 统一入口：切段 + 注音计划（只出计划，不改数据） |

**纪律**：只读只出计划、不 import app 包（可脱离 Qt 单测）、失败诚实降级。

### 3.2 四处接线（按 `agent-capability-wiring` 技能）

| # | 文件 | 改动 |
|---|---|---|
| 1 | `app/core/agent_capability_catalog.py` | `CAPABILITY_ROWS` 加 `pipeline.tts_polish`（effect=read） |
| 2 | `app/core/capability_handlers.py` | `PipelineCapabilityHandlers.tts_polish` + `register_builtin_handlers` 注册 |
| 3 | `app/core/agent_action_registry.py` | `_AGENT_ACTION_ROWS` 加 `tts_polish`（★ 守卫不覆盖） |
| 4 | 同上 | `build_agent_actions_help_block` 补参数说明（★ 守卫不覆盖） |

### 3.3 用法

```json
// 只切段 + 注音
{"text": "……长台词……", "max_chars": 40, "use_llm": true}

// 切段 + 注音 + 回读质检
{"text": "……", "asr_texts": ["第一段回读", "第二段回读"]}
```

调用方拿到 `segments` 后**逐段调 TTS**（而非整段喂），即可消除长文本漂移；
`readback.retry_indices` 告诉调用方**只需重生成哪几段**。

### 3.4 验证（V4.32.7 实测）

| 项 | 结果 |
|---|---|
| `_verify/check_tts_guard.py` | **44/44 全通过**（切段不丢字 / 脏数据容错 / LLM 降级 / 回读质检 / 四处接线静态断言） |
| 手工三向一致（catalog ↔ dispatcher ↔ action 白名单） | **8/8**（含守卫不覆盖的第 3/4 处） |
| `run_all_checks.py` | **22/22 全通过**（含 AGENTMAP） |
| 冻结区守卫 | `OK frozen zones intact (85 locks)` |

> 开发中由验证脚本抓出并修复一个真缺陷：LLM prompt 模板里的 JSON 示例大括号被 `str.format`
> 当占位符解析抛 `KeyError`，被 except 吞成「降级」——接真 LLM 时注音会**静默失效**。已改 `str.replace`。

## 4.5 深度优化（V4.33.1）

四个守护落地后做了一轮深度优化 —— 两类债：**四份重复代码** + 各模块的「浅」处。

| 优化 | 内容 | 解决什么 |
|---|---|---|
| **抽共享基座** | 四模块的 `_norm` / 指纹 / `diff_*` 曾在各自文件里重复实现（改一处要改四处，违背 SSOT）→ 收敛到 `guard_base.py`；对外接口与行为**完全不变** | 可维护性 |
| **统一门面** | 新增 `guards.py` + 能力 `pipeline.guard_all`：`plan_guards` 一次跑多守护、`guard_negative_all` 合并全量负面词 | 生成时**一次拼齐约束** |
| **tts 批量消歧** | 多音字消歧由逐段调 LLM（N 段 = N 次）改为**一次批量调用**（带 `index` 回填） | 省 token/延迟；跨段上下文更准 |
| **表情轨稀疏化** | `sparse_frames` 关键帧稀疏化（保首尾、只在变化处留帧） | 给下游渲染/传输瘦身 |
| **多角色批量** | `plan_multi_anchor` 一次建多张卡 + 跨角色冲突检查（同名 / 同指纹） | 揪「复制粘贴未改」类错误 |
| **双持武器** | `prop_guard` 支持 `hand="dual"` + `off_prop_type`，主副武器**各自**写结构约束 | 双持最易「长成一团」 |

验证：6 个 check 脚本共 **237 checks** 全通过 · 三向一致 **37/37**（五能力）·
`run_all_checks` **22/22** · 冻结区 `85 locks`。

## 4.6 挂进生成管线（V4.33.2）

比 §4.5 更深的一步：**守护从「Agent 工具」变成「管线守门人」** —— 不再需要谁主动调用。

| 时机 | 接入点 | 做什么 |
|---|---|---|
| 生成前 | `_gen_prompts` → `enhance_prompt` | 自动注入角色卡 / 道具结构 / 表情幅度约束 |
| 生成后 | `_inspect` 之后 → `_guard_inspect` | 守护质检（规则层 + **LLM 层**），问题并入 `issues` 走同一条回溯 |
| 修订 | `_revise_prompt(guard_hint=)` | 合并守护的明确 avoid 提示（80→160） |

**LLM 联动**：
- `guard_pipeline.make_llm()` —— 把项目 `ai_engine.chat_with_fallback` 包成守护需要的 `(prompt)->str` 回调；
- `augment_inspection` 的 **LLM 层**让大模型**针对守护维度聚焦审核**
  （角色一致性 / 表情幅度 / 道具结构 / 手部），比管线原有泛泛「穿模 / 畸形」初检更精准。

**接入方式**：全部用**可选参数** `guards=None` —— 不传时行为与接入前完全一致（零破坏）。

> 由测试抓出并修复：`enhance_prompt` 在空提示词时会以 `" | "` 开头（污染下游）。
