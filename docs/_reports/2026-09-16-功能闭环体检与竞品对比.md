## 一、结论先行（TL;DR）

1. **三段主链路「画布 → 剪辑 → Agent 贯通」全部闭环**，且是当前赛道里唯一「桌面端 + 真剪辑器」三段全接通的——这是结构性差异，不是功能数量差异。
2. **闭环的短板不在「缺链路」，而在「体验黑盒」**：画布生成是同步阻塞（挂起 1–3 分钟无进度）、已入轨无回标、失败节点无重试——三处已在 09-14 迭代表里立项（P1b/P3/P4）但**尚未落地**。
3. **代码健康度出现两处反向回潮**：`except: pass` 249→**261**（+12）、裸 `print` 729→**829**（+100），`editor_module.py` 8,563→**9,258**（+695 行）。撞了「只许降不许升」红线，需在下轮优先收敛。
4. **竞品维度真正该补的三样**（对照第一梯队）：**本地一键拉片**（我们本机隐私优势，云端竞品做不了）· **脚本→分镜→画布自动落地** · **对外 Agent 接口（Skill/CLI）**。多人协作/社区属云化路线，与本项目「本地优先」定位冲突，**不建议跟**。

## 五、竞品对比（对应赛道，实读报告口径）

### 5.1 剪辑 vs 剪映（N 轨）

| 维度 | 剪映 | 拾光剪影 | 差距 |
|---|---|---|---|

| 多人协作 | ✅ | ✅ 团队版 | ✅ | ❌（本地定位，不做） |
| **与真剪辑器闭环** | ✅ 剪映 | 内置合成 | 内置导出 | ✅ **本机剪辑器** |

### 5.3 定位结论

- **重复度最高对手 = 小云雀**（字节/剪映系，60 亿播放），资源量级不同，不拼规模。
- **唯一结构性差异 = 本地优先 + 真剪辑闭环**。云端三家短板是「重生成、轻精剪」，我们恰恰有真剪辑器。
- **可复用的对手「灵魂功能」**：LibTV 的脚本节点、TapNow 的一键拉片 + 非破坏性编辑、小云雀的录制运镜。这三样里**只有「一键拉片」完美契合本地定位**（参考片不上传，规避 IP 风险）。

## 六、可加入的创新功能 + 体验提升（分优先级）

### 6.0 判断原则

- **本地优先是护城河**：只加「素材不出机」能兑现的能力；云化功能（协作/社区）与定位冲突，不做。
- **先补体验黑盒，再上创新功能**：三处画布体验短板（进度/入轨标/重试）成本低收益大，先做。

### 6.1 P0 · 体验黑盒补洞（低成本高收益）

| # | 功能 | 说明 | 落点 |

| E2 | 已入轨回标 | 入轨后画布源节点显示「已入轨」徽标，撤销则清除 | `editor_canvas_link.py` → 前端事件 |

## 七、待提升清单（诚实，全部代码实测）

1. **体验黑盒**（最痛）：画布生成无进度、无入轨回标、无失败重试 —— 三处已在 09-14 立项，仍未落地，**是本轮最该补的**。
2. **代码健康度两处回潮**：`except:pass` +12、裸 `print` +100，撞「只许降不许升」红线。
3. **`editor_module.py` 回胖到 9,258 行**：拆上帝类需重启（Top 函数 252/1,021/773 行）。
4. **一键粗剪写 `_clips` 仍缺**：画布/Agent 产出到「可一键铺进时间线」还差最后一步。
5. **脚本→分镜→画布只到「部分」**：`breakdownStoryboard` 未走通「拆卡→平铺画布→批量生图」全链。
6. **无对外 Agent 接口**：Agent 四轨齐全但无 Skill/CLI 出口（对照 LibTV 是明确短板，但非短期刚需）。

## 八、一句话总结

> **链路都通了，差的是「最后一公里体验」和「一处健康度回潮」**：先补画布生成进度/入轨回标/失败重试三处黑盒，再还 `except:pass`/`print` 两笔红线债，然后上「本地一键拉片」这个既能拉开与云端竞品差距、又完全契合本地定位的创新功能。
