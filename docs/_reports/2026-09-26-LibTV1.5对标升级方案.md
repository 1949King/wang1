# LibTV 1.5 对标升级方案

> 对标对象：LibTV 1.5 官方宣传的五个独家功能升级（截图来源：LibTV 官方账号 2026 年 9 月发布）
> 盘点范围：`app/`（Python/Agent/剪辑）+ `vendor/shiguang-canvas/`（画布/3D 舞台）
> 证据纪律：本文所有「现状」结论均取自本地实际代码，标注 `文件:行号`，可用作核对清单
> 编制日期：2026-09-26 · 冻结区基线：85 locks（`python scripts/frozen_zone_guard.py` → OK）

---

## 0. 一页结论

**LibTV 1.5 的五件事，拾光剪影已有四件半的零件，但缺三根"连接线"。**

| # | LibTV 1.5 升级点 | 拾光剪影现状 | 差距定性 | 优先级 |
|---|---|---|---|---|
| 1 | 角色造型 · 沉淀可复用角色资产 | 20 字段角色库 + 提示词派生 + 跨镜头锚定（**比 LibTV 更深**），但**存不了任何形象图** | **缺资产本体**（只有文字，没有可复用视觉件） | P0 |
| 2 | 原创编剧 · 从想法到剧本，局部改联动全文 | 拆镜/机位/合规/重锚引擎都有，但剧本节点是**纯文本框** | **缺生成入口 + 题材层模板** | P1 |
| 3 | 导演分身 · 可调用的导演能力 | 拆镜/写词/批量三件**都有实现**，Skill 已注册进工坊 | **最后一公里断链**：结果不落时间线；且不是一等能力 | **P0** |
| 4 | LibTV 3D-BOX · 不会建模也能开机 | 5 体型内置人偶 + 姿态重定向 + ControlNet/BVH 导出（**已超过 LibTV 宣传口径**） | **缺与角色库/时间线的接口** | P2 |
| 5 | 成片精修 · 选一帧设计创意片头 | 「选帧」有技能但**选帧策略是假的**（取中间帧）；标题原语有 | **缺选帧判据 + 片头设计器** | P1 |

**一句话战略判断**：LibTV 走的是「**云端 Agent 全包，用户侧只做传话**」（见 `_comfy_compare/libtv-skills/skills/libtv-skill/SKILL.md:221`「用户侧不做创作，只做传话」）；拾光剪影的定位是「**我才是创作者**」。⇒ **不要接 LibTV OpenAPI 代替自己的创作链路**，只对标它的**产品形态**，不搬它的**架构哲学**。

## 1. 逐条对标：LibTV 1.5 上了什么 vs 项目有什么

### 1.1 角色造型 · 塑造专属主角，沉淀可复用角色资产

**项目已有的（比 LibTV 讲得更深）**

| 能力 | 证据 |
|---|---|
| 20 字段角色库，且**按流向分组** | `app/modules/lego/character_management_module.py:55` `CHARACTER_FIELD_SCHEMA`；分组语义见 `:41-49`（`visual` 进提示词 / `inner` 供剧本一致性、**刻意不进提示词**） |
| 角色库持久化 + 导入导出 | `:107` `CharacterStore`（`library.json`），`:204 export` / `:214 import_file` |
| 提示词派生（单一来源） | `app/core/canvas_bridge.py:306` `build_character_prompt` |
| 角色库 → 画布 | `app/core/canvas_server.py:499` `/host/characters`（`:520` 附派生 `prompt`，裁剪为 `CharacterEntry`） |
| 画布侧绑角色到分镜 | `vendor/shiguang-canvas/src/store.ts`：`bindCharacterToShot` / `syncCharacterToShot` / `bindCharacterFromShot` |
| **跨镜头防漂移**（LibTV 未提） | `app/core/ai/character_anchor.py:230 plan_anchor` / `:278 plan_multi_anchor`；能力 `pipeline.character_anchor`（`agent_capability_catalog.py:206`） |

**缺口（实测）**

1. **角色库存不了形象图**。`CHARACTER_FIELD_SCHEMA` 20 个字段中**没有任何 image / 立绘 / 参考图字段**；`CharacterStore` 只读写 JSON（`:138 _save`）。⇒ 「沉淀可复用角色资产」在项目里只沉淀了**文字**，没沉淀**视觉件**。这正是 LibTV「角色造型」的卖点。
2. **画布绑角色丢字段**（已识别的静默缺陷，未修）：`docs/_archive/knowledge/19-canvas-design-review.md:225` P0-2 — Python 侧 `build_character_prompt` 用 visual 组 **4** 字段，画布 `store.ts::bindCharacterToShot/syncCharacterToShot` **只拼 `[角色外貌: appearance]`**，`temperament`/`memory_anchors`/`personality` 被丢掉。而 `memory_anchors`（标志性符号）恰恰是跨集一致性的关键锚点。
3. **「参考图自动注入提示词」缺失**（上一轮 `docs/_reports/2026-09-21-鲸影插件对照学习报告.md:91` 已点出，仍未落地）。

### 1.2 原创编剧 · 从想法到剧本，局部修改联动全文

**项目已有的**

| 能力 | 证据 |
|---|---|
| 剧本 → 分镜（启发式 / LLM 双路） | `app/core/canvas_aigc.py:2458 storyboard_breakdown`（`use_llm` 可选，`:2468` LLM 分支明确要求「严格按剧本原文拆解，不要润色」） |
| 分镜 → 机位 + 运镜路径 | `:2636 storyboard_to_camera_plan` + `:2528 _SHOT_SIZE_CAMERA_PRESETS` + `:2566 _build_camera_path` |
| 已接线到后端 | `app/core/canvas_server.py:2019` `/host/storyboard-breakdown`、`:2033` `/host/storyboard-camera-plan` |
| 画布剧本类节点 | `src/nodes.tsx:345 ScriptNode`；`src/storyNodes.tsx` `StoryboardNode`/`ShotlistNode`/`MarkdownNode` |
| **剧本合规守护**（LibTV 未提，项目独有） | `canvas_server.py:427` / `:1165` `/host/compliance-check` |
| 剪辑动作 DSL（20 条，已实测计数） | `app/core/llm_editor.py:83-178`（`add_clip`/`remove_clip`/`move_clip`/`trim_clip`/`split_clip`/`duplicate_clip`/`add_track`/`remove_track`/`add_transition`/`add_effect`/`remove_effect`/`add_subtitle`/`add_title`/`change_speed`/`adjust_volume`/`replace_audio`/`add_marker`/`add_keyframe`/`ripple_delete`/`undo`） |
| 「局部改 → 联动」引擎 | `app/core/dialogue_anchor.py:179 plan_reanchor`；能力 `editor.reanchor_clips`（`agent_capability_catalog.py:154`，语义「按新台词重锚片段」） |

**缺口（实测）**

1. **ScriptNode 只是纯文本框**：`src/nodes.tsx:345-354`，placeholder 是「双击撰写剧本大纲…」，`EditableText` 直写 `content`。**没有**「从一句话生成剧本」入口，**没有**大纲→分集→分场，**没有**题材选择。
2. **缺题材层模板**。截图里的「#3 末世生存基建 / #7 重生复仇爽剧 / #4 非遗国潮视觉 / #8 仙门团宠日常」属**题材设定层**（世界观 / 主线 / 人设 / 禁忌）。项目现有 `vendor/shiguang-canvas/public/prompts/shiguang-drama.json` 只有 **8 条**，且全是**分镜/风格层**（开场俯拍 / 正反打 / 蒙太奇 / 定妆三视图 / 情绪特写 / 追逐手持 / 闪回滤镜 / 多机位会议桌），**题材层为零**。
3. **「局部修改联动全文」在剧本层缺失**。`plan_reanchor` 是**剪辑层**的重锚（改台词 → 挪片段），不是**剧本层**的联动（改一句设定 → 标记受影响的场次/分镜）。这两层目前没打通。

### 1.3 导演分身 · 可调用的导演能力，帮你拆分镜、写提示词、批量推进

**LibTV 说的三件事，项目**三件都有实现**：**

| LibTV 动作 | 项目实现 | 证据 |
|---|---|---|
| 拆分镜 | ✅ | `canvas_aigc.py:2458 storyboard_breakdown`；画布 `src/mediaExtraNodes.tsx:189 breakdownStoryboard(script)` |
| 写提示词 | ✅ | `src/shotCamera.ts:56 buildCameraPromptBlock`（景别/水平环绕/俯仰/焦段/光圈/运镜 → 提示词片段） |
| 多角度批量 | ✅ | `src/shotCamera.ts:85 multiAngleBatch`；`:23 MOVEMENT_OPTIONS` 9 种运镜 |
| 批量推进 | ✅ | `/host/video-batch`（`canvas_server.py:1618`，含 V2 多机位编排 + V3 完整时长）；`/host/batch-to-timeline`（`:1838` 批量结果回填时间轴） |
| 剧本→一堆分镜卡 | ✅ | `mediaExtraNodes.tsx` `DirectorCardNode`：`:189` 拆解 → `:196 planStoryboardCameras` → `:201 breakdownDirectorCard`；节点类型见 `stores/node-factory.ts` 的 `director` / `directorCard` |
| 完整导演流水线 Skill | ✅ | `app/modules/lego/director_skill.py:27 DirectorSkill`（剧本→分镜→剪辑指令→字幕→3D 片头→导演报告），`:46 _setup_steps` 六步 |
| Skill 已接线 | ✅ | `app/modules/lego/video_editing_skill.py:441-455 register_skills()`（注册 5 个，含 DirectorSkill）；调用点 `app/main_qt6.py:546`；UI 在 `app/modules/lego/extensions_module.py:426` Skill 工坊 |

**两个真断点（这是本次对标最值钱的发现）**

1. **导演分身跑到最后一步断了 —— 结果不落时间线。**
   `director_skill.py:442` 明写 `"edit_instructions_applied_to_timeline": False`；
   `:469` 摘要输出「（仅供参考，未自动应用到剪辑时间线，需手动剪辑）」。
   ⇒ LibTV 说「**批量推进**」，项目这边止于**出一份报告**。而项目**早有落时间线的通路**（`llm_editor.py` 的 17 条动作 DSL 能直接改时间线），只是 `DirectorSkill` 自造了一套 `{"clips":[{start,end,track,source,transition}]}` 格式，两边**格式不通**。

2. **导演分身不是"可调用的能力"，只是一个整体 Skill。**
   `agent_capability_catalog.py:73` 的能力表里，导演相关只有 `ext.run_skill`（`:77`，泛化技能执行，关键词含"导演"）。**没有** `pipeline.director_breakdown` / `director_prompts` / `director_batch` 这类**可被 Agent 单独调用**的能力。⇒ 对话面说"帮我把这集拆成分镜"时，Agent 无法精确路由到拆镜这件事，只能整包跑 Skill。

### 1.5 成片精修 · 选一帧画面，设计属于这部作品的创意片头

**项目已有的**

| 能力 | 证据 |
|---|---|
| 选帧 → 封面 Skill | `app/modules/lego/video_editing_skill.py:306 CoverGeneratorSkill`（`skill_id = "cover-generator"`） |
| 关键帧候选（按真实时长比例） | `:342 _extract_keyframes`（`:355` 取 20% / 50% / 75%；`:363 _probe_duration` 用 ffprobe 读真实时长，已修过"写死 10/25/40s"的老 bug） |
| 真落盘生成封面 | `:401 _generate_cover`（注释记录了"此前只塞路径就 success=True"的假成功修复） |
| 标题/字幕/关键帧原语 | `llm_editor.py:140 add_title`、`:135 add_subtitle`、`:168 add_keyframe` |
| 3D 片头（可选步） | `director_skill.py:370 _render_3d_intro`（Blender MCP，`:363 _should_use_blender` **默认 False**） |

**缺口（实测）**

1. **「选帧」是假的**。`video_editing_skill.py:376 _analyze_content` 自认占位：`:387-391` 三个值都写成「未识别（未接入CV模型，占位值）」，`:391 "is_placeholder": True`，`:394` 选帧策略是「取候选中间的一帧」。⇒ 不具备"选**最好**的一帧"的能力。
2. **「片头」在全库只是标签和时间线位置，不是功能**：
   - 素材语义分类里只是一个正则分支：`src/localLibrary.ts:196` `/封面|海报|cover|poster|标题卡|片头/i`
   - 剪辑器里只是时间线方位：`clip_widget.py:793`「片头吸附」、`timeline_widget.py:237`、`editor_timeline_tools.py:191`、`editor_module.py:5637`
   ⇒ **「从选中的一帧 → 设计版式/文字/动效 → 回填时间线」这条链没有中间连接器**。
3. 唯一的"片头生成"走 **Blender MCP 外部进程**（`director_skill.py:376-380`），且只渲染**一张 PNG**（`:395 render_scene → output_path`），不是可用的片头视频；连接失败即跳过（`:381-385`）。这与项目"离线可用"原则冲突。

## 2. 升级清单（按"先接断点，再补缺口"排序）

> 原则：**只补连接线和缺口，不推翻现有设计**。所有升级都优先复用已有函数。

### P0-1 · 导演分身收口到时间线（最高性价比）

**问题**：`director_skill.py:442` 结果不落时间线。
**做法**：让 `_generate_edit_instructions`（`:232`）输出**对齐 `llm_editor` 的动作 DSL**，而不是自造的 `{clips:[...]}`；再调用现成的动作执行器落地。
**为什么不新写**：`llm_editor.py:667+` 已有 20 条动作的全套执行分支（含 `add_clip`/`trim_clip`/`add_transition`/`add_title`/`add_keyframe`/`ripple_delete`），直接复用即可。
**验收**：导演报告里 `edit_instructions_applied_to_timeline` 由 `False` 变 `True`，且跑完能在时间线上看到片段。
**冻结区影响**：无（`director_skill.py` / `llm_editor.py` 均不在冻结区）。
**风险**：LLM 输出格式漂移 ⇒ 必须保留"解析失败即不改时间线 + 显式报告"的降级，不能静默。

### P0-2 · 角色形象图入库（对齐"沉淀可复用角色资产"）

**问题**：`CHARACTER_FIELD_SCHEMA` 无图字段。
**做法**：新增 `ref_images`（list，存相对路径或 asset id）与 `portrait`（主图）。
**必须同步 4 处**（否则静默失效，这是该字段模型已知的坑）：
1. `app/modules/lego/character_management_module.py:55` 本表
2. `app/core/canvas_bridge.py:306 build_character_prompt`（仅 visual 组）—— **`canvas_bridge.py` 在冻结区 `stage3d-core`**
3. `app/core/canvas_server.py:499 /host/characters`（已改为按本表派生，通常无需手改，仍需回归确认）
4. `vendor/shiguang-canvas/src/stores/node-factory.ts` 与 `vendor/AI-Canvas-tauri/src/libtv/stores/node-factory.ts` 两处 `CharacterEntry`
**守门**：`_verify/check_character_schema.py` 静态校验。
**验收**：给角色挂图 → `/host/characters` 返回带图路径 → 画布绑角色后生成提示词含参考图标记。
**冻结区影响**：**需解冻 `stage3d-core`**（整文件哈希，见 §4）—— 该 zone 锁了 7 个文件，角色库模块是其中之一。

### P0-3 · 修 P0-2 字段不一致（画布绑角色丢字段）

**问题**：`store.ts::bindCharacterToShot/syncCharacterToShot` 只拼 `appearance`（`docs/_archive/knowledge/19-canvas-design-review.md:225`）。
**做法**：画布侧改为消费 `/host/characters` 返回的 `prompt`（服务端已按 visual 组 4 字段派生，`canvas_server.py:520`），**前端不再自己拼**。这样字段模型只维护一处。
**冻结区影响**：**需解冻 `canvas-magnetic-intent`**（`store.ts` 整文件哈希）。
**顺带收益**：`memory_anchors`（标志性符号）恢复注入，直接改善跨集一致性。

### P1-1 · 剧本设定器 + 题材层模板

**问题**：`ScriptNode` 纯文本（`nodes.tsx:345`）；题材模板为零。
**做法**：
1. `ScriptNode` 增加 LLM 入口（"从想法生成剧本大纲"），复用现成的 `AIEngine.chat_with_fallback` 三级降级（云 → Ollama → 模板），与 `director_skill.py:107` 同款写法，保证离线可用。
2. 新增题材模板包 `vendor/shiguang-canvas/public/prompts/shiguang-genre.json`（**题材层**：世界观 / 主线 / 角色位 / 禁忌），与现有 `shiguang-drama.json`（**分镜层**）**分层并存**，不合并。
**注意**：不新增节点类型的话只需动 `nodes.tsx`；若新增"题材设定"节点，则 `nodes.tsx` + `registerBuiltinNodes.ts` + `NodePalette.tsx` **三处都在 `canvas-magnetic-intent`**（整文件哈希）⇒ 先解冻。
**双库同步**：前端新增节点/面板必须同步 `vendor/AI-Canvas-tauri/src/libtv/`（pre-commit 已有 `canvas-dual-repo` 守卫，`always_run: true`）。

### P1-2 · 剧本层「局部改 → 联动」（把 reanchor 的思路上移一层）

**做法**：复用 `dialogue_anchor.py:179 plan_reanchor` 的**计划-确认-落地**三段式（能力语义见 `agent_capability_catalog.py:155`：「默认只出计划，确认后落地」），把作用对象从"片段"换成"场次/分镜"：改一句设定 → 算出受影响的场次 → 标脏 → 只重生成脏的。
**为什么这样最省**：已有的"计划/确认/落地"交互契约不用重新设计，风险模型也是现成的。
