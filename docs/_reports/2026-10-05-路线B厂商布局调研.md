# 路线 B（控制层驱动）厂商布局调研

> 2026-10-05 · 数据来源：公开报道与招聘/产品信息（腾讯网雷报 2026-08、大河财立方 2026-09、
> 海外工具评测 2026）。厂商动态变化快，具体能力以各家最新产品页为准。

---

## 第 0 章 三个最重要的结论（先看这个）

| # | 结论 |
|---|---|
| 1 | **方向盘已经转了**：2026 年头部厂商的重心从「单点生成能力」转向「**控制最终成品结果**」——原文口径：「冲着控制最终成品结果，而不只是单个内容生成效果」 |
| 2 | **大厂主要走 B1（接 Maya/Blender 插件）**：字节即梦已适配「白模素材参考能力」并接入 **Maya/Blender 插件** —— 服务的是**专业创作者**，仍要会建模 |
| 3 | **B2（免建模）只有雏形**：小云雀 AI 扩充了「**角色动作库 + 相机运镜库 + 角色体系库**」——这正是 B2 的第 1、2 件缺件，说明方向被验证但远未成熟 |

**市场背景（决定一切的一组数字）**：

| 指标 | 数值 |
|---|---|
| AI 微短剧供给 | 2026 Q1 全行业上线微短剧约 **12.8 万部**，AI 占比 **>95%** |
| 用户规模 | 2025 约 1.2 亿 → 2026 预计 **2.8 亿+** |
| 制作成本 | 一年内跌近 **九成**（一分钟素材跌到几十元） |
| **爆款率** | 抖音上半年新增 AI 剧/漫剧 22.19 万部，**爆款率仅 0.47%**，超九成流量低迷 |

⇒ **产能不再是壁垒，质量与可控性才是。** 行业难题已从「能不能做出来」变成「能不能做出爆款」——
这正是控制层（路线 B）的价值所在。

## 第 3 章 中游工具层（夹缝求生的一层）

2026-08 报道口径：头部模型厂商**向下游工具层渗透**，中游工具厂商在两个方向上求生：

| 方向 | 做法 | 例子 |
|---|---|---|
| **垂直场景深耕** | 锁定某个内容场景做深 | Vidu 的一键 MV、Seko 3.0 的内容生产 |
| **多模型编排 + 一致性** | 自己不造模型，做「控制层 + 路由 + 一致性」 | **invideo Agent**（持久上下文引擎 + 相机控制 + 200+ 模型路由） |

> **对项目最有启发的一条**：invideo Agent 的做法与拾光剪影的定位高度重合——
> **不造模型、做控制层与编排**。区别是：invideo Agent 在云端做编排，
> 拾光剪影可以做「**本地 + 零门槛 + 全链闭环**」（从想法到成片，不只有生成）。

## 第 4 章 这对拾光剪影意味着什么（三条判断）

### 判断一：方向被大厂验证了 —— 但**大厂没在服务小白**

- 字节即梦接的是 **Maya/Blender 插件** ⇒ 服务专业创作者（B1）
- 阿里的 40 多项专业参数 ⇒ **需要懂镜头语言的人**才能用
- 小云雀的「动作库 + 运镜库」是 B2 雏形，但只是**素材库**，不是「零门槛流水线」

⇒ **「零建模能力的人也能做可控精品」这个位置，现在还是空的。**

### 判断二：行业痛点已经从「产能」变成「爆款率」

爆款率 0.47%、超九成内容流量低迷 ⇒ 堆量没有意义。
**能按导演意图精确控制结果** = 做出差异化的前提 ⇒ 控制层是刚需，不是加分项。

### 判断三：项目的差异化不在「造模型」，在**降门槛 + 全链闭环**

| 别人 | 拾光剪影可以做 |
|---|---|
| 造更大的模型（比不过大厂） | 用别人的模型，做**控制层 + 编排**（invideo Agent 同路，但本地化） |
| 专业工具（要会建模/懂镜头） | **零门槛**（程序化骨架 + 参考视频重定向 + 预设动作库/镜头模板） |
| 单点生成能力 | **全链闭环**（想法→剧本→分镜→生成→入轨→剪辑→导出），这是大厂工具不做的 |
| 云端付费 | **本地跑通 + 零调用费**（已有双栈引擎 + 记忆体策略） |

## 第 5 章 结论

> 路线 B 已经是**兵家必争之地**：国内字节、快手、阿里都在从「生成能力」转向「控制成品」；
> 海外有一整层专精厂商（Wonder Dynamics / Move AI / Viggle / DeepMotion / Cascadeur…）。
>
> **但主流打法是 B1（专业工具，要会建模/懂镜头）。B2（零建模）只有素材库雏形，没有人做成流水线。**
>
> ⇒ 拾光剪影的机会不是「再做一个生成器」，而是**做 B2 的那条流水线**：
> 用别人的模型 + 自己的控制层（程序化骨架 / 姿态重定向 / 预设库）+ 全链闭环 + 低门槛。
> 这与项目已有的地基（Stage3D / stage3dPoseRetarget / stage3dControlNet / pose 服务）**完全对齐**。
