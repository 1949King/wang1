## 0. 结论速览（先看这一页）

**一句话现状**：制作与工程能力已达一流（11 道门禁 / 1548 测试 / 85 锁 / 抽卡闭环骨架全通），  
但**内容源头（编剧部）仍是空的、真值裁判（审美）仍没眼睛**——这是一家「设备顶级的代工厂，  
还不会自己写故事」。

**一句话定位**：拾光剪影是**面向结果的 AI 短剧生产线**（想法→剧本→分镜→抽卡→粗剪→精剪→成片），  
用户站在导演位做三件事：定意图、定候选、验收；执行交给系统。  
**它不是 ComfyUI 那类面向过程的节点工具**（详见 §3，一次说清，后文不再纠缠）。

**三大战略目标（12 个月，详见 §4）**：

| #  | 目标                           | 一句话验收                                                       |
| -- | ---------------------------- | ----------------------------------------------------------- |
| G1 | 内容源头：建成编剧生产端（结构层→LLM 层→圣经层）  | 一句话梗概 → 3 分钟单集分镜表，人工只过 3 个卡点                                |
| G2 | 真值裁判：抽卡评分从几何分升级为真值分 + 成片体检报告 | 每集成片自动出体检报告；首抽合格率可统计、可环比                                    |
| G3 | 工程健康：巨石收敛 + 覆盖率上行 + 知识复活     | editor_module 拆到 8,000 行以下；覆盖率 30.2%→40%；\_archive 知识按新刀序复活 |

## 2. 核心模块盘点（哪些是命根子）

### 2.1 支柱一：精剪引擎（剪辑部）

- **真相源**：`EditorModule._clips`（RLock + `_clips_snapshot()`，整段替换唯一合法入口由  
  `glue/policies.py::TIMELINE_WRITE_ENTRYPOINTS` 声明）——全项目时间线只有这一个事实。
- **双内核调度**：`editor_scheduler.py`（预览走 PyAV 轻核，剪辑/导出走 FFmpeg/MLT 专业核），  
  渲染三级 fallback（C++ NVENC → FFmpeg CLI → moviepy CPU）。
- **转场语义分层**：exact（xfade-direct，≤4 LSB 漂移）vs bake（预览-导出对齐）——这是本项目  
  对「预览所见即所得」的原创解法。
- **AI 体力活 B 轨**：B0 词级帧绑定（text_frame_map）✅ / B1 薄指令写回 `_clips`（edit_commands）✅ /  
  B2 去水词静音（filler_silence_detect）✅——**这三个件是「一键粗剪」的最后三块积木，只缺编排层**（§5.5）。
- 撤销体系、速度斜坡（in_point 修复 + 速率节流）、代理媒体、墙钟播放。

### 2.2 支柱二：Agent 能力系统（调度中枢）

- **单一来源**：`agent_capability_catalog.py`（57 项直写 + 画布节点派生）——  
  `agent_policy`（effect/paid 映射）、`agent_brain`（左右脑神经元）、`capability_handlers`（运行时注册）  
  全部由这一张表派生，`verify_catalog_consistency()` 双向守卫。新增能力 = 表里加一行。
- 能力面覆盖：剪辑 13 项（split/trim/move/keyframe/ripple/reanchor…）、画布生成 12 项  
  （生图/生视频/本地生图/**best_of_draw 抽卡选优**/局部重绘/YuE 三段式/ComfyUI 执行/拼接）、  
  管线 17 项（报价/预检/五维打分/导演拆分镜/机位规划/质量守护四件套/异步任务…）、  
  拓展 3 项、模型 3 项。
- **哲学**：智能体只做「确认后执行」的遥控器——白名单 + 三档审批 + 建议清单勾选。  
  这个定位被 LAVE（IUI 2024，Meta 的 8 人用户研究）的结论正面印证：  
  *LLM 在素材整理与编辑规划阶段最有价值，人工保留最终决定权*。我们两年前就这么设计了。

### 2.3 支柱三：AI 画布（导演台）

- 21 种节点（shot/script/image/video/audio/music/prompt/text/config/generator/group/markdown/  
  shotlist/storyboard/director/directorCard/digitalHuman/animation/panorama/note/source），  
  磁吸意图系统（33 整文件冻结）、3D 导演台（GLB/骨骼/姿势库/机位视锥/控制网）、  
  小白模式（NoviceInspector）、桌宠「拾岚」（V4.41.9，懒加载 Three.js 独立 chunk）。
- 桥接：`canvas_server.py` 29 GET + 47 POST（agent 族 / 生成族 / 角色族 / 分镜族 /  
  拉片族 reference-breakdown L1+L2 / 重拍重配族 segment-retake + redub-* / 时间线族  
  batch-to-timeline + timeline-snapshot / 账本族 budget / 模型族 providers+model-preload）。
- **round-trip**：入轨带 `canvas_node_id` → 时间线快照 → outbox 落源节点，双向闭环。

### 2.4 支撑系统

两套插件体系（ExtensionsRegistry + PluginManager）· 16 家云 LLM provider + 视频/音频渠道抽象 ·  
`model_registry`（懒加载 + LRU 驱逐 + 显存水位守卫，V4.41.5）· `SHIGUANG_NO_EGRESS` 素材不出域硬开关 ·  
三层价格体系（budget_pacer/global_price/sampling_review）· MCP 客户端（Blender 通道已通）·  
一任务一分支 + 绿灯 tag 自动回滚（V4.41.0）。

### 2.5 技术路线判断（2026-10-10 深度探讨定稿版）

**本质 = 「意图分层的 Agent 编排 + 确定性精剪引擎 + 三档自适应混合算力」，不要动摇。**

> **定位起源与演进（用户裁定）**：项目算力定位起源 = **本地部署大模型为主（与 ComfyUI 同思路），
> 云 API 是后来加入的兜底 + 加速**（代码证据：V4.40.22 主备制「主选=DiffSynth 本地」、
> `local_generate_image` paid=False 与云端刻意分列、`local/` 前缀强制本地）。
> 2026-10-10 深夜用户进一步提出「不是人人有 5-10 万机器」的普适性追问——定稿升级为
> **三档硬件自适应**（详见《2026-10-10 算力路线深度探讨-三档自适应与生态兼容》）：

| 档位 | 探测条件 | 图像生成 | 视频/音乐/LLM | 对应谁 |
|---|---|---|---|---|
| **全云档** | 无独显/≤4G/探测失败 | 云 API（16 家） | 云 API | 核显轻薄本（最大用户池） |
| **主流档（8G）** | 6-12G 独显 | **本地双栈主选**（DiffSynth→自研备选，SD1.5/SDXL 零调用费）→ 云兜底加速 | 云 API 为主 + ACE-Step 音乐（实测过后） | 开发者自己这台 4060 = 目标用户主流环境 |
| **满血档（16G+）** | ≥16G | 本地主选 + ComfyUI 通道提示可用 | 可解锁更多 + 远程 YuE 端 | 发烧友（自装 ComfyUI 资产复用） |

地基已有 80%：`_detect_nvidia()` 显存探测（gpu_acceleration.py:94/:200）+ `model_registry`
水位守卫（懒加载/LRU/15% 余量/诚实失败）+ `execution_decider` 选路单点（R2）+ 主备降级
（R9 留痕）——只差把显存数字接进 `decide_execution()`（任务 H1，本季）。

**定稿红线**：① 不做自研 ComfyUI 节点适配/本地打包（双引擎分层：自研双栈当主轴可深度治理，
ComfyUI 通道只做已装用户的资产复用）；② 不给 YuE 做手工量化（3B 吃 24G 是双塔接力+长序列
KV cache 的结构性结果，8G 硬凑三条路——量化/offload/分段——已算账全是坑）；③ 音乐域本地
主力候选 = ACE-Step 1.5（Apache/MIT 可商用 + 8G 以下，10-09 盘点核实，本季 E2 同批实测），
YuE 退居远程「音质上限选项」。

判断依据：① 硬件红线决定本地扛不了 3B+ 生成模型，但**图像域本地优先已成立**——主备制 +
零调用费是刻意设计，不是权宜；② provider 抽象 + 抽卡账本已把「换模型可复现」做出来了——
供应商风险已被架构对冲；③ **下一步的胜负手不在更强的模型，而在内容源头（编剧）与真值
（审美）**——这与 10-05 报告「不缺工艺，缺内容源头与真值裁判」的结论一致，本文完全采纳并展开。

## 3. 定位辨析：我们是什么、不是什么（与 ComfyUI 的边界，一次说清）

### 3.1 本质区别

| 维度     | ComfyUI 类节点工具        | 拾光剪影                              |
| ------ | -------------------- | --------------------------------- |
| 面向     | **过程**：用户自己搭图、自己当执行者 | **结果**：用户提意图，系统当执行者               |
| 用户画像   | 懂扩散模型、会排图的创作者        | 短剧主创/小白：只要说清「我要什么」                |
| 图的意义   | 图灵完备的执行电路，图本身就是作品    | 画布是**导演台**：意图卡片+资产+分镜的排兵布阵，图不是产品  |
| 本地算力角色 | 主体（用户自带显卡跑整条渲染管线） | **同样是主体**（三档自适应：8G 主流档本地生图主选零调用费，云兜底加速；>8GB 模型域走云）——与 ComfyUI 差异不在算力路线（同是本地优先），在产品形态 |
| 生态策略   | 节点生态是产品生命线           | 生态是**供给侧**（provider/模型/工具），不是产品形态 |
| 质量机制   | 靠用户肉眼和经验             | 账本 + 代理分 + （本次要补的）真值分与体检报告        |

**小白比喻**：ComfyUI 是自炊厨房——你得会买菜、切配、颠勺，锅碗瓢盆自己组合，做出来的是你的手艺；  
拾光剪影是私厨后厨——你点菜、提要求、试味，后厨自动出菜，**菜谱（配方包）和采购账（draw_book）都记着**。

### 3.2 ComfyUI 在我们体系里的正确位置

它已经在正确位置上了：`comfy_provider.py` + `/host/comfyui/run` + `canvas.comfyui_run` 能力——  
**ComfyUI 是我们供给侧的「本地生成引擎之一」**（对齐秋叶整合包的检测已修），仅此而已。

### 3.3 可以借的三个思想（只借思想，不跟进形态）

1. **子图复用** → 我们的对应物是「导演卡 + 工序预设」（磁吸系统已是）；
2. **执行缓存/不变重算** → `canvas_node_cache` 已在做，继续深化（对比我们已把 prompt-image  
   负缓存做进 canvas_server，同一思想）；
3. **版本化工作流** → 我们缺的等价物正是**配方包 `gen_recipe.py`**（§5.3，恰好是缺口③的钥匙）。

### 3.4 明确不跟的三件事

节点生态市场（那是另一个产品的命）· 图灵完备图执行（画布永远服务于导演意图，不做通用编程）·  
把「接入更多模型」当战略（供给侧已够宽，16 家 provider 没有瓶颈，瓶颈在内容与真值）。

## 4. 战略目标（2026-10 → 2027-10）

> 北极星不变：**竖切可重复——导演台（含数字人）→ 分镜图 → 入轨精剪；智能体只做确认后执行的遥控器。**  
> 四轨配比（N30/P35/A25/D10）维持；编剧/母版工作在 P 轨与 A 轨内腾挪，不新开第五轨（若你不同意见 §10 决策点 Q4）。

### G1 内容源头（补缺口①，从「代工」到「原创」）

**目标态**：一句话梗概 → 结构大纲 → 分集剧本（带台词）→ 分镜表，全程人工只过 3 个卡点  
（剧本定稿 / 关键抽卡定稿 / 成片验收），产出可入轨。  
**验收**（2027 Q1 末）：用「梦浮生」语料做出 3 分钟单集全链 demo；伏笔账本回收率 100%（埋设必有回收记录）；  
角色库 9 个人格字段被编剧层真实消费（当前零消费，10-05 报告发现）。

## 5. 缺口补强方案（本案主体）

> 每节结构：现状（实测证据）→ 目标态 → 方案 → 参考方案/文献/开源 → 落地刀法。  
> 缺口②（抽卡闭环）骨架已建成，本节写「升级」；缺口①③④是本策划的重点增量。

### 5.1 缺口① 编剧生产端（最大空白，第一优先）

**现状（2026-10-10 实测）**：

- `script_structure.py` 全库不存在（find 实测）——10-05 已定稿的结构层方案未动工；
- `storyNodes.tsx`（578 行）= StoryboardNode：上传参考片→自动分镜表，**消费端**；
- `pipeline.generate_script` = `editing_script_generator.py`（396 行）：五维分→镜头顺序的**剪辑方案**，不是叙事剧本；
- `director_skill._generate_script` 只出 30 秒短视频脚本；
- 角色库 9 个人格字段注释写着「供剧本创作与跨集一致性校验」，**没有任何代码读它们**。

**方案：三层递进（每层独立可交付，上层依赖下层）**

| 层          | 模块                                | 干什么                                                                                                     | 成本                 |
| ---------- | --------------------------------- | ------------------------------------------------------------------------------------------------------- | ------------------ |
| L1 结构层     | `app/core/ai/script_structure.py` | 启发式结构骨架：前 10 秒冲突位 / 每 30 秒钩子位 / 集末悬念位 / 单集时长预算。输入一句话梗概+题材模板，输出结构化场次大纲 JSON                              | 零 API 成本，纯规则       |
| L2 LLM 编剧层 | `app/core/ai/screenwriter.py`     | 分层生成：梗概→角色卡（**消费人格字段**）→分场→场景动作→台词，每层人审卡点（与 Agent「确认后执行」哲学一致）；采样用 MC 排除防台词重复；产出过既有 compliance-check     | 云 LLM（已有 provider） |
| L3 圣经与账本层  | `app/core/ai/story_bible.py`      | 剧本圣经：世界观 / 角色档案 / **伏笔账本**（埋设点/回收点/状态机）/ 连续性检查表；剧本作为资产入库，供导演分解（storyboard-breakdown）、抽卡 prompt、配音角色绑定消费 | 结构化 JSON + 纯函数     |

**参考方案与文献**：

- **Dramatron**（DeepMind，CHI 2023，`github.com/google-deepmind/dramatron`，Apache-2.0）——  
  分层故事生成的范式：logline→title→characters→plot→locations→dialogue，每层可重写。  
  它的 15 位职业编剧用户研究结论要记住：**专业编剧不用它写全本，用它做世界观探索和备选方案**——  
  所以我们的 L2 永远保留人审卡点，不追求「一键全本」。
- **Re3 / DOC**（Yang et al. 2022/2023）——长故事的递归重提示与大纲控制，对应我们 L1→L2 的衔接；
- **RecurrentGPT**（ICML 2023，`aiwaves-cn/RecurrentGPT`）——交互式任意长文本生成，  
  对应「续写第 N 集」场景；
- 内部资产：`shiguang-genre.json` 题材模板（现仅 1 套）扩为题材库；  
  「梦浮生」105 章 22 梦境体是现成的首个实战语料 + 合规审查已接线。

**落地刀法**：刀 S1（结构层+能力 `pipeline.write_outline` 注册）→ 刀 S2（LLM 层+能力 `pipeline.write_script`）→  
刀 S3（剧本→分镜贯通：L2 输出直喂 `/host/storyboard-breakdown`，全链打通）。  
**验收**：见 G1。**红线**：剧本生成不落 `_clips`（生产端只产文本资产）；「梦浮生」敏感议题规避沿用既有合规审查。

### 5.2 缺口② 抽卡闭环升级（骨架已通，从几何分到真值分）

**现状（实测）**：

- `draw_book.py`（321 行）：参数指纹 sha1(kind|prompt|model|style|size) + EMA 均分/方差 +  
  **best_seed** + LRU 500 桶 + 60 天新鲜度 + 原子写——账本完整；
- `gen_critic.py`（320 行）：5 项代理分（非崩图 0.35 / 清晰度 0.25 / 尺寸 0.20 / 构图 0.10 / 成本 0.10），  
  崩图一票否决闸门，`is_proxy: True` 红线——**只能筛「可证伪的坏」，说不出「哪个更好」**；
- `canvas.best_of_draw`（n≤6 一次多张+选优+入账）、seed 复现（云/本地双通道）均已落地。
- ⚠️ 同日深潜复核（§12）：接线完备但 **`data/draw_book.json` 仍为空**（零真实流量）、  
  本地生图路径未入闭环——升级前先做 E1.5 首流量验收。


**升级方案**（10-09 报告 P0 已列 E2，此处给落地捷径与补充）：

1. **真值分并列一列，不改代理分语义**（守住 is_proxy 红线）：首选 **DiffSynth-Studio 的  
   `diffsynth.metrics`**（ModelScope 系，一站式提供 PickScore / ImageReward / HPSv2 / HPSv3 /  
   CLIP Score / Aesthetic / UnifiedReward，统一 `metric.compute(prompt, image)` API）——  
   比逐个接 4 个仓库省一个量级的工程量；备选单装 `hpsv2` pip 包（`tgxs002/HPSv2`，CUHK+商汤）。  
   CLIP 级模型，CPU/8GB 均可跑。
2. **视频侧**：VBench 的 `motion_smoothness` / `temporal_flickering` 帧采样评分（DOVER 的  
   technical+aesthetic 双头也在此列）——先只接两维，实测速度后如实记录（10-09 的节制原则采纳）。
3. **验收台 UI**（10-09 创新功能 4.1）：五列分排序 + 每行可看「扣分扣在哪一维」；未评估显示「未评估」，  
   绝不算假分。
4. **KPI 仪表**：首抽合格率 / 平均抽卡次数 / 重抽率——draw_book 已有全部原料，只差一个 summary 出口。

**文献**：ImageReward（NeurIPS 2023）、HPSv2（HPD v2 数据集 79.8 万人类偏好对训练）、  
PickScore——三个都是「人类偏好评分模型」，正是「真值裁判」的学术界等价物。

### 5.3 缺口③ 资产母版层（角色有档案没照片，场景道具整条空）

**现状（实测）**：角色库 22 字段（含 9 人格字段，六处同步不变量+守卫）+ `character_anchor` 一致性锚定算法 +  
prompt 库；**定妆照不存在**（character_anchor 无 reference_image/portrait 命中）、  
**场景库/道具库 grep 零命中**（10-05 已证，本次复核仍空）、**配方包 gen_recipe 全库不存在**。

**方案：四件套**

1. **定妆照（刀 M1）**：沿 `voice_clone.py` 的先例走**非 schema 资产字段**（`portrait_image`），  
   不碰 CHARACTER_FIELD_SCHEMA 六处同步不变量；生成链 `canvas_aigc` 消费它绑参考图。  
   定妆照本身用 `best_of_draw` 抽卡产生、人选定稿——**闭环复用，不造新轮子**。  
   （若日后要进提示词派生，再升 schema 字段，走六处同步+守卫，那是决策点 C 类。）
2. **配方包 `gen_recipe.py`（刀 M2）**：把「模型+prompt+style_tag+size+种子集+超参」冻结成可命名复用的  
   配方 JSON；血缘写进 draw_book（哪个配方出的哪张图）。**这是我们对「ComfyUI 工作流」的正确等价物**。
3. **场景卡/道具卡（刀 M2）**：照角色库模式克隆（场景=名称/氛围/时段/参考图；道具=名称/材质/  
   归属角色/握持描述）。注意：`pipeline.prop_consistency`（道具守护）**已经在等握持描述这个字段**——  
   道具卡一建，守护能力立刻吃饱。
4. **一致性技术评估（刀 M3，⚠️ 需实测）**：IP-Adapter（`tencent-ailab/IP-Adapter`，22M 适配器，  
   Apache-2.0，SD1.5 可跑）作为定妆照→生成的第一候选；InstantID（InstantX，SDXL）真人向备选；  
   StoryDiffusion（`HVision-NKU/StoryDiffusion`，NeurIPS 2024 Spotlight，MIT，一致性自注意力可插拔  
   SD1.5/SDXL）做**连拍一致性**（同角色多镜头）评估——注意其 low-VRAM 版官方测试机是 24GB，  
   8GB 上 SD1.5 基座需实测，不实测不写进能力目录（诚实红线）。

**不建议**：素材语义检索走向量库——**撞现行技术文档 §1.4 的 D1 不做红线**，本期不动；  
素材库先用「PySceneDetect 切片 + 标签体系」够用（见 §6.1）。

### 5.4 缺口④ 审美治理层（把审美从玄学变成验收单）

**现状**：五维评分（画面 25/高光叙事 25/文案匹配 20/BGM 适配 15/镜头时长 15）有 estimated_dims  
固定 70 基线的「假分」承认；gen_critic 只有几何分；规则/守卫零件散落 6 处 guard；  
**没有成片级的统一体检出口**。

**方案：三层治理（刀 G1）**

1. **规则层（零成本，先做）**：`app/core/aesthetic_rules.py` —— 20 条可编程剪辑语法检查：
   - **Murch 六法则数字化**（《眨眼之间》：情绪 51 / 故事 23 / 节奏 10 / 视线 7 / 平面 5 / 空间 4）——  
     做成相邻镜头切点的加权评分，纯工程可实现；
   - 跳轴检测（180° 轴线，需镜头方位数据，可先做提示级）；对白场景正反打覆盖检查（B0 词级绑定已有原料）；
   - 连续镜头长度单调告警；BGM/对白响度冲突（音频 DSP 8 件套已有）；字幕行宽/驻留时长；  
     黑场/静帧（复用 gen_critic 判据）。
2. **评分层**：真值分接入（§5.2）+ 五维逐维真值化路线图（画面质量→HPSv2/DOVER，  
   BGM 适配→既有 music_recommendation，文案匹配→CLIP，逐维替换 70 基线）。
3. **报告层**：**「成片体检报告」**——每集导出时自动生成：规则违规清单 + 评分雷达 +  
   **ASL 节奏曲线**（平均镜头长度，对照基线区间）+ **色彩审计条码图**（moviebarcode 风格，  
   一眼看出调色断裂）。出口：画布卡片 + **桌宠「拾岚」状态播报**（状态机已含  
   等确认/失败/成功/在忙/待命五态，体检报告出来让它换表情——差异化彩蛋，成本极低）。

**文献与参考**：Leake et al.《Computational Video Editing for Dialogue-Driven Scenes》  
（SIGGRAPH 2017，Stanford+Adobe，系统名 RoughCut）——**13 条剪辑 idioms 形式化为 HMM 约束求解**，  
是「审美规则引擎」的方法论鼻祖；其 2024-2026 新作 ChunkyEdit（CHI'24）/ RankCut（IUI'26）/  
Micro-Edits（UIST'26）证明「转录本驱动 + LLM 评分」正是当前研究前沿——**我们 B0/B1/B2 + Agent  
的组合恰好踩在这条线上**。Barry Salt 的 Cinemetrics（电影节奏统计学）提供 ASL 基线的学术框架。

### 5.5 北极星欠账：一键粗剪（对白驱动，素材侧入口）

**现状**：北极星竖切（生成侧：导演台→分镜→入轨）已可重复；但素材侧（口播/实拍）的  
「一键粗剪写 `_clips`」仍缺——积木齐了：B0 词级帧绑定 ✅ + B1 薄指令写回 ✅ + B2 去水词 ✅ +  
whisper ASR ✅ + 拉片 L1/L2 ✅ + segment-retake ✅，**只缺把「素材+台本」变成「粗剪时间线」的编排层**。

**方案（刀 R1，全部用已有件 + 两个开源思想）**：

```
素材 → PySceneDetect 切片打标（镜头边界+代表帧）
     → whisper 词级时间戳（B0）
     → 静音/水词标记（B2）
     → 粗剪 idioms v0（3 条：说话人可见优先 / 静音剪除+句间 pad / 情绪句给正反打位）
     → dry_run 出编辑计划（复用 canvas-run 的「计划→确认→执行」模式）
     → B1 写回 _clips（可撤销）
```

**参考**：auto-editor（`WyattBlue/auto-editor`，静音剪除成熟实现，还支持导出  
Premiere/Resolve XML——它的 export 思想值得我们抄）+ RoughCut 的 idioms 形式化（§5.4）+  
ChunkyEdit/RankCut（转录本编辑的 LLM 时代解法）。  
**纪律**：智能体只做「确认后执行」——粗剪永远先出计划再落剪，符合北极星；不默认一键成片。

### 6.3 纯粹有趣（低成本高辨识度，建议至少做一个）

1. **moviebarcode 成片色彩审计**：把整集压成一根「色彩条码」贴在体检报告里——  
   调色断裂一眼可见。百行内可实现（ffmpeg 抽帧 + PIL 均值条），却是体检报告里最「像产品」的一页。
2. **Cinemetrics ASL 基线**：用已有拉片 L1（reference_breakdown）批量统计真实短剧爆款的  
   平均镜头长度分布，给「节奏」一个**数据基线**而不是形容词——「审美治理」从第一天就有数可依。
3. **桌宠审片员**：体检报告/抽卡完成时，让「拾岚」用表情和气泡播报（状态机现成）——  
   陪伴感是差异化（V4.41.9 的定位原话），审片播报是它第一个「有工作」的岗位。

## 11. 结语（三句话）

1. 这个项目的**工艺和工程纪律已经是单人项目里的天花板**——11 道门禁、1548 测试、85 锁、  
   诚实失败铁律，这些别动，它们是护城河。
2. 接下来 12 个月的价值不在「更强的模型」和「更多节点」，而在**把编剧部建起来（内容源头）**  
   和**把品控的眼睛装上（真值裁判）**——前者决定它是代工厂还是创作公司，后者决定它敢不敢说「我的成片合格」。
3. 所有补强都建立在已建成的地基上（B0/B1/B2→粗剪，人格字段→编剧，draw_book→配方，  
   拉片→ASL 基线）——**没有一刀需要从零造轮子，这正是这家「公司」最健康的地方。**

> 本策划案为提案（proposal），按项目惯例：你确认后说「开始」，按 §9 刀序逐刀推进；  
> 每刀独立版本号 + 全套门禁 + CHANGELOG + 记忆沉淀。
