## 0. 一句话结论

**拾光剪影是一个"垂类 AI 原生桌面创作工具"**：把**专业 NLE 时间线**、**AIGC 节点画布**、
**3D 导演台**、**数字人**、**Agent 白名单执行**五样装进一个 PyQt6 单机软件里。
代码规模已到 **38.3 万行**（Python 16.4 万 + 自研前端 3.4 万 + 对照仓 18.5 万），
**功能面远超同类开源项目**，但**维护债已经明显拖后腿**——实测出 **2 处真实功能缺陷**、
**23 个零引用大文件（约 1.04 万行死代码）**、**9 个失效测试模块**。

## 1. 项目性质

### 1.1 是什么

| 维度 | 实测结论 |
|---|---|
| 形态 | **桌面单机软件**（PyQt6 + 本地 Python），非 SaaS、非 Web 应用 |
| 视频内核 | **双内核**：LIGHTWEIGHT（PyAV，预览/probe）/ PROFESSIONAL（FFmpeg + MLT ctypes，剪辑/导出）+ C++ NVENC 硬件加速，三级 fallback |
| AI 架构 | **本地优先 + BYOK**：Ollama 本地兜底 + **19 个云 Provider**（DeepSeek/豆包/OpenAI/智谱/通义/文心/星火/Kimi/Claude/Kling/FishAudio…） |
| 画布 | **自研** TypeScript + React + Zustand + Three.js + @xyflow/react；**20 种节点类型** |
| 商用外壳 | **完备**：注册/登录（手机+邮箱+OAuth）/ bcrypt 密码哈希 / Fernet PII 加密 / license 授权 / 自动更新 / 隐私政策 + 用户协议 / PyInstaller 打包 spec |
| 真相源 | 时间线 = `EditorModule._clips`；画布 = `vendor/shiguang-canvas` |

### 1.2 不是什么（代码侧证据）

- **不是 OpenShot 二次开发** —— 立项时的设想从未接线，遗物已于 2026-09-14 清除（见正文档 §9）。
- **不是「一键成片」黑盒** —— 北极星明确「智能体只做确认后执行的遥控器」，`agent_policy` 里有 `require_approval` 硬门。
- **不是真 Agent 应用** —— 控制流写死（`agent_pipeline_orchestrator.execute()` 固定阶段序列），工具调用无回环。
- **不是通用 NLE** —— 无多层嵌套序列、无正式 Gap 对象（对照 OTIO 结论）。

### 1.3 一句话比喻

> 剪映是「大众快餐店」，达芬奇是「专业西餐厅」，
> **拾光剪影更像「一家自带厨房的创作工作室」**——
> 你既能在案板上精雕（时间线），也能让机器先备好料（AIGC 画布 / Agent 体力活），
> 但**最后那道菜必须你自己尝一口才出锅**（人工确认门）。

## 3. 目标人群

### 3.1 核心人群（代码与帮助文档推断）

| 优先级 | 人群 | 依据 |
|---|---|---|
| **P0** | **短剧二创 / 影视混剪创作者** | 产品名与全部文档围绕「短剧」；精剪体验对标剪映；五维评分含「高光叙事价值」 |
| **P0** | **个人自媒体 / 短视频运营者** | 文案生成、标题话题、多平台适配、BGM 推荐；帮助文档直接推荐 DeepSeek / 豆包免费额度 |
| P1 | 小型 MCN / 剪辑工作室 | 多任务队列、批量处理、任务管理、账号运营（当前降级为壳）|
| P1 | **AIGC 创作者 / 分镜师** | 导演台、`@角色` 一致性、三视图、拉片宫格、数字人 —— 这批人是为画布来的 |
| P2 | AI 剪辑 / Agent 技术尝鲜者 | 拓展中心（Skill + MCP）、模型管理、可换 Provider |

### 3.2 人群特征（决定了产品形态）

1. **有本地素材、在意隐私** —— 桌面单机 + 素材库仅本机，不上传云端
2. **愿意自带 API Key（BYOK）** —— 不是「交订阅费用云端算力」的模式
3. **有一点点技术耐心** —— 要会配 API Key、可选装 Ollama；**不是纯小白**
4. **产出目标明确** —— 要发抖音/快手/B站/小红书，不是做电影
5. **痛点是「量」不是「质」** —— 单条精剪剪映够用，缺的是**批量化 + AI 体力活**

### 3.3 排除人群（主动放弃）

- 专业影视后期（无嵌套序列、无正式 Gap、无 ACES 色彩流程）
- 纯小白用户（要配 Key、要懂时间线，学习曲线高于剪映）
- 团队协作场景（无多人协同、无云工程）

**这是真实的空位**，也是这个项目最值钱的地方。

### 5.2 真实功能缺陷（2 处，非冻结区，可直接修）

#### 缺陷 A 🔴 `KeyframeAnimation.get_value()` 重复定义 → 三种插值静默失效

- 位置：`app/core/keyframe_animation.py`
- 事实：`get_value` 定义了两次 —— **283 行版（28 行）生效**，**363 行版（41 行，"增强版，支持贝塞尔曲线"）被覆盖成死代码**
- 后果：
  - `InterpolationType.BEZIER` / `STEP` / `SMOOTH` **全部退化为线性插值**
  - `_apply_bezier()` / `_smooth_interpolate()` 成为**永不执行**的死方法
  - `app/core/highlight_preview.py:77` 明确请求 `InterpolationType.SMOOTH` → **被静默吃掉**
- 影响面：关键帧动画、高光预览动画
- 修法：删掉 283 行版（或把 363 行版的插值分支合并进来），保留一份实现

#### 缺陷 B 🔴 `RegisterWidget._do_phone_register()` 重复定义 → 手机号注册 100% 失败

- 位置：`app/modules/lego/login_window.py`
- 事实：`_do_phone_register` 定义了两次 —— **414 行旧版生效**，**499 行带验证码的新版被覆盖成死代码**
- 调用链：生效版执行 `auth.register_with_phone(phone, password, nickname)`
- 而 `auth.register_with_phone(self, phone, password, code, nickname)` 的**第 3 位是 `code`**
  → `nickname` 被当成验证码传入 → `verify_phone_code()` 必然失败
- 后果：**手机号注册路径必然失败**（nickname 为空则报「请输入验证码」，非空则报「验证码错误或已过期」）；
  界面上**验证码输入框与「发送验证码」按钮从未被读取**
- 修法：删掉 414 行旧版，保留 499 行带验证码版

> 其余 4 处「重复定义」经核实为 `@property` + `@xxx.setter` 正常配对，**非缺陷**。

### C.7.1 最该先补的一条：生成链路异步化（差距 #1）

**关键事实：异步任务基建**其实**已经在仓库里**，只是没接到主生成路径上——

- `bridge.ts:1001 waitForVideoPostprocess` + `getVideoPostprocessStatus`（后处理轮询）
- `bridge.ts:323 waitForModelPreload`（人脸修复模型预载轮询，生图返回后**后台**跑，不阻塞）
- `bridge.ts:1155 getBatchStatus`（批量任务状态）

1. 后端 `/host/generate-image|video` 拆成「提交返回 `job_id`」+「`/host/generation-status` 查询」；
2. 前端 `generateImageViaHost` 复用现有 `waitFor*` 轮询骨架，补 `AbortController`；
3. 批量从 `for` 串行改为 Promise 池（并发 2–3，带限流）。

### D.5 结论：是否达标？

> **功能与架构层面：达到「主流可用」水平，局部原创领先。**
> 磁吸引擎、3D 导演台、数字人、分镜记忆回流时间线，这四件是 tldraw / Excalidraw **没有**的。
>
> **工程质量层面：未达到主流优秀水平。**
> 判定口径很直白——主流画布项目（哪怕是个人维护的 Excalidraw）都具备
> **单测 + lint + CI** 三件套；本项目这块是**空的**。40 个 >100 行函数、3 个千行组件、
> 104 处 `any`、41 处 `tsc` 报错、77% 代码平铺在根目录，这些都是同一个原因：
> **没有回归网，重构不敢动，于是只能往里加。**
>
> **一句话**：画布**功能上能打、工程上是裸奔**。
> 补上质量三层（测试 / lint / CI）的成本远低于重写，收益却是「后面所有画布改动都敢做」。
