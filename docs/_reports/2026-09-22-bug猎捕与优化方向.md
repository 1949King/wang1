## 二、算法优化方向（按 ROI 排序）

> 现状基线：昨日盘点确认全库 40+ 自研算法。以下不是「缺什么」，而是「已有算法怎么更强」。

### A1. ABCD 权重静态表 → 评分簿后验校正 ★★★
- **现状**：剧种→ABCD 权重是硬编码表（`drama_understanding_engine.py:1415`），全平台全用户同一套。
- **已有闭环**：评分簿按 `style_dna` 沉淀历史高分（`score_book.py:72`），生成前已会换用高分负面词（`guard_pipeline.py:166`）。
- **方向**：权重 = **静态先验 + 评分簿后验**。同 style_dna 下高分片段的 ABCD 维度分布回归出校正量，
  先验权重向实测分布缓慢收缩（如 0.9·先验 + 0.1·后验，样本越多后验占比越大，封顶 0.5）。
- **价值**：你的权重表从「行业经验」进化成「你的号的经验」——这是竞品（鲸影）静态权重表做不到的。

### A2. 报价单价静态估算 → 实际成本回写 ★★★
- **现状**：`provider_caps.py:35` 的 `price_per_clip` 是估算值（自己注释「非精确计费」），报价永远停在出厂值。
- **方向**：`report_success` 时若 provider 返回实际计费/耗时，滑动平均回写单价；报价展示「估算 ¥x（近 7 天实测均值 ¥y）」。
- **价值**：报价越用越准，成本确认弹窗（V4.36.0）从「大约」变「有凭据」。

### A3. 额度池退避参数静态 → 按失败类型自适应 ★★
- **现状**：`provider_pool.py:55` 退避 60s→30min 一刀切。
- **方向**：区分失败语义——HTTP 429（配额型）按天退避、5xx（故障型）按分钟退避、鉴权失败（凭证型）直接标记人工介入不退避。
- **价值**：429 多的号不会 60s 后又被选中白烧钱。

### A4. LLM 降级点不可观测 → 降级率指标化 ★★
- **现状**：`drama_understanding_engine.py:586` LLM 失败降级关键词匹配，只写 log，无统计。
- **方向**：降级事件进 `gateway_stats`，渠道健康灯（V4.36.0）增加「近 N 次 LLM 成功率」——
  关键词降级率高 = 提示词该修或渠道该换，现在这是盲区。

### A5. 观众记忆衰减开环 → 用户行为校准 ★
- **现状**：`memory_model.py` 衰减曲线参数是理论值；`storyboard_memory.py` 单向「模型→时长」。
- **方向**：你在时间线上手动拖拽调整的时长 vs 模型建议时长的差值，作为反馈样本校准衰减参数（半衰期）。
- **价值**：模型从「教科书观众」拟合成「你的短剧受众」。

### A6. 转场选择纳入反馈闭环 ★
- **现状**：`smart_editing_engine.py:467` 用 8 维情绪向量余弦距离选转场，选完即终。
- **方向**：你手动改掉的转场类型写入评分簿转场维度，同类情绪距离下优先你历史选择。

## 三、能力迭代升级方向

### B1. Agent 学习回路的缺失信号源：「用户撤销」★★★（最深的一个洞）
- **证据链**：`agent_brain.py:110` Hebbian 学习（成功+Δ/失败-Δ）已就位；
  `editor_module.py:8297` 异常路径会 `-Δ`；Agent 写操作已进撤销栈（`capability` 层自建 before/after）；
  **但** `history_manager.py:44-62` 的 undo 栈没有「Agent 来源」标记，undo 时无钩子回 agent_brain。
- **后果**：Agent 做了一件你不喜欢但没报错的事 → 你 Ctrl+Z → 这个最强的负反馈信号**白白流失**，
  Agent 下次还做同样的事。
- **方向**：撤销栈动作加 `origin="agent"|"user"` 标记；undo 到 agent 动作时触发
  `_agent_brain_learn(success=False)`。这是把「你每天的撤销行为」变成免费训练数据。

### B2. 词锚定全链自动化 ★★
- **现状**：重锚引擎已完成（`dialogue_anchor.py` + 能力 `重锚`），口型参数生成已有（`lip_sync.py`），
  TTS 正音守护已有（`tts_guard.py`）——三颗珠子都在，没串成链。
- **方向**：「改文案 → 自动重锚片段 → 自动重配音（带正音）→ 自动重算口型 blendshape」一键完成。
- **价值**：短剧改台词从「四个工具各点一遍」变「一句话」。

### B3. 工程源码双向编辑引擎 ★★
- **现状**：`timeline_source.py` 能渲染（`:143`）也能解析回工程数据（`:303`），格式为 diff 优化（`:16`）。
- **缺口**：没有「编辑源码文本 → 语义 diff → 最小操作集 → 进撤销栈」的引擎。
- **方向**：改源码文本后，引擎 diff 出「片段 a 时长 4.0→6.0」这类最小操作，走既有编辑命令进撤销栈
  （Ctrl+Z 可回）。工程源码从「只读视图 + 全量重写」升级为「真正的源码编辑」。

### B4. 升级清单 P2 三项（已排期，不展开）
P2-1 每段 gate（复用 `preview_validation_loop.request_regenerate`）·
P2-2 风格基因跨会话记忆（score_book 接 `memory_store`）· P2-3 凭证保险库加固。

### B5. 回归体系持续加固 ★
- SCOPE 扫描器已入列（本次）；教训：静态断言会在「调用形态变化」时静默过期
  （见 09-21 日志 V4.33.4 教训 3）——`_verify/` 下依赖硬编代码字符串的断言建议逐步换成语义断言。
