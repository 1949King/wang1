# 抽卡闭环深度求索报告

> 复核日期：2026-09-27 · 对象：P0a–P4 已交付的生成抽卡闭环
> 方法：不采信「测试全绿」的自我证词，逐条到**真实代码 / 真实数据文件 / 真实图片**上找反例
> 结论：**闭环骨架成立，但有 4 处「看着接上了、其实没接上」的断裂**，其中 1 处正在污染闭环赖以运转的账本本身

## 一、DEFECT A：测试污染生产账本（**最该先修**）

### 现象

`data/draw_book.json` 里只有一个桶，`prompt_head` 赫然写着「**测试**」：

```json
{"47ea0125dfd86583": {
  "prompt_head": "测试", "model": "m1", "size": "1024x576",
  "n": 21.0, "mean": 0.5,
  "best_seed": 1145068911,
  "samples": [
    {"seed": 42, "score": 0.5}, {"seed": null, "score": 0.5},
    {"seed": 255331173, ...}, {"seed": 42, ...}, {"seed": null, ...},
    ... 共 21 条
  ]}}
```

21 条样本里，seed 全是 `42` / `null` / 随机自增三类——正是测试用例的取值特征，**没有一条来自真实用户抽卡**。

`data/quality_prior.json` 同样被写入一个假桶：

```json
{"seedance::default": {"mean": 0.588, "n": 54.0},     ← 真实
 "dashscope::default": {"mean": 2.1e-05, "n": 35.0},  ← 真实
 "c1::proxy": {"mean": 0.5, "var": 0.0002, "n": 21.0}} ← 测试污染
```

### 危害（为什么这条排第一）

- 这份账本正是 P2 推荐、P5 配方排行、quality_prior 路由的**唯一真相源**。
- 现在真实桶 `seedance::default`(n=54) 与 `dashscope::default`(n=35) 已经在积累**真实**数据——污染和真相**混在同一个文件**里，不是干净的空账本。
- 继续跑测试 = 每跑一次就往真相源里多灌一批 `score=0.5` 的假样本，把均值往 0.5 拽。**闭环越用越脏。**

### 根因

`app/tests/` 下的测试直接 import 真实 store（`draw_book.get_store()` / quality_prior），store 的路径是写死的（`data/draw_book.json`），没有测试隔离。

### 修法（两步）

1. **store 支持环境变量覆写**：`DRAW_BOOK_STORE_PATH` / `QUALITY_PRIOR_PATH`，缺省仍是 `data/` 下的正式路径。
2. **加 autouse conftest**：`app/tests/conftest.py` 里用 `monkeypatch.setenv` 把两个路径指向 `tmp_path`，所有测试自动隔离，零改测试用例。
3. 顺手清掉生产文件里的污染桶（`47ea0125dfd86583` 与 `c1::proxy`），**保留** `seedance::default` / `dashscope::default` 两个真实桶。

## 二、DEFECT B：Agent 生图不传 seed（闭环断）

`app/core/capability_handlers.py:133` 的 `generate_image`（对应能力 `canvas.generate_image`）签名里**完全没有 seed**：

```python
res = generate_image_openai_compatible(
    prompt=..., model=..., size=..., channel_id=...,
    reference_image=..., strength=..., quality=...,
)   # ← 没有 seed 参数
```

而底层 `canvas_aigc.generate_image_openai_compatible` 早已支持 seed 贯通（P0a 已做）。**结果：Agent 通过对话让画布生图，永远不可复现**——因为 seed 在能力层就被吃掉了。

`app/core/agent_capability_catalog.py:100` 的能力声明也只有一句话描述，无 seed 参数位。

### 修法

能力声明加 `seed` 参数；handler 从 `p.get("seed")` 取值透传。改动极小（两处各 1–2 行），但这是**闭环能不能从 Agent 侧闭合**的关键。

## 三、DEFECT C：前端零消费（人看不见闭环）

```

→ 仅 bridge.test.ts / bridge.ts 里有 seed_sent 的类型声明
→ recommendation / proxy_score / repair_plan 命中：0
```

这条**不是 bug，是未完成的工作**，且与 P6「候选选优 UI」同源——都需要动 `canvas-magnetic-intent` 冻结区（锁 33 整文件，含 `store.ts` / `nodes.tsx`）。当前挂起，等 P6 一起解冻做。

## 四、DEFECT D：默认横版尺寸 vs 竖屏短剧（**需拍板**）

代码里尺寸表（`app/core/canvas_aigc.py:265`）：

```python
"draft":    "1024x576",   # 16:9 横
"standard": "1024x576",   # 16:9 横 ← 默认走这个
"cinema":   "1920x1080",  # 16:9 横
```

且**整条链路五处硬编码同一横版默认**：

| 位置 | 值 |
|---|---|
| `canvas_aigc.py:610/637` 函数默认参数 | `1024x576` |
| `canvas_aigc.py:786/789/805/810/937` body 兜底 | `1024x576` |
| `canvas_server.py` payload 兜底 | 经 default 传入 |
| `bridge.ts:245` / `bridge.ts:608` | `opts.size \|\| "1024x576"` |
| `App.tsx:781/819` | `size: "1024x576"` |

**而产品是竖屏短剧**，规格是 9:16。

### 真实素材反证（实测）

对齐 `assets/avatar/*.png`（8 张真实角色图）——**全部是 `1024x1536`（2:3 竖版）**，由另一条路径产出。也就是说：**真正在用的素材是竖的，默认生图路径却产出横的**。

### 这需要用户拍板

不是纯技术问题，涉及产品语义：
- 选项 1：把 `standard` 默认改成竖版（如 `1024x1536` 或 `1080x1920`）；
- 选项 2：保留横版做通用能力，另设「短剧竖版」为画布默认档；
- 选项 3：按画布项目类型自动选档。

## 五、校准级发现（非缺陷，但会影响你把闭环当真理用）

### 5.1 代理评分在真实美术图上「饱和」

对 8 张真实角色图跑 `score_image`：

| 图 | total | non_broken | sharpness | composition | 坏区数 |
|---|---|---|---|---|---|
| … | 0.838–0.996 | 0.54–0.99 | **1.00** | **1.00** | 0 / 1 / 4 / 7 / 8 |

- `sharpness` 与 `composition` **双双恒定 1.00** ⇒ 这两个子项在当前阈值下**无区分度**，等于白占 35% 权重。
- 8 张**已知好图**被判出 0–8 个坏区 ⇒ 坏区检测在**风格化动画图**上偏噪（真人照片上更准）。

含义：**当前代理分可以用来看「整体有没有崩」，但不能用它细排优劣**。这恰好印证了当初「代理分只记不路由」的纪律是对的——现在更不能急着让它进路由。

### 5.2 好消息：桶位纪律守住了

`quality_prior` 里代理桶挂的是 `c1::proxy` 后缀，路由函数 `route_mean()` 只读 `"quality"` 与 `"default"` 两个标签——**代理分零路由影响**已由守卫脚本 `_verify/check_gen_ledger.py` 断言覆盖。这条防线没漏。
