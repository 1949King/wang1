## P0-1 · 额度池调度（你最缺的一块）

### 现状证据（确认「真的没有」）

| 位置 | 内容 |
|---|---|
| `app/core/ai/video_generation_client.py:70-115` | `generate()` 逻辑：`_resolve_provider_order()` 拿顺序 → for 循环试 → **成功 `break`** → 全失败 `_call_local_fallback()` |
| 同上 `:34-62` | 类只有 `_providers`（延迟加载缓存）与 `_output_dir`，**没有任何账号/配额/健康字段** |
| 同上 `:129` | `_resolve_provider_order()` = 纯名字顺序，**无配额判断** |

⇒ **一次调用 = 一次赌**：撞上死号就整段失败，只能落到 ffmpeg 占位片。

### 要做什么

新增 `app/core/ai/provider_pool.py`（纯逻辑，不 import app 包）：

```python
账号条目 = {
  "provider":     "seedance",
  "credential":   "key 引用（不存明文）",
  "daily_quota":  100,        # 每日配额
  "used_today":   12,
  "quality_tier": 0,          # 0=免费档 1=低价 2=高价（越大越贵越稳）
  "health":       "ok",       # ok / cooling
  "cooldown_until": 0.0,
  "last_used_at": 0.0,
}

选路顺序（同 provider 内）：
  ① quality_tier 降序        # 免费档参与轮换，但不优先
  ② daily_quota > used_today # 配额未耗尽
  ③ last_used_at 升序        # 最久未用优先（均衡）

失败处理：
  指数退避：60s 起 → 120 → 240 … 封顶 30min
  当场换号：提交失败 → 标记 cooling → 立刻取下一个健康号重提
  免费耗尽：降级/升档策略（见 P2 / 可配）

持久化：~/.shiguang/accounts.json（0600 权限 + 原子写）
```

### 接入点（改动最小）

- `video_generation_client.generate()` 里，把 `_resolve_provider_order()` 换成 `pool.resolve_order(provider, tier_hint)`
- 成功后 `pool.report_success(account)`；失败 `pool.report_failure(account)`

### 验收标准（可核对）

- [ ] 用一个「必失败」的假号 + 一个「能成功」的假号，`generate()` 能**自动换号并成功**（不再落 ffmpeg）
- [ ] 配 `daily_quota=1`，第 2 次调用**不再选它**
- [ ] 连续失败 3 次后，该号进入 cooling，`resolve_order()` 不再返回它
- [ ] 重启程序后 `used_today` 保持（持久化生效）
- [ ] 审计日志：每次选号记录**理由**（tier/配额/最久未用）

## P0-2 · 评分回写闭环（改动最小、收益最大）

### 现状证据

| 位置 | 内容 |
|---|---|
| `app/modules/lego/editor_ai_tools_mixin.py:280-305` | `_build_agent_score_card()` —— 打分**只渲染到卡片** |
| 同上 `:308+` | `_render_score_results()` —— 把结果写进 `QListWidget`，**没有写回任何存储** |
| `app/core/ai/prompt_templates.py` | 提示词模板**静态**，不随历史得分变化 |

⇒ **你的守护/质检已经能「发现问题」，但学不到任何东西**——同一个坑下次还会踩。

### 要做什么

新增 `app/core/ai/score_book.py`（纯逻辑）：

```python
评分簿条目 = {
  "style_dna":   "都市逆袭|冷色调",     # 风格命名空间（隔离）
  "dims":        {"一致性":0.8,"构图":0.7,"动作":0.6,"时长利用率":0.9,"风格符合度":0.8},
  "gains":       ["8K","无阴影","中性表情"],  # 本次用的增益组合
  "negatives":   ["多余分支","三通结构"],      # 本次用的负面词
  "score":       0.78,
  "retake":      False,                  # 是否被用户重拍（重拍 → 降权）
}

查询：score_book.best_combo(style_dna, dim) -> {gains, negatives, score, samples}
```

**闭环**：
```
生成 → 打分（现有）→ 写回评分簿
                        ↓
下次同风格生成前 → best_combo() → 自动选用历史高分组合
```

### 接入点

- `_render_score_results()` 末尾：`score_book.record(...)`
- `guard_pipeline.enhance_prompt()`：`negatives` 由 `score_book.best_combo()` 优先（而不是固定全量）

### 验收标准

- [ ] 打分后 `~/.shiguang/score_book.json` 出现条目（含增益组合）
- [ ] 同风格第 2 次生成时，选用的负面词/增益**与第 1 次高分组合一致**
- [ ] 用户点「重拍」后，该组合得分被**降权**（下次不再优先）
- [ ] 不同 `style_dna` **互不污染**

## P0-3 · 能力声明 + 自动路由

### 现状证据

- `video_generation_client.py:129` `_resolve_provider_order()` —— **只有名字顺序**
- 没有「这个 provider 支不支持图生视频 / 首尾帧 / 5 秒 / 1080p」的声明

⇒ 要生成「首尾帧」时，可能选中一个**不支持**的 provider，白试一轮。

### 要做什么

给每个 provider 加 **capabilities 声明**（照鲸影的 6 方法精简版）：

```python
capabilities = {
  "text_to_video":  True,
  "image_to_video": True,
  "first_last_frame": False,
  "lip_sync":       False,
  "max_duration":   10,
  "resolutions":    ["1080p"],
  "quality_tier":   1,
}
```

路由改为：**按需求筛选（capabilities 满足）→ 再按 P0-1 的额度池排序**。

### 验收标准

- [ ] 请求「首尾帧」时，声明 `first_last_frame=False` 的 provider **不出现在候选里**
- [ ] 请求 `duration=12` 而某 provider `max_duration=10` → 被过滤
- [ ] 新增一个 provider 只需**加声明**，路由代码零改动

## 建议路线（三批）

```
第 1 批（省钱的底座）：P0-3 → P0-1        # 先能选对，再能选好
第 2 批（会学习的守护）：P0-2 → P1-1      # 打分回写 + 报价确认
第 3 批（可控与沉淀）：  P1-3 → P2-1 → P2-2
```

**为什么这个顺序**：
- P0-3 先做（半小时级），因为 P0-1 的排序**需要 capabilities 当筛选条件**
- P0-2 独立于额度池，可与 P0-1 **并行做**
- P1-3（异步）会动到 `generate()` 签名，放后面避免反复改
