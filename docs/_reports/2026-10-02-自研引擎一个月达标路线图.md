# 自研执行引擎 · 一个月达标路线图

> 目标：**30 天内让自研引擎（builtin）达到可做主选的水平**，
> 然后把 `SHIGUANG_EXEC_ENGINE` 从 `primary(主选 DiffSynth)` 切到 **自研主用**。
> 基准：**DiffSynth**（Apache-2.0）· 编制日 2026-10-02 · 配套《自研执行引擎-开发者阅读文档》

---

## 第 1 章 先把「达到主选水平」定义清楚（否则是空话）

「和 DiffSynth 一样好」必须落成**可测数字**，否则一个月后无法判定是否达标。

### 1.1 五条硬指标（验收门）

| # | 维度 | 指标 | 判据 |
|---|---|---|---|
| **M1** | **显存** | 同模型同分辨率**峰值显存 ≤ DiffSynth 的 110%** | 两边的 `torch.cuda.max_memory_allocated()` 实测对比 |
| **M2** | **速度** | 同模型同配置**耗时 ≥ DiffSynth 的 80%** | 端到端墙钟（含加载，多次取中位数） |
| **M3** | **模型覆盖** | **视频 ≥ 7 族**（已达）+ **图像 ≥ 2 族**（当前为 0） | `discover_local_video_models()` + 图像侧同类函数输出 |
| **M4** | **量化** | 支持 ≥ 1 种低精度加载（**FP8 或 NF4**），使 8GB 卡可跑 **≥14B 级**模型 | 实跑出片 + 峰值显存记录 |
| **M5** | **稳定性** | 连续 **50 次**生成，显存**无单调增长**（无泄漏），失败率 0 | 自动化脚本 + 显存曲线 |

### 1.2 三条「不许丢」的自有优势（DiffSynth **没有**的）

补短板时**不能把长板砍掉** —— 这三样是自研存在的理由：

| 优势 | 说明 |
|---|---|
| **治理层 12 切片** | 预算影子价格 / 全球价格 / 质量先验 / 六级降级 / 评分账本 / 渠道池 / 融合 … **DiffSynth 完全没有** |
| **渠道统一** | 21 家云 + 本地走**同一个决策出口**（`decide_execution`） |
| **深度集成** | 画布节点 / inbox 落箱 / 编辑器时间线 / 抽卡账本 / 漫剧场景实测调优（motion_bucket_id=80 等） |

## 第 2 章 差距分析（对 DiffSynth）

| 能力 | DiffSynth | 自研现状 | 差距 | 归周 |
|---|---|---|---|---|
| **逐层磁盘卸载** | ✅ Layer 级**四态状态机**（offload→onload→preparing→computation） | ⚠️ 仅 `enable_model_cpu_offload` + 调 chunk | **大** | **W1** |
| **量化** | ✅ FP8/INT8/NF4，统一 `QuantizeConfig`（bitsandbytes / torchao / comfy-kitchen） | ❌ 仅 fp16 | **大** | **W2** |
| **图像侧本地能力** | ✅ FLUX/Qwen-Image/Z-Image/Krea-2/Ideogram4… | ❌ **完全没有**（图像只有云端） | **大** | **W3** |
| **统一下载** | ✅ ModelScope 直连 | ⚠️ HF 镜像为主（需绕代理） | 中 | **W3** |
| **跨 run 缓存 / 节点级重跑** | ✅ | ❌ 每次重新加载（约 15~18s） | 中 | **W4** |
| 多卡并行（USP/TP） | ✅ | ❌ 单卡 | 小（本机单卡） | 不做 |
| 训练（LoRA/全参/拆分） | ✅ | ❌ | 小（本项目暂不需要） | 不做 |

> **结论：W1（逐层卸载）+ W2（量化）是「显存」这条主线的两块基石，
> 也是 DiffSynth 被 ComfyUI 生态抄走的那部分 —— 必须自己补上。**

## 第 3 章 四周计划

### W1 —— 显存分级（最核心的一块）

**交付物**
1. `app/core/neural/memory_policy.py`
   ```python
   pick_memory_policy(model_id, frames, free_vram_gb, params_b) -> dict
   #   返回 {mode, decode_chunk_size, offload, quant, floor_gb, reasons}
   #   mode ∈ {"whole_gpu", "model_offload", "sequential_offload", "layer_disk_offload"}
   ```
2. `layer_disk_offload` 最小实现：按 UNet block 逐层 `to("cpu")`/`to("cuda")`（**hook 式**，不改模型结构）
   —— 参考 DiffSynth `AutoWrappedModule` 的思路，但**只实现推理所需的部分**
3. 接进 `video_gen.load()` 与 `local_video_infer`，替换现在散落的 `if vram_gb < N`

**验收**
- [ ] 8GB 卡上跑通 **Wan2.1-T2V-1.3B**（需下载，约 16.4GB）
- [ ] 四档 mode 各有**实测峰值显存记录**（写进 CHANGELOG）
- [ ] 与现有「调 chunk」方案对比：**大模型场景显存显著更低**

> ⚠️ 纪律 **R8**：每档都必须**实测定**，不得凭直觉（已有「offload 是瓶颈」「chunk 调大更快」两次被推翻）。

### W2 —— 量化加载

**交付物**
1. 选一个后端并接入（**优先 torchao 或 bitsandbytes**，均为宽松许可）
2. `memory_policy` 增加 `quant` 档：`none / int8 / nf4 / fp8`
3. 量化权重落 `app/models/cache`（沿用现有下载链路，**不要新建第二套**）

**验收**
- [ ] 同模型 NF4/INT8 加载成功出片
- [ ] **画质退化可量化**：与 fp16 逐帧 **PSNR ≥ 30dB**（低于此则不上线）
- [ ] 显存再降（目标 **≥40%**）

> ⚠️ 若量化后端与项目 `torch 2.6.0+cu124` 冲突 ⇒ **优先保 torch 不动**（GPU 加速链路的依赖），
> 宁可换后端也不换 torch。

### W3 —— 模型覆盖 + 统一下载

**交付物**
1. **图像侧本地能力**：新增 `local_image_infer.py`（与 `local_video_infer` **对称设计**，
   共用 `_has_weights` / `_scan` / 落箱逻辑 —— **抽公共部分，别复制**）
2. **下载统一**：`ModelScope 优先 → HF 镜像兜底`（国内直连优先，减少绕代理）
3. `discover_*` 与 `decide_execution` 打通（图像能力进 `CAPABILITY_IMAGE` 路由）

**验收**
- [ ] 至少 **2 族**本地图像模型可列出 + 可出图（记入 CHANGELOG）
- [ ] `_verify` 增加图像侧守卫（与 `VIDEOGEN` 同规格）
- [ ] 模型产出**全部经 `publish_to_inbox`**（**R5**：WebView 播不了本地路径）

### W4 —— 性能 + 稳定性 + **切回验收**

**交付物**
1. **跨 run 缓存**：同模型 pipeline 复用（省每次 15~18s 加载）
2. **稳定性脚本**：连续 50 次生成 + 显存曲线（放进 `_verify/`）
3. **切回**：写 `docs/_reports/2026-XX-XX-自研引擎达标验收报告.md`，
   逐条对照 M1~M5 填实测数字

**验收（切回门）**
- [ ] **M1~M5 全部达标**（或明确记录未达标项与理由）
- [ ] **三条自有优势未退化**（治理层仍生效 / 渠道统一 / 深度集成可用）
- [ ] 全量回归：`pytest` · `run_all_checks` · 冻结区 85 锁
- [ ] 切回后**连续 3 天**用自研跑真实工作流无回退

**切回动作**（一行）
```bash
SHIGUANG_EXEC_ENGINE=fallback   # 自研升为主用；DiffSynth 退为备选
```
若需**彻底换向**（把自研设为 `PRIMARY_ENGINE`），改 `execution_decider.py:267` 的常量即可 ——
但**建议先只改开关**，保留随时换回的能力。

## 第 5 章 风险与「不做」

### 5.1 主要风险

| 风险 | 应对 |
|---|---|
| **量化后端与 torch 2.6.0+cu124 冲突** | 优先保 torch；换后端而非换 torch（本项目踩过 pip resolver 卡死 20 分钟） |
| **逐层卸载把速度拖垮** | DiffSynth 自己也是「压显存换速度」；**必须同时记录耗时**，与 M2（≥80%）一起判 |
| **Wan 1.3B 下载 16.4GB** | 先确认网络与磁盘（当前 477GB 空闲）；走 ModelScope 可省绕代理 |
| 一个月内做不完 | W1/W2 是**主线**，W3/W4 可顺延；**切回门不降级**（M1~M5 缺一不切） |
| 补短板时丢了长板 | 每次改动都过一遍 §1.2 的三条优势 |

### 5.2 明确不做（沿用既定决策）

- ❌ **不引入 ComfyUI**（GPL-3.0 发行闸门；用户 2026-08-08 已定「明确不做」）
- ❌ **不引入 SGLang / vLLM-Omni**（需 ~384GiB 主机内存，与本机 15.3GB 差距过大）
- ❌ **不集成 Wan2GP**（自定义许可**禁商用**；可借鉴技术，不可集成）
- ❌ **不自研推理内核**（千万元级投入且打不过社区）
- ❌ **不追多卡并行 / 训练**（本机单卡、当前不需要）

### 5.3 与主选引擎的共存关系（过渡期）

```
现在：  SHIGUANG_EXEC_ENGINE=primary  → 主选 DiffSynth（未装 ⇒ 自动退自研）
W1-W3： 主选仍是 DiffSynth；自研边补边用（备选身份，保证不断供）
W4：    M1~M5 达标 ⇒ 切 SHIGUANG_EXEC_ENGINE=fallback ⇒ 自研升为主用
之后：  DiffSynth 退为备选，**随时可用一行切回**（双向可逆）
```

> ★ **双向可逆是关键**：任何一方出问题，一行配置即可切换，**不需要改代码、不需要回滚版本**。

## 附：本周就能开始的第一个动作

W1 的最小起步（**不需要先下载大模型**）：

1. 先建 `memory_policy.py` 的**骨架 + 档位判定逻辑**，用**已有的 SVD** 做基准验证
   （SVD 的实测数据已有：5 帧 4.66GB / 8 帧 5.58GB / 10 帧 6.2GB）
2. 把 `video_gen.load()` 里现有的 `should_offload()` / `decode_chunk_size` 判定**迁进**它
   —— 即先「收口」，再「增强」
3. 之后再接逐层卸载（这一步才需要下大模型验证）

> 好处：**第一周前半段零下载、零风险**，纯逻辑收口，且立刻可回归验证。
