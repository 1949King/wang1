## 一、诊断：弱在哪（实测，非推断）

### 0. 抽卡优化的九层体系（先定位"提示词"在哪一层）

**提示词只是第 3 层，且天花板明确。** 按性价比排序：

| 层 | 手段 | 效果 | 项目现状（实测） |
|---|---|---|---|
| 1 | **种子控制**（固定 / 搜索 / 黄金种子库） | **最猛**——同提示词换种子 = 换一张完全不同的图，且**可复现**；抽卡本质是「在种子空间搜索」 | ❌ **完全不支持**：`canvas_aigc.py` 生成链路与 `bridge.ts` 均无 `seed`（grep 仅命中 `seedance`/`seedream` 模型名） |
| 2 | 母版垫图（参考图 + 强度 + 一致性锁定） | 极强，治"变脸" | ✅ 有垫图 `canvas_aigc.py:608 reference_image`（图生图，失败降级文生图）；⚠️ 缺母版资产 |
| 3 | **结构化提示词**（模板 + 槽位 + 负面词） | 中，天花板明确 | ⚠️ 角色 prompt 自动拼装 ✅（`build_character_prompt`）、负面词 ✅（`anchor_negative` + `guard_all`）；但**生图侧无模板库**（`prompt_templates.py` 的 8 套模板是**智能剪辑**用的） |
| 4 | **参数组合沉淀**（模型/步数/CFG/尺寸/风格强度） | 中高，同提示词参数不同差异巨大 | ❌ 无（本方案 P0-P2 补） |
| 5 | 多候选 + 选优 | 中，省人眼时间 | 出多张 ✅（`bridge.ts:205` count 1~4）/ 选优 ❌ |
| 6 | **局部重绘替重抽** | 反直觉但极省 | ✅ 能力已有 `canvas_aigc.py:832 inpaint_via_host`；❌ **无策略**（现在 90% 好的图因局部崩就整张重抽） |
| 7 | 模型/渠道路由 | 中，按题材选模型 | ✅ 已有（provider 路由 + `quality_prior`） |
| **8** | **生成配方包（Recipe Pack）** —— **替代"ComfyUI 工作流固化"** | 中高：把「提示词模板 + 槽位 + 负面词集 + 模型/渠道 + 参数（尺寸/强度/步数）+ 后处理步骤」打包成一个**可按题材一键复用的配方**；配方级沉淀比提示词级更可复用 | ❌ **缺**（本方案 P5 补）。**不依赖 ComfyUI 引擎**，复用项目已验证的 `preset_manager` 美学包模式（`list_packs` / `apply_pack` / 可撤销 / 落盘） |
| 9 | 约束（负面词 / 结构守护 / 规格硬校验） | 兜底 | ✅ 守护族齐全（角色锚定 / 表情 / 道具 / 穿模） |

> **为什么第 8 层不用 ComfyUI 固化**（用户指定替换）：
> ComfyUI 是**重依赖**（需独立引擎 + 节点环境 + workflow 文件管理），且**只覆盖本地生成渠道**
> —— 云端 API 渠道无法执行 ComfyUI graph，导致"配方"与"渠道"绑死。
> 改用**配方包**后：配置是**声明式数据**（不绑定执行引擎），可跑在本地 ComfyUI、也可跑在云端 API；
> 且与 `preset_manager` 的既有模式一致（同一套 list/apply/撤销语义），学习成本为零。
> **ComfyUI 保留但降级**：作为"进阶用户的自由编排通道"（`comfy_provider.run_workflow` 不动），
> 不再是配方体系的主路径。

**约束的四种手段与现状**：

| 手段 | 现状 |
|---|---|
| 负面词（负向约束） | ✅ `anchor_negative` + `guard_all` 合并全量负面词 |
| 结构守护（防畸形） | ✅ 角色锚定 / 表情钳制 / 道具守护 / 穿模修复 |
| 一致性锁定（硬锁） | ⚠️ 检测端有（`character_anchor.diff_anchor` 漂移检测），**输入端缺母版** |
| 规格硬校验 | ⚠️ 部分（`pipeline.preview_validate` 有基础），缺漫剧规格（9:16 / 片段 ≤15 秒 / 单集时长） |

### 1. 「抽卡」拆三段：模型层不弱，弱在后两段

| 段 | 现状 | 证据（文件:行） |
|---|---|---|
| ① 出多张 | ✅ 已有 | `vendor/shiguang-canvas/src/bridge.ts:205` `count = Math.max(1, Math.min(4, opts.n \|\| 1))`；`App.tsx:855 onCompareGenerate` 双模型对比 + 叠卡切换 |

## 二、目标与边界

### 目标（本轮）

1. 生成结果**自动产生可追溯的质量代理分**，写入账本
2. 账本**按参数指纹**沉淀（提示词 / 模型 / 风格 / 种子），而不只是按 provider
3. 下次生成时能**查历史均分并给出推荐参数**
4. 把真值质量分**接进** `quality_prior` 既有通道（先记录、后影响路由，见 §五 红线）

### 明确不做（本轮）

| 不做 | 原因 |
|---|---|
| 候选选优 UI（画布前端） | 画布前端文件在冻结区，需解冻；**本方案纯后端** |
| 视频质量评分 | 图像先跑通；视频维度差异大（时长/动作连贯），单独一批 |
| 用 VLM 做「审美真值」 | 成本 + 违反项目既有红线「AI 打分禁当真值」 |
| 分发/回流 | 用户已确认不做（平台承担） |

## 三、设计

### 3.1 新增模块 A：抽卡账本 `app/core/ai/draw_book.py`

照 `quality_prior.py` 的既有范式写（分桶 EMA + RLock + 原子写 + 异常绝不抛出）。

```
数据文件：data/draw_book.json
键（参数指纹）：sha1( normalized_prompt | model | style_tag | size )[:16]
值：{
  "key": 指纹,
  "prompt_head": 前 60 字（人读用）,
  "model": "...", "style_tag": "...", "size": "...",
  "n": 观测次数,
  "mean": 质量均分（EMA，α 同 quality_prior）,
  "var": 方差（保留探索语义）,
  "best_seed": 得分最高的种子,
  "best_score": 该种子得分,
  "last_used": 时间戳,
  "samples": [{"seed":..,"score":..,"ts":..}]   # 上限 20 条环形
}
```

API：

```python
record_draw(prompt, model, score, *, seed=None, style_tag="", size="", kind="image") -> None
recommend(prompt, model, *, style_tag="", kind="image") -> Optional[dict]
    # {"key","mean","n","best_seed","best_score","advice"} | None（无数据返回 None）
stats() -> dict          # 总桶数/总观测/平均分
```

**淘汰策略**：桶数上限（如 500）+ LRU；`samples` 环形 20 条 —— 防止 JSON 无限增长。

### 3.2 新增模块 B：生成品代理评分 `app/core/ai/gen_critic.py`

**关键设计：只给「可测代理指标」，不假装审美客观分。**

| 指标 | 方法 | 权重 | 治什么 |
|---|---|---|---|
| 非崩图 | 颜色直方图分布 / 非单色 / 非纯黑 | 高 | 生成失败、糊成一片 |
| 清晰度 | 拉普拉斯方差（灰度） | 中 | 糊图 |
| 尺寸达标 | 与请求 size 一致性 | 中 | 参数未生效 |
| 构图中心度（可选） | 主体区域方差分布 | 低 | 大面积留白/切头 |
| 生成成本信号 | 耗时 / 是否重试 | 低 | 抽卡效率 |

输出：`{"score": 0~1, "detail": {...}, "is_proxy": True}`
—— **`is_proxy: True` 强制标注**，任何下游不得当审美真值（呼应红线）。

只依赖已装库（numpy / cv2 已在项目中使用，见 `preview_manager` 的 filter2D 用法）。

### 3.3 接线点（全部为**非冻结区**）

| 位置 | 改动 | 说明 |
|---|---|---|
| `app/core/ai/video_generation_client.py:608` | `record_outcome(name, ok)` → `record_outcome(name, ok, quality=score)` | **A 通电**（一行语义改动，路由侧 `:444` 的 q̂ 自动受益） |
| 图像生成收尾处（`canvas_aigc.generate_image_openai_compatible` 返回前 / 或调用方） | 落盘后调 `gen_critic.score_image()` → `draw_book.record_draw()` | 记录参数指纹与得分 |
| 生成入口（`/host/generate-image` 等，位于 `canvas_routes_post.py`，**非冻结区**） | 生成前查 `draw_book.recommend()`，命中则在响应体中附 `recommendation` 字段 | **B 推荐**；前端可暂时不显示，Agent 侧可立即用 |
| （可选，P2 后）App.tsx | 显示推荐参数 | ⚠️ **需解冻**，挂起 |

**不新增端点、不改前端** ⇒ 无需解冻，不破双库一致性。

### 3.4 数据流

```
生成请求(prompt/model/seed…)
   ├─→ [B] draw_book.recommend(prompt, model) → 命中则附推荐（含 best_seed）
   ↓
   provider 生成（本地/云端）
   ↓
   [评分] gen_critic.score_image() → score(0~1) + detail（is_proxy）
   ↓
   [A] quality_prior.record_outcome(provider, ok, quality=score)   ← 通电
   └─→ [B] draw_book.record_draw(prompt, model, score, seed=…, style=…)
```

### 3.5 新增模块 C：生成配方包 `app/core/ai/gen_recipe.py`（第 8 层的替代方案）

**定位**：把"抽卡"从「单次调参」升级为「**配方复用 + 配方选择**」。配方是**声明式数据**，不绑定执行引擎。

数据结构（`data/gen_recipes.json`，与 `preset_manager` 同款落盘语义）：

```json
{
  "id": "recipe_ancient_xianxia_portrait",
  "name": "古风玄幻 · 定妆照",
  "kind": "image",
  "slot_prompt": "【主体】{character}，{scene}，{action}。古风玄幻，电影感光效，竖屏构图",
  "negative_extra": ["多余手指", "水印", "变形肢体"],
  "model_hint": {"capability": "image", "prefer": ["<模型关键字>"]},
  "params": {"size": "1024x1536", "strength": 0.70, "style_weight": 0.80},
  "require_ref": true,
  "post_steps": ["consistency_check", "inpaint_retry"],
  "tags": ["古风", "玄幻", "定妆照"]
}
```

API：

```python
list_recipes(kind=None) -> List[dict]
get_recipe(recipe_id) -> Optional[dict]
render_prompt(recipe, slots: dict) -> {"prompt": str, "negative": List[str], "params": dict}
    # slots 由调用方填：character（走 build_character_prompt）/ scene / action
save_recipe(recipe) -> None          # 校验必填字段，重复 id 拒绝
apply_recipe(recipe_id, slots) -> dict   # 返回可直接喂生成入口的参数包
```

**与既有资产的关系（复用而非另起一套）**：

| 配方中的段 | 来源 |
|---|---|
| `{character}` 槽位 | `build_character_prompt`（角色库 visual 组 4 字段） |
| 负面词 | `anchor_negative` + guard 族负面词 → 与 `negative_extra` 合并 |
| 参数 | 直接进生成入口 payload（含 **P0a 的 seed**） |
| `post_steps` | `consistency_check`→`character_anchor.diff_anchor`；`inpaint_retry`→`inpaint_via_host`（P4） |
| 执行 | **仍是现有生成入口**（本地管道 or 云端 API 皆可），配方不引入新引擎 |

**执行链路**：

```
选配方 → render_prompt(角色库 + 槽位) → 现有生成入口 → gen_critic 评分
      → draw_book.record(recipe_id, seed, score) → 配方排行（哪类题材用哪个配方出片好）
```

**与 ComfyUI 的关系**：ComfyUI（`comfy_provider.run_workflow`）**保留但降级**为"进阶用户的自由编排通道"，
不再是配方体系主路径。配方可指向 ComfyUI 渠道、也可指向云端 API —— **渠道解耦**正是替换它的核心理由。

## 五、风险与红线

| # | 风险 | 处置 |
|---|---|---|
| 1 | **代理分误导路由**：`V = q̂ − λc·price` 会因错误评分选错渠道 | **两阶段上线**：P1 只写入、**观察期不改变路由行为**（路由可先读旧桶或加开关）；观察后再放开 |
| 2 | 代理分被当审美真值 | 所有输出带 `is_proxy: True`；文档与代码注释写明「仅供筛选与效率优化」 |
| 3 | 账本无界增长 | 桶上限 500 + LRU；samples 环形 20 |
| 4 | 指纹碰撞/归一化不当导致跨风格串桶 | 归一化规则显式写进测试（大小写/空白/同义风格标签）；指纹含 model+style 隔离 |
| 5 | 并发写 | 照 `quality_prior` 用 RLock + 原子写（tmp→replace） |
| 6 | 违反"静默 except 判定线" | 账本/评分所有异常路径用 `logger.debug(..., exc_info=True)` |

## 六、预期收益

1. **报告弱点 #1 被兑现**：质量先验从「可用性先验」升级为「带真值的质量先验」
2. **抽卡从运气变经验**：同一提示词/风格的最佳种子与参数可跨集复用
