## 2. 行业要点（TapNow / Comfy Agent）

### 2.1 ComfyUI 官方 **Comfy Agent**（2026-10-01 发布，本轮最大行业事件）

来源：blog.comfy.org/p/comfy-agent-the-first-agent-for-craft · comfyui-wiki.com（2026-10-06 获取）

| 能力 | 细节 | 对我们的含义 |
|---|---|---|
| **画布即动作面** | Agent 直接在**已打开的图**上选址、放节点、连线、跑图、改结构——**不是**给你一份 JSON 去导入 | 我们已有画布 Agent + 能力白名单；差距在**"让 Agent 真正改图"的覆盖度** |
| **可复用 skills** | 自己写技能、也能用公开预设技能 | 我们有 Skill 概念（提示词库/skill 导出），**缺"技能仓库/沉淀"** |
| **最多 5 个并行对话**（各自完整历史） | 多线程协作 | 我们 AgentPanel 是单会话 |
| **双向协作不互锁** | 你在编辑，agent 也在编辑，谁都不锁死对方；每个节点参数照旧可查 | 我们的审批/白名单模型更保守——**这是我们的特点，不必照抄** |
| **权限两档**（approval / auto） | ⚠️ 官方明确：**approved 只管"运行"，不等于每次画布改动都问你** | 我们已是**三档**（plan/collaborative/autonomous）+ dangerous 级 ⇒ **我们更细**，可对外讲 |
| **解释与调试** | 读整图 → 解释、指慢点、追错误 | 我们有医生式诊断，但**未做"读整图解释"** |
| 本地化路线 | 先 Cloud；Desktop 几周后；本地 GPU + 自定义节点更晚 | 我们**天生本地** ⇒ 是优势 |
| ⚠️ **隐私关键条** | 官方文档：**本地执行 ≠ 离线推理**——agent 的消息与相关画布信息**会走线上** | ⚠️ **我们必须自查并如实标注**：我们哪些环节出网（否则就是"假本地"，撞我们自己的诚实红线） |
| 生态 | 社区 `comfyui-mcp` 宣布**归档（10-09）**，让位官方 agent / **Comfy MCP（public beta）** | MCP 已成"Agent 接画布"的标准接口 ⇒ 我们**已实现 MCP 客户端**，应把**服务端接线**排期 |

### 2.2 TapNow（深圳添科智能，tapnow.ai）

来源：爱企查条目 / ima.qq.com 评测文 / converge.ai 评测（2026-10-06 获取，**官方宣称**）

- 定位：**AI 视觉创作平台 →「Creative OS」**（2026-09 大版本），主打**商业视觉生产**（广告/电商/影视）
- **Tapflow 画布**：节点式工作流，拖拽连接脚本/镜头/商品图 → 全流程自动化
- **Agent OS**（2026-06）：**无限上下文记忆 + 画布感知 + 把经验沉淀成「技能仓库」**；支持 Brainstorm 模式、**按用户偏好生成专属 Skill**
- **多模型协同**：Seedance 2.5 / Kling 3.0（含 Omni 4K）/ Gemini Omni Flash / Veo / Sora / Midjourney 自动匹配
- **Cinema Lab**：3D 空间操控 + 影棚布光；draw-to-video；故事板生成
- **TapTV 社区**：截至 2026 初**开源 12 万+ 公开工作流可克隆**
- 关键外部集成：给 Agent 开 **飞书 / Notion / Unsplash** 读取权限（读你的剧本链接）

**对我们的含义**：
1. 「**工作流配方可克隆的社区**」是行业共识 ⇒ 我们的 **B-12（配方包 `gen_recipe.py`）** 方向正确，且应把"可分享/可导入"当一等公民。
2. 「**把经验沉淀成技能仓库**」= 我们 Skill 能力的延伸，值得作为 Agent 侧下一阶段。
3. TapNow 的**多模型池**（含国产 Seedance/Kling）说明：**我们不缺模型（已接 15 provider），缺的是"自动匹配模型组合"**。

## 3. 三张截图功能逐项评估

### 3.1 图1 · 使用帮助（带「操作演示」动画 + ↺ 重播）

- **上游实现**：0.9.21 明确写了「更新使用手册」；面板为**画布内 React 组件**（左侧分区导航 + 右侧内容 + 顶部「操作演示」步骤条 + 右上 ↺ 重播）
- **我们的现状**：`app/modules/lego/help_module.py`（876 行，PyQt 侧文档式）+ 画布侧入口 `LibTvChrome.tsx`；**没有动画演示**；`help_module.py` 里 `QPropertyAnimation/QTimer` **零命中**
- **复刻可行性**：**高**。画布前端已经有成熟动画基础（磁吸回弹/过冲/落座动画、弹簧动效）⇒ 做一个「步骤条 + 依次点亮 + 连线绘制」的 CSS/React 动画，成本约 1 个组件 + 1 段演示数据
- **必要性：中**。理由：① 对**小白用户**（我们的目标用户画像）价值明确，属于"降低理解成本"；② 但**不解决任何闭环卡点**；③ 上游的价值一半来自**持续更新的手册内容**（0.9.21 专门发了"更新使用手册"）⇒ 我们若只做动画壳、内容不跟进，会变成一次性装饰
- **建议**：**做**，但要求 ① 内容与 `help_module` 单一真源（不许两份手册漂移）；② 动画演示的每一步**在真实画布上可重放**（点「观看演示」能高亮真实按钮），否则只是"看着动"的装饰

### 3.2 图2 · 输出历史（分类 + 搜索 + 固定面板）⭐

- **我们的现状：完全没有**（画布前端 `输出历史/OutputHistory/outputHistory` **零命中**）
- **但数据基础已存在**：
  - `app/core/ai/draw_book.py`（**抽卡账本**：prompt/model/score/seed/best_seed）
  - 画布节点产物（`imageUrl`/`videoUrl`/`audioUrl`）
  - `/host/generation/list`（生成任务表：kind/status/模型/耗时）
- **复刻可行性：低难度、高确定性**。要做的是：一个面板 + 四类过滤 + 搜索（匹配提示词/输出内容/模型）+ 固定开关；后端把 `draw_book` + 生成任务 + 画布产物**合一查询**（新端点 `/host/output-history`，纯读、可分页/搜索）
- **必要性：高** ⭐ 理由：
  1. **它补的正是"闭环的复盘端"**——我们做了抽卡选优、代理评分、全量入账，但用户**没有任何地方能看到"我抽过什么、哪张最好、用了什么提示词/种子"**；账本价值被锁在数据里
  2. 「**最佳种子复用**」是抽卡闭环的**兑现口**：账本里已有 `best_seed`，但用户拿不到 ⇒ 没有面板，抽卡闭环等于**半截**
  3. 与我们的刀序**同向**（A-2 抽卡选优已完成 ⇒ 这是它的自然收口），且**零冻结**（新组件 + 新端点）

### 3.3 图3 · 桌宠式 Agent 形象（可动）

- **我们的资产（已找到）**：`assets/mascot/shilan-主形象卡-v2-大姐姐.png`、`shilan-主形象卡-v3-成年比例.png`、`xiaoshi-主形象卡.png`、`assets/avatar/*.png`（4 张虚拟形象定妆）、
  副库 `public/prompts/shiguang-mascot.json`（**形象包 v7「职场秘书套装·含丝袜·端庄版」**）、`shiguang-avatar.json`；
  上游还自带 `src/components/chat/MascotAvatar.tsx`（**可对照**）
- **我们的现状**：Agent 是 **IM 面板**（`AgentPanel.tsx` + 人格设定「知心秘书」夹在 `agent_persona.py`）；**画布上没有常驻形象**
- **复刻可行性：高**（React 组件 + CSS 动画；素材已有；上游组件可参照）⇒ 按**零解冻**做法放 `App.tsx` 渲染的新组件（不进 `CanvasShell` 冻结文件）
- **必要性：中高**。理由：① 用户明确表达了偏好（"感觉挺好用""做成这样的"）；② 桌宠是**低成本高感知**的体验锚点，能把"Agent 存在感"从"要点开面板"变成"一直在"；③ 但**必须绑定真实状态**（思考中/生成中/待确认/失败/空闲各自不同动作），否则就是**随机效果**——这是项目明确拒绝的
- ⚠️ 注意：**"会动"不等于"随机动"**。建议的动作映射：空闲=呼吸+偶尔眨眼；思考=点头/转圈；生成中=进度环；**待确认=举手/闪动**（因为有审批闸门，这个状态最有价值）；失败=垂头

## 4. 建议的复刻优先级（我的判断）

| 序 | 项 | 为什么这个顺序 | 成本 |
|---|---|---|---|
| **1** | **输出历史面板**（图2）+ `/host/output-history` 端点 | 补闭环复盘端、兑现 `best_seed`、复用现成账本、零冻结 | 低 |
| **2** | **桌宠 Agent**（图3，绑定真实状态） | 用户明确偏好 + 资产已有 + 零冻结（挂 `App.tsx`） | 中 |
| **3** | **帮助操作演示动画**（图1）+ 内容与 `help_module` 同源 | 小白用户价值明确，但需内容持续跟进才有意义 | 中 |
| **4** | 连线自动 @ 上游素材（上游 0.9.21） | 低成本提质量，属"跟上游即可" | 低 |
| **5** | MCP **服务端**接线（上游有 MCP 场景写入；行业 MCP 成标准） | 我们客户端已实现、服务端欠账；生态正在向 MCP 收敛 | 中 |
| 暂缓 | 外观主题面板 / 逐镜工作台形态 / 本地 ONNX 管理面板 | 非闭环、低收益，或已有等价物 | — |

**不建议做的**：
- 照抄「Agent 与你同时编辑画布不互锁」——我们已有**三档审批 + dangerous 级**，比上游更保守也更安全；改成"不锁"会**削弱我们刚做的闸门**。
- 用「本地」当卖点却不标注出网环节——Comfy 官方都明确写了"本地执行 ≠ 离线推理"，我们必须自查并如实列出**哪些能力出网**（这是诚实红线，不是可选项）。

## 5. 一句话回复你的三个问题

1. **帮助能不能做到那个动态效果？** 能，且成本不高（画布前端已有成熟动画基础）；但我们**必须先解决"手册内容单一真源"**，否则动画只是壳。
2. **输出历史搜索需不需要加？** **需要，而且最该先做**——它是我们抽卡闭环**唯一缺失的复盘端**，数据（账本/产物/任务表）**都已经有了**，只差一个面板 + 一个只读端点。四类过滤 + 搜索 + 固定面板都是小工作量。
3. **桌宠 Agent 做不做？** **做**，资产（shilan/xiaoshi 主形象 + 形象包 v7）已在库里；关键是**动作要绑定真实状态**（尤其「待确认」状态），否则就变成你明确不要的"随机效果"。
