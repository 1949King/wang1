# 团队协作：对标调研与新版方案

> 调研时间：2026-11-04 ｜ 对象：拾光剪影 `app/core/team_*` + `vendor/packages/libtv/src/TeamPanel.tsx`
> 竞品证据强度：官方定价/帮助页 > 官方产品页 > 第三方评测（后者单独标注）

---

## 0. 一句话结论

**现在的团队协作是「局域网文件搬运层」——能传、能锁、能交接；缺的是「审阅—批准—交付」这条创作流程层，和「权限—通知—在线状态」这条组织层。**

对标六家之后，唯一与我们「本地优先 + 零云成本 + 局域网」架构相容、且性价比最高的是：

> **DaVinci 的锁 + Frame.io 的审阅链接**。
> 不是 Figma 的实时协同（那需要 CRDT + 云端常驻 + 带宽，我们的架构和成本都撑不住，收益也有限）。

理由在 §3 展开。先说现状——用代码说话。

| 能力 | 实现 | 评价 |
|---|---|---|

### 1.2 三个致命空洞（都有代码证据）

**① `role` 是装饰品，不参与任何鉴权。**

`role` 只在三处出现：建表默认值（`team_hub.py:266`）、写入（`:381-384`）、`auth()` 返回（`:386-393`）。全库**没有一处**按 role 拒绝操作。后果：
- 任何拿到令牌的人都能 `push`（覆盖项目）、`handoff`（把项目转给别人）、`delete_asset`（删素材）。
- 所以**不敢给客户、外包、实习生开账号** —— 一开就是全权限。这是团队功能最大的天花板。

**② 全库零「评论 / 审阅 / 审批」代码。**

`grep -l "comment|review|approve" app/core/team_*.py app/core/canvas_routes_team.py` → **无命中**。
意味着：同事看完片只能在微信里说「第 3 秒那个转场再快点」，没有任何一条意见留在项目上。版本再多也无法回答「这一版为什么被否」。

**③ 没有任何「在线状态」。**

不知道谁在线、谁正在改哪个项目、锁在谁手上（只有项目列表里那一行 🔒）。所有协调靠人喊。

### 2.2 四家值得抄的「具体做法」

**Frame.io —— 审阅链接的五个细节**（官方定价页 / 功能页）
1. **链接不换，版本往上堆**：同一项目反复迭代，客户永远点同一个链接，看到最新版，且能翻旧版对比。
2. **评审者不占席位**：客户、导演、甲方不需要账号、不需要付费席位（VEED 也明确「review mode 不占席位」）。
3. **链接本身就是权限对象**：可设密码、可设过期时间、可禁下载、可隐藏历史版本。
4. **内部评论 vs 客户评论分离**：团队内部吐槽和给甲方的意见不在同一个流里，避免事故。
5. **会话水印**：把观看者的邮箱/IP 打进画面，防泄露追责。

**DaVinci Resolve —— 锁的正确粒度**（Blackmagic Cloud / Project Server 文档 + 第三方部署指南）
- 锁的是 **bin 和 timeline**，不是整个工程：别人锁了 A 箱，你照样能改 B 箱。
- **live save**：改动实时进数据库，不靠人记得保存。
- **时间线对比**：别人改完不直接盖你，先给你看差异，逐条接受或整段合并。
- 项目库（元数据）与媒体（素材）**分开**：共享工程 ≠ 共享素材，这是实操里最大的坑。

**Canva —— 品牌治理**（官方 Brand 页面）
- Brand Kit 一个团队管多个品牌；Brand Templates **锁死元素**（只留文案和图片可改），非设计人员也不会跑版；**Approver** 角色 + 下载限制。

**剪映 / CapCut —— 反面教材里也有可抄的**
- 剪映小组云空间：打开项目时其他人看到「正在编辑」——**成本极低的 presence**，值得抄。
- CapCut Teams：官方明确「同一时间只有一人持有编辑权限，可转移」——这就是我们该走的档位。
- 但剪映是**手动上传 + 冲突靠人协调**，CapCut 的团队治理只在网页端能做、桌面端不能邀请成员。这两条我们不抄。

### 2.3 一个反直觉的结论

**越专业的视频工具，越不做「实时多人同时间线」。**
DaVinci 用锁，Premiere 用序列交接 + Frame.io，CapCut 用单编辑权转移。只有 Figma 这类「小对象、低帧率、可自动合并」的设计工具才做真实时。

视频项目 = 大二进制 + 时间轴强耦合 + 无法语义合并 ⇒ **实时协同在这里是负资产**。
所以我们选的路线不仅省钱，而且是**专业工具的主流选择**。

## 3. 差距诊断：缺的不是功能，是三层

```
        ┌─────────────────────────────────────────┐
  缺    │ L3 流程层：审阅 → 批准 → 交付            │  ← 完全空白
        ├─────────────────────────────────────────┤
  缺    │ L2 组织层：权限 / 通知 / 在线状态        │  ← 只有雏形
        ├─────────────────────────────────────────┤
  有    │ L1 数据层：成员 / 项目 / 版本 / 素材     │  ← 骨架不错
        └─────────────────────────────────────────┘
```

**顺序很重要**：先补 L2 的权限，否则 L3 的审阅链接等于把项目裸奔给任何人；先补 L2 的通知，否则 L3 的审批没人知道。

## 4. 新方案：四层架构 + 一条主线

### 4.1 主线：一个项目的一生

```
草稿 draft ──提交审阅──▶ 内部审 in_review ──▶ 客户审 client_review ──▶ 批准 approved ──▶ 交付 delivered
   │                        │                      │                      │
   │                     批注/@提及            审阅链接(免账号)         审批留痕            交付包+回执
   │                        │                      │                      │
   └──────────────── 每一次状态变化都产生一条通知 + 一条审计记录 ────────────────┘
```

**这一条线，就是「团队协作」和「文件共享」的分界线。** 现在缺的就是它。

### 4.2 四层各自要装什么

| 层 | 内容 | 对应竞品 |
|---|---|---|
| **L1 数据层**（已有，补强） | 内容寻址素材、不可变版本、服务端 diff、项目锁 | DaVinci / Frame.io |
| **L2 组织层**（重点补） | 权限矩阵、访客席位、通知中心、在线状态、审计日志 | Figma / Penpot |
| **L3 流程层**（从零建） | 批注（时间码+节点锚定）、审批状态机、审阅链接、交付包 | Frame.io / Canva |
| **L4 接入层** | 双向设备发现、长期邀请链接、手机只读页、IM 通知 | 剪映 / CapCut |

## 6. 三个关键机制（要拍板的）

### 6.1 权限矩阵（`role` 终于有用了）

| 动作 | owner | editor | reviewer | guest |
|---|---|---|---|---|
| 看项目/版本 | ✓ | ✓ | ✓ | ✓ |
| 拉取项目 | ✓ | ✓ | ✗ | ✗ |
| 推送新版本 | ✓ | ✓ | ✗ | ✗ |
| 认领/释放锁 | ✓ | ✓ | ✗ | ✗ |
| 删素材 | ✓ | ✓ | ✗ | ✗ |
| 写批注 | ✓ | ✓ | ✓ | ✓ |
| 批准 | ✓ | ✗（可配） | ✗ | ✗ |
| 交接 | ✓ | ✓ | ✗ | ✗ |
| 改成员/权限 | ✓ | ✗ | ✗ | ✗ |
| 启停服务 | ✓ | ✗ | ✗ | ✗ |

落地纪律：**enforce 写在端点入口，不写在业务函数里**（否则新端点一定漏）。用一张 `ROUTE_PERMISSIONS` 表 + 一个装饰器，测试里断言「每个已注册路由都在这张表里」——**新增端点不登记就红**。

### 6.2 审阅链接（最值得做的一件）

```
http://192.168.1.4:18770/review?t=<24位>        ← 给客户/导演，不需要账号
```
- **三种令牌严格分开**：邀请令牌（能进团队）、审阅令牌（只能看+评这一个项目）、成员令牌（API 全权）。混用等于把钥匙和门禁卡做成一张。
- 链接属性：密码 / 有效期（1天/7天/长期）/ 是否允许下载 / 是否显示历史版本 / 是否允许留批注。
- 打开后看到的是**播放器 + 时间轴标记 + 批注栏**，不是文件列表。
- 所有批注带 `rev`，版本更新后旧批注仍在，但标注「此条属于 v3」。
- 这是唯一能让「甲方」参与进来又不用装软件、不用注册、不占席位的机制 —— **Frame.io 的全部商业价值就在这一条**。

### 6.3 并发编辑：我们选「1.5 档」

| 档 | 做法 | 成本 | 适配我们 |
|---|---|---|---|
| 0 档 | 无锁，靠人喊（现在的剪映） | 0 | ✗ 已经会覆盖 |
| **1 档** | 项目锁 + 冲突检测（**我们现在就在这**） | 低 | ✓ 但粒度太粗 |
| **1.5 档（推荐）** | 项目锁 + **节点级软冲突提示** + 服务端 diff 合并助手 | 中 | ✓✓ 最优 |
| 2 档 | 分支 + 显式合并（Figma 企业版） | 高 | 慢 |
| 3 档 | 实时 CRDT 共编 | 极高 | ✗ 与本地优先冲突 |

**1.5 档具体长什么样**：
- 认领时不是「整个项目归你」，而是**列出你正在改的节点集**（前端把当前选中/编辑的节点上报）。
- 别人认领时看到的不是「锁了」，而是「张三正在改 `场景3 / 镜头7`」，冲突区以外你照样能改。
- 推送前服务端用已有 `diff` 算一次：与最新版有交叠 ⇒ 弹「这三处会覆盖别人的改动，逐条选：保留我的 / 用他的 / 都要」。
- **不做自动合并**：视频时间线的自动合并几乎必然出错，宁可让人点三下。

## 7. 路线图（5 刀，按依赖排序）

| 刀 | 内容 | 为什么排这里 | 验收 |
|---|---|---|---|
| **刀 1 · 地基** | 权限矩阵 + owner 自动引导 + 令牌分域 | 没有权限，后面每个功能都要返工 | 用 reviewer 令牌调 push 必须 403；路由覆盖率测试 100% |
| **刀 2 · 邀请与发现** | 双轨邀请（24h 链接 + 6 位码）+ 双向设备发现 + 主机批准 | 上一轮已批准，直接并入 | 两台机器互见；拿链接免确认进；近场申请需批准 |
| **刀 3 · 批注** | comment 表 + 时间码批注 + 线程 + @提及 + 通知中心 + 红点 | 审阅的最小可用形态 | 在时间线第 3.2 秒留批注，同事面板收到红点并能跳转 |
| **刀 4 · 审阅链接** | `/review?t=` 播放器页 + 链接属性（密码/过期/禁下载）+ 版本堆叠 | 杀手锏，但依赖刀 1 的令牌分域 | 手机浏览器打开链接可看片、留批注、切版本；无账号 |
| **刀 5 · 审批与交付** | 审批状态机 + 批准留痕 + 交付包 + 审计日志 | 有批注才知道在批什么 | 一条项目走完 draft→approved→delivered，全程有记录 |

每刀独立可验证、可回滚；每刀结束跑一次「真机两台设备」验收，不接受只跑单测。

## 9. 明确不做（防摊大饼）

| 不做 | 理由 |
|---|---|
| 实时 CRDT 共编 | 与「本地优先、无云常驻」冲突；视频项目无法语义合并；DaVinci/CapCut 也不做 |
| 多租户 SaaS 计费 | 现阶段是工具不是平台；先做席位概念，不做账单 |
| 手机端剪辑 | 手机只做「看 + 评 + 批」，这是 Frame.io 验证过的分工 |
| Avid 级 MAM（媒体资产管理系统） | 我们没有磁带库/多版本代理/审片室那套需求 |
| 把「短剧连续性」当护城河 | 已有教训：产品是通用创意生产工具，不是短剧工具 |

## 10. 与上一轮已批准计划的关系

上一轮批准的「双轨邀请 + 同网双向设备发现」**不废弃**，作为本方案的：

- **刀 2** 的主体（邀请链接 + 设备目录 + 主机批准）；
- L4 接入层的 #34 / #10。

差异只有一处：本方案要求它**排在权限矩阵之后**（原计划是刀 0/1 先做邀请）。理由：邀请做出来但对方进来是全权限，等于把洞挖得更大。owner 自动引导仍可先做（它不涉及放人进来）。
