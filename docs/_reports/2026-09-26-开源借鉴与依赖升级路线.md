| **缺失（essentials 不含）** | **`af_whisper`** · **`scale_vulkan`** · **`nlmeans_vulkan`** · **`h264_vulkan`** · **`av1_vulkan`** |
| MLT | ctypes 直调 `libmlt-7.dll`（本机可用）；**MLT 版本未调研，列为待办** |

### 2.2 FFmpeg 8.0 带来的、与本项目相关的亮点

> 来源：ffmpeg.org 官方发布说明（8.0 "Huffman"，2025-08-22；8.0.1 / 8.1 后续）

| 亮点 | 对本项目的直接价值 |
|---|---|
| **`af_whisper` 滤镜（FFmpeg 内直接 ASR）** | 项目现在走 `faster-whisper` + `whisper_asr.py` + `subtitle_generator.py` 自建链路；FFmpeg 原生滤镜可**少一层依赖与一次中间文件** |
| **Vulkan compute 编解码**：`h264_vulkan` / `hevc_vulkan` / **`av1_vulkan` 编码（8.0 新增）** / VP9 解码 | 跨厂商（AMD/Intel/NVIDIA 通用），不锁厂商；项目现在只有 NVENC（`rc=vbr, cq=crf`）+ QSV 两条路 |
| **GPU 滤镜**：`scale_vulkan` / `pad_cuda` / `scale_d3d11` / `nlmeans_vulkan` | 文档记录「滤镜长片仍可能卡」⇒ GPU 滤镜是最直接的解法 |
| `colordetect` 滤镜 | 可用于 `highlight_detect.py` 的场景/色彩切换检测 |
| `ebur128` 响度 | 成片响度标准化（交付合规） |
| `libplacebo` | HDR→SDR tone mapping |
| AVX-512 专项优化 + 改用 NASM | CPU 路径提速 |

**⇒ 结论：不是「要不要升 FFmpeg」（已经是 8.0.1），而是「换掉 essentials 这个精简版」。**
项目里**已有 `install_ffmpeg_btbn.ps1` / `install_ffmpeg_manual.ps1`**（BtbN 通常是 full build）—— 说明装 full 的路子早就准备好了，只是没落地。

## 四、依赖链：numpy「钉死」的理由已经失效（最重要一项）

### 4.1 依赖链真相（本机实测）

```
librosa 0.11.0          ←── 项目 4 处直接使用：
   │                        · app/core/ai/audio_emotion_analyzer.py:33,34
   │                        · app/core/local_asset_manager.py:263
   │                        · app/modules/lego/smart_editing_engine.py:597
   └─ numba 0.64.0      ←── 项目 **0 处直接 import**（纯传递依赖）
        └─ numpy <2.1   ←── 这就是 numpy 被钉死在 1.26.4 的**唯一原因**
```

`pip show numba` 实测：`Required-by: librosa` —— **项目自己从不 import numba**。

### 4.2 约束条件已变化

| 包 | 版本 | 日期 | numpy 约束 |
|---|---|---|---|
| numba（本机） | 0.64.0 | 2026-02-18 | `<2.1`（旧约束的来源） |
| numba | 0.65.x | 2026-04-01 | 放开 |
| **numba** | **0.67.0** | **2026-08-11** | **支持 NumPy 2.5**，依赖声明只剩 `numpy>=1.22` |
| **librosa** | **1.0.0** | **2026-08-11** | **强制 `numpy>=2.1.0`**（自己就要求 numpy 2！） |

> ⇒ **项目文档 §2b 的「升 numpy 2.x 会连锁炸整条 AI 链」这条结论，前提已经不存在。**

### 4.3 前置条件核查：**10/11 已满足，只差 numpy**

| librosa 1.0 要求 | 本机实测 | |
|---|---|---|
| python ≥3.12 | **3.12.10** | ✅ |
| numba ≥0.61 | 0.64.0 | ✅（但需另升到 ≥0.65 才支持 numpy 2） |
| scipy ≥1.15 | **1.17.1** | ✅ |
| scikit-learn ≥1.6 | **1.9.0** | ✅ |
| soundfile ≥0.12.1 | **0.14.0** | ✅ |
| soxr ≥1.0.0 | **1.1.0** | ✅（已装） |
| joblib / pooch / lazy-loader / msgpack | 1.5.3 / 1.9.0 / 0.5 / 1.2.1 | ✅ |
| **numpy ≥2.1.0** | **1.26.4** | ❌ **唯一拦路石** |

### 4.4 升级包（三者必须一起动）

```
numpy    1.26.4  →  2.x
numba    0.64.0  →  ≥0.65（建议 0.67.0，2026-08-11）
librosa  0.11.0  →  1.0.0（2026-08-11）
```

### 4.5 ⚠️ 破坏性变更清单（必须逐项回归）

> 来源：librosa 官方 1.0 发布说明 + 1.0.0 PyPI 元数据

| 变更 | 影响面 | 本项目受影响点 |
|---|---|---|
| **`amplitude_to_db` / `db` 相关 stereo 行为变化**（`ref` 语义修正，**影响 MFCC 计算**） | 数值结果会变 | `audio_emotion_analyzer.py`（**情绪分析依赖音频特征 ⇒ 最需要回归**） |
| sparse **matrix → sparse array** | 返回类型变 | 若用到 chroma/harmonic 相关函数的返回值解析 |
| **移除 `audioread` 后端**（全走 `soundfile`/libsndfile） | mp3 加载路径变化 | `librosa.load` 若有 mp3 输入（libsndfile ≥1.2.2 已支持 mp3） |
| 移除 `filters.constant_q` → 用 `wavelet` | API 移除 | 若有使用 |
| `random_state` → `rng`（SPEC7） | 参数名变更 | 若有使用 |
| `display.waveshow` 的 `x_axis` → `axis`；`cmap` → `infer_cmap` | API 变更 | 若画波形图 |
| `stream(filename=)` → `path`；`vqt(res_type)`；`yin/pyin(win_length)` | API 移除 | 若使用 |
| Python 下限升到 **3.12** | — | ✅ 本机 3.12.10 已满足 |

**另需实测确认**：
- `torch 2.6.0+cu124` 与 numpy 2 的互操作（PyTorch 2.3+ 官方支持 numpy 2，需实跑验证）
- `opencv-python-headless 4.13.0.92` 与 numpy 2（4.10+ 支持）
- `mediapipe 0.10.21` / `easyocr 1.7.2` / `onnxruntime 1.20.1` 与 numpy 2

### 4.6 收益

- 摆脱「被传递依赖绑架」的状态（numba 的 numpy 上限不再卡住整条链）
- numpy 2.x 的性能与内存改进
- librosa 1.0 的 SPEC0/SPEC1/SPEC7 现代化（活跃维护线）

## 七、本轮的三处自我纠正（重要）

| # | 我一开始的判断 | 实测结论 | 纠正 |
|---|---|---|---|
| 1 | 怀疑「venv 是 3.13 但 `.pyd` 是 cp312 ⇒ C++ 引擎 ABI 不匹配、静默降级」 | venv 实为 **Python 3.12.10**（3.13 是我跑脚本用的托管运行时）；`CPP_ENGINE_AVAILABLE = True`、`is_cpp_engine_available() = True` | **无 ABI 问题，C++ 引擎正常** |
| 2 | 一度以为 numpy 钉死是「多个库联合约束」 | 实测唯一原因就是 `librosa → numba 0.64 → numpy<2.1`；而该约束**已随 numba 0.67 / librosa 1.0 失效** | 从「不能升」改为「**有明确解锁路径**」 |
| 3 | 怀疑「文档说前端已打补丁，但 package.json 写的是旧范围 ⇒ 补丁没落盘」 | lock 解析为 12.11.6 / 19.3.0 / 5.0.15，与文档一致（`^` 范围允许） | **文档准确，补丁已生效** |

> 三处都是「先怀疑、后实测、再纠正」。**规律复用**：凡涉及版本/兼容性，必须查 `pip list` / `package-lock.json` / 二进制实测，不能靠语义推断。
