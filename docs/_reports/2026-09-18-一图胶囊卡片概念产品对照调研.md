# 「一图胶囊卡片 + 磁吸成关系」概念的产品对照调研

日期：2026-09-18
问题：市面上有没有和小白模式「一图胶囊卡片」概念**完全相同**的产品？
结论：**没有完全相同者**，但有 4 类产品各占其中一部分，覆盖并集几乎等于你的全部设计。

---

## 一、先定义「完全相同」的判据

把「小白模式」拆成五层。只有五层全中的产品，才能说「完全相同」。

| 层 | 含义 | 在代码中的落点 |
|----|------|--------------|
| **L1 卡片形态** | 缩略图为主视觉 + 一条胶囊承载元信息 | `NoviceCard.tsx` `.nv-card-thumb` + `.nv-capsule` |
| **L2 连接方式** | **拖近即吸附成关系，不画连线**；空间邻接本身即语义 | `MagneticEngine` + `bonds.ts`，`flowEdges` 在小白模式置空（`CanvasShell.tsx:535`） |
| **L3 参数降维** | 专业参数收进折叠层（L1 导演参数 / L2 按类型 / L3 专业） | `NoviceInspector.tsx` |
| **L4 生成闭环** | 卡片本身就是生成任务，结果回填同卡（多版本层叠） | `pushLayer` / `CardStack.ts` |
| **L5 档位切换** | 小白/专业**共用同一份 nodes**，不重建画布 | `buildNoviceNodeTypes`（`novice/index.ts:16`），`editorTier` |

---

## 二、四类产品对照

### 类别 A：节点式 AI 生成画布（覆盖 L1 + L4）

这是**最接近**的一类，也是竞争最激烈的。

| 产品 | 卡片形态 | 连接方式 | 档位切换 | 与你的差异 |
|------|---------|---------|---------|-----------|
| **ComfyUI** | 节点是**参数块**，不是「一图卡片」；缩略图只是输出预览 | **必须拉线**（dataflow 图） | ❌ 只有专业态 | 无小白档；节点是算子不是内容卡 |
| **Krea Nodes** | 节点含实时预览图（**实时生成**是招牌） | 拉线 + 并行分支 | 🟡 有模板降低门槛 | 无「磁吸成关系」；有 prompt→workflow |
| **Flora** | 无限画布 + 节点 | 拉线，支持分支对比 | ❌ | 有 in-canvas agent（FAUNA）自动连线 |
| **Wireflow** | 节点 + **REST endpoint** | 拉线 | ❌ 面向开发者 | 「画布即 API」，157+ 节点 |
| **Figma Weave**（原 Weavy） | 节点 + 合成能力 | 拉线 | ❌ 面向设计团队 | 有品牌守则（brand guardrails） |
| **Magnific / Freepik Spaces** | 节点画布 + 素材库 | 拉线 | ❌ | 素材库是护城河 |
| **Runway Workflows** | 节点流水线 | 拉线 | ❌ 视频优先 | 运镜/运动预设是一等公民 |

**关键发现**：这一类的**共性缺陷**恰好是你在解的题——
- Flora 官方文章自己承认：「**Nodes front-load a cost: you have to think in graphs before you've earned a reason to**」（节点前置了成本：在你还没挣到理由之前，就得先学会用图思考）
- 同文承认有些工具「ship a wizard and bury the graph, which builds a dead end」（发个向导然后埋掉图，结果是死胡同）

**你的 L5（档位切换）正是对这一缺陷的正面回答**——但这一类产品**没有一个做了**。

### 类别 B：AI 分镜/故事板画布（覆盖 L1 + L4，且**业务域与你完全重合**）

这是**最需要警惕**的一类，因为做的是同一件事（短剧/影视分镜）。

| 产品 | 卡片形态 | 连接方式 | 与你的差异 |
|------|---------|---------|-----------|
| **Storyflow** ⭐ | 「Every frame is a real card」——**无限画布上的卡片式分镜**，可拖拽/重排/换色/批注 | **靠位置排序**（拖拽重排 = 顺序），**不拉线** | 最接近！但**没有磁吸吸附**，靠自由拖拽 + 位置表达顺序 |
| **upuply** | 「storyboard panels live as **nodes on a canvas**」 | 节点式 | 节点画布 + 参考图并置 |
| **Boords** | 固定网格分镜 + animatics | 网格顺序 | 传统分镜工具（G2 4.8/5） |
| **StudioBinder** | 分镜内嵌制片软件 | 制片流程 | 分镜只是制片的一环 |
| **Miro Storyboard AI** | 无限画布 + 分镜卡 | 自由摆放 | 白板基因，非生成软件 |
| **Sora 2 Storyboard** | **时间轴上的卡片**（每卡 = 视频一个时刻） | 时间轴顺序 | 卡片在时间轴而非二维画布 |

**Storyflow 是最值得研究的对照**。它的原话：

> "Most storyboard tools box you into a fixed grid of panels on a page... Storyflow builds the storyboard on an open infinite canvas instead. **Every frame is a real card you can drag, reorder, recolor, and annotate**, so the sequence bends to the edit rather than snapping to a template."

**差异点**：
- 它的「重排」是**自由拖拽到新位置**，没有磁吸吸附、没有咬合阻力、没有「贴合成关系」
- 它的排序靠**位置顺序**（"Reorder by dragging: Move a frame and the sequence follows"）
- **它没有把「空间邻接」升格为关系语义**——这正是你 L2 的核心

### 类别 C：白板/画布 SDK 的吸附系统（覆盖 L2 的**算法**，但不含 L4）

| 产品/库 | 吸附能力 | 与你的关系 |
|---------|---------|-----------|
| **tldraw** | 6 吸附点/轴（minX/midX/maxX/minY/midY/maxY）、**分轴独立判定**、对齐辅助线、`gridSize=10` 原子单位、`Alt` 键临时禁用吸附 | ⭐ **算法可直接借鉴**（详见《拖拽卡顿与吸附排查》报告） |
| **Miro / Mural** | 智能辅助线、网格吸附 | 白板场景，无生成闭环 |
| **dnd-kit** | `createSnapModifier` / `snapCenterToCursor` Modifier 机制 | 架构借鉴：吸附写成纯函数 |
| **Windows 11 Snap Layouts / PowerToys FancyZones** | 预览矩形 + 松手落座 | ⭐ **手感标杆**（你 V4.28.0 已选定为对标） |
| **GNOME Tiling Shell** | 复刻 Win11 Snap Assistant，拖动时显示布局 + 高亮 tile | 参考「预览先到位」 |
| **SmartGrid**（Windows，纯 Python） | 「拖标题栏 → **蓝色预览矩形** → 松手 snap 到预览位置」 | 参考「预览矩形」这一手 |

**关键**：这一类有你要的**吸附手感和算法**，但**全都不含生成闭环（L4）**——它们是通用工具，不是创作软件。

### 类别 D：卡片式生成工具（覆盖 L1 + L4，但无画布）

| 产品 | 形态 | 差异 |
|------|------|------|
| Sora 2 Storyboard | 时间轴卡片 | 一维时间轴，非二维画布 |
| OpenArt / Leonardo AI | 网格卡片 + 复用流 | 网格/列表，非空间画布 |
| Taskade | 卡片 + 任务 | 生产力工具基因 |

### 三句话总结

1. **「节点式 AI 画布」有一堆**（ComfyUI / Krea / Flora / Wireflow / Weave / Freepik），但它们**全都要求拉线**，而且**都没有小白档**——Flora 自己写文章承认这是「死胡同」。
2. **「卡片式 AI 分镜」有 Storyflow / upuply**，业务域跟你完全重合，但它们的排序靠**自由拖拽 + 位置顺序**，**没有把「空间邻接」做成关系**（无吸附、无咬合、无贴合缝）。
3. **你的独占位置 = L2「磁吸吸附 + 咬合阻力」× L4「生成闭环」× L5「档位切换」的交集**。这个交集**目前空白**——有吸附手感的（tldraw / Win11）没有生成，有生成的（ComfyUI / Flora）没有吸附，有分镜的业务重合但没做空间关系。

## 四、可直接借鉴的具体来源

| 借鉴目标 | 来源 | 具体位置/机制 |
|---------|------|-------------|
| **吸附算法（分轴独立判定）** | tldraw | `packages/core/src/utils/utils.ts` → `Utils.getSnapPoints()`（约 1085–1262 行）：6 吸附点/轴、9 组合/轴、2px 容差、保留 gap 符号定方向 |
| **对齐辅助线画法** | tldraw | 吸附后用修正 bounds 生成线：X 轴在 minX/midX/maxX 画竖线，长度覆盖移动形状 + 目标形状两端 |
| **吸附写成纯函数** | dnd-kit | `createSnapModifier` / `snapCenterToCursor`（`packages/modifiers/src/`） |
| **预览矩形 + 松手落座** | Win11 / FancyZones / SmartGrid / Tiling Shell | SmartGrid：「拖标题栏 → 蓝色预览矩形 → 松手 snap 到预览位置」 |
| **无限画布 + 卡片式分镜的交互** | Storyflow | 「Every frame is a real card you can drag, reorder, recolor, annotate」 |
| **性能架构（画布即 API / 不订阅整图）** | React Flow 官方 + Wireflow | React Flow performance 指南；Wireflow「canvas graph = REST endpoint」 |

## 五、给你的三个产品判断

1. **你的方向是站得住的**。Flora 自己的文章承认节点工具的「认知前置成本」是行业公认痛点，而你说的「小白模式」正是这个痛点的解法——**而且市面上没人做「同数据双档位」**。
2. **最该研究 Storyflow**。它和你业务域最重合（AI 分镜画布 + 卡片拖拽重排），但它**没做磁吸**。你应该去看它的自由拖拽是怎么做到「不卡、不瞬移、重排自然」的——那正是你现在卡顿要解的问题。
3. **最该抄 tldraw 的算法**。它的吸附点是**每轴 3 个（边+中）**，你只有「边对边」。加上中线对齐会让「对齐到位」的手感提升一大截；而「分轴独立判定」直接解你那个「纵坐标被拽走」的 bug。
