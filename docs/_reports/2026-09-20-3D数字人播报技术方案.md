## 1. 目标与边界

**做**：离线「数字人播报」——输入一句台词，输出一段「3D 角色开口说这句台词」的 mp4，落进剪辑时间线。

**不做**（明确排除）：
- ❌ 实时语音对话 / 打断（这是语音助手，不是剪辑工具）
- ❌ 上传本人视频克隆分身（需 LivePortrait/SadTalker 级模型，太重）
- ❌ GLB 精细模型的口型（见 §6 风险 1，前端禁止改 GLB 材质，属美术资产工作）

**定位**：补上北极星缺口里「精剪 → 文案」之间缺的一环——短剧角色念台词。

## 2. 现状盘点（证据链）

### 2.1 角色形态：Dummy13 风格关节素模

`riggedHumanoid.ts` 头部构造（`:1949-1977`）：
- `head` 是 `THREE.Group`，依次挂 `skull`（头球）+ 双眼 `lEye/rEye`（SphereGeometry）+ 鼻子 `nose`（ConeGeometry）+ 发型 `hair`
- 面部材质 `faceMat`（`MeshStandardMaterial #0f172a`）
- **唯独没有嘴（mouth）**

⇒ 加嘴落点明确：在 `head` 组里加一个「嘴部子网格」，与 eye/nose 并列，风格一致。

### 2.2 口型数据源已写好但零接入

`lip_sync.py` `LipSyncEngine`：
- `analyze_audio(audio_path, use_asr)` → `List[MouthParams]`（25fps 帧级）
- `MouthParams`：`jaw_open`（下巴开合）/ `mouth_width`（嘴宽）/ `lip_round` / `lip_pucker` / `tongue_tip` + `is_speaking`
- `export_blendshapes` 已支持 ARKit 格式导出
- **全库 grep 确认 `LipSyncEngine` 零引用**（同 `timeline_dsl`，又一个孤儿模块）

### 2.3 渲染链已通（第四刀）

`stage3dPoseVideo.ts`（**不在冻结区**）：
- `planPoseVideoFrames`：帧规划（超 900 帧抽稀、保首尾）
- `capturePoseFrames`：逐帧 `renderFrameToRT(idx)` → `readRTAsDataUrl()`，诚实失败（空帧即中止），`setTimeout(0)` 让出主线程
- `encodePoseVideo` → `bridge.ts:1089 poseVideoEncodeViaHost` → `canvas_server.py:1512 /host/pose-video-encode` → `pose_video_service.encode_pose_video`（FFmpeg 合成 mp4 落 inbox）

⇒ 数字人播报的「逐帧驱动 → 渲染 → 合成」**就是同一套**，只是把「应用姿态」换成「应用口型 + 姿态」。

## 3. 端到端链路

```
台词文本
  │
  ├─(1) TTS ──→ 音频 wav ──┬─(2) LipSyncEngine.analyze_audio ──→ 帧级 MouthParams[]
  │                         │
  │                         └─(4) FFmpeg mux 音视频 ──────────────→ 有声 mp4
  │
  └─(3) 口型参数轨 + 音频 URL ──SSE/HTTP──→ 前端 Stage3D
                                              │
                                              └─ recordLipSyncVideo()
                                                  逐帧：嘴 mesh.scale(口型) + 可选动作
                                                  → capturePoseFrames → encodePoseVideo
```

数据流三句话：
1. 后端编排模块：TTS 出音频 → lip_sync 出帧级口型参数
2. 口型参数轨（`[{t, jawOpen, mouthWidth, ...}]`）经桥下发前端
3. 前端逐帧把口型参数写到嘴 mesh 的 scale，复用第四刀渲染合成

## 4. 分阶段实施

### P1 — 给素模角色加「嘴」（核心，触碰冻结区）

**改** `vendor/shiguang-canvas/src/riggedHumanoid.ts` 的 `makeRiggedHumanoid`：

- 在 `head` 组新增一个 `mouth` 子网格，挂在 `nose` 下方，用 `faceMat` 材质（深色 `#0f172a`，与眼鼻一致）
- 几何体选型：一个扁椭圆（`SphereGeometry` 压扁，或 `BoxGeometry` 细条），初始「微闭」状态
- 开合驱动约定（素模风格，只需两维）：
  - `jaw_open`（0~1）→ mouth 的 Y 方向 `scale`（0.05 → 0.8，模拟张合）
  - `mouth_width`（0~1）→ mouth 的 X 方向 `scale`（0.3 → 1.0，模拟咧嘴）
  - `lip_round` / `lip_pucker` / `tongue_tip`：素模暂不用，**接口保留**（后续换精细模型再用）
- `mouth` 挂到返回结构里（如 `rig.mouth`），供 Stage3D 驱动

**验证**：渲染角色正脸，断言 mouth mesh 存在、材质正确、初始 scale 微闭。

### P2 — 后端口型编排（新文件，不触碰冻结区）

## 6. 风险与「稳字诀」

1. **GLB vs 素模**：角色有两种形态。素模（`makeRiggedHumanoid`）加嘴容易；GLB 模型（bodychan/bodykun.glb）加嘴需模型自带 morph、且前端禁改材质。**方案落点在素模**（Stage3D 当前主用素模路径）；GLB 口型 = 后续美术重导 blend，不在本轮。

2. **口型映射取舍**：lip_sync 输出 5 维，素模风格只需 `jaw_open` + `mouth_width` 两维，其余三维保留接口不实现（避免「随机效果」）。

3. **音频对齐**：TTS 音频时长 → 帧数 = duration×25；lip_sync 默认 `fps=25`，天然对齐。帧数超 900 时复用 `planPoseVideoFrames` 抽稀保首尾。

4. **性能（稳字诀）**：
   - 逐帧渲染是 WebGL/CPU 密集操作，但复用第四刀已通的「离屏 RT + `setTimeout(0)` 让出主线程 + 900 帧上限」，**不卡死主线程**
   - TTS / lip_sync 放后台线程 + 串行队列 + CPU 兜底（whisper 已在 `device="cpu"`）
   - 显存：lip_sync 走 CPU，本地几乎不新增显存（见 2026-09-20 稳定性评估）

5. **诚实失败**：复用 `capturePoseFrames` 的空帧中止，不产半成品。
