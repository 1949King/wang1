## 第 0 章 五分钟建立心智模型

### 0.1 一句话

> **拾光剪影的生成端 = 自研的「决策 + 治理 + 编排」层 + 借用的「执行」层。**
> 执行内核**零自研**（全仓无 `nn.Module` 子类）；价值在**选路、语义统一、能力诚实探测**。

### 0.2 三层图

```
┌─ L1 决策层 ──────────────────────────────────────────────┐
│  execution_decider.decide_execution()   ← ★ 选路唯一出口   │
│  └─ 主选/备选引擎选择（resolve_execution_engine）          │
├─ 治理层（12 切片，ai/*）─────────────────────────────────┤
│  预算/价格 · 渠道能力 · 质量先验 · 降级 · 评分 · 融合 …    │
├─ L2 执行层 ──────────────────────────────────────────────┤
│  GenerationRegistry（本地后端注册表）                      │
│  ├─ local_video_infer   本地 diffusers（6 族 + SVD）       │
│  ├─ neural/video_gen    SVD 专用（含下载 + 实测调优）      │
│  └─ 云端 HTTP 适配（21 家 provider）                       │
├─ 异步任务层 ────────────────────────────────────────────┤
│  canvas_gen_jobs  诚实进度 + 协作式取消 + 阶段上报          │
└─ 旁路：comfy_provider（ComfyUI 工作流宿主，仅文生图闭环）   │
```

### 0.3 真相源（别搞错）

| 概念 | 真相源 | 不要用 |
|---|---|---|
| **选路/决策** | `ai/execution_decider.decide_execution()` | 各处自行查表（历史上画布就这么干的） |
| **本地后端** | `canvas_aigc.local_generation_registry` | 直接 new 一个 pipeline |
| **时间线（非本链路）** | `EditorModule._clips` | `AppState` / 孤儿 `ExportRenderer` |
| **生成产物给前端** | `canvas_bridge.canvas_inbox_dir()` + `/inbox_file/` | 直接把 `D:\...` 丢给 WebView（**播不了**） |

## 第 1 章 L1 决策层 —— `app/core/ai/execution_decider.py`

### 1.1 它是干什么的

**「决定用谁执行」的唯一入口。** 2026-10-02 新建，起因是核查发现
**画布侧生成链对治理切片的引用数为 0**（详见 §4.1）。

### 1.2 公开 API

```python
# app/core/ai/execution_decider.py:49
decide_execution(
    *, capability="image", quality="standard", motion="normal",
    channel_id="", model="", allow_local=True, allow_cloud=True,
    frames=0, has_image=False, duration=0.0, resolution="",
    default_model_key="imageModel",
) -> {ok, channel_id, model, params, reasons, degrade_level, engine, message}

# :289
resolve_execution_engine(*, prefer="") -> {engine, available, is_fallback, reason, switch}
```

### 1.3 决策顺序（照这个顺序读代码）

```
decide_execution()
 ├─ 0) 引擎选择     resolve_execution_engine()   → 主选 diffsynth / 备选 builtin
 ├─ 1) 本地优先     channel_id 以 "local/" 开头 → 查 local_generation_registry
 └─ 2) 云端渠道     _resolve_aigc_channel() → 治理切片 resolve_order 能力筛选
                   └─ 若筛选首选与解析不一致且配了 Key ⇒ 切换（保守）
                    └─ 渠道内挑首个具备该能力的模型
                    └─ translate_quality / translate_motion 出 params
```

### 1.4 三条不可违背的契约

| 铁律 | 内容 | 为什么 |
|---|---|---|
| **A1** | `reasons` **必定非空** | 选路必须可解释，否则线上「为什么走了这条渠道」无法排障 |
| **R2** | 选路**只在这里**，调用方不得自行查表 | 否则预算/价格/降级全部失效 |
| **R3** | **诚实失败**：无可用渠道时 `ok=False` + 指引 | 绝不静默换路或伪造产物 |

### 1.5 三个易踩的坑（都实测过）

| 坑 | 症状 | 正解 |
|---|---|---|
| **词汇不一致** | `video_gen` 用 `calm/normal/lively`，`translate_motion` 认 `low/medium/high` ⇒ 传错**静默退回 medium** | 出口内做单向归一；**新代码统一用 low/medium/high** |
| **`normalize_spec` 的键** | 传 `capability`/`quality` ⇒ 得到**空 spec**、能力筛选**静默空转** | 它认的是**语义标志**：`text_to_video` / `image_to_video` / `first_last_frame` / `duration` / `resolution` |
| **单例访问器名** | `budget_pacer` 是**类**不是实例 | 用 `get_pacer()` / `get_store()` 等（见 §3） |

## 第 2 章 L2 执行层

### 2.1 本地后端注册表 —— `canvas_aigc.py:129-240`

```python
class LocalGenerationBackend(ABC):        # :129
    backend_id: str = ""
    capabilities: Tuple[str, ...] = ()
    def is_available(self) -> bool        # 依赖可导入 / 引擎可探测
    def generate(self, capability, **params) -> Dict   # 返回 {ok|success, ...}

class LocalVideoInferBackend(...):        # :152  id=local_video_infer, caps=(video,)
class LocalVoiceBackend(...):             # :182  id=local_voice,       caps=(audio,)

local_generation_registry = GenerationRegistry()   # :238（实例化即登记）
```

**设计约束（原作者注明，务必遵守）**：
- 统一的是「**能力声明 + 可用性 + 分派**」；各后端返回结构**保留原约定**
  （视频 `{ok,...}` / 音频 `{success,...}`），**调用方读取字段不变**
- **`comfy_provider` 与 `neural_engine` 属不同域，不纳入本抽象**

### 2.2 本地视频主实现 —— `app/core/local_video_infer.py`

```python
# :189
discover_local_video_models() -> List[Dict]      # 扫本地模型（含权重存在性过滤）
# :832
generate_video_local(*, prompt, model, model_path, duration, size,
```

**支持族**（`MODEL_KEYWORD_MAP` / `PIPELINE_CLASS_MAP` / `_INFER_FUNC_MAP` **三表必须一致**）：

| kind | 模型 | 输入形态 |
|---|---|---|
| `wan` | Wan 2.1/2.2/2.6/3.0 | t2v / i2v |
| `cogvideox` | CogVideoX 1.0/1.5/2.0 | t2v / i2v |
| `hunyuan` | HunyuanVideo 1.5 | t2v |
| `ltx` | LTX-Video | t2v |
| `mochi` | Mochi 1 | t2v |
| `minimax_h3` | MiniMax H3 | t2v（含音频） |
| **`svd`** | Stable Video Diffusion | **i2v（`I2V_KINDS`：无 prompt、必须有图）** |

**扫描目录**（`LOCAL_MODELS_DIR_CANDIDATES`）：
`~/.cache/huggingface/hub` · `~/.cache/modelscope` · `~/Downloads/video_models` ·
`app/models/video` · **`app/models/cache`**（项目自己的下载位）

> ⚠️ **`_has_weights()` 不是可有可无**：HF 缓存里"只建了索引"的仓库会留
> `models--xxx/refs/main` 这种 **1KB 空壳**，而调用方取 `matches[0]` ⇒
> 不过滤就会「明明下载了却加载失败」，报错还指向模型不存在。

### 2.3 SVD 专用引擎 —— `app/core/neural/video_gen.py`

```python
tuned_for(model_id) -> dict           # :182 实测调优表（单一真源）
should_offload(model_id, frames)      # :187
available_models() -> List[Dict]      # :255 供 UI
class VideoGenEngine:                 # :273
    is_available() / is_downloaded() / download progress / pull() / load() / generate() / unload()
publish_to_inbox(video_path) -> dict  # :598 落画布 inbox，返回可播 URL
get_video_engine() -> VideoGenEngine  # :676 进程级单例
```

**实测调优表**（RTX 4060 Laptop 8GB，2026-10-01/02）：

| 参数 | 值 | 依据 |
|---|---|---|
| `decode_chunk_size` | **1** | VAE 解码 37.5s → **2.4s**（小了反而快约 6 倍）；8 帧 chunk=2 实测 **377s** |
| `offload` | **保持开启** | 实测全程不亏（更快更省显存）；关掉后 10 帧 **>600s 卡死** |
| `steps` | 14（`balanced`） | 唯一的质量/速度旋钮；每步约 2.27s |
| `motion_bucket_id` | **80**（`calm`） | 立绘主体 6 帧全程稳定（默认 127 后段崩坏），**耗时相同** |
| CFG | min1.0/max3.0 | 关掉快 1.85x 但**输出报废**（首帧保持 35→16dB） |
| `distilled` | False | 蒸馏权重**要求 CFG=1.0**（与基模相反）；置 True 时守卫自动旁路 |

### 2.5 异步任务层 —— `app/core/canvas_gen_jobs.py`


## 第 3 章 治理层 —— 12 个切片（`app/core/ai/`）

**统一模式：模块级 `get_xxx()` 单例。**

| 切片 | 单例访问器 | 干什么 |
|---|---|---|
| `budget_pacer` | `get_pacer().get_lambda()` | **PI 影子价格** —— λ 随预算消耗连续调节（抗卷绕/观测门控/跨日回退） |
| `global_price` | `get_global_price()` | L0 全局价格层 + 配额拍卖（`λ_eff = λ^G + λ^τ`） |
| `provider_caps` | 函数式：`resolve_order()` / `filter_by_caps()` / `normalize_spec()` / `supports()` | **能力筛选 + 收益排序**（`V = q̂ − λ·price`） |
| `quality_prior` | `get_store().predict(pid)` | 期望质量 q̂（EMA + 冷启动不确定度） |
| `degradation` | `get_stats()` / `classify_error()` / `DegradationSession` | **六级降级体系** |
| `score_book` | `get_score_book()` | 评分账本 |
| `provider_pool` | `get_pool()` | 渠道池（额度/轮询） |
| `execution_modes` | `choose_mode()` / `score_modes()` / `fused_quality()` | 执行模式选择（本地/云端/融合） |
| `divergence_probe` | `get_probe()` | 本地 vs 云端 发散探测 |
| `sampling_review` | `get_review()` | 抽样审查 |
| `fusion` | `fuse_text()` / `plan_video_fusion()` / `plan_audio_mix()` | 多源融合 |
| `module_scheduler` / `engine_api` / `simulator` | — | **实现完整但未接生产** |

> ★ **画布侧接入状态（2026-10-02 起）**：`decide_execution()` 已消费
> `provider_caps` + `budget_pacer` + `quality_prior` 三者。
> 其余切片仍**只在 Agent 侧**被消费（经 `ai_video_generation_pipeline` → `video_generation_client`）。

## 第 5 章 扩展指南（照着做）

### 5.1 加一个本地模型族

1. `local_video_infer.py` 的 **三张表**都加（`MODEL_KEYWORD_MAP` / `PIPELINE_CLASS_MAP` / `_INFER_FUNC_MAP`）
   —— **少一张就会「认得但跑不了」**
2. 写 `_infer_xxx()`，签名对齐既有族（`model_path` / `device` / `vram_gb` / `duration` / `size` / `out_dir` / `steps`）
3. 若是 **i2v**（需图不需 prompt），加进 `I2V_KINDS`
4. 若模型在 `app/models/cache` 下，确认 `_guess_model_kind` 能认出（否则扫不到）
5. 更新 `_verify/check_video_gen.py` 的族清单断言

### 5.2 加一个云端渠道

1. `model_config.PROVIDERS` 加声明
2. `provider_caps.register_caps()` 声明**能力**（是否支持 i2v / 首尾帧 / 12 秒 / 1080p）
   —— **不声明就会被能力筛选静默筛掉**
3. 参数翻译若需特殊处理，**加在 `translate_*`**，不要在调用处写 `if 渠道 == ...`

### 5.3 加一个新能力（capability）

1. `canvas_aigc.py:100-104` 的 `CAPABILITY_*` 常量
2. 实现 `LocalGenerationBackend` 子类并 `register()`
3. `generate_xxx_via_host()` 里经 `decide_execution()` 路由

### 5.4 ★ 加任何**新生成路径**之前（血泪教训）

**必须同时搜两样东西**：

```bash
# ① 同功能模块（别重复造）
rg -l "本地视频|diffusers|i2v|infer" app/core
# ② 谁在治理生成（别绕过治理）
rg -l "budget_pacer|global_price|provider_caps|quality_prior|degradation" app/core
```

> 本项目**两次**栽在这上面：一次是没发现 `local_video_infer`（同功能模块，27KB 早就存在）；
> 一次是没发现治理层（画布侧引用数为 0）。
> **更快的判据：直接看「那个能力的注册表」与「治理表」里已经有什么。**

## 第 6 章 铁律与坑速查

### 6.1 铁律

| # | 铁律 |
|---|---|
| **R1** | 新增生成路径前，先查注册表与治理表（见 §5.4） |
| **R2** | 选路只在 `decide_execution` |
| **R3** | 诚实失败：不支持就报错 + 给指引，禁静默降级/伪造产物 |
| **R4** | 语义→参数翻译只在 `translate_*` |
| **R5** | 本地产物必须落 inbox 才能给前端（**WebView 播不了 `D:\...`**） |
| **R6** | 成本与后端 id 必填（否则 L1 预算控制与归因断链） |
| **R7** | 引入第三方引擎前先定许可证结论（ComfyUI=GPL-3.0；Wan2GP=禁商用集成） |
| **R8** | 显存策略**必须实测定**，不得凭直觉（已有两次推翻） |
| **R9** | **降级必须可见**：退备选时写进 `reasons` + 返回 `engine`，禁静默切换 |
| **R10** | 单文件规模守卫阈值 2000 行、**存量只许减不许增** ⇒ 涨了就**拆模块**（不要调基线） |

### 6.2 坑速查

| 症状 | 根因 | 正解 |
|---|---|---|
| 「明明下载了却加载失败」 | 扫到 HF 空壳目录（1KB `refs/main`） | `_has_weights()` 过滤 |
| 能力筛选像没生效 | `normalize_spec` 传了 `capability` 键（它认语义标志） | 传 `text_to_video` / `image_to_video` |
| 运动档改了没反应 | `calm/normal/lively` vs `low/medium/high` 词汇不一致 ⇒ 静默退回 medium | 出口内归一 |
| 决策出口把冷启动拖慢 | 里面 import 了 torch/diffusers | 用 `find_spec` 探测 |
| 改一处渠道、另一处没变 | 内联重写了 `_resolve_aigc_channel`（历史遗留） | 收敛为只调该函数 |
| 云端口径与本地不一致 | 语义没经 `translate_*` | 一律走翻译层 |

- **与画布前端**：`vendor/shiguang-canvas/src/{bridge,localVideo,App}.tsx`（`localVideo.ts` 是本地视频的画布侧唯一入口）
