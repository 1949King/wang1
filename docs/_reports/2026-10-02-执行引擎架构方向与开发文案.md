## 第零篇 项目现状（先回答「现在用的是哪一个」）

### 0.1 结论：**四方案里的第 1 个（diffusers）+ 自研的两层**

| 层 | 实际是什么 | 属四方案吗 |
|---|---|---|
| **L1 路由 / 编排 / 治理** | **自研**（7,494 行）：`canvas_aigc` + `canvas_gen_jobs` + `local_generation_registry` + `ai/*` 治理切片 | ❌ **自研，不在四方案内** |
| **L2 本地执行** | **`diffusers`**（Apache 2.0） | ✅ **正是四方案的第 1 个** |
| **L2 云端执行** | **自研 HTTP 适配层**（21 家 provider，urllib） | ❌ 自研 |
| **旁路** | `comfy_provider` = 工作流宿主（**P2 · 仅文生图闭环**），非主执行引擎 | ❌ 不在四方案内 |

**决定性证据**（`grep -oE "from diffusers import ..." app/core/`）：


**另三个方案在项目里 0 引用**：`diffsynth` 0 文件 · `sglang` 0 · `vllm_omni` 0 · `xfuser` 0。

### 0.2 一句话
> **本地执行用 diffusers，云端执行用自研 HTTP 适配，选路与治理全自研。**
> 所以准确说法是：**「四方案之一（diffusers）做执行底座 + 自研做一切上层」**。

## 第一篇 四方案各自该拿走的优点

| 方案 | ✅ **该拿走** | ❌ **不该带走** |
|---|---|---|
| **diffusers** | 进程内调用（零额外进程）· 纯 Python（**报错栈是自己的代码**）· 生态最广（6 族 pipeline）· Apache 2.0 | 跨 runs 缓存 / 节点级重跑 / 显存分级调度——**都得自己写** |
| **DiffSynth** | ★ **逐层（Layer 级）磁盘卸载 + FP8** —— 低显存机器的解药；推理与训练同路径；纯 Python API；Apache 2.0。**注：应看 `DiffSynth-Engine`（面向工业界/稳定部署）而非仅 Studio** | 社区体量小、新模型适配慢半拍、API 变动要盯 release note |
| **SGLang / vLLM-Omni** | ★ **明确的服务契约**：OpenAI 兼容 `POST /v1/videos`（异步任务）+ `/v1/videos/sync`（同步阻塞）· 任务状态机 · 进程隔离可单独重启/扩实例 · 并行策略（TP/USP/CFG 并行） | ⚠️ **官方验证是多卡 + 巨量主机内存**（SGLang 双 5090 profile 需 **~384 GiB 主机 RAM**；文档明说单卡配方**未确立 24/32GB 基线**）⇒ **本机 15.3GB 完全不可行** |
| **ComfyUI-to-Python** | ★ **「编排产物可固化成脚本」**的可复现思路（图→代码，可版本管理、可 code review） | ⚠️ **GPL 传染风险不因「变成 .py」而消失**（导出脚本通常仍 import ComfyUI 节点实现）；上游节点一变脚本就废 ⇒ **只能当桥，不能当地基** |

## 第二篇 架构方向：**「一决策 · 一契约 · 多后端 · 显存分级」**

### 2.1 总图（三层 + 两条契约）

```
┌────────────────────────────────────────────────────────────┐
│ L1 决策层（自研 · 异构动态协作引擎）                          │
│   budget_pacer(影子价格) · global_price · provider_caps      │
│   quality_prior · degradation · score_book                   │
│   ⇒ 产出【决策】选谁 / 多少预算 / 允许多高质量 / 降级到几级    │
└───────────────────────────┬────────────────────────────────┘
                            │ ★ 契约 A：Decision
┌───────────────────────────▼────────────────────────────────┐
│ L2 执行层（可插拔后端 · 默认 diffusers）                      │
│   GenerationRegistry  ← 按【能力 + 可用性 + 成本】选后端      │
│   后端们：diffusers · (DiffSynth-Engine 预留) · 云端 HTTP     │
│   ⇒ 消费【执行请求】产出统一【执行结果】                       │
└───────────────────────────┬────────────────────────────────┘
                            │ ★ 契约 B：ExecutionRequest / Result
┌───────────────────────────▼────────────────────────────────┐
│ L3 内核层（模型权重 · 各厂开源；项目零自研）                  │
└────────────────────────────────────────────────────────────┘
```

### 2.2 ★ 契约 A：Decision（L1 → L2 的**唯一**入口）

**问题**：现在画布侧**根本不问 L1**（静态查表），Agent 侧问了但 L1 只能影响云端选路。
**方向**：把「选路」收敛成**一个函数**，两侧共用。

```python
def decide(req: DecisionRequest) -> Decision:
    """L1 唯一出口。画布与 Agent 两侧都必须经它，禁止任何一侧再自行查表。"""

@dataclass
class DecisionRequest:
    capability: str          # CAPABILITY_IMAGE / VIDEO / AUDIO / MUSIC / TEXT
    quality: str             # 统一语义：fast / standard / best（由 translate_* 落到各家）
    motion: str              # 统一语义：calm / normal / lively
    allow_local: bool        # 是否允许本地执行（画布上可由用户开关）
    allow_cloud: bool
    frames: int = 0          # ★ 帧数（本地显存分级的输入，见 3.3）
    budget_hint: float = 0.0 # 本次可接受成本（0 = 不限）

@dataclass
class Decision:
    channel_id: str          # "local/xxx" 或云端 provider id
    backend_id: str          # L2 后端标识（可插拔）
    params: dict             # 已翻译好的执行参数（steps/motion/cfg/size/duration…）
    reasons: list[str]       # ★ 为什么这么选（可观测、可解释，便于排障）
    degrade_level: int = 0   # 降级级别（0 = 无降级）
```

**铁律 A1**：`Decision.reasons` **必须非空** —— 选路要能解释，否则线上无法排障。
**铁律 A2**：**只有 L1 能决定「用谁」**；L2 只执行，**不得自行换后端**（失败要如实上报，由 L1 决策降级）。

### 2.3 ★ 契约 B：ExecutionRequest / Result（L2 内部统一）

**问题**：现在本地后端返回 `{ok,...}`、音频返回 `{success,...}`，**两套字段**；云端又是另一套。
**方向**：统一结构，**保留兼容读取**（不破坏既有调用方）。

```python
@dataclass
class ExecutionRequest:
    capability: str
    params: dict             # 由 Decision.params 直传，后端不自行解释语义
    output_dir: str = ""

@dataclass
class ExecutionResult:
    ok: bool
    artifacts: list          # [{kind, path, url, mime}]  kind: image/video/audio
    backend_id: str          # ★ 谁真正执行的（可观测）
    cost: float = 0.0        # ★ 本次花费（供 L1 记账，本地为 0）
    elapsed_ms: int = 0
    degraded: bool = False
    message: str = ""
```

**铁律 B1**：`ExecutionResult.backend_id` **必填** —— 混用多后端时，不知道谁跑的就没法归因。
**铁律 B2**：`cost` **必填**（本地填 0）—— L1 的预算控制依赖它，缺失即预算失控。
**铁律 B3**：`artifacts[].url` 必须是 **WebView 可播**的形式（本地走 `/inbox_file/`）——
**画布加载不了 `D:\...`**（这一条已在 V4.40.18 踩过）。

### 2.4 该从哪借哪一块（映射表）

| 架构需求 | 从哪个方案借 | 落地形态 |
|---|---|---|
| 执行底座 | **diffusers**（已在用） | `LocalVideoInferBackend` 扩展 |
| 低显存分级 | **DiffSynth 的逐层卸载 + FP8 思路** | `_pick_memory_policy(frames, free_vram)` |
| 服务化契约 | **SGLang/vLLM-Omni 的 `/v1/videos` 形状** | **只借接口形状**（本地仍进程内）；将来多卡再切真服务 |
| 编排可固化 | **ComfyUI-to-Python 的「图→脚本」思路** | 把 `Decision + params` 落成可版本化的**配方文件**（不引入 ComfyUI） |
| 渠道统一 | **LiteLLM（MIT）** | 收敛 `_resolve_aigc_channel` + `translate_*` |

## 第三篇 开发文案（可照着做）

### 3.1 铁律总表（先立规矩）

| # | 铁律 | 为什么 |
|---|---|---|
| **R1** | **新增任何生成路径前，先查 `GenerationRegistry` 与 `ai/*` 治理切片** | 本项目已两次踩坑：漏看 `local_video_infer`（同功能模块）、漏看治理层（画布零消费） |
| **R2** | **选路只在 L1**，L2 不得自行换后端 | 否则预算/价格/降级全部失效 |
| **R3** | **诚实失败**：不支持的组合必须报错并给指引，禁止静默降级或伪造产物 | 项目既有纪律 |
| **R4** | **统一语义 → 各家参数 的翻译只在 `translate_*`** | 防「每条渠道一段 if」 |
| **R5** | **本地产物必须落 inbox** 才能给前端 | WebView 播不了本地路径 |
| **R6** | **成本与后端 id 必填** | 没有它，L1 的预算控制与归因都断链 |
| **R7** | **许可证闸门**：引入第三方引擎前先定许可证结论（ComfyUI=GPL-3.0；Wan2GP=禁商用集成） | 商业化发行的前置条件 |

### 3.2 落地步骤（按依赖排序）

#### 步骤 1（P1·低风险·先做）—— 收敛重复的本地视频实现
现况：`local_video_infer.py`（6 族，已接线，**不认 SVD、不负责下载**）与
`neural/video_gen.py`（认 SVD、会下载、有调优，**未接线**）**并存**。

动作：
1. `local_video_infer.MODEL_KEYWORD_MAP` / `PIPELINE_CLASS_MAP` **补 SVD**（含 `svd`/`stable-video` 关键字）；
2. `LOCAL_MODELS_DIR_CANDIDATES` **补 `app/models/cache`**（否则永远扫不到项目自己下载的模型）；
3. 把 `video_gen.TUNED` 的**实测调优**（chunk=1 / 14 步 / motion80 / CFG 显式）移植过去；
4. `video_gen` 的**下载链路**（既有模块唯一缺的能力）并入；
5. **入口收敛为一条**（建议 `channel_id="local/..."`），`/host/local-video-generate` 退化为薄封装或废弃。

#### 步骤 2（P0·高收益·改动大）—— 画布生成接入 L1 决策
现况：画布走 `_resolve_aigc_channel`（静态查表），**零治理**。

动作：
1. 实现契约 A 的 `decide()`（**先薄**：内部先包一层现有 `_resolve_aigc_channel` + `provider_caps`，
   行为不变但**出口统一**，为后续加价格/预算留插点）；
2. `canvas_aigc.generate_video_via_host` 的本地分支改为「问 `decide()`」；
3. **灰度**：加开关（env/配置），默认关，验证无损后开；
4. 验收：同一请求在开关开/关下**结果一致**（回归），且 `Decision.reasons` 可用于排障。

#### 步骤 3（P2）—— 蒸馏档位（**收益最大，20x 量级**）
1. `QUALITY_PRESETS` 增 `preview`（4~8 步，配蒸馏权重）；
2. `TUNED` 表增 `distilled: true` 字段；
3. **蒸馏模型要求 CFG=1.0** —— 守卫已留旁路（`_verify/check_video_gen.py` 里 `if _spec.get("distilled"): continue`）；
4. 落「预览档改提示词/找种子 → 成片档出交付」的产品分档。

> ⚠️ 需要**下载蒸馏 LoRA/checkpoint**（GB 级），属外部依赖，需单独授权。

#### 步骤 4（P3）—— 渠道层按 LiteLLM 收敛
1. 把 `_resolve_aigc_channel` + `translate_*` 收成**单一 provider 抽象**（`Provider.supports/cost/translate`）；
2. 参照 LiteLLM：**参数映射表 + 降级链 + 成本统计**三件套。

### 3.3 显存分级策略（借 DiffSynth 思路的落地）

按「帧数 + 可用显存」自动选策略（本项目已有实测基础）：

| 条件 | 策略 | 依据 |
|---|---|---|
| 帧数 ≤ 6 且显存充足 | 免 offload？**→ 实测为否** | 本项目实测：offload 全程不亏，**保持开启** |
| 帧数 ↑ 显存吃紧 | `decode_chunk_size=1`（**关键**） | 实测 VAE 解码 37.5s→2.4s |
| 仍不够 | 逐层卸载 / FP8（**DiffSynth 思路**） | 待实测 |
| 极端 | 降分辨率 / 降帧数 / 降级级别 ↑ | `degradation` 六级体系 |

**铁律 R8**：显存策略**必须由实测定**，不得凭直觉（本项目已有两次教训：
「offload 是瓶颈」被推翻、「chunk 调大更快」被推翻）。

## 第四篇 验收与不做

### 4.1 验收清单

| 项 | 判据 |
|---|---|
| 契约统一 | 画布与 Agent 两侧**都**经 `decide()`；两侧回归结果一致 |
| 可观测 | 每次生成都能拿到 `backend_id` / `cost` / `reasons` |
| 无重复实现 | `GenerationRegistry` 里**每个能力只有一个**本地后端 |
| 显存安全 | 峰值 < 上限 8GB，且**有实测数据**支撑 |
| 许可证 | 引入任何第三方引擎前有明确结论 |

### 4.2 明确不做（沿用既有决策）

- ❌ **ComfyUI 宿主**（GPL 闸门；用户 2026-08-08 已定「明确不做」）
- ❌ **SGLang / vLLM-Omni**（需 ~384GiB 主机内存，与本机 15.3GB 差距过大）
- ❌ **Wan2GP 集成**（自定义许可**禁商用**；可借鉴技术，不可集成）
- ❌ 自研推理内核（千万元级投入且打不过社区）
