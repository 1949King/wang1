## 〇、直接回答「是自研的还是怎么样的」：**自研编排 + 借用执行，无自研内核**

画布生成端**不是一个第三方引擎，也不是纯套壳**，而是清清楚楚的**两层**：

| 层 | 归属 | 具体内容 |
|---|---|---|
| **L1 路由 / 编排** | **✅ 完全自研**（**7,494 行** / 7 文件） | `canvas_aigc.py`(2932) 统一路由 · `canvas_server.py`(1754) · `canvas_gen_jobs.py`(494) 异步任务底座 · `local_generation_registry`（本地后端注册表）· `comfy_provider`(558) + `workflow_importer`(294) |
| **L2 执行** | **❌ 完全借用** | **云端**：21 家 provider 的 HTTP API（`_json_request` / urllib 直连，算力在厂商侧）<br>**本地**：**HuggingFace `diffusers`**（`from diffusers import WanVideoPipeline / CogVideoXPipeline / HunyuanVideoPipeline / LTXVideoPipeline / MochiPipeline / MiniMaxH3…`） |
| **L3 推理内核** | **❌ 项目零自研** | 全仓 `app/` 下**没有任何 `nn.Module` 子类** ⇒ 无自研 UNet / Attention / 扩散采样器；权重全部来自各模型厂开源 |

> 佐证：搜 `(nn.Module)` / `(torch.nn.Module)` 在 `app/core` `app/modules` 下**零命中**。
> （`ai/module_scheduler.py` 与 `editor_scheduler.py` 名字像但**是任务调度器**，
> 职责为「模块注册/发现、任务下发、资源配额限流、优先级仲裁、依赖 DAG 拓扑调度」，与扩散采样无关。）

### 自研的增值到底在哪（这才是差异化资产）

`canvas_aigc.py` 共 **29 个顶层函数**，关键增值点：

| 函数 | 作用 |
|---|---|
| `_resolve_aigc_channel` (:996) | 渠道解析（云端） |
| `translate_quality` (:268) / `translate_motion` (:285) | 把**统一语义**翻译成各家不同参数（各厂 quality/motion 取值口径不一） |
| `_probe_video_motion_support` (:1283) | **能力探测** —— 不支持时诚实失败，不假装 |
| `_apply_local_postprocess` (:1366) | 本地结果后处理（超分/补帧挂载点） |
| `canvas_gen_jobs.py` 三条硬约束 | **诚实进度**（拿不到真实百分比就保持 `None`，禁止伪造平滑进度）· **协作式取消**（queued 真取消）· 独立于冻结区 |

**⇒ 结论：项目是「自研调度 + 开源执行」。** 价值在**编排、语义统一、能力诚实探测**，
不在推理内核 —— 而后者**本来也不需要自研**（自研扩散内核是千万元级投入，且打不过社区）。

## 一、结论速览

画布的执行引擎**不是一套，是四套并行的「域」** —— 而且这个分治是**项目自己刻意设计的**，
在 `app/core/canvas_aigc.py:132-137` 的类文档里写得很明确：

> 统一「本地推理」后端的能力声明、可用性探测与生成分派…
> **comfy_provider（ComfyUI 工作流引擎，走 `/host/comfy/*`）与 neural_engine
> （剪辑特效 ONNX/Torch 推理，走特效插件）属不同域，不纳入本抽象。**

### 四域对照表

| # | 域 | 核心模块 | 入口 | 覆盖 | 规模 |
|---|---|---|---|---|---|
| ① | **云端渠道** | `canvas_aigc._resolve_aigc_channel` | `/host/generate-image\|video\|audio\|music` | 即梦/可灵等云 AIGC | `canvas_aigc.py` 2932 行 |
| ② | **本地生成后端**（注册表） | `local_generation_registry`（`LocalVideoInferBackend` + `LocalVoiceBackend`） | 同 ① 的 `channel_id="local/..."` 强制本地 | 本机 diffusers 视频 + 本地 TTS | `local_video_infer.py` 27KB |
| ③ | **ComfyUI 工作流引擎** | `comfy_provider`(557) + `comfy_client`(401) + `workflow_importer`(293) | `POST /host/comfyui/run` | **仅「文生图闭环」** | 合计 **1251 行** |
| ④ | **剪辑特效推理** | `neural_engine`(480) + `neural/*` | 特效插件 / `/host/canvas-enhance` | ONNX 特效 + `video_gen`（SVD） | — |

**① 与 ② 由两套机制共同构成「画布生成的统一路由」**：
`GenerationRegistry`（本地，按能力查后端）+ `_resolve_aigc_channel`（云端，按渠道解析）。
③ ④ 是**独立域**，各有自己的入口与生命周期。

### 关键代码锚点

- 本地后端抽象：`canvas_aigc.py:129`（`LocalGenerationBackend` ABC）、`:211`（`GenerationRegistry`）、`:238-240`（登记 2 个后端）
- 云端/本地分流（视频）：`canvas_aigc.py:1443-1456`

- ComfyUI 端点：`canvas_routes_post.py:381-413`（`/host/comfyui/run`，支持 `dry_run` 演练）
- ComfyUI 能力边界：`comfy_provider.py:1` 自述「**P2 · 文生图闭环**」

## 二、要不要上 ComfyUI 执行引擎？—— **不建议，且你 2026-08-08 已经定过**

### 2.1 已有的决策记录

`docs/_archive/knowledge/16-aigc-canvas-gap.md`：

- 第 3-4 行：
  > 源清单：用户 2026-08-08「LibTV / **ComfyUI** / TapNow / 即梦 / InvokeAI / Krea / Runway」
  > 策略：**抄能力不换壳**；AIGC 走模型广场 → `/host/generate-image` / `/host/generate-video`
- 第 92 行「**明确不做（仍有效）**」清单里**明确包含「完整 ComfyUI 宿主」**

### 2.2 三条独立支撑理由（代码里找到的）

| # | 理由 | 证据 |
|---|---|---|
| 1 | **★★ GPL-3.0 硬闸门**（最要紧） | `comfy_provider.py:11-12`：「合规提醒（方案 §4/§11 **硬闸门**）：本模块仅『就地拉起已安装的引擎进程做开发验证』，**内置引擎的打包 / 发行必须在 GPL 合规结论通过后再做**，此 provider 不负责打包。」 |
| 2 | **第二套模型管理** | ComfyUI 有自己的 `models/` 与下载器，会与项目 `app/models/cache` 形成**两套真源** |
| 3 | **本机未安装** | `comfy` 包未装；常见安装目录未发现 ComfyUI ⇒ 当前要上得先引入一整个外部运行时 |

> 第 1 条是**法律风险**，不是技术偏好：商业化发行前必须先有 GPL 合规结论，
> 否则有开源传染（derivative work）风险。

### 2.3 该「抄」的是什么

策略文档 `14-canvas-strategy.md:90` 已把「**ComfyUI 向节点编排体验**」列进**要做的能力**。
⇒ 要抄的是**交互**（「粘贴一段工作流 JSON 即用」这种低门槛体验），
**不是**它的运行时。而这一点 ③ **已经在做**（`/host/comfyui/run` + `workflow_importer` 的 schema 校验）。

## 三、★ 调查中发现的一个**应当收敛的问题**（我的疏漏）

### 3.1 事实

`app/core/local_video_infer.py`（**27KB，2026-09-25**）**早就存在**，
做的正是「本地 diffusers 视频生成」—— 而我 V4.40.17 新建 `app/core/neural/video_gen.py` 时**没有查到它**，
导致现在项目里**两套本地视频生成并存**。

### 3.2 两者对照（实测核对，非推测）

| | 既有 `local_video_infer.py` | 我的 `neural/video_gen.py` |
|---|---|---|
| **模型覆盖** | Wan / CogVideoX / Hunyuan / LTX / Mochi / MiniMax H3（**6 族**） | SVD-xt / Wan2.2-5B / Wan2.1-1.3B（3 个） |
| **是否认得 SVD** | ❌ `MODEL_KEYWORD_MAP` 无 `svd` 关键字 | ✅ 认得，且**已下载 + 有实测调优** |
| **扫描目录** | `~/.cache/huggingface/hub` · `~/.cache/modelscope` · `~/Downloads/video_models` · `app/models/video` | **`app/models/cache`**（项目自己的下载位） |
| **下载能力** | ❌ **只扫已存在的，不负责下载** | ✅ 完整下载链（HF镜像 → ModelScope） |
| **实测调优** | ❌ 无 | ✅ chunk=1 / 14 步 / motion80（见 CHANGELOG V4.40.19-20） |
| **接线** | ✅ 已进 `local_generation_registry` | ❌ 未进注册表，自己开了 `/host/local-video-generate` |

⇒ 两者**范围互补、职责重叠**：既有的「广覆盖 + 已接线 + 不下载」，
我的「认 SVD + 会下载 + 有调优 + 未接线」。

### 3.3 建议的收敛方向（**待你拍板，本轮未动**）

1. 把 **SVD 补进** 既有模块的 `MODEL_KEYWORD_MAP` / `PIPELINE_CLASS_MAP`（让它认得 SVD）；
2. 既有模块扫描目录**加上 `app/models/cache`**（否则永远扫不到项目自己下载的模型）；
3. 把我实测的 **SVD 调优参数**（chunk=1 / 14 步 / motion80）移植进既有模块对应分支；
4. 把**下载链路**（既有模块唯一缺的能力）接到既有模块；
5. **统一入口，两套留一套**（建议保留 ② 的 `channel_id="local/..."` 体系，
   让 `/host/local-video-generate` 只作薄封装或直接废弃）。

## 四、方法论教训（写给下一次）

**新建模块前，必须按「能力关键词」全仓搜一遍，而不是按自己打算起的名字搜。**

我当时的搜索词是 `video_gen` / `comfy` / `ComfyUI`，
**没搜** `local_video_infer` / `diffusers 视频` / `本地视频` / `i2v` ——
于是漏掉了一个 27KB、同职责、且**早已接线**的模块。

正确做法（本项目已有的守则）：
1. 按**能力**搜（「本地视频生成」「diffusers」「i2v」「infer」），不按**命名**搜；
2. 顺带查那个能力的**注册表/路由表**（本项目是 `local_generation_registry`）——
   注册表里已有什么，就是「这块已经被谁做了」的最直接答案。
