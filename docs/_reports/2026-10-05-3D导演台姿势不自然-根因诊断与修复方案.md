# 3D 导演台「姿势不自然」根因诊断与修复方案

> 2026-10-05 · 用户反馈：3D 导演台里的动作姿势不符合正常人体动作。
> 本文为**只读诊断**（未改任何冻结区代码），附全部代码实证与修复方案。

---

## 第 0 章 结论：不是"预设做得不好"，是**关节模型缺了一个自由度**

项目**已经有**姿势库与动作库（不是缺失）：

| 资产 | 位置 | 数量 |
|---|---|---|
| 静态姿势预设 `POSE_PRESETS` | `riggedHumanoid.ts:406-873`（467 行） | **29 个**（站立/挥手/思考/叉腰/抱胸/坐/战斗/鞠躬/踢腿/持剑/瞄准/打电话/靠墙/插手/伸懒腰/打哈欠/欢呼/沮丧/惊讶/出拳/格挡/投掷/下蹲/转身/立正/T-pose/走路/下跪） |
| 动作预设 `MOTION_PRESETS` | `riggedHumanoid.ts:1454-1465` | **8 个**（走路步态/呼吸/摆臂/转头/待机摇摆/挥手问好/下蹲起立/侧倾） |
| 缓动函数 | `riggedHumanoid.ts:12-113` | **12 种** |

⇒ **问题不在"没有姿势库"，而在"姿势库本身表达不出自然人姿"。**

## 第 1 章 根因（4 条，全部有代码实证）

### 🔴 根因一：四肢**缺少 Y 轴（扭转/内旋）** —— 这是最致命的一条

**关节模型只有 26 个自由度，其中肩/髋只有 X（前后）+ Z（侧展），肘/膝/踝只有 X（弯曲）**：

```ts
// riggedHumanoid.ts:286-312 —— JointPose 的完整字段清单
lShoulderX, lShoulderZ, lElbowX, lWristX,     // ← 没有 lShoulderY（上臂内旋）
rShoulderX, rShoulderZ, rElbowX, rWristX,     // ← 同样没有
lHipX, lHipZ, lKneeX, lAnkleX,                // ← 没有 lHipY（大腿内旋）
rHipX, rHipZ, rKneeX, rAnkleX,                // ← 同样没有
```

**应用端把 Y 硬编码成 0**：

```ts
// riggedHumanoid.ts:2192-2215 —— capsule 骨架
bones.lShoulder.rotation.set(deg(neg(p.lShoulderX)), 0, deg(p.lShoulderZ));
//                                                    ↑ Y 恒 0
bones.lHip.rotation.set(deg(neg(p.lHipX)), 0, deg(p.lHipZ));
//                                          ↑ Y 恒 0

// riggedHumanoid.ts:3259+ —— GLB 骨架（用户实际看到的 BodyKun/BodyChan）
applyBoneDelta(bones.lArm, identity, "lArm", neg(p.lShoulderX), 0, p.lShoulderZ);
//                                                               ↑ 0
applyBoneDelta(bones.lHip, identity, "lHip", neg(p.lHipX), 0, p.lHipZ);
//                                                          ↑ 0
```

**为什么这会让姿势"不像人"**：

| 现实人体 | 项目模型 | 后果 |
|---|---|---|
| 肩关节是**3 自由度球窝关节**（前举/侧举/**内旋外旋**） | 只有 2 自由度 | 手臂只能"前后摆 + 左右张"，**像板子** |
| 肘的弯曲**平面**由肩的内旋决定 | 平面被锁死 | 侧举手臂后弯肘会**朝上/朝外拐**（"胳膊肘朝外翻"） |
| 「手叉腰」「抱胸」「拿东西」「握手」「背手」**必须**有上臂内旋 | 无法表达 | 这些日常动作**在数学上做不出来** |
| 走路时大腿有内旋、脚尖有方向 | 髋无 Y | 腿只能前后摆+侧张，**像木偶**，脚尖方向恒定 |

### 🟠 根因二：肩带（锁骨）几乎没有运动

```ts
applyBoneDelta(bones.lShoulder, identity, "lShoulder", 0, 0, p.lShoulderZ * 0.35);
//                                                        ↑↑ 前伸与上提恒为 0，只剩 0.35 倍侧倾联动
```

真人抬臂时锁骨会上提+旋转（肩带参与），这里没有 ⇒ 抬臂时肩部形态僵死。

### 🟠 根因三：没有 IK，脚不会贴地

全库无 IK 求解（只有 FK 正推）。后果：
- 下蹲、迈步、屈膝时**脚会浮空或穿地**
- `applyPoseToGLBResolved` 里专门写了注释「腰部绝不能打到 Hips，否则脚离地」——**说明"脚离地"是已知且在用注释规避的问题**，但没有根治

### 🟡 根因四：Euler `"XYZ"` 顺序 ⇒ 举臂时万向节锁

```ts
// riggedHumanoid.ts applyBoneDelta
bone.quaternion.multiply(
  new THREE.Quaternion().setFromEuler(new THREE.Euler(deg(xDeg), deg(yDeg), deg(zDeg), "XYZ")),
);
```

当侧举 Z 接近 ±90°（举手/侧平举）时，X 轴与 Y 轴退化重合 ⇒ **肩部旋转会突然翻转**。
这也是"举手姿势特别怪"的直接原因。

### ⚪ 次要观察
- 全部角度过 `neg()` 取负，配合 `deg()` 转换 —— 方向约定，本身不算错但增加了出错面
- 躯干前倾被 `spine` 与 `abdomen` 两段分担，系数是手调的（retarget 里 0.5/0.6/0.7） ⇒ 姿态偏软
- `resolveChainPose` 是**累加非幂等**的，注释自述"二次执行会把肩→肘、髋→膝、胸→头等联动放大"——已有踩坑记录

## 第 2 章 修复方案（四步，按性价比）

| 步 | 修什么 | 改动 | 难度 | 效果 |
|---|---|---|---|---|
| **① 补 Y 轴自由度** ⭐ | JointPose 加 `lShoulderY/rShoulderY/lHipY/rHipY`（+可选 `lElbowY/rElbowY` 前臂旋前） | 类型 +4~6 字段；`applyBoneDelta` **已支持 yDeg 参数**（只是调用处传 0）⇒ 执行端只改 4 行；`JOINT_LABELS` 加对应滑杆；预设库补内旋 | **低** | ⭐⭐⭐ **根治"板子手臂""肘朝外翻"** |
| ② 改旋转顺序 | Euler `"XYZ"` → `"YXZ"`（先扭转后摆动，符合人体） | `applyBoneDelta` 一行 | **极低** | ⭐⭐ 消除举臂翻转 |
| ③ 补肩带 | 锁骨给前伸/上提自由度（或按 shoulderZ 联动上提） | `lShoulder/rShoulder` 的 delta 从 `(0,0,z*0.35)` 改为含 X/Y 分量 | 低 | ⭐⭐ 抬臂形态自然 |
| ④ IK 脚接地（可选） | 髋/膝/踝三角解算，保证脚在支撑面 | 新增纯函数模块（**非冻结文件**） | 中 | ⭐⭐ 消除浮空/穿地 |

**另需补的预设**（有了内旋才能做）：
- 手叉腰（实测当前"hands_hips"预设因无内旋而畸形）
- 抱胸、背手、双手插兜
- 拿手机看、端杯子、握手、指路
- 行走（骨盆旋转 + 手臂内旋摆动）

## 第 4 章 验收标准（怎么算"修好了"）

| 项 | 现状 | 目标 |

## 附：一句话总结

> **不是姿势库不够用，是关节模型少了"内旋"这半个肩关节。**
> 补齐 Y 轴（4 行执行端 + 类型 + 滑杆）就能根治"手臂像板子、肘朝外翻"；
> 再把 Euler 顺序改成 `YXZ`、补上肩带运动，姿势就"像人"了。
> 但这两个文件都在冻结区 ⇒ **需要一次「解冻 stage3d-core」授权**（限姿势相关符号，不碰端口/GLB/材质）。
