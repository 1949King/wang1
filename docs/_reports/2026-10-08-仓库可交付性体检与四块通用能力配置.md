### 4.1 块① 测试套件 —— ✅ 已有，缺「一条命令跑全部」

**现状**：pytest 877 绿、vitest 235 绿、run_all_checks 72 项绿、hook 9 道绿。**四套入口分散**。

**缺口**：没有单一「全量体检」入口（无 Makefile / 无 `scripts/check_all.bat`）。

**可执行配置**：新建 `scripts/check_all.bat`（或 `check_all.sh`）

```bash
#!/usr/bin/env bash
# scripts/check_all.sh —— 全量体检单入口（仓库根执行）
set -u
cd "$(dirname "$0")/.."
PY=".venv312/Scripts/python.exe"

echo "== [1/4] 提交前 9 道门禁 =="
bash .git/hooks/pre-commit || exit 1

echo "== [2/4] Python 单测（877）=="
QT_QPA_PLATFORM=offscreen "$PY" -m pytest -q || exit 1

echo "== [3/4] 画布前端单测（235）=="
( cd vendor/shiguang-canvas && npx vitest run --pool=threads ) || exit 1

echo "== [4/4] 验证套件（72 项，含 bridge e2e）=="
"$PY" _verify/run_all_checks.py || exit 1

echo "✓ 全量体检通过"
```

`keyframe_animation` → `timeline_manager` → `llm_editor` → `subtitle_manager` → `local_asset_manager`
（均为纯逻辑 + 0 覆盖 + 语句多，冻结区文件跳过或走解冻）。

### 4.3 块③ 一任务一分支 + 自动回滚 —— ❌ **完全没有**

**现状（实测）**：无分支模型、无回滚脚本；全仓库长期在 `main` 上直提，19 次语义提交全在本机。

**风险**：Agent 夜间长跑一旦改坏，没有「一键回到上一个绿灯」。

**可执行配置**：`scripts/task_branch.sh`（一任务一分支 + 绿灯标记 + 回滚）

```bash
#!/usr/bin/env bash
# scripts/task_branch.sh —— 一任务一分支 + 自动回滚
# 用法： ./scripts/task_branch.sh start  <任务名>     # 开新任务分支
#        ./scripts/task_branch.sh done   <任务名>     # 跑全量体检 → 打绿灯 tag → 合并
#        ./scripts/task_branch.sh rollback            # 回滚到最近绿灯 tag
set -eu
cd "$(dirname "$0")/.."

case "${1:-}" in
  start)
    TASK="${2:?任务名必填}"
    git switch -c "task/$TASK" 2>/dev/null || git switch "task/$TASK"
    echo "✓ 已切到 task/$TASK（基线 $(git rev-parse --short HEAD)）"
    ;;
  done)
    TASK="${2:?任务名必填}"
    bash scripts/check_all.sh || { echo "✗ 体检未过，留在 task/$TASK 自行修"; exit 1; }
    git tag -f "green/$TASK" && echo "✓ 绿灯 tag: green/$TASK"
    git switch main && git merge --no-ff "task/$TASK" -m "merge: $TASK"
    ;;
  rollback)
    TAG="$(git tag -l 'green/*' --sort=-creatordate | head -1)"
    [ -n "$TAG" ] || { echo "✗ 没有绿灯 tag"; exit 1; }
    git switch -C main "$TAG" && echo "✓ 已回滚到 $TAG"
    ;;
  *) echo "用法: $0 {start|done|rollback} <任务名>"; exit 2 ;;
esac
```

> 这套直接对上分析里那句「防的不是模型笨，防的是模型会犯错」：
> 分支隔离把爆炸半径限制在一个任务内；`green/*` tag 是回滚锚点；
> `check_all.sh` 是「能不能合并」的唯一判据。

### 4.4 块④ 沙箱权限 —— ⚠️ **半有；「素材不出域」无开关**

**已有的**（实测）：

| 机制 | 位置 | 作用 |

| 9 道 pre-commit 门禁 | `.git/hooks/pre-commit` | 统一卡点 |

**缺口（实测证据）**：`app/core/ai/provider_caps.py:233 resolve_order()`
**没有任何「禁止出域 / local-only」开关** —— 它做的是「能力筛选 + quality_tier 降序 + `local` 兜底」，
即 **默认优先走云端 provider**，`local` 永远排最后：

```python

filtered = filter_by_caps(order, s)

```

**这意味着**：面对「客户素材不能出域」的硬约束，现有机制**兜不住** ——
只能靠调用方硬传 `provider="local"`（且该分支会返回 `["local", "local"]`，是个已存在的瑕疵）。
