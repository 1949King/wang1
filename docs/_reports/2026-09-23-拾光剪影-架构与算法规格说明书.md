# 第一篇 总体架构

## 1. 核心设计思想

不是"先决定本地/云端/双路、再执行、再补救"，而是**把质量、成本、延迟、资源放进同一个实时目标函数，动态选路，并用执行结果持续修正下一次决策**。这一思想由《异构动态协作引擎规格书》v4.3 引入，在本项目以 **12 个切片**落地（见 §35）。

与之并列的第二条主线&#x662F;**「真相源唯一 + 冻结区锁死」**：任何跨线程共享状态只允许有一个所有者；任何已收敛的关键行为用哈希锁保护，防止被后续改动无声破坏。

## 2. 系统定位（北极星）

闭环 7 阶段，自 V4.19.0「发布/数据采集/优化建议」随账号运营下线后，活路径收敛为两条：

```
剪辑精剪  +  AI 画布
   │            │
   └─ 精剪 → 人工改 → 文案 → 选题
```

- 已有：C3 剪辑 workflow_hint、四守护、词锚定重锚、Agent 全链路编排
- 仍缺：选题自动导入时间线、一键粗剪直接写 `_clips`
- 优先级：**先剪辑（稳→快→全→可维护），后 AI 闭环**

# 第六篇 工程约束与铁律

## 46. 复杂度与算力铁律

> 源自《异构动态协作引擎规格书》第十三篇 §69，已在项目中作为设计红线。

1. **核心调度与控制器必须 O(1) ~ O(log n)**。全局路由打分、影子价格更新、资源仲裁**禁止大模型推理**。
2. **算力严格分层**：
   - O(1) 数值计算：路由收益、PI 更新、可行集投影、配额重分配（核心路径）
   - 允许小模型：DAG 解析分解、B 模块多级质量评分
   - 禁止进入核心链路：全模态大模型
3. **优化器只能重分配资源，无法突破物理下界**：端到端时延 ≥ DAG 关键路径各单元累加；Token 成本 ≥ 每单元至少一路推理的基础输入量。
4. **代理指标失真必然导致闭环反向优化**：机器评分只是低成本观测代理，必须永久保留「多指标加权 + 周期人工抽检校正 + 误差超限自动冻结闭环 + 人工强制否决通道」四件套。
5. **AI 打分永远不能作为真值**参与闭环更新；只有人工确认标签才允许校正评分权重与质量先验库。
