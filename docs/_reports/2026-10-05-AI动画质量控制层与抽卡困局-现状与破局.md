## 第 0 章 四问四答（先看结论）

| 问题 | 答案 |
|---|---|
| 要高质量，是否必须依赖高精度白模/建模？ | **必须依赖「控制层」，但不一定是「高精度建模」**。白模/骨骼/深度图/姿态/边缘图，任一种控制信号都比纯文字强得多 |
| 没有建模，是不是就得狂抽卡？ | **逻辑上必然**：控制信号越少 → 不确定性越大 → 抽卡次数越多。这是纯 2D 路线的结构性代价 |
| 是不是高阶玩家的玩具？小白做不出精品？ | **现状部分成立**（纯手搓要吃美术功底），但**正在被工具化**——本项目做的就是这件事 |
| 本项目从哪打破？ | 项目已铺好三条控制层出口（实证见 §3），缺的是**把出口接到模型上 + 补 3D 资产来源 + 串成一键产线** |

## 第 1 章 两条生产路线的真实分野

### 路线 A：纯 2D 抽卡（文生图 → 图生视频）

```
文字提示 → 出图（抽 N 张）→ 人眼挑 → 局部返修 → 图生视频 → 剪辑
              ↑
        全靠概率，没有控制信号
```

| 维度 | 现实 |
|---|---|
| 单次命中率 | 低（可用率通常两位数百分比，角色一致性更差） |
| 角色一致性 | 只能靠「垫图 + 提示词锚定」近似，跨镜头漂移 |
| 动作准确度 | 图生视频靠模型自己编，**要它抬手不一定抬手** |
| 镜头语言 | 几乎不可控（推拉摇移靠提示词祈祷） |
| 成本结构 | **时间全花在抽卡与筛选**，而非创作 |

### 路线 B：控制层驱动（白模/骨骼/深度/姿态 → 生成）

```
参考视频 / 手摆白模 → 提姿态/渲染 Depth·Normal·OpenPose
                          ↓
                  作为条件输入 → AI 只负责「风格化渲染」
                          ↓
                     动作/构图/镜头 100% 可控
```

| 维度 | 现实 |
|---|---|
| 单次命中率 | 高（构图动作已定，AI 只需画得好看） |
| 角色一致性 | 骨架固定 + 参考图固定 ⇒ 稳定得多 |
| 动作准确度 | **完全可控**（动作来自参考视频或手 K） |
| 镜头语言 | **完全可控**（相机在 3D 场景里摆） |
| 成本结构 | 前期摆一次，后面前提复用；**抽卡次数大幅下降** |

> **这就是答案**：工业上要「高质量 + 可控」，控制层几乎必需。
> 但「白模」不必是人工高精度建模——**它是「控制信号的载体」**，
> 可以是粗糙几何体、火柴人骨架、甚至只是一张深度图。

## 第 2 章 为什么「没控制层 = 狂抽卡」是结构性的（不是技术不够好）

抽卡的次数 ≈ 不确定性 ÷ 单次命中率。控制层做的事就是**直接消掉不确定性**：

| 不确定性来源 | 纯抽卡怎么解 | 控制层怎么解 |
|---|---|---|
| 角色长什么样 | 垫图 + 提示词 + 锚定（近似） | 定妆照 + 骨架绑定（确定） |
| 动作是什么 | 靠提示词猜 | 参考视频提取姿态（确定） |
| 镜头怎么动 | 靠提示词猜 | 3D 相机路径（确定） |
| 构图在哪 | 靠提示词猜 | Depth 图（确定） |

**结论**：控制层的价值不是「画得更好」，而是**把「运气」换成「确定性」**。

## 第 3 章 本项目已经铺好的地基（实证）

**你的项目早就选定了控制层路线**，并且已经建了完整的地基：

| 已有资产 | 代码位置 | 干什么 |
|---|---|---|
| 3D 导演台 | `vendor/shiguang-canvas/src/Stage3D.tsx` · `stage3dScene.ts`（235 行） | 在 3D 场景里摆角色、摆相机、走路径 |
| 骨骼角色 | `riggedHumanoid.ts` | 带骨骼绑定的可动角色 |
| **姿态重定向** | `stage3dPoseRetarget.ts`（336 行） | **把参考视频的姿态套到 3D 角色上** |
| **ControlNet 三通道导出** | `stage3dControlNet.ts`（348 行） | 渲染 **Depth / Normal / OpenPose**（COCO 18 点），供 ComfyUI/SDXL ControlNet 用 |
| 白模视频合成 | `stage3dPoseVideo.ts` + `app/core/ai/pose_video_service.py` | 逐帧渲染 → 合成 mp4 → 作 `reference_video` |
| 姿态提取（独立子进程） | `app/core/ai/pose_extract_service.py` + `pose_worker.py` | 视频 → BlazePose 关键点（推理完立即退进程释放显存） |
| video_motion 通道探测 | `app/core/canvas_aigc.py:1283` | 检测渠道是否有「视频运动参考」能力模型（**通道就位、待模型**） |

**三条出口的设计（这是最值钱的部分）**：

```
                        3D 导演台（摆好动作/镜头）
                                 │
        ┌────────────────────────┼────────────────────────┐
        ↓                        ↓                        ↓
  出口①白模视频            出口②ControlNet 三通道      出口③video_motion
  帧序列→mp4→               Depth/Normal/OpenPose       姿态/运动参考
  reference_video            → SDXL ControlNet           → 云端渠道模型
        │                        │                        │
        └───── 都指向同一目标：让 AI 只做「风格化」而不用猜「动作」 ─────┘
```

## 第 4 章 缺什么才能打破闭环（三个缺口 + 减抽卡三件）

### 缺口一：控制层出口**没接上模型**（最关键）

| 现象 | 实证 |
|---|---|
| ControlNet 通道能导出 Depth/OpenPose，但**本地没下 ControlNet 权重** | `app/models/cache/` 只有 SD1.5 / SDXL / SVD 三个 |
| `video_motion` 通道探测就位，但**没有任何模型标记该能力** | `canvas_aigc.py:1301-1320` 探测到就报错并提示「请选带 video_motion 的模型，或改用图片条件 / 3D 白模模式」 |
| **没有「白模帧序列 → 逐帧条件生成 → 拼成视频」的本地闭环** | 三通道导出是散点，无人串成产线 |

⇒ **补法**：下 SDXL ControlNet 权重（OpenPose + Depth，各约 2.5GB）→ 写一条「帧序列 → 逐帧 ControlNet 生图 → 拼片」的本地流水线。**这是投入最小、确定性最高的一步。**

### 缺口二：没有 3D 资产来源

| 现象 | 实证 |
|---|---|
| 无单图转 3D（TripoSR / InstantMesh / Hunyuan3D / TRELLIS） | 全库 grep **0 命中** |
| 角色白模是程序化几何体（`riggedHumanoid.ts`），**不是「长得像角色」的模型** | — |

⇒ **补法**：两条腿——① 引入单图转 3D（把定妆照变成粗糙 3D 壳，够用即可）② 支持 GLB 导入（项目有 GLB 处理痕迹，但未成闭环）。

### 缺口三：三条出口没串成「一键产线」

现在要在画布上手工走：摆 3D → 导出 → 手动接生成 → 手动拼。缺一个**导演台节点 → 生成节点 → 拼片节点**的自动化链路。

### 并行必做的「减抽卡三件」

| 件 | 现状 | 作用 |
|---|---|---|
| **best-of-n 自动选优** | 零件全在（评分器 + 账本），**差 ~80 行编排**（刀 A2） | 出 4 张自动挑最好的，直接砍掉人工筛选时间 |
| **局部重绘（省重抽）** | ✅ 已有 `inpaint_retry.py` + 端点 | 画面局部坏 → 只重画那一块，不重抽整张 |
| **配方包 + 账本复用** | 账本 ✅（`draw_book` 记哪个 seed 好）；配方包 ❌（`gen_recipe.py` 不存在） | 好配方可复用，不必每次重新试 |

## 第 5 章 所以「小白能不能做精品」——诚实回答

| 判断 | 说明 |
|---|---|
| **现在（纯手搓）** | ❌ 做不了精品。要懂分镜、提示词、ControlNet、后期修图——确实是高阶玩家玩具 |
| **工具链成熟后** | ✅ 可以。控制层工具 + 自动选优 + 局部重绘，把门槛从「美术功底」降到「会用工具」 |
| **本项目的定位** | **就是这座桥**——把高阶玩家的手工活变成流水线。这不是「又一个 AI 视频工具」，而是「把控制层工业化」 |

一句话：**控制层是分水岭。谁先把「白模/姿态 → 生成」这条链做成傻瓜流水线，谁就把精品 AI 漫剧从「高阶玩家玩具」变成「普通人产能」。**

| 序 | 动作 | 投入 | 确定性收益 |

# 第 7 章（补充 · 2026-10-05 用户追问后修订）

> 用户追问：「路线 B 如果基于没有建模能力的玩家，那不也是高阶玩家玩具吗？路线 A 不就是当前
> AI 视频生成那批使用者的现状吗？」——**两条都对**，且暴露了本文初稿的一处混淆：
> 初稿把「控制层」当成了一条路，实际应拆成 B1 / B2 两条。

## 7.1 三条路线（修正第 1 章的二分法）

| 路线 | 控制信号从哪来 | 门槛 | 谁在用 | 结果 |
|---|---|---|---|---|
| **A 纯抽卡** | 无（只有文字） | 低 | **当前主流**（文生视频抽卡那批人） | 靠运气 · 一致性差 · 动作不可控 · 时间黑洞 |
| **B1 建模控制** | **人工建模**（Blender/Maya 白模） | **高（要会建模）** | 专业团队 | 可控，但**仍是高阶玩家玩具** |
| **B2 免建模控制** | **图 / 视频 / 预设 / 程序化骨架** | **低（给张图就能用）** | 本项目在做 | 可控 **且不需要会建模** |

**结论修正**：决定「是不是玩具」的不是「有没有控制层」，而是**控制层需不需要你会建模**。
用户对 B1 的判断完全成立；B2 才是把精品交到小白手里的唯一路径。

## 7.2 本项目站在 B2，而且不是从零开始（实证）

关键事实：**项目的白模是「程序化生成的人体骨架」，不是导入的建模资产**——
这正是 B2 的典型做法。

| 资产 | 属于哪条路线 | 说明 |
|---|---|---|
| `riggedHumanoid.ts` | **B2** | 程序化生成带骨骼的人体——**用户不需要会建模**，代码造人 |
| `stage3dPoseRetarget.ts`（336 行） | **B2** | 参考视频的姿态 → 自动套到程序化骨架上（自动，非手工） |
| `pose_extract_service.py` + `pose_worker.py` | **B2** | 视频 → BlazePose 关键点（控制信号从视频白嫖） |
| `stage3dControlNet.ts`（348 行） | B2 的输出端 | 从 3D 场景渲 Depth/Normal/OpenPose，喂给生成模型 |
| `Stage3D.tsx` / `stage3dScene.ts` | 混合（偏 B1 手感） | 需要**手工摆**姿势与相机路径 ← 当前的门槛残留 |

⇒ **项目已经把「建模」这道门槛拆掉了**（程序化骨架 + 姿态自动重定向），
但还留着「手工摆动作」这道**半截门槛**——这才是它当前「仍像玩具」的真实原因。

## 7.3 让 B2 真正「小白可用」还差的三件事

| # | 缺什么 | 补什么 | 现状 |
|---|---|---|---|
| 1 | 手工摆姿势/走路径 | **预设动作库**（走 / 跑 / 转头 / 挥手 / 坐下」，一键套用） | 无 |
| 2 | 手工调机位 | **镜头模板**（推 / 拉 / 摇 / 移 / 环绕，一键套用） | Stage3D 有路径能力，无模板库 |
| 3 | 全手工串流程 | **一键驱动入口**：给一张参考图 / 一段参考视频 / 一句分镜文字 → 自动出「姿态序列 + 机位序列 + ControlNet 三通道」 | 零件全在，未串 |

> 第 3 件是真正的分水岭：**从「会用 3D 工具」降到「会给素材」**。
> 做完它，B2 才从「半截门槛」变成「零门槛」。

## 7.4 为什么这是机会窗口

- **当前主流 = 路线 A**（用户判断正确）⇒ 说明 **B2 是空白区**，不是红海
- 业内 B2 也才刚起步（多停留在「视频重定向」「ControlNet from video」的单点工具）
- **谁先把 B2 做成傻瓜流水线，谁就把「精品 AI 漫剧」从手艺变成产能** —— 这是本项目最硬的护城河

## 7.5 本项目的下一步（修正后的排序）

| 序 | 动作 | 补的是哪一环 |
|---|---|---|
| 1 | **预设动作库 + 镜头模板**（不需要 GPU、不需要新模型，纯前端 + 数据表） | 拆掉「手工摆」门槛（本项成本最低、见效最直接） |
| 2 | 下 SDXL ControlNet 权重 + 白模帧序列逐帧生成拼片闭环 | 让控制层真的接上模型 |
| 3 | **一键驱动入口**（图/视频/文字 → 姿态+机位+控制图） | 把 B2 从「半截」变「零门槛」 |
| 4 | best-of-n 自动选优（刀 A2） | 减抽卡人工 |
| 5 | 角色定妆照 + 单图转 3D | 资产来源 |
