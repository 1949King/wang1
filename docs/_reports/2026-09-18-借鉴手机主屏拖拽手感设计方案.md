# 借鉴手机主屏拖拽手感 — 设计方案

日期：2026-09-18
用户提出：**借鉴手机操作系统桌面（iOS 主屏 / Android 桌面）的拖拽排序手感，再叠加「靠近即吸附」**
状态：设计阶段。涉及 `canvas-magnetic-intent` 冻结区的改动需用户授权解冻。

---

## 一、为什么这个类比是对的

用户说的「桌面图标排序手感」，是**被十亿级用户验证过的商用标准**。它由四条机制叠加而成，缺任何一条手感都会「不对」。

| # | 机制 | 说明 | 本项目现状 |
|---|------|------|-----------|
| **1** | **跟手浮起** | 长按 → 图标放大 + 投影 + 轻微上浮；**手指到哪它到哪，1:1，绝无瞬移** | ❌ **缺（且是反的）** |
| **2** | **整列让位** | 拖到已有图标上方 → 被占位图标**主动平移让开**，形成空槽 | ❌ **缺** |
| **3** | **靠近吸附** | 进入范围显示「将占的格子」预览，**松手才落座** | 🟡 半有（只有贴合缝线，无落点预览） |
| **4** | **格点落位** | 每次松手都落在格点上，**不存在「差 3px」** | 🟡 半有（只对齐一个轴） |

### 关键洞察

**第 1 条是全部差异的根源。** 手机主屏上，你**从不会看到图标跳走**——因为手指和图标是绑定的。而你现在的实现里：

```ts
// useMagneticDrag.ts:245  onNodeDrag
if (result.level !== "none" && result.targetId) {
  writeNodePos(draggingNode.id, { x: result.snapX, y: result.snapY });  // ← 进入 120px 就整卡瞬移
```

再叠加 `MagneticEngine.ts:203` 的**强制边对齐**（吸 X 轴时把 Y 也拽走，位移最大 ±200px），用户看到的就是「卡片自己跳走了」——**这跟手机主屏的手感是反的**。

**所以你要的效果 = 把机制 1 做对（跟手）+ 补机制 2（让位）+ 把机制 3 做成预览（而非瞬移）。**

## 二、四条机制的具体设计

### 机制 1：跟手浮起（最高优先级）

这是**手感的底座**，必须先做对。

**设计**：

| 项 | 手机主屏 | 本项目应对 |
|----|---------|-----------|
| 位置 | 图标 1:1 跟手指 | 拖拽中**绝不覆写卡片位置**，让它跟指针走（React Flow 原生行为） |
| 视觉 | 放大 ~1.1x + 加深投影 + z-index 提升 | 拖拽卡：`scale(1.03)` + `box-shadow` 上浮 + `z-index` 提升 |
| 反馈时机 | 长按后浮起 | 鼠标按下即浮起（桌面端无长按需求） |

**改动点**：
- `useMagneticDrag.ts` `onNodeDrag`：**删掉 `writeNodePos`**，只更新 `magState` 记录「如果松手会落在哪」
- `NoviceCard.tsx`：新增 `dragging` 态（从 store 读 `draggingId === id`），挂 `.nv-card.drag` class
- `novice-cards.css`：`.nv-card.drag { transform: scale(1.03); box-shadow: ...; z-index: 50; transition: none; }`

> ⚠️ 注意：`.nv-card.drag` 上**必须 `transition: none`**，否则 scale 的过渡会跟每帧位移打架，反而卡。

### 机制 2：整列让位（让「插入」零成本）

这是**当前完全缺失**的能力，也是手机主屏最「魔法」的部分。

**设计**：拖拽中的卡片靠近某张卡的「贴合位」时，不是吸上去，而是：
1. 在目标位置**显示一个半透明幽灵占位**（虚线圆角矩形，240×200）
2. 让该位置**右侧/下侧的卡片链整体平移让出空间**（带动画，~180ms）
3. 松手 → 幽灵位置落座（带吸附动画）

**需要新增的模块**：

```
magnetic/
  reflow.ts            — 让位计算（纯函数，可测）
  SlotGhost.tsx        — 幽灵占位渲染
```

**`reflow.ts` 核心接口设计**（纯几何，不依赖 React）：

```ts
export interface ReflowPlan {
  /** 幽灵占位的位置（松手后卡片会落在这） */
  ghost: { x: number; y: number };
  /** 需要让位的卡片：id → 目标位置（带动画） */
  shifts: Array<{ id: string; to: { x: number; y: number } }>;
}

/**
 * 计算插入落位时的让位方案
 * @param dragging 拖拽卡（当前矩形）
 * @param predictedSlot 预测的吸附落点
 * @param allNodes 全画布节点
 * @param axis 让位轴（水平）/ 垂直
 */
export function planReflow(
  dragging: Rect,
  predictedSlot: { x: number; y: number },
  allNodes: Node[],
  axis: "horizontal" | "vertical",
): ReflowPlan;
```

**算法**（对齐手机主屏行为）：

1. 从 `predictedSlot` 出发，沿 `axis` 正方向扫描所有与「插入带」投影重叠的卡片
2. 按坐标排序，形成「让位链」
3. 让位链中每张卡向后推 `CARD_SIZE + gap`（即「自己的宽度 + 一个缝」）
4. 只推「同一行/列」的卡（`axis=horizontal` 时要求 Y 投影重叠 ≥ 40px，与 `MIN_OVERLAP` 一致）
5. 推进过程中若撞到「不在链上的卡」，**该卡不再推**（链断裂），避免误伤远处的卡

**关键取舍**：让位链**只推一行**，不做递归 cascading。手机主屏也只推同一行/同一列——递归会让远处卡片乱动，反而破坏「可预期性」。

### 机制 3：靠近吸附 → 改成「预览 + 落座」

**设计**：

| 阶段 | 现状 | 改为 |
|------|------|------|
| 拖拽中 | 贴合缝线 + **卡片瞬移** | 幽灵占位（半透明）+ 让位预览，**卡片本体不动** |
| 松手 | 钉回落点 | **吸附动画**落到幽灵位（`snapAnimationMs=200` + `overshootPx=5`，这两个常量已在 `types.ts` 预留但闲置） |

**吸附动画的曲线**（对齐手机主屏的「啪」一下）：

- 前 70%：ease-out 快速接近
- 后 30%：轻微过冲 `overshootPx` 再回弹（`animateNodeTo` 已实现这个逻辑，见 `useMagneticDrag.ts:123-126`，只需把 `overshootPx` 从 0 改成 5）

### 机制 4：格点落位（只对齐被吸附轴）

**这直接解你报告里的根因 E**：`getSnapPosition` 目前在吸 X 时把 Y 也强制对齐。

**改为**：

```ts
// 吸 X → Y 保持拖拽当前值（不被拽走）
case "left":   return { x: targetPos.x - dragSize.width - gap, y: dragPos.y };
case "right":  return { x: targetPos.x + targetSize.width + gap, y: dragPos.y };
// 吸 Y → X 保持拖拽当前值
case "top":    return { x: dragPos.x, y: targetPos.y - dragSize.height - gap };
case "bottom": return { x: dragPos.x, y: targetPos.y + targetSize.height + gap };
```

再叠加 **tldraw 式的中线对齐**（`midX`/`midY` 吸附点）：当拖拽卡的**中心线**接近目标中心线时，吸附到中心线。这样「排列整齐」这件事有了第二条路径，用户更容易摆齐。

## 三、和「靠近即吸附」的关系（重要）

你之前裁定过 V4.28.2「靠近就自动吸附」。**手机主屏的类比对这条有修正建议**：

| 方案 | 行为 | 手机主屏是否如此 |
|------|------|----------------|
| **A. 靠近即吸附（现状）** | 进入 120px 立刻瞬移到落点 | ❌ 主屏不是这样，主屏是「预览 + 松手落座」 |
| **B. 预览 + 松手落座（建议）** | 进入范围显示幽灵 + 让位，松手才落座 | ✅ **正是主屏行为** |
| **C. 混合** | 靠近显示预览，**距离够近（如 <20px）才即时吸附** | 🟡 部分场景 |

**建议采用 B**，理由：
1. 它才是手机主屏的真实行为（用户的类比目标）
2. 它同时解决「瞬移感」和「纵坐标被拽走」
3. 它保留了「吸附」——只是把时机从「拖拽中」挪到「松手时」

> 如果保留 A（靠近即吸附），至少要把「纵向不强行对齐」修掉（机制 4），否则手感仍然怪。

## 五、风险与红线

| 风险 | 应对 |
|------|------|
| **机制 2（让位）可能引发「大面积乱动」** | 限制：只推同一行/列（投影重叠 ≥ `MIN_OVERLAP=40`）；链撞到「非链卡」即断；**不递归** |
| **让位动画与拖拽帧冲突** | 让位动画只作用于**非拖拽卡**；拖拽卡始终跟手 |
| **冻结点解冻** | P1-1/P1-3/P1-4/P1-5、P2-3/P2-4 均触碰 `canvas-magnetic-intent`，**动手前需用户明确授权**；改完 `frozen_zone_guard.py --update` 并复核 `OK frozen zones intact` |
| **`medium` 档死代码** | 顺带定夺（删档 or 修阈值顺序） |
| **`.nv-card.drag` 的 transition** | 必须 `none`，否则 scale 过渡与位移打架 |

## 六、与手机主屏的差异（不要盲目照搬的部分）

| 手机主屏 | 本项目 | 理由 |
|---------|-------|------|
| 固定网格，卡片只能落格点 | **自由二维画布** | 你的画布需要「上下左右成关系」，不能锁死一维网格 |
| 拖动即重排（位置=顺序） | **位置=关系语义 + 顺序** | 你的 L2 设计里，邻接方向带关系含义（虽已剥离业务语义，但几何邻接仍是关系） |
| 一格一卡，无重叠 | 允许重叠（层叠 / stack） | 你有「多版本层叠」需求，手机没有 |
| 翻页（超出一屏换页） | 无限画布 | — |

**结论**：机制 1/3/4 **可完全照搬**；机制 2（让位）**要改造**——手机是「一维让位」，你要做「二维局部让位」（只在被插入的那一行/列让位，不做全局重排）。

## 七、最小可验证版本（建议先做这个）

如果一次上太多不好验证，建议**先做「机制 1 + 机制 4」**这一个小组合：

- **只改两个文件**：`useMagneticDrag.ts`（删 writeNodePos）+ `MagneticEngine.ts`（只动被吸附轴）
- **不加任何新模块**（不碰让位）
- **效果**：卡片 100% 跟手 + 松手吸附 + 横向拖不纵向乱跳

这个组合能**立刻验证「跟手」这个底座是否成立**。如果成立，再上机制 2（让位）—— 因为让位是建立在「跟手」之上的，跟手不对，让位一定做不好。

> 注意：即便如此，仍触碰冻结区（两个文件都在 `canvas-magnetic-intent` 内），需解冻授权。
