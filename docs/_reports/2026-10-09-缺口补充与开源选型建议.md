## 4. 三个创新功能（都建立在**我们独有**的组合上）

### 4.1 「验收台」——把抽卡从"看着好"变成"可解释的验收"

**组合**：`draw_book` + `gen_critic` + **DOVER/VBench 真分** + 输出历史 + 桌宠。

做什么：每个候选都出 **5 列**（几何分 / 技术分 / 审美分 / 运动平滑 / 时序闪烁），
**按列排序**，任一行可看"它扣分扣在哪一维"。没跑过评估就**显示"未评估"**，绝不算个假分糊过去。

为什么是我们能做而别人难做：别人要么只有生成（没有账本），要么只有评估（没有生成闭环）；
**我们两头都有**——这正是闭环的力量。

### 4.2 「草稿抽卡」——为 4060 8GB 量身定做的省钱姿势

**组合**：`draft_mode`（480p）+ `draw_book` + 超分 + 片段重拍。

流程：写提示词 → **先出 4 张 480p**（成本约 1/4）→ 按验收台挑 1 张 → **一键高清** → 若某段不满意直接**片段重拍**那 2 秒。
LibTV 已验证这个思路（样片 480p → 无损高清），但**它没接抽卡账本与验收分**；我们接上就是"选完还有依据"。

### 4.3 「拉片 → 复刻 → 抽卡 → 验收」一条链（我们的真正差异化）

**组合**：`reference_breakdown`（拉片 L1）→ 深度/姿势（L2）→ 分镜节点 → 草稿抽卡 → 验收台 → 片段重拍。

一句话：**别人做"生成"，我们做"生成之后的生产线"**。
参考片的镜头语言被拆成结构化数据 → 变成我们自己的分镜 → 出片 → 验收 → 局部修。
这条链上每一步都是这几轮做过的模块，**只是还没串起来**。

> ⚠️ 诚实提示：L2 的景别/运镜**目前不推断**（留空），需接视觉模型才填得上；
> 接入前不要对外宣称"自动复刻运镜"。

6. **P2**：`core` 层 52 个 0% 模块的测试补充（按 10-08 报告的清单）

## A.3 采纳 / 修正 / 拒绝 清单

**采纳（写入任务清单）**
1. **P0「换词重配」**：导演台改台词 → 克隆角色原声重配（IndexTTS-2 优先，CosyVoice2 备选）
   → **接入 `segment_retake` 只重拍该段**（不是整条重生成）→ MuseTalk 口型同步 → 建议入轨。
   *这条比原建议更强：接上我们本周刚造的地基，成本和失败面都降一个量级。*
2. **P1 说话人分离**：给已有 `whisper_asr` 加多角色分流（FunASR 的 `speaker-diarization`），
   这是"哪句话属于哪个角色"的前置件。
3. **P1 统一模型管理器（本地权重注册表）**：懒加载 + 显存守卫 + CPU 降级，
   与 `RenderManager` 同构（建议里这条与我们现状完全对齐）。
4. **纪律**：新产的"重配片段"必须打 **「AI 重配」标记**（延续 `super_resolution_honesty` 的诚实生成原则）。

**修正（不建议按原文做）**
- 不要把「实时对话数字人」排进近期：既非四条专注轨内的重点，也会冲破"专注即护城河"；
  其工程参考（OpenTalking 的编排结构）只作调研记录。
- 「AI BGM」不是缺口（YuE 已在），**不要**再立项。
- LatentSync 不在 8GB 主路径上（16GB+），只作为未来换机后的备选记录。

**拒绝**
- ❌ Wav2Lip 进产品线（研究许可）——只允许用于本地验证/基准对比，并在文档标明。
