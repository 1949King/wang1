# 第一部分 差异化打法

## 1.1 先厘清：你打不赢的战场，和你能赢的战场

| 战场 | 谁赢 | 你该不该打 |
|---|---|---|
| 模型能力（画质/时长/物理正确性） | 大厂（字节/快手/阿里，几亿级算力与数据） | ❌ **绝对不打** |
| 生成速度/并发 | 大厂（云集群） | ❌ 不打 |
| 价格战 | 大厂（成本可摊薄到全平台） | ❌ 不打 |
| **控制层怎么用**（零门槛） | **空位** | ✅ **打这里** |
| **从想法到成片的全链** | **空位**（大厂只做生成那一段） | ✅ **打这里** |
| **本地/私有/零边际成本** | **空位**（云端是大厂的商业模式） | ✅ **打这里** |
| **垂直场景深度**（漫剧产线） | **空位**（大厂做通用工具） | ✅ **打这里** |

**核心判断：大厂不做这三件事，不是不想，是商业模式决定他们做不了。**

| 大厂做不了的事 | 为什么 |
|---|---|
| **本地优先** | 云端按次计费是他们的收入来源，做本地等于自断营收 |
| **降门槛到「给张图就行」** | 他们服务专业创作者/企业客户（字节接 Maya/Blender 插件、阿里给 40+ 专业参数），越专业越付费 |
| **打通「想法→成片」全链** | 生成、剪辑、配音、合成分属不同部门/产品线，跨线整合不经济；且剪辑赛道已有 Adobe/剪映占位 |

## 1.2 七条差异化轴（可组合成护城河）

| # | 差异轴 | 大厂现状 | 你的打法 | 为什么是护城河 |
|---|---|---|---|---|
| 1 | **本地优先** | 全云端 | 本地推理 + 可选云补充 | 零边际成本、隐私、可离线、不被审查/调价绑死 |
| 2 | **全链闭环** | 只做生成 | 想法→剧本→分镜→生成→入轨→剪辑→导出 | 用户要的是成片，不是素材 |
| 3 | **零门槛（B2）** | 专业工具（B1） | 程序化骨架 + 预设动作库 + 镜头模板 + 参考视频重定向 | 抢的是「不会建模的 99% 用户」 |
| 4 | **成本结构** | 按次付费 | 本地跑 = 零调用费 | 量产漫剧时，成本差异是**生死线** |
| 5 | **资产归属** | 资产在平台 | 角色库/配方/账本在本地 | 用户越用越离不开（数据护城河） |
| 6 | **垂直深耕** | 通用视频工具 | 只做漫剧/短剧产线 | 垂直场景的细节打磨是通用工具不会做的 |
| 7 | **模型可插拔** | 自研模型闭环 | 站在大厂肩膀上（可切换 provider） | 大厂模型越强，你越强——不跟他们竞争，**吃他们的红利** |

## 1.3 一句话定位

> **「本地 AI 漫剧制片厂」——不是又一个生成器，而是「一台电脑就是一条产线」。**

- 大厂卖的是「生成能力」（按次计费）
- 你卖的是「**成片产能**」（一次投入，无限次生产）

## 1.4 竞争策略：站在他们肩上，而不是正面硬碰

| 做法 | 说明 |
|---|---|
| **接他们的模型当渲染后端** | 项目已有 provider 体系；大厂模型越强越好（吃红利） |
| **用他们的控制层输出** | 字节 Seedance 2.5 已接受 pose/camera 输入、阿里有分镜控制公式——**这些是你控制层的免费出口** |
| **自己掌握「控制层 + 编排 + 成片」** | 这三块大厂不做，也是用户真正付费的地方 |
| **别做「更好的模型」，做「更好的产线」** | 模型 3 个月一代，产线能沉淀资产与流程 |

# 第二部分 场景 / 背景怎么做（回答「导入建模 vs AI 粗模+贴图」）

## 2.1 先纠正一个前提：**场景和角色，本质需求不同**

| | 角色 | 场景/背景 |
|---|---|---|
| 是否要跨镜头一致 | **必须**（同一个角色要多镜头出现） | **不需要**（一个场景画一次就复用） |
| 是否需要「结构正确」 | 要（骨骼/比例） | 只在**复杂运镜**时要（透视/遮挡） |
| 结论 | 需要控制层（骨架） | **多数情况不需要 3D** |

⇒ **这就是为什么背景不该照搬角色的做法。**

## 2.2 项目现状（实证）

| 项 | 现状 | 证据 |
|---|---|---|
| 3D 场景构造方式 | **程序化基础几何体拼装**（Box/Cylinder/Sphere/Plane 当道具：椅子、桌子、方块） | `Stage3D.tsx:459-521`、地面 `PlaneGeometry(40,40)` |
| 能否导入 Blender 模型 | ❌ **不支持**（无 GLTFLoader / 无 .glb 加载） | 全文件 grep 无命中 |
| 场景库 | ❌ **不存在**（无 SceneStore / 场景资产） | grep 0 命中 |
| 全景能力 | ⚠️ 有 `panorama` 节点类型，但**不在可执行列表** | `canvas_workflow_runner.py:52` |
| 深度估计（单图→深度） | ❌ **完全没有**（Depth Anything / MiDaS 0 命中） | grep 0 命中 |

## 2.3 四条技术路线对比（含你提的方案）

| 方案 | 怎么做 | 成本 | 适用 | 评价 |
|---|---|---|---|---|
| **① 导入 Blender 建模** | 人工建模 → 导入 → 贴图 | **最高（要人+要学）** | 关键场景、复杂运镜 | 质量最好，但是 B1，**不是你的路线** |
| **② AI 生粗模 + AI 2D 贴图**（你提的） | 文/图生 3D → 生成纹理贴图 → UV 附着 | 中高 | 需要 3D 但不想建模 | ⚠️ **理论可行但性价比不高**：3D 生成质量不稳（尤其拓扑/UV），纹理烘焙是学界难题；且**场景本来就不需要那么强的 3D** |
| **③ 2D 背景图 + 深度图 → 2.5D 视差运镜** ⭐ | AI 生一张高质量背景图 → 深度估计 → 按深度分层做推拉摇移 | **最低** | **90% 的镜头** | ✅ **最推荐**：背景图质量直接等于最终画质（AI 生图最强的地方），3D 只提供"透视感" |
| **④ 全景图 skybox** | 生 360° 全景 → 贴到大球 → 相机在里面转 | 低 | 环绕、漫游、大空间 | ✅ 补 ③ 的短板（可环绕），项目已有节点类型待接通 |

## 2.4 推荐方案：**分层策略**，而不是二选一

```
普通镜头（推拉摇移）      → ③ 2D 背景图 + 深度图（2.5D 视差）    ← 覆盖 90%
需要环绕/漫游的镜头       → ④ 全景图 skybox
需要人物与场景互动/穿越   → ② 粗模（只求遮挡与透视，不求贴图精度）
极少数关键镜头           → ① 导入建模（可选，非必需）
```

**为什么这样分**：场景的价值在于**画面好看 + 透视对**，不在于模型精度。
- AI 生图恰恰**最强**在"画面好看"
- 深度图能**低成本**解决"透视对"

⇒ **用 AI 的强项（生图）去做背景主体，用轻量几何（深度/全景）补运镜需求**，这是性价比最高的组合。

## 2.5 因此场景侧的补件清单（按优先级）

| # | 补什么 | 成本 | 解决什么 |
|---|---|---|---|
| 1 | **深度估计**（Depth Anything V2，模型仅 ~100MB，本地可跑） | **很低** | 打通「2D 背景图 → 2.5D 视差运镜」——**最高性价比** |
| 2 | **场景库**（照角色库模式克隆 SceneStore：场景名/风格/参考图/深度图/可用机位） | 低 | 场景可复用、可绑定（同角色锚定的套路） |
| 3 | **接通 panorama 节点**（现已存在但不可执行） | 低 | 环绕/漫游镜头 |
| 4 | 背景生成配方（场景提示词模板 + 风格锚定） | 低 | 同场景跨镜头风格一致 |
| 5 | （可选）GLB 导入 / 单图转 3D | 中 | 少数需要 3D 互动的镜头 |

> ⚠️ 注意顺序：**先做 1（深度）+ 2（场景库）**，就能覆盖绝大多数漫剧镜头；
> 用户提的「AI 粗模 + 贴图」应排在最后——它成本高、收益窄，且不是刚需。

## 2.6 一个关键判断（回答你的原问题）

> **场景不需要「高精度建模」，需要的是「画面质量 + 透视正确」。**
> 而 AI 生图天生解决画面质量，深度图廉价解决透视 ⇒ **场景侧根本不必走建模路线**。
>
> 你的方案（AI 粗模 + 2D 贴图）**方向没错但代价过高**——它是"用 3D 的思路解决 2D 的问题"。
> 真正的最优解是：**2D 图当主角，深度/全景当配角，3D 只在少数镜头出场。**

# 第三部分 合并结论：两条建议的执行序

| 序 | 动作 | 属于 | 成本 | 收益 |
|---|---|---|---|---|
| 1 | **预设动作库 + 镜头模板** | 差异化（零门槛） | 极低（纯数据+前端） | ⭐⭐⭐ |
| 2 | **深度估计 + 场景库** | 场景方案 | 低（小模型+克隆现有模式） | ⭐⭐⭐ |
| 3 | 下 ControlNet 权重 + 逐帧生成拼片 | 控制层接模型 | 低 | ⭐⭐⭐ |
| 4 | 一键驱动入口（图/视频/文字→控制层） | 零门槛 | 中 | ⭐⭐ |
| 5 | best-of-n 自动选优（刀 A2） | 减抽卡 | 极低 | ⭐⭐ |
| 6 | 全景节点接通 + 背景配方 | 场景方案 | 低 | ⭐⭐ |
| 7 | （可选）单图转 3D / GLB 导入 | 场景方案 | 中 | ⭐ |
