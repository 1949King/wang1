## ② 实测约束（硬事实，决定方向取舍）

### C1：RAM 15.3GB 是 Wan 系视频的**硬墙**（不是 VRAM）

Wan 全系（1.3B / 5B / 14B，T2V / TI2V）都绑 **umt5-xxl 文本编码器 = 10.58GB（bf16）**
（ModelScope `muse/wan2.1-umt5/umt5.safetensors` 当日 API 实测）。

DiffSynth 的 `cpu_offload` 模式（`pipelines/base.py:326-356`）要求**全量权重驻留 RAM**：
DiT 2.6GB + T5 10.58GB + VAE 0.5GB ≈ **13.7GB pinned**，加 OS 占用 > 15.3GB 总量。
`offload_to_disk=True` 在 0.7.0 的真实语义是「用完即焚」（`model_lifecycle_finish` 删除模型），
且 `__call__` 内部不触发 —— 救不了首次加载峰值。
⇒ **本机跑 Wan 视频不可行**，与 V4.40.16 在 diffusers 路径的实测结论一致（「offload 不动那个 T5」）。

### C2：量化 T5 当前**无货**（双渠道实测）

GGUF/FP8 版 umt5-xxl：ModelScope 6 个候选 id 全部 HTTPError；
HF 镜像 `city96/QuantFactory` 两个候选 401（2026-10-02 实测）。
⇒ 「等量化 T5」是看板项，不是计划项。

### C3：图像族**无此墙**

SD1.5 文本编码器 CLIP 仅 0.46GB；一体化权重 3.97GB（UNet+CLIP+VAE，
ModelScope `AI-ModelScope/stable-diffusion-v1-5` 当日 API 实测）。
RAM/VRAM 均无压力 ⇒ **主选引擎的真实落地口在图像**。

### C4：视频侧自研 SVD 已是本机最优

8GB VRAM + 15GB RAM 下唯一跑得动的视频模型 = SVD（i2v，4.2GB fp16 子集），
已调优到 1.6x（10 帧 48.9s）。短期内**没有任何视频模型能在本机超过它**。

## ③ 迭代方向分层

> 北极星对齐：先剪辑（稳→快→全→可维护），后 AI 闭环；四大缺口顺序 ④抽卡→①编剧→②导演→③美术。
> 本规划只动「执行引擎」这条线，不越界改优先级链。

### P0（本轮执行）：主选引擎落地 = 图像族（SD1.5 → SDXL）

- **做什么**：`app/core/neural/diffsynth_image.py` 适配器（对齐 `video_gen` 契约：
  is_available / pull / load / generate / unload + `publish_to_inbox`），
  首模型 SD1.5（3.97GB，ModelScope 直下），随后 SDXL（6.9GB）。
- **补哪个缺口**：M3「图像 ≥2 族（当前为 0）」；主选引擎从「装了」变「在用」。
- **不做什么**：不接画布 UI（先引擎层 + 测试，UI 随后单独一轮）。

### P1（下周）：自研 W1 剩余 + W2 量化档

- W1 剩余：`memory_policy` 的 `layer_disk_offload` 从预告变真实现（对标 DiffSynth
  `pipelines/base.py:326` 的 swap 机制 + `utils/offload.py` 的 pin_memory 做法）。
- W2：`quant` 档（NF4/INT8），**画质退化 PSNR ≥30dB 才上线**（路线图既定门）。

### P2（看板，不排期）：Wan 视频

- 触发条件（任一）：① 社区出 GGUF/FP8 量化 umt5-xxl（盯 `city96` / `QuantFactory` / `muse`）；
  ② 硬件升级（副线 5070Ti/5080 16GB 评估中）；③ DiffSynth 出真正的逐层磁盘卸载（RAM 零驻留）。
- 盯法：每月第一天 API 探一次两个渠道（脚本化，5 分钟）。

### P3（既定顺序，本轮不动）：四大缺口

④抽卡闭环（seed 透传 + draw_book + gen_critic）→ ①编剧 → ②导演·节奏 → ③美术·母版。
**与执行引擎线的接口**：抽卡闭环落地时，图像族（P0 产物）就是抽卡的第一批候选源。
