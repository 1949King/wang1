## 1. 产品定位与北极星

### 1.1 是什么

**拾光剪影**是 PyQt6 桌面端「**短剧精剪 + AI 导演台画布**」。活路径只有两条：

- **剪辑模块**（时间线编辑、预览/播放、导出）
- **AI 画布**（导演台节点、生图/生视频、含智能体与画布数字人）

运营/发布、短剧筛选已**彻底删除**（2026-09-15），不再作为迭代主题。

### 1.2 北极星（当前）

> 竖切可重复：**导演台（含数字人）→ 分镜图 → 入轨精剪**。智能体只做「确认后执行」的遥控器，**不默认一键成片**。

### 1.3 四条专注轨（资源配比）

| 轨 | 配比 | 内容 |
|---|---|---|
| **N 剪辑** | ~30% | 时间线手感、建议入轨、冻结区回归 |
| **P 画布** | ~35% | `vendor/shiguang-canvas` 节点/落盘/诚实生成 |
| **A Agent** | ~25% | 白名单、确认后拉片/去水词/批量；剪辑↔画布 round-trip |
| **D 数字人** | ~10% | 画布 `digitalHuman` 节点（TTS+形象；口型成片有模型再接） |

### 1.4 明确不做

- 不重写时间线架构（真相源永远是 `EditorModule._clips`）
- 不换壳：Wails / OpenTake-Tauri 宿主 / tldraw 替换主画布 / Dify 当剪辑运行时
- 不默认「一键全链路成片」当主入口
- 不恢复短剧筛选/账号运营的功能体（仅保留接口壳）
- 不做 D1–D4（向量库 / 智能 B-Roll / 万能 EDL / 完整的转场库）

## 3. 架构分层与真相源

### 3.1 分层铁律

```
Application (main_qt6.Application)
  └── MainWindow + ModuleRegistry（懒加载 LEGO 模块）
        ├── ui_widgets / modules/lego    # UI：只负责渲染、交互、事件分发
        ├── app/core                    # 业务：数据、状态、渲染调度、AI 调用
        └── app/main_qt6.py             # 入口：调度
```

- UI 层不写复杂业务逻辑；core 层不写界面代码。
- 模块间优先 **EventBus**，避免硬依赖、跨模块硬编码。
- 状态（登录/权限/版本/用户）统一归集 auth/core 相关模块，禁止 UI 层乱放全局变量。

### 3.2 真相源

- **时间线真相源 = `EditorModule._clips`**。
- 禁用 `AppState`、孤儿 `ExportRenderer`（已清理，见[12-app_state](#附录)历史说明）。
- 轨索引用 `find_track_index_by_type`，禁止硬编码 `track == 1`。

### 3.3 双内核调度（`app/core/editor_scheduler.py`）

| 操作 | 倾向内核 |
|---|---|
| preview / probe | LIGHTWEIGHT（PyAV） |
| clip / export / multi_track / ai_clip | PROFESSIONAL（FFmpeg/MLT） |

### 3.4 渲染三级 fallback

```
RenderManager.render()
  ├─ ① C++ 引擎（NVENC/QSV/AMF 硬件加速）
  ├─ ② FFmpeg CLI（subprocess）
  └─ ③ CPU 回退（moviepy/纯计算）
       └─ 失败自动降级，需保留兼容回退
```

- 导出统一走 `RenderManager` + `editor_export`，禁止在 UI 里硬拼复杂 FFmpeg 命令。
- GPU 检测统一走既有 `GPUDetector`/`HardwareDetector`，禁止重复造硬件检测逻辑。

共 **9** 个 zone、**85** 个锁点。改这些范围前必须先获用户「解冻 \<zone-id\>」，改完 `--update` 并确认输出 `OK frozen zones intact`。

**`stage3d-core`（3D导演台 · 模型渲染与桥接）锁点**（2026-08-20 冻结，`symbols=[]`，按整文件哈希锁定 7 个文件）：
- `bodyFigureUrl` 只返回 `bodychan.glb` / `bodykun.glb`（来自用户 blend 文件）
- `prepareBodyFigureMeshes` / `loadGLBRiggedHumanoid` 加载 GLB 后不覆盖、不替换原始材质与颜色
- 端口锁定：`canvas_bridge` **18765**、`canvas_runtime` 静态 **3011** / dev **3010** 不得改
- `export_vinchau_glb.py` 导出不改骨名映射、不改材质设置
- **画布预热只能在模块可见时触发**（`_bootstrap_if_visible` / `showEvent` + `_booted` 幂等）；不得恢复 `setup_ui` 末尾的无条件 `QTimer.singleShot(200, self._bootstrap)`（2026-09-13 加锁）
- **角色库字段六处同步**：`CHARACTER_FIELD_SCHEMA` 新增字段必须同步 `canvas_bridge.build_character_prompt`（仅 visual 组才进提示词）、`canvas_server./host/characters`（按 schema 派生并下发拼好的 `prompt`）与两个前端包的 `CharacterEntry`（含派生字段 `prompt`）；画布 `store.ts` 的绑定/解绑/同步必须消费服务端下发的 prompt，**不得自己拼字段**。静态校验 `_verify/check_character_schema.py`（六处）+ 行为校验 `_verify/check_char_prompt_block.mjs`（Node，抽真实源码跑）（2026-09-13 加锁，同日字段由 10 扩到 20，V4.14.5 起五处→六处）

锁定整文件（7 个）：`vendor/shiguang-canvas/src/{riggedHumanoid.ts, Stage3D.tsx, stage3dControlNet.ts}`、`app/core/{canvas_bridge.py, canvas_runtime.py}`、`app/modules/lego/character_management_module.py`、`scripts/export_vinchau_glb.py`。

**`canvas-magnetic-intent`（画布磁吸意图系统）核心不变量**（33 个整文件，清单见 `frozen_zones.json`）：
- 磁吸等级判据用**边缘间隙 edge-gap**，不是中心距（卡片 240×200，并排贴合时中心距恰 240px，用中心距判 25px 阈值必然失效——V4.13.0 修正的根因）
- 阈值 weak/medium/strong/instant = **120/50/60/10px**、过冲 5、回弹 200ms、拉伸 30、断裂 50
- **跟手浮起 + 松手落座**（2026-09-18「借鉴手机主屏拖拽手感」，推翻 V4.28.2）：拖拽中 `onNodeDrag` **绝不覆写卡片位置**（不调 `writeNodePos`），卡片 1:1 跟指针走，只记录 `magState`；松手才走 `animateNodeTo(snapAnimationMs=200)` 平滑滑入，强吸附（strong/instant）带 `overshootPx(5)` 过冲。禁止恢复「拖拽中直接贴齐落点」
- **单轴吸附**（2026-09-18）：`getSnapPosition` 只动被吸附的那一轴——吸左右时 `y` 取拖拽卡当前 `y`，吸上下时 `x` 取拖拽卡当前 `x`；禁止硬取 `targetPos` 的另一轴坐标（旧行为实测垂直错开 180px 时落点瞬移一整个卡高，是「上下吸附不对」的真实根因）
- **整列让位**（2026-09-18「借鉴手机主屏拖拽手感」第 2 条机制）：`magnetic/reflow.ts` 的 `planReflow()` 纯函数规划——挡住落位点的**同行/列**卡片顺次推开一格，拖拽卡落进锚点让出的坑。三条红线：① 只推同行/列（对侧轴投影重叠 ≥ 40px，与 `bonds.ts` 同尺）；② 链式**整体平移一格**、绝不递归放大；③ 推动后撞上同行紧贴的链外卡则整条链放弃。层叠（两轴均插进）不让位。**时序红线**：拖拽中只记录 `reflowPlan` 预览、绝不移动任何卡（含邻居）；位移一律在 `onNodeDragStop` 执行，顺序为「邻居先滑开（180ms）→ 拖拽卡再落进 ghost」。预览组件 `magnetic/SlotGhost.tsx`（ViewportPortal 虚线框）
- **空间记忆第一层**（2026-09-18「下一代概念」首落）：`NoviceCard` 挂 `data-depth`(= `intentDepth`)，CSS 三档配色**只允许改颜色**（`filter` + 描边透明度）——不得改尺寸（破坏磁吸落位基准 240×200）、不得加 `box-shadow`、不得改圆角
- **画布版本号单一事实来源**（2026-09-19）：画布版本线与主程序**刻意不同步**——主程序在 `app/version.py`（Qt6 侧显示），画布只能来自 `src/canvasVersion.ts` 的 `CANVAS_VERSION`（导航栏 `.ic-nav-ver` 显示）。**禁止在组件里内联版本字符串**；`AppNav` 的 `version` 为必填参数（已移除默认值）。维护三件套：改 `canvasVersion.ts` → 同步 `package.json` → 记 CHANGELOG
- Bond 咬合由几何推导（边距 ≤2px 且投影重叠 ≥40px），不落盘、刷新后自动恢复；只认 左/右/上/下 四向缝
- 拖拽分离阻力三段式：≤30px 不动 / 30~50px 只跟出 28% / ≥50px 断裂
- 小白模式 `snapToGrid` 必须关闭
- 卡片视觉（2026-09-18「1+4 结合」）：大圆角 **16px** + 深色实色块（`#151a26`）+ 类型色由标题栏整块承载 + 选中白描边环；拖拽占位线为蓝色直线占位缝（`#378ADD`），替换旧弯曲发光磁力线

（磁吸系统 33 个整文件清单见 `docs/knowledge/frozen_zones.json`，机器校验 `scripts/frozen_zone_guard.py`。）

**音画纠偏**：约 **280ms**（冻结），勿压回 80ms。

## 7. 编码规范（浓缩）

- 命名：类大驼峰；方法/函数 `snake_case`；私有成员 `_` 前缀；常量 `UPPER_SNAKE_CASE`；变量见名知意。
- 导入：标准库 / 第三方 / 本地项目模块三段分组；优先 `from app.xxx`；禁冗余导入与循环导入。
- 分层：UI 只渲染；core 处理数据与状态；MainWindow 调度；不跨层硬编码调用。
- 注释：类与核心方法必须说明职责；关键逻辑加行内注释；不写废话。
- 异常：禁止裸 `except: pass`；必须记日志或给用户清晰提示；必填/格式校验、按钮防重复点击覆盖。
- 日志：core 用 `logger`，禁止裸 `print()`。
- 弹窗：必须绑定 `parent`；关闭后刷新父界面；耗时任务后台线程 + 信号回主线程更新 UI。
- 状态：登录/权限/版本/用户归 auth 模块统一管理。
- 修改原则：**最小侵入、最大兼容**；保留旧路径或 fallback；不擅删原代码、不私增无用文件。
- 验证：改 Python 后至少 `py_compile` 或对应测试；改导出/渲染后验证 C++/FFmpeg fallback。
